> **本项目独有的"踩坑记忆"**——只属于这个项目的坑：特定样式/主题色、本项目的字段命名怪癖、这套技术栈/库的专属陷阱、某个模块的隐藏规则……随本项目走、提交进本项目 git。

## 规矩（dev agent 必须遵守）
1. **开工前**：本文件 + 全局 `$STEWARD_LESSONS` **两层都扫一遍**，避开已知坑。
2. **收尾时分流**：解决了非显然的坑 →
   - **只对本项目成立**（样式/主题色/本项目字段或模块怪癖）→ 记**这里**。
   - **换个项目也会犯**（通用交互/通用功能/通用栈陷阱）→ 记**全局** `$STEWARD_LESSONS`。
3. 显然的小改不用记；宁缺毋滥，只记真实发生、确认有效的解法。

### L-011 运营端统一自定义下拉组件（ui.js 的 `.ui-sel-*`）：值同步靠 setter 覆盖 + 派发 change{bubbles:true}；面板 position:fixed 逃 overflow；只接管 `.select` 别碰 `.fancy`/field.html

- 解法：① **保留老 `.fancy` IIFE 不动**，新增独立 IIFE 接管 `select.select`（`window.enhanceUiSelect`）；两者天然隔离（无 select 同时挂 `.fancy`+`.select`）。② 自动增强 = **初次扫描 + `document.body` 子树 `MutationObserver`（childList+subtree）**，凡 `select.select:not([data-enh])` 出现即增强、打 `data-enh="1"` 防重；`<select multiple>` 跳过留原生。③ 值同步三管齐下：`Object.defineProperty` 覆盖 select 实例的 `value`/`selectedIndex` setter（调 `syncFromSelect()`）+ 监听 select 自身 `change` + `MutationObserver`（childList 选项变 / attributes `disabled`）；选中项时**回写 `select.value` 并 `dispatchEvent(new Event('change',{bubbles:true}))`**——这一式保住每页原有 `select.value`/`addEventListener('change')` 逻辑零改动。④ 面板 `position:fixed` 挂 `document.body`、据 `trigger.getBoundingClientRect()` 定位（下方空间不足则上翻）、`z-index:9600`（盖过 drawer/modal 300/310 与 ui.js 弹窗 9000）——**逃祖先 overflow 裁剪**（与 field.html `.f-proddd`/L-010 同一招）。⑤ 每个 select 的增强 `try/catch` 兜底，失败复原原生 select（清 `data-enh`+恢复可见）不冻结页面。⑥ 样式**内联注入**（`<style data-ui-sel>`，用 theme.css token）——未改 theme.css；`.filter-bar .ui-sel-trigger` 镜像 `.filter-bar .select` 收到 30px/12.5px。
- 防复发：见自检清单三条新增项。回归 `tools/ui-select.test.mjs`（A 组源码静态 + B 组手搓 fake DOM 实跑「点选→value 变+change 冒泡」load-bearing 路径 + C 组护栏 field.html 0 处 ui.js / submit.html `.fancy` 保留）。删/改 `ui.js` 下拉相关代码前，先 `grep -rn 'class="[^"]*fancy' public/*.html` 确认 `.fancy` 仍有人用（submit.html）。

### L-007 全库跨产品聚合 kbSearch 要在外层「重算分」——kbSearch 只回排好序的 Top-N、不带分数
- 范围/模块：intake · 经验库检索（server.mjs kbSearch / /api/kb-search）· FS-07
- 现象：FS-07 要做「全库跨产品检索」——遍历所有产品各调 `kbSearch(pid,q,n)` 再合并成全局 Top-N 按分排序。想直接拿每条的分数合并，但 `kbSearch`（L475）**只返回排好序的内存对象数组**（`[{id,q,a,subsystem,module,tags,from,at}]`），**不带 `sc` 分数**——各产品内部排好序了，但跨产品合并没有可比的全局分。

- 防复发：见自检清单。凡要「跨产品/跨集合合并 kbSearch 结果并全局排序」，别指望 kbSearch 回分数——外层用 `kbTokenize` 同口径重算（保持打分逻辑单一事实源在 kbSearch 里、外层只复制 token 重叠计数），别改 kbSearch 签名去塞分数（会波及 consult/intake-chat 两个内部调用方）。

### L-003 注入式 shell 套壳：全高内滚页要 data-content-layout="list"，否则内部滚动区塌成 0 高
- 范围/模块：intake · 前端外壳（public/assets/shell.js + theme.css）· UI-01
- 现象：把 UI-01 re-target 到原型的注入式 `shell.js`（收集页面内容进 `.page-content` 再注入侧栏+顶栏+多标签）。inbox/projects 原本靠 `body.sidebar` 撑满视口、内部 `.content{flex:1;overflow:auto}` 内滚；套壳后若直接放进普通块级 `.page-content`，`#app{flex:1}` 没了 flex 父 → 高度塌陷、内部滚动区变 0 高、表格/列表看不见。
- 根因：`.page-content` 默认是 `flex:1;min-height:0;overflow-y:auto` 的**块级**容器（走整块滚动），而这些页的内部结构 `#app{flex:1;min-height:0;display:flex;flex-direction:column}` 依赖**祖先是 flex 列且高度受限**才能让子级 `flex:1;overflow:auto` 生效。块级父下 `flex:1` 被忽略。
- 解法：给 shell 加 `data-content-layout` 开关 —— `<body data-content-layout="list">` 时 shell 给 `.page-content` 加 `list-layout` 类（`theme.css`：`display:flex;flex-direction:column;overflow:hidden`），恢复 flex 列 + 内滚骨架。只给 inbox/projects 标；`.wrap` 型页（console/detail/customers/kb/accounts/model-config）保持普通 `.page-content` 整块滚动。
- 防复发：见自检清单「注入式 shell.js 套壳：全高内部滚动页要 data-content-layout=list」。判断法 = 页面原来是否靠 `body.sidebar` + 内部 `overflow:auto` 内滚。
- 关联：UI-01 AC-19；public/assets/shell.js（pcCls / data-content-layout）；theme.css `.page-content.list-layout`；tools/ui-shell.test.mjs A17。

### L-004 re-target 原型抽屉页：部署 shell.js 无 UI.openDrawer + 原型 mock 字段名 ≠ 真实端点字段

- 防复发：见自检清单「shell.js 无 UI.openDrawer」「工单管理前端事实源 re-target 原型」两条。凡「照原型 HTML 重做部署页」，先核对：a) 原型引的 JS(shell.js/mock-data.js) 部署有没有同名同能力的；b) 原型 mock 字段名逐个对真实端点出参（禁止把 mock 字段当真）。
- 关联：TK-01 AC-1/3/11~22/30；public/inbox.html；spec §5.4；theme.css `.drawer`/`.pipeline`/`.decision-option`。

### L-005 写「不得依赖某 token」的静态断言时，被测文件里的注释别写该 token 字面量
- 范围/模块：intake · 测试（tools/*-01.test.mjs 前端静态断言）· 多页 re-target 通用
- 现象：给页面写 `assert.doesNotMatch(html, /UI\.openDrawer/)`（校验抽屉自写、不依赖 shell.js 没有的 helper）时，页面里一句解释性**注释**「// 部署 shell.js 无 UI.openDrawer」含该字面量 → 断言假阳性失败。KB-01/MC-01 两个 agent 都踩了。
- 根因：`doesNotMatch` 扫全文含注释；解释性注释无意中留了触发词。
- 解法：① 注释改等价说法（「无 openDrawer helper」）不留 token 字面量；② 或断言收窄到调用形态 `/UI\.openDrawer\(/`（带括号，只命中真调用）。
- 防复发：见自检清单。凡"禁止出现某 token"类静态断言，源文件（含注释）别留该 token；断言尽量匹配调用/DOM 形态而非裸字符串。
- 关联：L-004；KB-01/MC-01 测试。
