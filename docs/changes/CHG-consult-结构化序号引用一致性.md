# CHG · 咨询终稿结构化序号引用一致性

## 现象

生产可见浏览器复测中，答复声明对照三份值并只定义①②③，却在后续判断和留证中引用未定义的④。业务事实与动作边界没有出错，但实施无法确定④代表什么。

## 修复

- 最终语义审计建立圈号定义集合，支持行首、Markdown 表格单元格及冒号/分号内联枚举。
- 后文出现没有前文定义的圈号时记录 `undefined_ordinal_reference`，在同一次请求中触发一次不新增事实的全文修订。
- 修订仍失败时按完整自然句或完整表格行删除含未定义序号的内容，不通过局部 token 替换制造残句，也不凭空补造新项。
- normal/deep 共用的运行时终稿守卫同步要求编号定义和引用一致。

## 验证

- `node --test tools/fs-04-consult-conversation.logic.test.mjs tools/pd-02-prompts.logic.test.mjs`
- 负例：表格只定义①②③，后文引用③/④及“有则含④”。
- 正例：冒号/分号内联定义后复用；表格定义①②后在正文复用。

本次不改数据库、业务接口或 PWRS 业务代码。
