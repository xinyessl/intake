# CHG · 认证授权链路语义分层

- **日期**：2026-08-31
- **来源**：浏览器正式测试 Q0849。模型截断后的确定性链路虽已具备结构，但宽关键词分桶把安全说明误标为入口，把 `/comm`、`/external` 与 Shiro/JwtFilter 分支误标为数据与状态，产品和实施难以按链路理解。
- **类型**：纯缺陷修复；既有认证、授权和外部依赖事实不变，因此不修改 spec。

## 改动

- 仅当 current route 明确同时提供认证实现事实、授权边界事实和链路所需维度时，启用认证授权专用语义分层。
- 输出按“业务入口 → 接口认证分支 → 授权/数据边界 → 外部依赖 → 证据停点”排列；没有已核入口或真实外部调用证据时直接说明未知并停住。
- 裸接口路径归接口认证分支，不再因“请求/响应”等宽词被误标为数据；页面可见与方法级权限事实归授权/数据边界。
- 普通业务 route 只有具体路径与通用权限说明时不触发该分层，保留原链路生成逻辑。

## 验证

- Q0849 精确验证维度标签、先后顺序、用户中心外部依赖、真实外部调用证据停点及 `finalViolations=[]`。
- Q0029 作为普通业务链路反例，确认不被认证分层误触发。
- Conversation + safe-final-stream：54/54 通过；`node --check`、`git diff --check` 通过。
