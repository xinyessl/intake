# CHG · consult 答疑 —— 覆盖判定从「精确覆盖才答」再平衡为「相关就尽量答、只是不臆造具体名，完全不相关才说没覆盖」

- 日期：2026-08-11
- 关联 spec：无（提示词规则再平衡，行为强化，非结构变更）。这是对上一条 CHG（`CHG-consult答疑-未覆盖简洁说没覆盖不硬编-KB注入二次门槛.md`）的**修正**——上一版把门槛调得太严，本条把它调回可用的平衡点。答疑「据证据作答、不臆造」的 spec 意图未变。
- 类型：逻辑/行为调整（提示词规则再平衡），**不改库、不改接口契约、不改 SSE 事件结构、不改 server.mjs 的 KB 二次门槛、不改路由**。
- 改动文件：`prompts.mjs`（`DEFAULT_PROMPTS.consultNormal` / `consultDeep` 首条规则重写）、`tools/pd-02-prompts.logic.test.mjs`（`refConsultSystem` 逐字参照同步）。

## 现象（用户真实反馈 + 已回放确认）
上一版（前一条 CHG）加的规则是「先判是否**直接覆盖那个精确点**，没覆盖就一句话说没覆盖」——门槛太高：
- 「患者视图通过床位号无法查询出患者」→ 检索到高度相关的 `患者列表与筛选`(16.8 分) + 路由 QR-DQ-004（患者查询），**内容相关**，却被答「没覆盖」。
- 大量本可帮实施排查的问题被一刀切拒答。用户反馈：「限制太死，基本问题都答不出来了。」

**但原始痛点仍要防**：问「检验报告异常值箭头」，检索到的是**完全不相关**的（患者外网自助/登录鉴权），AI 却凭常识编了 4 步排查——不相关时必须老实说没覆盖，别臆造具体技术细节。

## 修复 —— 判据从「是否精确覆盖」改成「是否相关/能否帮上忙」
`prompts.mjs` 的 `DEFAULT_PROMPTS.consultNormal` / `consultDeep`「规则：」区**首条**（上一版加的「最高优先·先判是否真覆盖」那条）整条重写为**平衡版**，三档：

1. **只要检索到的规格摘录/源码/经验库与问题相关**（同一功能/模块/主题、能帮上排查或理解）→ 就据真实内容尽量帮实施把问题讲清楚：给相关规则/机制/配置逻辑/排查方向，帮 TA 定位，**不要求 100% 精确讲到那个点**也可以答（如「床位号查不到患者」，摘录/源码里有患者列表/查询的相关内容，就据此说清查询怎么匹配、先查什么，别因为「没逐字讲到床位号」就拒答）。
2. **红线·不臆造具体技术名**：绝不编造规格/源码里**没有出现**的**具体**表名、字段名、接口路径、配置项 key、开关名——没依据的具体技术细节一律不写；拿不准就说「具体的表/字段/接口这块说明书没写明，建议转工单或问开发确认」。一般性排查方向/思路可以给，但别把猜的具体名当事实。
3. **只有当摘录/源码/经验库跟问题基本不相关**（明显是别的模块/别的主题、帮不上忙，如问「检验箭头」却只检索到「登录鉴权/患者外网自助」）→ 才**只回一句话**：「当前系统说明书摘录（deep：/源码）里没有覆盖【用户问的那个点】，建议转成工单或联系开发确认」，这种情况下别凭空编排查步骤。

deep 版同理（把「源码片段」并入「相关内容」的判断对象、话术带上源码，作答优先据源码的实际实现）。**其余规则一字未动**；`{{specExcerpts}}` / `{{codeExcerpts}}` / `{{kbBlock}}` / `{{subsSentence}}` / `{{specIndexBlock}}` / `{{projectName}}` 等占位全部保留。

## 与上一版的差别（核心）
| | 上一版（过严） | 本版（平衡） |
|---|---|---|
| 判据 | 是否**直接/精确覆盖**用户问的那个点 | 是否**相关/能否帮上忙**（同功能/模块/主题即算） |
| 相关但没逐字覆盖 | 拒答「没覆盖」 | **据相关内容尽量答**，给排查方向 |
| 不臆造的边界 | 沾边就整段拒 | 只**不写没依据的具体表/字段/接口/配置/开关名**，一般思路可给 |
| 完全不相关 | 一句话说没覆盖 | 一句话说没覆盖（**不变**） |
