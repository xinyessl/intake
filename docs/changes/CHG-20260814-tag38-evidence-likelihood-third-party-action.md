# CHG · tag38 原因概率证据门与跨主体动作审计

- 日期：2026-08-14
- 关联：FS-04 AC-59/AC-60、Q0120–Q0128 浏览器回归
- 类型：咨询答疑通用安全与事实边界修复

## 变更

1. `consultNormal` / `consultDeep` 默认提示词新增原因概率证据门：没有 Spec 正文、源码、已核经验库或统计样本直接支持时，不再使用“最高频/最常见/通常/大概率”等词排序成因，只列不排序待验证分支。
2. 删除排查格式旧规则中“必须先说最高频原因”的反向诱导，改为先给已核结论和依据本轮证据可区分的分支；核心事实答清即停，不补模板变更、复制重存或行业惯例。
3. 运行时追加最终证据与概率语言审计，并把动作一致性扩展到实施、患者、对接方、运维和开发。改参数、报文类型、映射、配置后复测，或运维重跑、开发重试，不因执行主体变化而绕过只读/完整受控条件。
4. PWRS 患者号字段 route 补充窄自然问法“患者号少一位/字段对不上/丢位精度/数字还是字符串”，并保留患教身份、患者列表、token 等反例不抢路由。
5. 生产 Chrome 首轮暴露模型仍在答案中写“多半是服务端时区差”；r2 消除该词后，又暴露“转运维/开发改时区”的执行主体绕行。因此新增并扩展服务端发布前确定性语义校验：首轮完整草稿先留在服务端，命中无证据概率词或跨主体副作用动作（含改参数/映射/配置、改时区/系统时间/环境、复测/重跑等）时最多调用模型修订一次；修订仍失败则删除违规句并降级为安全边界。未经校验的草稿不先流给浏览器，结果写入 `retrieval.answerAudit` 并随 SSE 透出，便于生产回放。
6. r3 Chrome 回归中，模型把已核 `/pwrsapi/month/view/today` 缩成 `…/month/view/today`，并臆造无前缀的 `/month/view/today`。r4 将具体路径纳入同一发布前确定性审计：只允许当前问题或 route/Spec 事实中的逐字路径；前缀、路径段和尾斜杠任一漂移均触发一次修订，失败删除新路径并改为“该已核接口/当前请求”。
7. r4 Chrome 又暴露路径提取器把“服务器/JVM”中的 `/JVM` 当作路径，安全降级破坏原句。r5 将前置边界改为 Unicode 字母/数字边界，中文/英文两侧的普通斜杠短语均不进入路径集合，同时保留空格、标点或 `GET` 后真实绝对路径的检测。
8. r5 Chrome 验证路径已安全删除，但降级残留“GET 该已核接口”且把审计元说明展示给实施。r6 改为整体替换 HTTP 方法与未核路径，输出自然的“该已核接口/当前请求”；审计原因只保留在 `answerAudit`，不污染用户答复。
9. r6 Chrome 暴露同答同时出现合法完整路径和未核短前缀时，全局字符串替换会把合法长路径内部一起改坏。r7 改为带前后路径字符边界的 token 替换：短前缀只在独立出现时降级，已核完整路径逐字保留。
10. r7 Chrome 暴露模型把 Unicode 省略号换成 ASCII `.../path` 绕过检测。r8 将 `…/path`、`.../path` 与合理的连续点+空格+斜杠变体（如 `.. /path`）都作为完整缩写路径 token 审计并整体替换，普通句号、版本号、IP 和已核完整路径边界保持不变。
11. r8 Chrome 的今天视图答复主线正确，却从相邻检索片段引入 `/comm/*`、外部调度与补跑。r9 新增当前事实作用域审计：只允许用户本轮和当前/继承 route facts/refs 的实体与路径；通配路径同样受控，越界触发一次修订，失败删除整句，诊断仅落 `answerAudit`。
12. r9 Chrome 又出现“接口与浏览器不一致很常见”，暴露概率审计只覆盖“最常见/常见于”而漏独立词族。r10 扩展到常见及程度变体、经常、多发/高发、首要/主要原因等整句概率定性；权威统计或正文明确命名仍可照实引用。
13. r10 Chrome 在今天视图排查末尾自行引入“患者 hospitalId/patientId/visitId 三元身份”作排除说明。r11 将相邻业务实体词族与强业务标识符统一纳入当前事实作用域审计：自动识别 camelCase 的 `*Id/*Code/*Status/*No/*Type` 和 snake_case 复合标识符，仅本轮问题或当前/继承 route facts/refs 逐字出现时放行；显式新实体重路由后使用新事实，无关主题整句删除，裸 id/code/status 与 HTTP/JSON/JWT 等共享词不误拦。
14. r11 Chrome 的排查答复仍以“可能是/很像/更像”包装无证据成因，并在“由运维改时区”后用“不在实施侧乱改”逃过整句否定检测。r12 将未核成因倾向词纳入整句审计，并按每个跨主体动作前的局部否定判断，句尾否定其它动作不再抵消此前修改指令；失败仍走一次修订后整句安全降级。
15. r12 Chrome 的“只有截图、没有日志”被宽泛 DQ-013 抢路由，导致今天视图事实丢失、调度事实越界，fallback 又把未知路径局部替换成残句。r13 将“只拿得到/只有截图/没有日志”等识别为证据限制并继承原主题；修订稿、降级稿均执行完整语义与 Markdown 再审，未知路径优先删除整句，二次仍违规则安全停止，同时在 answerAudit 记录修订违规和降级轮次。
16. r13 Chrome 的今天视图排查仍用“最容易出现”和“优先查服务端时区”给未核成因排序。r14 将“最/更/尤其容易、易发生”等倾向词及面向具体成因对象的“优先/首先/先查”纳入确定性证据审计；只有本轮已给具体现象差异或 route/Spec 明确顺序时放行，权威步骤编号与只读采证流程不误拦。
17. r14 Chrome 虽移除概率排序，仍在条件分支把“前端展示/缓存异常”写成故障定论，并以“只能改部署时区或产品口径”给出无主体副作用方案。r15 不再按句式补词，而把诊断最终稿统一约束为已核事实、本轮观察、明确待验证假设、安全动作四类；未核组件故障触发修订，配置/时区/口径修改无完整受控条件时按动作本身删除。
18. r15 Chrome 的四类审计仍被“页面用了别的数据源/缓存”绕过：句子没有“异常/故障”后缀，却从相邻知识引入未点名实现机制。r16 把诊断技术机制纳入 current scope 允许集合；缓存、数据源、兜底、中间件等只允许来自用户本轮或 current/inherited route facts/refs，否则整句删除并退回不点名机制的呈现链路待验证。
19. r16 Chrome 的诊断答复用“很多是规则内的预期”绕过概率词族，并以“对齐服务端时区与业务日切要求”委婉建议配置/口径动作。r17 将无统计依据的模糊比例词纳入同一语义门，并把对齐、校准、统一参数/配置/时区/业务口径纳入副作用审计；仅对照已有请求、响应和页面的只读比较放行。
20. r17 Chrome 虽守住比例与动作边界，仍把绝对接口缩成不带前导斜杠的 month/view/today、month/view，并在结尾引入未点名的折线图/统计同步。r18 将 slash-separated 裸相对路径纳入逐字路径审计，只有用户/route 本身逐字给出才放行；相邻组合实体进入 current scope 短语表，显式切题仍可重新路由。
21. r18 Chrome 在同一今天视图 route 内仍写“服务器时区非东八区、临近午夜更容易暴露”。r19 将概率放行从 route 全局布尔收紧为自然句 claim 级证据绑定：无关统计词不能放行另一原因，多 facts 混合只保留同对象有证据句；东八区、UTC/GMT 偏移和 Asia/Shanghai 等具体环境值纳入 current scope 技术事实审计。
22. r19 Chrome Q123 的修订稿虽已删除越界路径与概率判断，却留下未闭合括号的半截列表项，并从相邻患者主题引入“患者入参”；r20 将患者/医生/药师/订单纳入 current/inherited scope 实体门，对最终稿增加中英文括号与 Markdown 二次完整性审计，并在请求核对且 route 只有一个已核主接口时强制逐字保留 HTTP 方法和完整路径（多接口不强塞）。
23. r20 Chrome Q120 已正确给出今天视图接口，却继续追加 Network 排查、无当前观察的鉴权失败原因、优先级和“把截图发来”邀约。r21 将原子事实题扩展到接口、路径、状态码、字段属性和是非事实，并在发布前按最终自然句删除未问诊断、原因、动作与邀约；显式“为什么/排查/现场/怎么验证/接下来”和多子问题不触发止答。
24. r21 Chrome Q121 的事实和只读边界正确，但安全降级把 Markdown 表格单元格内的中文分号按句切开，生成孤立空列行。r22 将普通段落与结构化块分流：普通段落按完整句清理，表格按完整行清理；违规单元格删除整行，最终复审列数、分隔行、稀疏残行与有效数据行，无有效行时删除整表。
