# CHG · 答疑（consult）新增「排查/操作类答复的格式规范」——连续编号 + 明确操作

- **日期**：2026-08-11
- **来源**：用户反馈——答疑给排查类问题时答复内容不错，但两个问题：① 主步骤模型写成「1. …/1. …/1. …」（每步都 1.），前端 markdown 渲染（已按源码序号渲，见 HEAD 提交 `9bcdf08 fix(ui): markdown 有序列表带真实起始序号`）就成了 1/1/1；② 用户希望排查类答复有明确、可照着做的操作步骤。
- **spec**：PD-02（提示词配置，`DEFAULT_PROMPTS.consultNormal`/`consultDeep`）。**这是提示词正文里的「输出格式规范」，不改任何行为规则**（覆盖判定、红线、正文顺序、技术依据、KB 门槛全不动）→ 归 §4.5「重构/格式微调（行为不变）」类，**不改 spec**，CHG 记一条。
- **范围**：**只改** `prompts.mjs` 的 `consultNormal` / `consultDeep` 两条默认模板（各加 1 条规则，位于「功能级覆盖判定」之后、「默认正文顺序」之前）；同步 `tools/pd-02-prompts.logic.test.mjs` 的 `refConsultSystem` 逐字参照（normal/deep 两分支同加）以保「`renderPrompt(默认) === 参照`」逐字回归。**未碰** `server.mjs` / 路由 / KB 门槛 / 数据结构 / 前端渲染。

## 类型
格式规范补充（答复排版口径，行为不变），不涉 spec。CHG 记一条。

## 改动要点
- 在 consultNormal / consultDeep 规则区、「功能级覆盖判定」那条**之后**新增一条「**排查/操作类答复的格式：步骤要能照着做、编号连续递增**」：
  1. 主步骤用**连续递增**的阿拉伯数字编号 `1.` `2.` `3.` `4.` ……每往下一步 +1，**绝不每步都写 1.**（每步 1. 渲染成 1/1/1 是错的）。
  2. 每个编号步骤 = 一个明确动作（去哪个页面 / 点哪个按钮 / 看哪个值 / 观察什么 + 这步看到什么算正常/不正常、据此怎么判断），让实施能照着一步步做。
  3. 步骤细节 / 补充说明用 `-` 子项列在该步下面；**不要在两个编号步骤之间插入顶格大段文字**（打断编号连续性）。
  4. 先用 1~2 句给结论（最高频原因 + 怎么快速验证），再给编号步骤；保持简短可执行。
- 明确标注这条**只是格式规范**：不改变上面的功能级覆盖判定（没覆盖仍一句话说没覆盖、不硬编步骤），也不放松红线（步骤里照样不臆造具体表/字段/接口/配置名）。
- 与 HEAD 渲染器修复（有序列表带真实起始序号）互补：渲染器已按源码序号渲，本次让模型**产出连续序号**，两半合起来才不再 1/1/1。
