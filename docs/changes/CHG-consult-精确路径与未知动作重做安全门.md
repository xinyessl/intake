# CHG · consult 精确路径与未知动作重做安全门

## 背景

tag32 浏览器 Q71–Q80 严格验收暴露三处同根问题：模型把 `/comm/` 自行扩写为 `/comm`；截图不足时要求“再点一次”未知业务操作抓包；已正确回答患教签名规则后又附带真实“点完成”验证步骤。

## 通用修复

- 新增路径前缀/allowlist 精确边界守卫：证据中的斜杠与路径段逐字保留，不归一化、不补无证实例外，也不得在已核前缀后拼接自造的“示例路径”。
- normal/deep 默认提示词与运行时守卫共同禁止为抓包重做未确认无副作用的动作；优先使用已有请求、日志、审计和历史记录。
- 已核业务事实只用于回答结论，不自动授权“验证一下/试试看/用创建人点/正常点完成或提交”等真实写操作。
- 消息、通知、患教与咨询场景中的“当面确认/看看患者端/点进详情”也不默认只读；未确认打开不会改变已读、接收或完成状态前，只复用当前已显示页面、已有截图、历史状态、既有请求响应与审计。
- “这个动作/这个列表/下一步”等承接型泛化诊断只沿当前继承 route 回答，禁止因关键词召回相邻 Spec 就主动罗列用户未点名实体的接口、字段或状态。
- 保留明确只读动作；会改状态的受控验证仍须隔离环境或专用数据、授权、回滚清理、幂等与影响范围同时齐全。

## 影响边界

不修改数据库、接口契约或 PWRS 业务实现；PWRS `QR-JWT-ANON-PREFIX` 仅增强自然问法和精确边界表达，保留现有 `/comm/`、`/external`、`/swagger`、`/v3/api-docs` 权威事实。
