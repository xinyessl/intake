# CHG · 同会话已核事实在后续诊断中持续生效

- **日期**：2026-08-13
- **关联 spec**：FS-04 AC-49（现场诊断边界补充，待人验收）
- **现象**：首轮已命中退出跳转等业务 route 后，实施用“第一步看过了/接口返回 200/下一步”继续排查时，由于当前句未重复完整业务名，路由退化为 miss，答复错误地说“说明书未覆盖”。
- **根因**：承接识别只覆盖代词与保存/提交后等句首，不识别现场排查进度口语；连续两轮省略业务名时也只检查紧邻 user 句，无法回溯最近已核 route。
- **修复**：通用识别“回到/关于/第 N 步已查/接口或响应正常/接下来或下一步”等承接意图；中间仅为纯进度句时回溯最近已核 route，仍以当前直达 route、显式新实体和高风险 UI 门阻止串话。normal/deep 提示与服务端诊断守卫明确要求先应用 route/当前召回的已核事实，未知只局部限定，历史 assistant 自由文本不作证据。
- **产品地图**：PWRS `DQ-001` 补齐退出跳转权威事实：Web 经 `LcUtils.getPortalDomain()` 回 main-admin 根 `/login`，开发为 hostname:9999、生产为当前域名，不加 `/pwrs/`、不用 PWRS 自己端口；Navbar“首页”独立回根 `/home`；HTTP 200 仍需核对业务 code 与实际 Location。
- **边界**：不新增接口、数据库或业务代码；不从历史回答提取事实；新实体仍重新路由，未证实技术细节仍不得臆造。
