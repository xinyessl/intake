# CHG · tag37 咨询最终答案发布前动作一致性审计

## 背景

tag36 可见浏览器 Q0119 已正确命中“反馈发送后正文锁定、不能编辑或删除”的事实，也多次写明不要重复发送、保存或删除；但同一答案后半段仍建议“点编辑/删除看有没有请求”。旧非破坏守卫是局部禁令，未强制模型对最终成稿的全部段落统一检查。

## 变更

1. `consultNormal` / `consultDeep` 默认模板新增发布前动作一致性审计：逐项扫描正文、Markdown 表格、编号步骤、条件分支、补充说明、示例和结尾追问。
2. 动作只允许三类进入最终答案：读取已有证据；Spec/route/源码已证明无副作用的动作；隔离/专用数据、授权、回滚清理、幂等与影响范围全部齐全的条件式受控动作。
3. 新增运行时 `consultFinalActionConsistencyGuard`，在其它诊断/非破坏守卫之后注入；编辑、删除、新建、保存、提交、发送、完成、签名、审批、星标、可能标已读的打开、重试、复现、补跑等未知动作必须从最终答案所有位置删除并改查已有证据。
4. 同一答案不得一处说“不要操作”，另一处再建议点击未知按钮观察请求；用户只问按钮是否发请求时，只能使用已有请求、日志、审计、代码或契约。纯事实题答清即停，不强塞诊断步骤。

## 测试

- `tools/pd-02-prompts.logic.test.mjs`：normal/deep 默认模板逐字基线与审计契约。
- `tools/fs-04-consult-conversation.logic.test.mjs`：反馈、CRUD、患教、收费、按钮请求、只读刷新、完整受控条件、原子事实题及运行时接线顺序。
- PWRS 真实地图回归：反馈锁定 route 与权限/收费/患教等相邻主题不串，显式新实体覆盖旧主题。

## 数据与接口

不新增接口、不改数据库、不改 PWRS 业务事实；仅调整咨询生成约束与回归规约。
