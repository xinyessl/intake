## 新逻辑全链路（定稿）
```
实施提单(带图) → 运营【逐单评审】(落实/暂缓/驳回) → 运营【定档】
→ 分批次：该产品所有"已落实"单(跨全部医院合并) → 一个批次(=一条产品线)，内部【按子系统分组】
→ 【导出开发清单】(按子系统·描述清晰·带截图) → 开发拿清单去 steward 做
→ steward 打包 →(外部测试验收·框架外)→ 【管理身份上传包】(填包版本/说明/地址 + 转「可下载」)
→ 实施【下载/应用更新包 + 一键改版本】 + 【逐单确认"现场验证过"】(不过→人工反馈)
→ 全批单验证过 → 批次闭环(已交付)
```

## 相对原设计推翻的点（写进两份 spec §0）
1. **批次粒度**：产品·固定周期（一周期一包） → **一条产品线一批**，跨全部医院合并，内部按子系统分组；去掉 `uk_product_week` 唯一约束（同产品可先后多批）。
2. **时间主导**：固定 1周/N周自动周期 + `batchCycleWeeks` 配置 + 周日封板定时任务 + `cycle_weeks` 快照 → **全删**；改为运营评审后【定档】即建批。
3. **收集中/封板阶段**：`收集中→待开发会议→...` + `batch-lock` 封板 → **删**；批次定档时创建即含全部已落实单，无游离期。状态机重定为 **`开发中 → 可下载 → 已交付`**。
4. **test 角色**：**无**；外部测试验收在框架外，包验收后由**管理身份（admin）直接上传包**转可下载。角色仍 `admin/pm/impl`，不新增。
5. **steward 三接口自动化**：本期不做。改为 **出站=导出开发清单（人工拿去 steward）+ 入站=管理身份手动上传包**；steward→intake **自动回写包列为 future / NH-6**。
6. **实施端新增**：下载/应用更新包 + 一键改版本（回写 customers.json）；**逐单确认「现场验证过」**（`待验证→已关闭`）；验证不过 → 人工反馈（`待验证→已重开`）；**按批次视图**（FS-02 曾标 P2 的落地）。
