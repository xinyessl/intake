# CHG · 咨询终稿观测点与具体发生层归因守卫

- 日期：2026-08-14
- 关联 Spec：FS-04 AC-76
- 类型：回归边界补全

## 现象

生产可见 Chrome 复测中，回答已改为只读核对既有原始号与出站报文，也不再要求改类型重传，但仍把“出站报文已经少位”直接写成“丢位发生在对接方传参/序列化侧”。已有观测只能确定变化不晚于该观测点，不能在没有逐层证据时定位具体实现机制。

## 修复

- 发布前 claim 级证据门补充具体发生层审计：传参、序列化/反序列化、类型/格式转换、映射、缓存、网关、前后端、数据库、中间件、对接方/第三方侧等定位必须有同一 claim 的权威逐层证据。
- 没有直接证据时允许保留“该观测点已变化/变化不晚于该观测点”，删除具体机制或责任层结论。
- 一次修订仍违规时按完整自然句降级，保留已核字段类型及既有报文只读对比，不产生残句。

## 回归

- 固化生产 Q127 r26 原始失败句。
- 覆盖出站报文观测边界正例、无证据传参/序列化归因负例，以及 route 明确逐层契约的放行正例。
