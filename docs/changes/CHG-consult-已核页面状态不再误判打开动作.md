# CHG · 已核页面状态不再误判为打开动作

## 现象

Audit 真实 Q354 已命中 `AUD-QR-FAQ-01`，路由显式开启 `fallbackMode=verifiedFacts`，两条 `answerFacts` 已明确“页面骨架可打开不等于真实后端数据已接通”。模型初稿和修订稿未通过后，确定性已核事实终稿仍被 `focused_fact_overreach` 拒绝，最终只发布通用“未通过安全校验”提示。

## 根因

`consultFocusedFactOverreach` 将任意“打开/点击/刷新 … 页面”都当成现场排查动作。已核事实中的描述性状态“只有可打开的前端页面”因此被误识别为“打开页面去排查”。生产函数夹具复现的具体误判句为：

`- 当前实际状态：审核问题统计只有可打开的前端页面、筛选项和表格骨架；`

## 修复

- 将该动作扩写分支收窄为：句首命令，或带“请/建议/先/再/然后/去/尝试/需要/应当/应该”等明确指令前缀的打开、点击、刷新，才按排查扩写处理。
- 不针对 Q354 文字或 route id 硬编码；`verifiedFacts` 仍必须逐行、逐序精确等于当前 route 全部原句才可进入既有窄门。
- 新增 `FS-04 AC-142`，固定“已核页面状态”与“现场动作扩写”的语义边界。

## 验证

- 使用现有 `extractFn` 夹具组合真实 `server.mjs` 审计、fallback 与终审函数，以 Q354 原问、`AUD-QR-FAQ-01` 和两条原始 facts 回归。
- 断言 `consultVerifiedFactsFallback` 非空、终审 `violations=[]`，保留固定空列表与“只能验收页面骨架”，且不展开 HIS、AI、Redis。
- 反例仍拦截未经 route 证据的“建议打开页面抓包”扩写、“大概率是后端配置错误”和“属于后端服务故障”。

本变更不涉及数据库结构、真库读写、接口契约或部署。
