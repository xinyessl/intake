# CHG · consult 答疑 —— 覆盖判定第三次精修：从「同域相关就答」收紧为「功能级精准覆盖」（检索内容是否真的在讲用户问的那个功能本身）

## 现象（两轮拉扯后的精修）
- v2「必须精确覆盖那个点」**太严** → 「床位号查不到患者」有相关 spec（患者列表/查询）也被拒答。
- v3「同域相关就答」**太松** → 「检验异常值箭头怎么显示」（检验域相关，但箭头显示规则 spec 没写）也长篇作答了。
- 用户要的是**更严但精准**：判据既不是「精确逐字」、也不是「同域沾边」，而是——**检索到的规格/事实/源码是不是真的在讲【用户问的那个功能/机制/行为本身】**。

## 修复 —— 判据从「同一模块/域相关」精确到「是否在讲用户问的那个功能本身」
`prompts.mjs` 的 `DEFAULT_PROMPTS.consultNormal` / `consultDeep`「规则：」区**首条**整条重写为**功能级覆盖判定**，三档 + 两个校准例子：

1. **是（真的在讲这件事）→ 据此作答**：给该功能的规则/机制/配置/排查方向，帮实施定位。**哪怕没逐字用到用户的措辞也算**。校准例①：问「床位号查不到患者」，摘录讲的是**患者列表/查询/筛选/院区范围**的机制，这就是在讲「怎么查到患者」（床位号只是查询入口之一）→ 据此说清查询怎么匹配、先查什么。
2. **否（检索到的是同域/同模块下别的方面，没在讲用户问的那个功能本身）→ 只回一句**：「当前系统说明书摘录（deep：/源码）里没有覆盖【用户问的那个点】，建议转成工单或联系开发确认」，**别再据周边内容编排查步骤**。校准例②：问「检验报告**异常值箭头怎么显示/为什么不显示**」，但检索到的只是「检验数据**搜不到/怎么拉取**」这种**别的方面**（没讲箭头显示规则）→ 一句没覆盖。
3. **红线·不臆造具体技术名（不变）**：任何时候都不编造规格/源码里**没有出现**的**具体**表名、字段名、接口路径、配置项 key、开关名；拿不准就说「具体的表/字段/接口这块说明书没写明，建议转工单或问开发确认」，一般性排查方向/思路可给，但别把猜的具体名当事实。

**一句话抓手（给模型的）**：判断标准是「**检索到的内容有没有在讲用户问的那个功能本身**」，而不是「在不在同一个模块/领域」。同模块但讲的是别的功能 → 没覆盖。

deep 版同理，把「源码片段」纳入判断对象、话术带上源码（作答优先据源码的实际实现）。**其余规则一字未动**；`{{specExcerpts}}` / `{{codeExcerpts}}` / `{{kbBlock}}` / `{{subsSentence}}` / `{{specIndexBlock}}` / `{{projectName}}` 等占位全部保留。

## 与上一版（相关就答）的差别（核心）
| | v3 上一版（相关就答·过松） | 本版 v4（功能级·精准） |
|---|---|---|
| 判据 | 是否**相关**（同一功能/模块/主题即算，「不要求 100% 精确讲到那个点」） | 检索内容是否**真的在讲用户问的那个功能/机制/行为本身**（同模块但讲别的方面 = 没覆盖） |
| 「床位号查不到患者」 | 相关 → 答 | 摘录在讲患者查询机制 = **在讲这件事** → 答（**结论一致**，判法更明确） |
| 「检验异常值箭头显示」但只检到「检验数据搜不到/怎么拉取」 | 同为检验域「相关」→ **误答**（问题所在） | 讲的是**别的方面**（没讲箭头显示规则）→ **一句没覆盖**（修正点） |
| 措辞焦点 | 「同一功能/模块/主题、能帮上排查就算相关」 | 「就在描述用户问的这件事怎么工作/怎么配/什么规则」 |
| 校准例子 | 举「不相关」（检验箭头 vs 登录鉴权）一例 | 举**正例**（床位号 vs 患者查询=答）+ **反例**（检验箭头 vs 检验拉取=不答）两例 |
| 红线·不臆造具体名 | 保留 | 保留（**不变**） |
