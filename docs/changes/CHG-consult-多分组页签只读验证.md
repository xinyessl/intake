# CHG · consult 多分组页签只读验证

- **日期**：2026-08-13
- **关联 spec**：FS-04 AC-48（现场诊断边界补充，待人验收）
- **类型**：生产真实浏览器回归暴露的通用答疑行为修复

## 现象与根因

tag26 的药物重整医生端回归题中，AI 把“切换页签没有新请求”直接判成异常，并建议点开未读、切换星标来验证。实际已确认的列表接口会在首次加载时一次返回 `all/read/unRead/mask` 四组，页签可以只在前端切换已有分组；点开未读或切换星标还会改变业务状态。

根因不是业务 Spec 缺失，而是通用诊断规则只有“观察请求”和“不重复提交”边界，缺少“一次返回多组”和“只读验证分组关系”的明确优先级。

## 改动

- normal/deep 默认提示词与服务端诊断守卫同步增加通用规则：先判断首次响应是否已含多个分组；没有明确契约时，不得断言每次切页签都必须发新请求。
- 实施验证优先比较首次响应与页面各组的数量、成员集合，以及已有证据确认的互斥/包含关系；不得通过点开未读、切换已读/星标、审批或提交来验证。
- 只有 Spec、源码或接口契约已明确“切换时逐次请求”时，才允许把逐页请求作为预期。
- PWRS 地图仅为药物重整医生端补充已由现有 Spec/源码确认的四组一次返回及集合关系；显式换业务实体仍重新路由。

## 安全边界

- 该规则不放宽按钮、接口、字段、状态值等具体事实的证据门。
- 不预设现场响应中的技术字段名；具体关联键仍以本次实际响应和已有契约为准。
- 不用会改变已读、星标、审批、采纳或提交结果的动作做诊断。

## 自动化证据

- normal/deep 精确提示词基线与服务端会话守卫覆盖“本地页签允许、明确契约例外、只读集合比较、禁止改状态”。
- PWRS 真实地图覆盖原失败意图及自然变体，并覆盖显式换成新业务实体时不继承的反例。
- 无数据库、接口或 PWRS 业务代码改动；本次不适用真库写入冒烟。
