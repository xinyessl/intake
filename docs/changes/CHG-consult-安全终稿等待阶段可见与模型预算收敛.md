# CHG · 咨询安全终稿等待阶段可见与模型预算收敛

- 日期：2026-08-25
- 关联 spec：FS-04 AC-136（行为补充，待人验收）
- 范围：Intake `/api/consult` 与两套咨询客户端；不改数据库、Audit Spec、PWRS fixture/evidence。

## 现象与根因

生产 Q0017 在约 190 秒内始终只显示“正在思考中…”，随后才开始输出安全终稿。服务端为防止未审计草稿泄露，会先完整生成草稿并做语义审计，必要时再完整生成一次修订；旧流式模型调用每个候选可等 90 秒，主备和修订可串行叠加。等待期只有 SSE 注释心跳，两套前端只识别正文 `v`，因此连接虽未断，用户仍看不到处理阶段。

## 改动

- 保持草稿、修订稿只在服务端内存；新增白名单 `progress` SSE 事件，覆盖读取上下文、生成、校验、修订与安全终稿输出。事件没有 `v`，前端只更新等待占位，不进入 `acc/full/messages/chat`。
- 模型流增加 25 秒首个有效文本上限、60 秒单候选生成上限、最多两个候选；consult 草稿与最多一次修订共用 90 秒整轮预算。
- 整轮失败仍由既有安全错误发布器输出带请求编号的可见正文并发送 terminal `done`；用户主动停止优先，不改写成超时。
- 安全终稿继续按自然句/Markdown 结构逐块输出；首个 `v` 到达后才从阶段占位切到正式正文。

## 自动化证据

`tools/fs-04-consult-safe-final-stream.logic.test.mjs` 覆盖：阶段事件字段隔离和双客户端不持久化、真实无首字超时、最多两个候选、正常流式正文、草稿/修订共享 deadline、超时安全收口、停止优先，以及既有安全终稿分块/心跳/空 EOF 回归。

## 风险边界

- 25/60/90 秒是服务端完成预算，不是模型质量承诺；慢模型可能更早切备用或进入安全降级，但不会再无限叠加等待。
- 阶段文案只说明处理状态，不表示相关事实已经确认；生产浏览器耗时与代理行为需另行验收记录。
