# CHG · 咨询终稿确定因果与第三方改类型重传守卫

- 日期：2026-08-14
- 关联 Spec：FS-04 AC-75
- 类型：回归边界补全

## 现象

生产可见 Chrome 复测中，模型在“很容易/很可能”被拦后改写为“超过精度就会直接丢位”“就是对接方类型传错了”，并建议“改成字符串再传”。前者仍是无证据确定因果，后者把未受控副作用动作交给第三方执行。

## 修复

- 发布前句级审计补齐一定会、必然、肯定会、就会直接导致、就是某方传错/配置错等确定因果结构；只有同一 claim 有 route/Spec/源码确定证据时放行。
- 跨主体动作门补齐把字段或报文改成字符串/数字/指定类型后再传、重传、重新发送或复测；完整受控条件不齐时删除完整句。
- 修订失败安全降级保留已核字段事实及已有原始值、既有请求响应、日志/审计的只读对比，不做责任方或发生层定论。

## 回归

- 生产 Q127 原始失败整段进入自动测试。
- 覆盖确定因果同义句、权威确定规则放行、跨主体改类型再传、否定动作和安全降级后二次审计。
