- **日期**：2026-08-28

## 问题

- 多类任务结果询问是否在同一事务时，答案可能只有事实结论，没有逐任务可执行的只读核对顺序。
- 批量失败重试边界改写成实施清单时，编号步骤可能完整，但遗漏 route 已明确的重试安全事实后仍被发布。

## 修复

- 通用识别至少三类状态/流水/缓存键/消息/外部回调与“同一或统一事务”的组合，进入 `field_diagnostic`。
- 确定性 fallback 按主状态→审核流水→Redis 超时/任务键→医生消息/通知→HIS/外部回调日志输出五层只读顺序。
- 批量或多对象失败重试清单从 current route 动态派生四组覆盖门：操作前状态校验、幂等键与并发锁、重复执行外部副作用、局部幂等不代表整体幂等。
- as-built 原句里的再提交、发消息、触发回调改写成风险判断基线，避免被理解为现场操作；明确禁止写入、补发、重放和盲目整批重试。
