# CHG · TK-01 · 工单管理「状态」筛选精简为 5 个关键里程碑

> 日期：2026-07-30　类型：UI 精简（不改状态机/后端）　来源：用户裁决
> 页面：public/inbox.html 状态筛选下拉

## 现象/决策
状态下拉原列 11 个原始 lifecycle（待处理/分析中/已回复/已立项/开发中/已出包/待验证/暂缓/已驳回/已关闭/已重开），太细、噪音多。用户裁决保留 **5 个关键里程碑**：`待处理 / 已立项 / 已出包 / 待验证 / 已关闭`（待办·已排期·已交付·现场验收中·已完结）。

## 改动
`public/inbox.html`：状态下拉 `lcs` 数组由 11 态精简为 `['待处理','已立项','已出包','待验证','已关闭']`。**筛选逻辑不变**（仍按 `i.lifecycle===f.status` 精确匹配）；去掉的 6 态（分析中/已回复/开发中/暂缓/已驳回/已重开）在「全部状态」下仍显示、不丢单，顶部流水线仍能按大阶段筛。

## 澄清（用户问「待验证是验证反馈吗」）
是。`已出包(发包) → 待验证` = 现场/客户验收该修复是否生效（实施端 `intake-verify` + 详情验证卡）；通过→已关闭，不通过→已重开。

## 部署
rsync inbox.html → 线上（静态即时生效）。
