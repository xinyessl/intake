# 收件 intake · 运维部署手册

零依赖 Node http 服务（仅 `mysql2` 一个运行依赖）+ MySQL 持久化 + 原生前端。

## 1. 依赖
- Node ≥ 18（开发用 22）。
- MySQL 8（本机已用 Docker `mysql8-container`，库 `intake`）。

## 2. 首次启动（本机）
```bash
cd intake
npm install                      # 装 mysql2
# 确保 MySQL 有库 intake + 用户（若没有，用 root 建）：
#   CREATE DATABASE intake CHARACTER SET utf8mb4;
#   CREATE USER 'intake'@'%' IDENTIFIED WITH mysql_native_password BY 'intake@123';
#   GRANT ALL ON intake.* TO 'intake'@'%'; FLUSH PRIVILEGES;
npm start                        # = node server.mjs，默认 127.0.0.1:5180
```
- 首启自动建表、把旧 `data/*.json`/`intake-store` 迁入库、播默认管理员 **admin / admin123**（**请登录后立即改密**：右上「改密」）。
- 打开 `http://127.0.0.1:5180/` → 登录。

## 3. 配置
| 项 | 位置 | 说明 |
|---|---|---|
| 数据库连接 | `data/db.json`（gitignore） | `{host,port,user,password,database}`；或用环境变量 `INTAKE_DB_HOST/PORT/USER/PASS/NAME` 覆盖 |
| 模型 API Key | 页面「模型配置」→ 存 `data/model-api.json`（gitignore） | 不入库、掩码回传 |
| 监听端口 | 环境变量 `PORT` | 默认 5180 |
| 监听地址 | 环境变量 `BIND` | 默认 `127.0.0.1`（仅本机）；部署到网络设 `BIND=0.0.0.0`（见 §5） |
| 数据目录 | 环境变量 `INTAKE_DATA` | 默认 `./data`；密钥/配置/`.md` 双写都在这，已 gitignore |

> `data/` 全部被 `.gitignore` 挡住：库口令、模型 Key、提交链接密钥、会话都不入版本库。

## 4. 角色与账号
- **管理员(admin)**：全权（分析/回复/立项/流转/关闭 + 项目/模型/账号/经验库）。
- **产品经理(pm) / 实施工程师(impl)**：现场侧，登录后只提交、看工单、做验证；可绑现场后只看本现场。
- **提交链接**（现场免账号）：项目管理页每个项目「提交链接」→ 生成带 token 的 `/submit.html?token=...`，发给现场即可提交（限定到该项目/现场/版本/类型），不能进管理端。

## 5. 部署到网络（供现场访问）
1. `BIND=0.0.0.0 PORT=5180 npm start`（公网模式会放开"仅本机 Host/Origin"硬校验，靠登录 + 提交链接 + SameSite cookie 鉴权）。
2. **强烈建议前面挂 HTTPS 反向代理**（Nginx/Caddy）：`https://intake.example.com` → `http://127.0.0.1:5180`。Caddy 示例：
   ```
   intake.example.com {
     reverse_proxy 127.0.0.1:5180
   }
   ```
3. 进程守护：用 pm2 / systemd 常驻。systemd 示例见文末。
4. 登录后**务必改默认 admin 密码**，并按现场建账号或发提交链接。

## 5.1 双域名部署（admin / field 两 vhost，共用后端 + 库）

> 上线后**运营后台（admin）与实施端（field）各用一个完全独立的域名**，但**共用同一 `server.mjs` 进程 + 同一 MySQL 库**——现场经 field 域提交的工单**同库直连**进运营工单箱，**不做任何跨库/跨服务同步**。拆分只在 **web/域名层**（两个 nginx vhost 同源反代到同一后端）。详见 spec `docs/specs/FS-08-双域名部署与访问隔离.md`（决策 D，2026-07-21 已裁决）。
>
> **本期实际域名（FS-08 NH-1，2026-07-22 已裁决）：**
> - **field 域（实施端 · 现场入口）** = `http://intake.lcpharmacy.cn`（现有域名，由「按 role 分发」改为 field 入口）。
> - **admin 域（运营后台入口）** = `http://intake-ops.lcpharmacy.cn`（新增，fake-ip 路由已达服务器，仅需加 nginx vhost）。
> - **本期先 HTTP**（两域名均 `http://`，与现状一致）；**HTTPS/证书为后续待办**（FS-08 NH-4，不阻断本条落地）。下面 nginx 样例给的是 HTTP（`listen 80`）；上 HTTPS 时改 `listen 443 ssl` + 补 `ssl_certificate*`（见文末 HTTPS 追加块）。

**要点（先理解再抄配置）：**
- **不拆进程、不拆库**：仍是一个 `node server.mjs` + 一个 MySQL；两域名反代到**同一后端** `127.0.0.1:5180`。
- **同源免 CORS**：每个 vhost 的 `/api/` 反代到同一后端，浏览器看来「页面与其 `/api/*` 同域名同源」→ 免 CORS、`intake_sess`（`SameSite=Strict`）cookie 正常携带。
- **Host 必须透传**：nginx `proxy_set_header Host $host;` 把真实访问域名透传给后端，`server.mjs` 才能据 Host 判「这是 field 域还是 admin 域」（否则 Host 闸判不出，越域隔离失效）。
- **域名层访问隔离（deny-by-default）**：`server.mjs` 按 Host 收窄允许集——field 域只暴露 `field.html`/`submit.html`/`assets` + 现场提交/查看接口；admin 域只暴露后台页 + 后台接口。越域访问（field 域敲 `/console.html` 或后台接口）→ 拒（404/403），不依赖前端隐藏。
- **cookie 天然隔离**：两独立域名各自 `intake_sess`（`SameSite=Strict; Path=/`）互不可见 → 各域各自登录，无需额外代码。
- **免登录链接绝对地址**：配了 `FIELD_ORIGIN` 后，`/api/submit-link` 返回 field 域**绝对 URL**（`http://intake.lcpharmacy.cn/submit.html?token=...`）——两独立域名下相对路径打不通，必须绝对。运营端产品管理复制该 URL 发现场即可打开。
- **灰度安全**：`FIELD_ORIGIN`/`ADMIN_ORIGIN` **任一未配 → 整体回退单域名现状**（Host 闸不启用、`/` 按 role 分发、submit-link 返相对路径）。故可**先部署代码（env 未配）验证行为零变化**，再配这两个 env 灰度切到双域名——见 §4③ FS-08 回退语义。

**环境变量（在 §3 配置之外新增，供 `server.mjs` 判域 + 生成绝对链接）：**

| 变量 | 本期实际值 | 说明 |
|---|---|---|
| `FIELD_ORIGIN` | `http://intake.lcpharmacy.cn` | 实施端（现场）域名。`server.mjs` 据此把 Host 判为 field 域（`/`→`field.html`、只暴露现场提交面）；`/api/submit-link` 用它拼 field 域**绝对**链接。**未配置**则回退单域名行为（按 role 分发、submit-link 返回相对路径），本机开发 `127.0.0.1`/`localhost` 不受影响。 |
| `ADMIN_ORIGIN` | `http://intake-ops.lcpharmacy.cn` | 运营后台域名。`server.mjs` 据此把 Host 判为 admin 域（`/`→`console.html`、暴露后台页+接口）。 |

> **两者必须同时配**才启用双域名闸；只配其一 = 未配 = 回退单域名。本期 HTTP，值用 `http://`（NH-4）。

> 未匹配任一域名（直接用 IP / 未配域名 / 本机回环）时的兜底行为见 FS-08 NH-2（本机 `127.0.0.1`/`localhost` 须仍可用，不能因 Host 闸把本地开发打死）。

**nginx 双 vhost 样例（本期 HTTP · 两 `server` 块，`/api/` 反代同一后端）：**
```nginx
# ---------- 运营后台域名（admin） ----------
server {
    listen 80;
    server_name intake-ops.lcpharmacy.cn;          # ← 实际 admin 域名（NH-1）

    # 后台页 + admin 接口：反代到同一后端（server.mjs 按 Host 判为 admin 域）
    location / {
        proxy_pass http://127.0.0.1:5180;          # ← 同一后端
        proxy_set_header Host              $host;   # ← 必须透传真实 Host，server.mjs 据此判域
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
    location /api/ {
        proxy_pass http://127.0.0.1:5180;          # ← /api 同源反代（免 CORS）
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_buffering off;                        # SSE（/api/consult 流式）需关缓冲
    }
}

# ---------- 实施端（现场）域名（field） ----------
server {
    listen 80;
    server_name intake.lcpharmacy.cn;              # ← 实际 field 域名（NH-1，现有域名改作 field 入口）

    # 现场页（field.html / submit.html / assets）+ 现场接口：反代到同一后端（判为 field 域）
    location / {
        proxy_pass http://127.0.0.1:5180;          # ← 同一后端（与 admin vhost 相同）
        proxy_set_header Host              $host;   # ← 透传 Host → server.mjs 判为 field 域，/→field.html
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
    location /api/ {
        proxy_pass http://127.0.0.1:5180;          # ← /api 同源反代（field 页与其 /api 同域名同源，免 CORS）
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_buffering off;
    }
}
```

> 静态资源（`public/`）由**同一后端** `server.mjs` 分发，两 vhost 都反代到它 → 指向**同一份** `public/`，不复制两份。域名层的「哪个域看哪些页/接口」由 `server.mjs` 的 Host 闸负责（deny-by-default），nginx 只做同源反代 + Host 透传。
> systemd / Docker 里给后端加 `FIELD_ORIGIN=http://intake.lcpharmacy.cn ADMIN_ORIGIN=http://intake-ops.lcpharmacy.cn`（见 §7 样例可追加；两者必须同时配才启用双域名闸）。

**HTTPS 追加（NH-4 后续待办 · 上证书时把上面两块的 `listen 80;` 改为 `listen 443 ssl;` 并各补证书位）：**
```nginx
# admin vhost 内追加：
    listen 443 ssl;
    ssl_certificate     /etc/nginx/certs/intake-ops.lcpharmacy.cn.crt;   # ← admin 域证书（待签发）
    ssl_certificate_key /etc/nginx/certs/intake-ops.lcpharmacy.cn.key;
# field vhost 内追加：
    listen 443 ssl;
    ssl_certificate     /etc/nginx/certs/intake.lcpharmacy.cn.crt;       # ← field 域证书（待签发）
    ssl_certificate_key /etc/nginx/certs/intake.lcpharmacy.cn.key;
# 并加 80→443 跳转（上 HTTPS 后启用）：
server { listen 80; server_name intake-ops.lcpharmacy.cn intake.lcpharmacy.cn; return 301 https://$host$request_uri; }
```

## 6. 备份 / 健康
- **备份**：`mysqldump -uintake -p intake > intake-$(date +%F).sql`（工单/项目/账号/经验全在库）；`intake-store/*.md` 是可读镜像可一并备份。
- **健康检查**：`GET /api/health` → `{ok,projects,intakes,kb}`；`GET /api/version`。
- **冒烟自测**：`BASE=http://127.0.0.1:5180 node tools/smoke.mjs`（建临时项目跑全流程再清理，19 项断言）。

## 7. systemd 示例
```ini
[Unit]
Description=intake
After=network.target docker.service

[Service]
WorkingDirectory=/opt/intake
Environment=PORT=5180 BIND=0.0.0.0 INTAKE_DB_HOST=127.0.0.1 INTAKE_DB_PASS=xxxx
# FS-08 双域名：两者同时配才启用双域名闸；未配则整体回退单域名现状（可先不配灰度验证零变化）
Environment=FIELD_ORIGIN=http://intake.lcpharmacy.cn ADMIN_ORIGIN=http://intake-ops.lcpharmacy.cn
ExecStart=/usr/bin/node server.mjs
Restart=always
User=intake

[Install]
WantedBy=multi-user.target
```
