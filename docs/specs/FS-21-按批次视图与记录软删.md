## 1. 用户故事 / 目标
作为**现场实施工程师（role=impl）**，我要在医院视图里**按批次**（回答"这家医院这批提的都进展到哪了、能不能下载了"）查看提交记录；同时对我误提/作废的记录能**删除**（软删、保护在办流程、留痕可追）；且**绝不看到别的账号负责医院的数据**——越权传参、未登录、跨 sites 删除一律拦住。

## 2. 范围
**包含（本条 = 医院视图的 按批次视图 + 数据权限收敛 + 软删除）：**
- **按批次视图（P2，BP-01 上线后为默认）**：按「产品·周批次」分组，组头 = 产品名 / 周次(时间范围) / 批次状态 / 条数 / 节奏提示；批次状态 → 现场语义映射（见 §6.3 表）；组内每条 = 类型标签 + 标题 + 状态标签 + 子系统·医院 + 时间。**BP-01 未上线前降级**（保持按批次选中 + 空态提示，见 AC-3）。
- **数据权限与收敛（贯穿 · 本机制必守）**：sites/projects 双收敛、越权传参不泄露、未登录不返数据（坐实导读 §3.1 收敛机制，FS-20 清单渲染同守）。

### D. 按批次视图（依赖 BP-01 · P2）

- **AC-3【P2 · 降级】**（原 AC-15）Given BP-01 `batches` 表**尚未就绪**（当前）When 请求 `groupBy=batch` Then 端点**降级**：不返回 `batches` 分组，而是 `{degraded:true, groups:[], msg:'批次分组待运营端发包功能上线'}`（后端契约不变，见 §4.1）—— 前端据此**保持「按批次」选中不回弹**（点了「按批次」按钮就切过去，`.f-tab2` 仍高亮「按批次」、`state.groupBy='batch'`），在**批次容器（`fListBatch`）显空态提示**（复用 `.f-list-empty`，标题「批次分组暂未开放」+ 描述透传后端 `msg`、前端 fallback「批次分组功能待运营端上线后开放」避 FS-01 A6 禁词），**不强切回按类型、不加载按类型数据混入批次视图**；点回「按类型」→ 正常加载三组（FS-20 C 组）。「按批次」恒 degraded 属预期（P2 未上线），BP-01 上线后端不再 degraded 时自然显真实批次。**不报 500、不臆造批次**。〔2026-07-23 裁决：由「回弹按类型 + 顶部提示条」改为「保持按批次 + 空态提示」，解决"按钮没切过去内容却变了"的割裂观感。〕
- **AC-4【P2】**（原 AC-17）Given 咨询类记录 When 按批次视图 Then 咨询单独成组「咨询答疑（不发包）」，**不参与发包批次**（PRD §4.3：咨询不进批次），组头无批次状态标签。

### E. 数据权限与收敛（贯穿 · 本机制必守）【P1】
- **AC-5【P1】**（原 AC-18）Given 现场账号 A（sites=["山东省立医院"]）When 请求 `GET /api/field/submissions?hospitalId=郑州人民医院`（越权传参，郑州不在其 sites）Then 服务端**忽略越权传参**，只返回其 sites 内数据（郑州记录一条不出），或返回 403；**绝不**因前端传参而泄露非负责医院数据（对齐 PRD §3.3/§7 硬约束）。
- **AC-6【P1】**（原 AC-19）Given 未登录 When 请求 `GET /api/field/submissions` Then 返回登录态错误（依 FS-01 登录门 / authGate），不返回任何数据。
- **AC-7【P1】**（原 AC-20）Given 现场账号且 `accounts.projects` 有限定 When 请求 Then 返回结果同时受 `projects`（产品范围）与 `sites`（医院范围）双重收敛（复用 `intake-list` 现有 project+site 收敛逻辑，见 §6.1）。

### F. 记录删除（软删除）【P1】
- **AC-8【P1】**（原 AC-21）Given 现场账号处于医院视图/系统视图、某条提交记录**可删**（非已转工单、非已归批）When 渲染该记录卡 Then 卡右上角挂删除入口（`.f-item-del`）；`/api/field/submissions` 的 item 下发 `deletable=true`（=`!convertedTo && !batch`）。已转工单/已归批的记录 `deletable=false`、不挂删除入口。
- **AC-9【P1】**（原 AC-22）Given 点击某可删记录的删除入口 When 触发 Then 弹 **app 风格确认框**（复用 `#fModalMask`，非浏览器原生 confirm/prompt）；确认 → `POST /api/intake-delete {project,id}`；点击 `stopPropagation`，不触发卡片 reopen。
- **AC-10【P1】**（原 AC-23）Given 确认删除一条记录 When `POST /api/intake-delete` 成功 Then 服务端**软删除**：置 `data.deleted=true`+`deletedAt`+`deletedBy`（随 `data` JSON 落库、**不加库列、不真删库/磁盘**，media/history 全保留），并在 `history[]` 追加一条 `{to:'已删除', note:'删除', by, byRole, at}` 留痕；此后该记录**不再出现在任何提交清单/聚合/导出/待办**（`listIntake` 过滤 `deleted`），`intake-detail` 对其返回 404（不可 reopen）。前端从清单移除该卡；若删的正是右侧当前打开的会话则清空右侧对话区。
- **AC-11【P1】**（原 AC-24）Given 记录**已转工单**（`convertedTo` 有值）或**已归批**（`batch` 有值）When 请求删除 Then 服务端**拒绝**（400，error 分别为「已转工单的咨询不可删除」/「已归批的需求/BUG 不可删除」），保护在办流程；前端 toast 显该原因。
- **AC-12【P1】**（原 AC-25）Given 现场账号请求删除**不在其 `sites`** 的记录 When `POST /api/intake-delete` Then 服务端 **403**「无权删除该记录」（现场账号只能删自己名下 sites 的记录；管理员不限）。已删记录再删 → 幂等返回 `{ok:true,alreadyDeleted:true}`。

> **AC 计数**：本条共 **12** 条 —— P2 共 **4** 条（AC-1~4，按批次）；P1 共 **8** 条（AC-5~7 数据权限 3 条 + AC-8~12 软删 5 条）。医院下拉 / 子控件 / 按类型视图（原 AC-1~13）在 **FS-20**。

## 4. 接口契约

> 统一前缀 `/api`；返回 `{...}` JSON。实施端接口一律按**当前登录用户 `sites`（+`projects`）** 服务端收敛，忽略前端越权传参。契约锚点见 `docs/specs/00-实施端-spec清单.md §4` + 导读 §3.1。`GET /api/field/submissions` 入参 + `groupBy=type` 出参见 **FS-20 §4**（同一端点）。

### 4.1 `GET /api/field/submissions`（本条约定 `groupBy=batch` 出参 + 降级契约）
**出参（P2 · `groupBy=batch`，BP-01 就绪后）：**
```jsonc
{
  "groupBy": "batch", "degraded": false,
  "groups": [
    { "batchId": "...", "product": "药师工作站", "week": "第37周（07-14~07-20）",
      "status": "collecting", "statusLabel": "本周·收集中", "hint": "周日截止 → 开发会议",
      "count": 2, "items": [ { ..., "deletable": true, "convertedTo": "" } ] }
  ]
}
```

**出参（P2 降级 · `groupBy=batch` 但 batches 未建，当前）：**
```jsonc
{ "groupBy": "batch", "degraded": true, "fallback": "byType", "groups": [], "msg": "批次分组待运营端发包功能上线" }
```
> 后端契约不变（`degraded/groups/msg/fallback` 照旧）。2026-07-23 起前端**不再消费 `fallback` 字段做「切按类型」**（改为保持按批次 + 空态提示，见 AC-3）；`fallback` 保留为向后兼容的信息字段，供后续策略化降级复用。
> 🔴 **P2 · NEEDS-HUMAN**：`batches` 表结构（`product/week/status/pkgVersion/release_note` 等）、批次-工单归属关系（工单归到哪个批次的判定）、周次时间范围规则，**均由 BP-01 定义、尚未建表** → 本条只约定 `groupBy=batch` 的**降级契约**，实际批次分组待 BP-01 ready 后补实 + 重跑本条 P2 AC。

### 4.2 🆕 新增：`POST /api/intake-delete`（本域定义 · 本条实现）
现场提交记录软删除。入参 `{project, id}`。守卫（真值以本端点为准，不信前端 `deletable`）：不存在→404；已删→200 `{ok:true,alreadyDeleted:true}`（幂等）；`convertedTo` 有值→400「已转工单的咨询不可删除」；`batch` 有值→400「已归批的需求/BUG 不可删除」；现场账号 `site∉sites`→403「无权删除该记录」（管理员不限）。通过→置 `data.deleted/deletedAt/deletedBy`+`history` 留痕、`saveIntake` 双写（不加库列），返回 `{ok:true}`。已在 `FIELD_OK`+`FS08_FIELD_API` 双白名单。
> `field/submissions` 出参 item 补两字段：`"deletable": true, "convertedTo": ""`（P1 type 出参 + P2 batch 出参同理；供删除入口判定）。

## 6. 业务规则 / 非功能

### 6.1 数据权限（硬约束 · 本机制核心 · E 组坐实）
- 所有查询/删除以**当前登录用户 `accounts.sites`（医院）+ `accounts.projects`（产品）** 为边界，**服务端过滤，忽略前端越权传参**（PRD §3.3/§7；复用 `server.mjs` L1055-1057 的 `intake-list` 收敛：`!isAdmin(user) && projects.length && !projects.includes` → 空；`!isAdmin(user) && sites.length` → `filter(sites.includes(site))`）。
- `hospitalId` 越权（不在 sites）→ 裁掉该项 / 或 403（AC-5），不泄露。
- 判断"是否现场账号（非管理员）"用 `isAdmin(u)` 取反（`isAdmin` 含 `admin/dev`）——现场 impl/pm 走收敛分支（与 `docs/lessons.md` isAdmin 条一致）。
- **软删同守**：现场账号只能删自己名下 sites 的记录（`site∉sites`→403，AC-12）；管理员不限。
- **🔴 关联缺口（FS-01 修）**：`server.mjs scopedForField` 仍判 `role==='field'`（归一后永不命中）——本机制**依赖 FS-01 修复该缺口**；本条若走 `/api/intake-list` 则已被其内联收敛保护，不受该缺口影响；若新增 `/api/field/submissions` 必须用 `isAdmin`+sites 收敛（**不得**复用有缺口的 `scopedForField`）。

### 6.2 状态标签映射（`lifecycle` → 现场 UI 标签 · 批次组内 f-item 沿用）
> 与 FS-20 §6.2 / 导读 §3.3 同一张表（组内每条记录状态标签沿用，不重列——见导读 §3.3）。批次组头的**批次状态**是另一维度（§6.3），别与工单 `lifecycle` 状态混。

### 6.4 校验 / 非功能
- **软删幂等**：已删记录再删 → `{ok:true,alreadyDeleted:true}`（AC-12），不重复写、不重复留痕。
- **确认框**：删除用 app 风格确认框（复用 `#fModalMask`），非浏览器原生 confirm/prompt（AC-9，对齐现场统一交互）。
- **时间格式**：批次组头周次/组内时间统一 `yyyy-MM-dd HH:mm`（全局规范⑫；纯日期到 `yyyy-MM-dd`），空值 `—`。
- **即选即查**：按批次/按类型切换为「选择型」→ 选中即刷新（全局规范⑪）；降级态下点「按批次」仍切过去（AC-3 不回弹）。
- **文案禁词**：批次降级空态描述避 FS-01 A6 禁词（不用「发包」类字样，用「批次分组功能待运营端上线后开放」fallback）。
- **双域名同步**：`POST /api/intake-delete` + 新增 field 端点须同进 `FIELD_OK` + `FS08_FIELD_API`（对齐 FS-08，避免 field 域被 `originGate` 判 deny 隐蔽挂掉）。
- **空态**：批次降级（AC-3）/ 某医院无记录均有占位，不报错。
