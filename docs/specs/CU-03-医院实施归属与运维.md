> **拆分自 CU-01（2026-09-02，见 CHG-2026-09-02-CU01-拆分归档.md）。** 本条承载**医院的实施归属与运维**：实施人↔医院**双向写穿**（唯一真源 `account.sites`、`impl` 读时派生）、**维保到期回写**、**激活文件生成**、以及**部署清单历史**（2026-08-05 已废弃，仅作追溯）。台账列表/增删改/关联产品/工单数见 **[CU-02](CU-02-客户管理.md)**；数据模型全景、关系图、全局 NEEDS-HUMAN、护栏见 **[CU-01 导读](CU-01-客户医院管理导读.md)**。
> **唯一真源 = `account.sites`（MySQL `accounts.sites JSON`，负责医院名数组）。** 修复历史缺陷：医院管理设的 `customer.impl.name`（纯名字串，只写 customers.json）与账号 `accounts.sites`（只写 MySQL）**存两份、各写各的、无同步链路** → 医院管理设了实施人但账号 `sites` 空 → 实施端「尚未分配医院」（线上现象：安吉县人民医院 `impl.name=王隆` 但 `wanglong.sites=[]`）。定版：`account.sites` 为唯一真源（实施端可见性 + 全后端隔离 `scopedForField` 唯一认它），关联键 = 医院名（`account.sites` 元素 `===` `customer.name` `===` `intakes.site`，重名会串号，同 CU-02 AC-18 限制 NEEDS-HUMAN）。

## 1. 用户故事 / 目标
作为**运营 / 管理员 + 负责实施**，我要让「某医院归谁实施」在医院管理和实施端**始终一致、零漂移**（一院一实施，唯一真源 `account.sites`）；让实施能在实施端**回写维保到期**、运营端同源可见并留痕；并能对某台机器**生成产品可识别的激活文件**（`.lc-activation.lic`）供下载分发。

## 2. 范围
- **包含**
  - 实施人↔医院**双向写穿**：`customer-save` 指定实施人 → 把该医院名唯一归给目标账号 `sites`（排他移动）；`GET /api/customers` 的 `impl` 从 `account.sites` **读时派生**（不信文件死值，零漂移，共管优先真正实施人）。
  - **维保到期回写**（`maintainEnd`）：实施端 `POST /api/customer-maintain` 回写 + 留痕 + 幂等；运营端 `customers.html` `#edMaintainEnd` 也可编辑（同源）。**主实现 / 完整 AC 在 FS-05 §I（AC-25~31）+ §4.6**，本 spec 只承载「运营端同源可见 + 双向写穿视角」的接口 AC-22。
  - **激活文件生成**（`POST /api/activation/generate`）：设备码 → `.lc-activation.lic` 内容，前端 Blob 下载；算法复刻产品注册/激活机制（逐字校对 + 反编译校验器确认）。
- **不包含 / 见他处**
  - 台账列表 / 增删改 / 关联产品·版本 / 工单数 → **CU-02**。
  - 维保回写的实施端 UI、越权收敛、待办闭环细节 → **FS-05 §I**（本 spec 只引接口契约）。
  - **停用/开通独立切换 + 留痕** → 待决策（见 CU-01 §5 待决策 6）。
  - **部署清单模板 / 每院勾选**（AC-23~25）→ **2026-08-05 架构重构整体废弃并从代码删除**，仅在 §附录保留历史追溯（现改为跟随产品代码，见 BP-01 §I / FS-05 §K）。

## 3. 验收标准（AC · Given-When-Then）

### 实施人↔医院 双向写穿（2026-07-23 模型裁决）
> 【裁决模型】**一院一实施 · `account.sites` 为唯一真源 · 双向写穿。** 唯一真源 = `account.sites`（实施端可见性 + 全后端隔离 `scopedForField` 唯一认它）；关联键 = 医院名（重名会串号，同 CU-02 AC-18 限制 NEEDS-HUMAN）。
- **AC-19 [接口]（医院管理 impl 读时派生，零漂移 · 共管优先 impl）** Given 读 `/api/customers`（或 save/delete 出参）When 派生每条 `impl` Then **不信 customers.json 里那份死值**，改为从 `account.sites` 反查（`deriveImpl` → `implAccountForSite`，server.mjs L467-480）：取 sites 含 `customer.name` 的**启用 impl/pm 账号**（`isImplAccount`：`role∈{impl,pm}` 且 `enabled!==0`）——**共管场景**（impl 落地 + pm 统筹同持一院，2026-07-23 裁决允许）「负责实施」**优先取 `role==='impl'` 的账号**（真正实施人），其次 pm，同角色再按 `username` 字典序取首；`impl={name:(a.name||a.username), phone:(a.phone||'')}`；查不到 → `impl={name:'',phone:''}`。这样医院管理显示/筛选永远跟账号一致、且共管时显示真正实施人而非统筹 pm。
- **AC-20 [接口]（customer-save 写穿账号 sites · 一院一实施）** Given 保存客户（新增/编辑）When `b.impl.name` 指定实施人 Then 把该医院名（新增=`b.name`；编辑=新 name）**加进目标账号 sites**（去重）、并**从所有其他账号 sites 移除**该医院名（排他移动，`reconcileSiteToImpl` server.mjs L495-505）；`b.impl.name` 为空 → 从**所有**账号 sites 移除该医院名（解绑）；**编辑改名**（`existing.name!==newName`）→ 先把**旧名**从所有账号 sites 移除（`removeSiteFromAllAccounts` L482-491），再按新名调和（sites 以名为键，防孤儿）；目标名匹配不到任何账号 → 仅执行移除、跳过写入（防御性边界，UI 只给存在账号）。`await saveAccounts` 落库（server.mjs L6147-6151）。
- **AC-21 [接口]（改绑派生跟随）** Given 医院 H 先归账号 A、后经 customer-save 改 impl=B When 读 `/api/customers` Then H 的 `impl.name` 从 A 变为 B（派生跟随账号，零漂移），且 A.sites 不再含 H、B.sites 含 H。

### 维保到期回写（🆕 2026-07-31 · 主实现在 FS-05 §I / §4.6）
- **AC-22 [接口]（维保到期实施端可回写 · 运营端同源可见 · 留痕）** Given 医院 H 有维保到期字段 `maintainEnd`（`yyyy-MM-dd`，运营端 `customers.html` `#edMaintainEnd` 已可编辑）When **负责该院的实施**在实施端调 `POST /api/customer-maintain {site:H.name, maintainEnd}`（越权 site→403、非法日期/空→400、`isAdmin` 不限）Then 回写 `data/customers.json` 该医院 `maintainEnd`（`.slice(0,20)`）+ 追加 `maintainLog[]`（`{by,at,site,from,to}`，≤200 条）+ 幂等（新值===旧值不写不留痕）；运营端因**同源 `customers.json`**（`GET /api/customers`）立即可见新 `maintainEnd`。**接口/AC 细节见 FS-05 §I（AC-25~31）+ §4.6。**

### 激活文件生成（🆕 2026-08-28 · 运营端·admin 限定）
> 复刻被跟踪产品的注册/激活机制（`cn.momosoft.ops.system.service.impl.IRegistrationServiceImpl`）：运营在「医院管理」传入目标机器的**设备码**，生成产品可识别的 `.lc-activation.lic` 激活文件供下载分发。算法已逐字校对 + 反编译校验器（`SystemActivationValidator`）确认，设备码对则文件必过产品本机校验。
- **AC-26 [接口]（激活文件生成 · admin 限定 · 算法复刻）** Given 运营在「医院管理」传入设备码 When 调 `POST /api/activation/generate {deviceCode}`（**仅管理员**：不在 `FIELD_OK`/`LINK_OK`/`FS08_FIELD_API`，`authGate` deny-by-default 对非 admin 返 403/401，field 域经 `originGate` deny→403）Then 算 `license = Base64_标准(SHA-256(UTF8(设备码 + "lingchuang@123")))`（`"lingchuang@123"`=产品固定 `CommonConstant.VERIFY_KEY`，**服务端常量 `ACTIVATION_VERIFY_KEY`、不暴露前端**；标准 Base64 含 `+`/`/`/`=` padding = Node `crypto.digest('base64')`），返回 `{ok:true, filename:".lc-activation.lic", license, content:"#System Activation License\nactivation_key=<license>\n"}`。**黄金向量**（证复刻 Java 一致）：设备码 `4aea73e50cc4f679124cb68ac02942e` → license 恒 `Kz3W2wXfWO9/NvRWxl7UCxLyyYcKh2WxMT+aeBSnxi8=`。`deviceCode` 空/纯空白 → 400「设备码不能为空」；长度 >200 → 400（防滥用，不做格式强校验，machineId 各平台格式不同）。**纯计算：不落库、不写盘、无字段映射**（不像 Java 存文件，本平台只要下载）。文件格式为 Java Properties（`VerifyConstant.LICENSE_FILE=.lc-activation.lic` / `ACTIVATION_KEY=activation_key`）：首行注释 `#System Activation License`，base64 值里的 `=`/`+`/`/` 直接写不转义（`Properties.load` 取第一个 `=` 后全部为 value 字面量，读回正确）。实现 = `activationLicense`/`activationFileContent`（server.mjs L1548-1552）。
- **AC-27 [前端]（医院管理落点：行内 + 工具条 + 预填 + Blob 下载）** Given 医院列表 When 某行「操作」列点「激活文件」（`data-act="activation"`）Then 打开激活抽屉（`#activationDrawer`，共用本页 `openDrawer`/`closeDrawer` 自实现），设备码输入框**从该医院 `deviceCode` 字段预填**（可编辑）；工具条另有「激活文件生成」按钮（`#btnActivation`）→ 复用同一抽屉（`openActivation('')`，空设备码手输）。点「生成并下载」→ 设备码空则提示、不发请求；否则打 `/api/activation/generate` 拿 `content` → `Blob` + `a.download=".lc-activation.lic"` 触发浏览器下载，并回显生成的文件内容（`.lc-activation.lic` 已生成提示）。

## 6. 业务规则 / 非功能
- **权限**：`customer-save`（写穿）/ `activation/generate` = **仅管理员**（`authGate` deny-by-default，不在 `FIELD_OK`/`LINK_OK`/`FS08_FIELD_API`）；`customer-maintain` = 管理员 + 负责该院实施（`isAdmin` 不限、越权 site→403，见 FS-05 §I）。
- **零漂移**：`impl` 唯一真源 = `account.sites`，医院管理显示/筛选/实施端可见性**永远一致**——`customer.impl` 文件死值不再被信任（`deriveImpl` 读时反查）。
- **一院一实施排他**：`reconcileSiteToImpl` 先从**所有**账号 sites 移除该医院名再加进目标账号（保证一个医院名只在一个账号 sites 里）；共管（impl+pm 同持）时显示优先取真正实施人（`role==='impl'`）。
- **改名防孤儿**：编辑改名先清旧名（`removeSiteFromAllAccounts(oldName)`）再按新名调和（sites 以名为键）。
- **激活算法安全**：`VERIFY_KEY` 为服务端常量，不暴露前端；纯计算不落库不写盘；设备码只做长度上限（≤200）防滥用，不做格式强校验（machineId 各平台格式不同）。
- **幂等**：维保回写新值===旧值不写不留痕（FS-05 §I）；写穿 `reconcileSiteToImpl` 先移除再加、天然去重幂等。
- **留痕**：维保回写追加 `maintainLog[]`（谁/何时/哪院/from→to，≤200 条）；实施人写穿不单独留痕（`account.sites` 即当前态）。
