## 1. 用户故事 / 目标
作为**运营 / 管理员**，我要维护一份「客户（现场 / 医院）台账」——记录每家医院的名称、等级、地区、负责实施人、开通状态，以及它上了哪些产品及各自版本，还能看到该医院的**工单数**，以便按等级/地区/状态筛选管理，且**提交需求/BUG 时选客户即自动带出产品 + 版本**，让工单对齐到正确的客户与版本。

## 2. 范围
- **包含（re-target 原型 + 扩字段实现）**

  - 筛选（`.filter-bar`/`.filter-grid`）：**地区 / 等级 / 状态 / 关键词**四项——**选择型（地区/等级/状态）即选即查**（`change` → 重置第 1 页 + 重渲染），**关键词回车触发**（本地按医院名 `includes` 过滤）。地区下拉选项由现有客户 `region` 去重动态生成。

  - 工单数（`ticketCount`）读时派生（按 `intakes.site ↔ 客户名`）。

### 列表（整宽 `.data-table` + 分页 + 筛选）
- **AC-1 [接口]（列表渲染 + 扩字段 + ticketCount）** Given 台账有 N 家医院 When 打开客户管理页（`GET /api/customers` → `{customers:[...]}`）Then 每条含 `{id,name,level,region,impl:{name,phone},status,products,updatedAt,ticketCount}`；页面整宽 `.data-table` 逐行渲染：医院名 + 等级标签（三甲=`tag-primary`/其它=`tag-gray`）、地区、负责实施（`.avatar` 头像 + 姓名 + 电话）、上线产品·版本（`tag-info`，版本空显「未指定」）、状态（`tag-dot`，已开通=`tag-success`/未开通=`tag-gray`）、工单数（`text-link` 当 >0）、操作（编辑/删除）；顶部「共 N 家医院」。
  - **实施人姓名/电话取自账号（单一来源，2026-07-22；2026-07-23 定为读时派生）**：列表实施人**姓名 + 电话**均**不再取 `customer.impl` 那份死值**，改由 `custWithTicketCount → deriveImpl` 从 `account.sites` 反查启用 impl/pm 账号派生（`name=a.name||a.username`，`phone=a.phone||''`）；匹配不到显 `—`。手机号统一在「账号管理」维护（AM-01 `accounts.phone`）。抽屉实施人为账号下拉 `#edImplName`（无电话输入），`impl.phone` 沦为遗留字段（仍在文件但列表不用）。**派生细则 = CU-03 AC-19。**
- **AC-2 [前端]（空态）** Given 台账无医院 When 渲染 Then 表格 `.empty` 显示「还没有医院，点右上角『新增医院』」；有数据但筛选无命中 → 显示「没有匹配的医院」，均不报错。
- **AC-3 [前端]（产品名映射）** Given 客户 products 存 `{project=产品id, ...}` When 渲染标签 Then 显示**产品中文名**（`pname(project)` 从 `/api/projects` 映射），未知 id 回退显示 id。
- **AC-3b [前端]（分页）** Given 客户数 > 每页 When 渲染 Then `.pagination` 显总数 + `.pager` 页码；切每页条数（8/20）或翻页正确；筛选/删除后当前页超界自动回退到末页。
- **AC-3c [前端]（筛选·选择即选即查/关键词回车）** Given 地区/等级/状态下拉 When 选中 Then 立即重置第 1 页 + 重渲染（无需点查询）；关键词框回车才按医院名 `includes` 过滤。地区下拉选项由现有客户 `region` 去重生成。

### 新增 / 编辑（抽屉 `#editDrawer`，自实现开关）
- **AC-4 [接口/前端]（新增成功 + 扩字段落库）** Given 抽屉表单 When 填医院名/等级/地区/状态/负责实施 + 关联产品后点「保存」（`POST /api/customer-save`，无 id）Then 返回 `ok:true`，新记录含 `{id,name,level,region,impl,status,products,updatedAt,ticketCount}`，`updatedAt` 格式 `yyyy-MM-dd HH:mm`；列表出现该医院。
- **AC-5 [接口/前端]（名称必填 · 前后端双层）** Given 表单 When 名称空 Then 前端 `invalid` 高亮 + toast「请填写医院名称」不发请求；绕过前端直调 `customer-save` 且 `name` 空/纯空白 → 后端 400 `{ok:false,error:'请填客户名称'}`。
- **AC-5b [前端]（地区必填 · 前端）** Given 表单 When 地区空 Then 前端 `invalid` 高亮 + toast「请填写地区」不发请求。（后端 region 可空、不拦——前端拦，见 §6。）
- **AC-6 [接口]（扩字段归一 + 名称长度）** Given 表单 When 名称输入 Then 前端 `maxlength=60` + 字数计数；后端 `normCustomer`：`name.trim().slice(0,60)`、`region.trim().slice(0,40)`、`impl.name/phone` 各 `.slice(0,20)`；`level` ∉ {三甲,三乙,二甲} → 归「三甲」，`status` ∉ {已开通,未开通} → 归「已开通」，缺 `impl` → `{name:'',phone:''}`。（名称 60 vs 原型 40 统一取值 = NEEDS-HUMAN，见 CU-01 §5 待决策 2。）
- **AC-7 [接口/前端]（编辑回填 + 整条覆盖含扩字段）** Given 某医院 When 点「编辑」Then 抽屉标题「编辑医院」、名称/等级/地区/状态/负责实施/产品行全部回填；改动后点「保存」（`customer-save` 带该 id）Then 该记录被**整条覆盖更新**（含扩字段，不新增），列表总数不变、展示新值。**偏更新保留**：`serverInfo/deviceCode/maintainEnd/contacts/remark/deployTasks/updateProgress` 用 `'k' in b`/`existing` 判存在，未传不清空（`normCustomer` L437-450）。
- **AC-8 [前端]（多产品行增删）** Given 抽屉 When 点「添加产品」新增一 `.prow`、或点某行删除 Then 产品行相应增减；无产品行时显占位「还没关联产品」。
- **AC-8b [前端/接口]（版本改为选择型 · 从 `/api/versions` 选，2026-07-23）** Given 产品行 When 选定/换某产品 Then 版本单元格是 `<select class="select cver">`（**不再自由手输**，被 ui.js 自定义下拉增强），选项 = 首项「未指定」(value='') + 该产品 `GET /api/versions?project=<产品id>`（git tag，最新在前）各版本；按产品懒加载 + 缓存（`fetchVersions`/`VER_CACHE`），**换产品重拉重填、重置为「未指定」**。
  - **保留历史自定义值**：编辑医院时某产品已存的版本（如历史手输 `v2.0`）若**不在** `/api/versions` 列表里 → 仍作为一个选中项加进 options（标「（历史值）」），避免下拉丢值、保存时被清空。
  - **产品无版本**（`/api/versions` 返回空）→ `.cver` 只有「未指定」一项（可加禁用提示「该产品暂无版本」），不允许自由手输。
  - **存储/回读不变**：后端 `normProduct` 未改，版本仍是**自由字符串**存 `data/customers.json`（前端只改「怎么填」，不改「存什么」）。动态填充的 options 由 ui.js 自定义下拉的 childList MutationObserver + value setter + change 三路自动重同步。
  - **读值必须用原生 select（`select.cver`/`select.cprod`，带 tag）· 2026-07-23 保存失败回归修订**：ui.js 自定义下拉增强器会把原 select 的附带 class（`.cprod`/`.cver`）**复制到它生成的 `<div class="ui-sel-wrap …">` 上，且该 wrapper 排在原生 select 之前**；`collectProducts` **必须**用 `r.querySelector('select.cprod')`/`sr.querySelector('select.cver')` 读原生 `<select>` 的 `.value`——若用裸 `.cprod`/`.cver`，`querySelector` 按文档预序**先命中无 `.value` 的 wrapper `<div>`** → pid/version 落空 → `collectProducts` 返回 `[]` → 保存把客户产品清空（用户看「保存失败/无反应」）。收集结果须判空、缺元素跳过不抛。
- **AC-8c [前端/接口]（关联产品维护到「子系统 + 各自版本」· 2026-07-23 裁决 · 向后兼容）** Given 抽屉产品行 When 选定某产品 Then 该产品行**展开该产品的子系统清单**——每个子系统一项：`[☑ 是否上线勾选] 子系统中文名(desc) [版本下拉(/api/versions?project=)]`；**只有勾选的子系统**随 `collectProducts` 存进 `subsystems:[{name,version}]`（`name`=子系统英文/原始 name=过滤键与后端校验键；`version` 复用 AC-8b 的 `.cver` 选择型下拉）。**换产品**（`.cprod` change）→ 重建该行子系统清单（新产品的子系统、全不勾）。
  - **数据形状（新）**：`products[i] = { project, subsystems:[{name,version}] }`——勾选的子系统各维护一个版本；`name` 须命中 `projById(project).subsystems[].name`（后端 `normProduct` 用 `subsystemNames(proj)` 校验，不命中丢弃、防臆造），`version` 后端 `String().trim().slice(0,30)`、按 `name` 去重。**无勾选子系统的产品** → `subsystems:[]` 仍保留该产品（实施端兜底显全部，避免误删）。
  - **向后兼容旧形状**（不做破坏性迁移）：老数据 `products[i]={project,version}`（无 `subsystems` 字段）**照存照读**、后端 `normProduct` 原样保留；消费方（实施端 `buildSubOptions`/`currentArchive`/`renderHospChip`、`custProductVersion`/`custSubVersion`）遇无 `subsystems` 的产品 → **兜底按「该产品全部子系统 @ 该产品级 version」处理**（= 保持现状行为，绝不删老字段、不强迁）。
  - **编辑回填**：客户产品是**新形状**（有 `subsystems`）→ 勾选并回填各子系统版本（`checkedMap={name:version}`）；是**旧形状**（只有 `version`）→ 默认**勾选该产品全部子系统、各版本预填旧 `version`**（保存即无损升级成新形状、保持现状「全部子系统」行为），admin 再改。
  - **列表页展示**：上线产品·版本列，新形状显「产品 · N 个子系统」、旧形状显「产品 版本」。
  - **保存不得静默失败（回归 · 2026-07-23）**：`saveCustomer` 里 `products:collectProducts()` 须在 `try{}` 块内调用；任何前端收集异常经 `catch(e)` → `toast('保存失败：'+e.message)` 可见 + `finally` 恢复保存按钮——不再出现「点保存无反应」的静默态。`collectProducts` 自身对缺元素健壮（判空跳过、恒不抛）。
- **AC-9 [接口]（产品去重 / 有效性 / ≤40）** Given 同产品多行或含未登记产品 When 保存 Then `normCustomer` 每 project 去重（保留首条）、只保留 `projById` 命中的有效产品、至多 40 条；产品内 `subsystems` 由 `normProduct` 规范化（命中该产品子系统 name + version≤30 + 按 name 去重）。

### 删除
- **AC-10 [前端]（删除确认 · 走 uiConfirm）** Given 一家医院 When 点行内「删除」Then 弹 `uiConfirm('删除医院「X」？',{title:'删除医院',danger:true,okText:'删除'})`；确认后 `POST /api/customer-delete` 传该 id，成功后列表移除。
- **AC-11 [接口]（精确删除不误删）** Given 多家医院 When 调 `customer-delete` 传某 id Then 仅该 id 被删、其余不动；不存在 id → 404 `{ok:false,error:'not found'}`；缺 id → 400 `{ok:false,error:'缺少 id'}`。

### 工单数派生
- **AC-18 [接口]（工单数按 site↔name 派生）** Given 客户名 = 某工单 `intakes.site` When 读 `/api/customers`（或 save/delete 出参）Then 该客户 `ticketCount` = 全项目 `intakes` 中 `site === 客户名` 的**非 consult 工单**条数（`custTicketCountBySite` 全项目扫 `listIntake`）；无同名工单 → 0；**读时派生，不落文件、不入库**。**关联键 `site↔name`（真库无 `customerId` 列）会因重名串号 = NEEDS-HUMAN**（见 CU-01 §5 待决策 3/4），本次按名称匹配落地。

## 4. 接口契约（3 端点，server.mjs）
> 本次**不新增端点、不改路由**，仅在 `normCustomer` 扩字段 + `/api/customers`/save/delete 出参挂读时派生的 `ticketCount`（+ 派生 `impl`，见 CU-03）。入参兼容旧调用（未传扩字段则归一为默认值）。对 `docs/P0-数据模型对账与接口清单.md §A.4 / §D.3` 核对：3 端点均为**现有 API**（P0 §A.4 客户：customers / customer-save / customer-delete），`customer-save` 属 P0 §D.3「改·增字段 level/region/impl/status」。

- **`GET /api/customers`**（server.mjs L6135）→ `{ customers:[...] }`，每条 = `{ id, name, level, region, impl:{name,phone}, status, products:[...], updatedAt, ticketCount, ...扩字段 }`。同一端点同时供**提交端现场下拉**与本管理页（在 `LINK_OK`/`FIELD_OK` 白名单内，现场侧只用 `id/name/products`——扩字段对现场侧无害）。`ticketCount` **读时派生**（`custWithTicketCount` L506-511），不落文件。`loadCustomers()` 读 `data/customers.json`，文件不存在返回 `[]`。
- **`POST /api/customer-save`**（server.mjs L6136；新增/编辑；**仅管理员**，`authGate` deny-by-default，不在 `FIELD_OK`/`LINK_OK`）。入参 `{ id?, name, level?, region?, status?, impl?:{name,phone}, products:[...], serverInfo?, deviceCode?, maintainEnd?, contacts?, remark? }`（`products` 元素为新形状 `{project,subsystems:[{name,version}]}` 或旧形状 `{project,version}`，见 AC-8c）；`name` 空/纯空白 → 400 `{ok:false,error:'请填客户名称'}`。经 `normCustomer()`→逐产品 `normProduct()` 规范化（见 AC-6/AC-8c）。出参 `{ok:true, customer, customers}`（均带派生 `ticketCount`+`impl`；products 原样透传新旧形状）。带 id 命中整条覆盖、否则新增（id = `'c'+4字节hex`）。**副作用**：写穿 `account.sites`（见 CU-03 AC-20）。
- **`POST /api/customer-delete`**（server.mjs L6156；按 id 精确删，绝不批量；仅管理员）→ `{ok:true, customers}`（带 `ticketCount`）；id 未命中 → 404 `{ok:false,error:'not found'}`；缺 id → 400 `{ok:false,error:'缺少 id'}`。

**关系点出（不在本 spec 实现）**
- **`GET /api/versions?project=<产品id>`** → `{ versions:[...git tag，最新在前...], syncedAt }`（现有端点，field.html 系统视图版本下拉在用；在 `LINK_OK`/`FIELD_OK` 白名单）。本 spec 抽屉产品行「版本」下拉的候选数据源（AC-8b/AC-8c）。**server.mjs 未改。**
- `POST /api/customer-version`（版本回写）在 FS-05 / BP-01，非本 spec。本 spec 产品行「版本」由自由文本输入改为**从 `/api/versions` 选择**（`.cver` 现为 `<select class="select cver">`，见 AC-8b）。

## 6. 业务规则 / 非功能
- **权限**：新增/编辑/删除为**管理员**操作——`authGate` deny-by-default：`customer-save`/`customer-delete` **不在 `FIELD_OK`/`LINK_OK`**，非管理员自动 `forbidden`（管理员判定走 `isAdmin`，兼容存量 `role==='dev'` 账号，见 lessons）。列表读取 `GET /api/customers` **在 `LINK_OK`/`FIELD_OK` 白名单内**，同时供提交端现场下拉（现场侧只用 `id/name/products`——扩字段对现场无害，已冒烟核实 products 结构未破坏）。
- **产品字段映射**：JSON 产品 `{project,...}`（`project`=产品 id），展示用中文名（`projById`/`pname()`）；`normProduct` 校验 `project` 命中 `projById`（有效性 + 去重 + ≤40）、子系统 name 命中 `subsystemNames(proj)`。
- **校验（前后端双层）**：名称必填 `maxlength=60`（前端）+ 后端 `.trim().slice(0,60)`；地区**前端必填** `maxlength=40`（后端可空、`.slice(0,40)`）；impl 姓名/电话各 `maxlength=20` + 后端 `.slice(0,20)`；**版本改为下拉选择（AC-8b），不再手输**，值来自 `/api/versions` tag 或保留的历史值，后端仍 `.slice(0,30)`；等级/状态前端下拉限定 + 后端枚举归一（非法→默认）。名称空后端返 400。
- **时间展示**：`updatedAt` 由 `nowStamp()` 生成，已是 `yyyy-MM-dd HH:mm`（对齐全局 UI 规范第 12 条）。
- **工单数派生**：`custTicketCountBySite()` 全项目扫 `listIntake`（不含 consult）按 `site` 计数，`custWithTicketCount()` 给每条客户挂 `ticketCount = cnt[name]||0`；只读、不落文件、不入库。
- **数据权限**：台账全局共享（现场提交下拉认领），列表不做行级过滤；越权控制在写操作（仅管理员）。
- **幂等/并发**：`customer-save` 按 id upsert（整条覆盖），无并发锁——同客户后写覆盖，低频可接受；`customer-delete` 按精确 id 单删、绝不批量。
- **无留痕/无状态机**：删除为**硬删**；状态改由抽屉编辑（无独立「停用/开通」切换端点 + 留痕，属待决策，见 CU-01 §5 待决策 6）。
