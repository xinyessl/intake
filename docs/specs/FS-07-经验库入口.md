## 1. 用户故事 / 目标
作为**现场实施工程师 / 现场产品经理（真实库 role=`impl`/`pm`）**，我要在实施端顶栏点开「经验库」，输入关键词检索运营端沉淀的「问题 → 解法」条目（`kb_entries`），以便**提单前先自查已知解法、减少重复提单**；查得到就自查解决，查不到再走 AI 对话提交（FS-04）。

> 落地形态遵循 **决策 A（Node 栈）**：入口落在 `public/field.html` 顶栏 + 检索面板/页，复用 `server.mjs` 的 kb 能力，**不是 Vue3/Java**。
> 权限遵循 **决策 B（角色 impl）**：现场账号可**只读检索**经验库，**无权新增/编辑/删除**（`kb-save`/`kb-delete` 仍仅管理员）。
> 分期遵循 **决策 C**：本条不涉批次 → **P1**。

## 2. 范围
- **包含**：
  - 实施端顶栏「经验库」入口（原型 417 行 `<span><i class="ti ti-book"></i> 经验库</span>`，与「待办」并列），点击打开检索面板/页（抽屉或独立视图，前端形态见 §6）。
  - 关键词检索「问题 → 解法」：输入关键词 → 调后端检索接口 → **跨全公司经验库（所有产品）** 返回匹配的 `q`（问题）/`a`（解法）/`subsystem`（子系统）/来源 + **所属产品**，按相关度排序（全库积累对现场自查更有价值；结果按产品区分）。
  - 结果列表：每条显示 问题（`q`）+ 子系统 + 来源徽标，可展开查看完整解法（`a`，Markdown 受控渲染，复用 KB-01 的 `md()` 口径）。
  - 空态引导：查不到（结果为空）→ 提示「未找到相关经验，可去 AI 对话提交」并给一个跳到 AI 对话提交（FS-04）的入口；命中并展开 → 自查解决、不必提单。
  - 权限：现场只读检索；检索面板内**无**新增/编辑/删除按钮。
- **不包含**：
  - 经验库的新增/编辑/删除（属 KB-01 运营端，现场无权）。
  - RAG 召回算法改造（复用现有 `kbSearch` 的中文 bigram + 英文词重叠打分，本 spec 只声明其为检索来源，不改打分逻辑）。
  - 咨询工单沉淀经验（`kb-from-consult` 属答疑侧，本条不含）。
  - 「按医院/子系统上下文自动预填检索词」等联动增强（非本条范围，若需另立）。

## 3. 验收标准（AC · Given-When-Then · 每条必须可自动化判定）

### 入口与面板
- **AC-1（顶栏入口）** Given 现场账号已登录 `public/field.html` When 渲染顶栏 Then 顶栏右侧「待办」旁出现「经验库」入口（`ti-book` 图标 + 文案「经验库」，对齐原型 417 行）；点击 Then 打开检索面板/页（抽屉自实现 open/close 或独立视图；**不依赖** `UI.openDrawer`，参见 lessons L-004）。
- **AC-2（检索框 · 回车/点击触发 · 全库）** Given 检索面板已打开 When 在关键词自由文本框输入并按 Enter（或点「搜索」按钮）Then 以关键词调检索接口**跨全公司经验库（所有产品）**拉结果并重渲，**不限当前工作空间产品**（`project` 为可选过滤参数，缺省即全库）；**自由文本框不即输即查**（对齐全局规范 #11：文本框靠回车/按钮触发，避免每敲一字请求）。
- **AC-9（2026-07-23 新增 · 打开即浏览全部）** Given 现场账号点开经验库面板（`openKb`）When 面板打开 Then **默认拉取并展示全库所有条目**（调 `GET /api/kb-search?all=1`：`all=1` 且无 `q` → 返回**跨所有产品**的全库条目，按**分数无关的稳定顺序**（产品登记序 × 产品内条目序）、**封顶 50**，每条带 `project`+`productName`+`q/a/subsystem`，复用现有结果渲染 `mkKbItem` 按产品分辨、答用 `md()`），**而不是一打开就空态**；输入关键词回车/点搜索 → 走 `?q=` 精确检索**覆盖**浏览结果，**清空关键词** → 回到浏览全部；空态文案「经验库暂无内容」**仅在全库真的一条都没有时**显示。**契约保护**：`q` 空且**无 `all`** 时仍返回 `[]`（现有温和空态契约不变，不被 `all` 分支破坏）。

### 检索结果
- **AC-3（结果渲染 问题→解法 · 标产品）** Given 全库 `kb_entries` 有匹配条目 When 检索返回 Then 结果列表按相关度顺序渲染，每条显示：**所属产品（`project` id + `productName` 产品名，用于区分产品）**、问题（`q`）、子系统显**中文**（服务端 `subsystemLabel`：`kbSubLabel(project, subsystem)` 查该产品 `subsystems[].name===subsystem` → 取 `desc||name`，查不到回退原 `subsystem` 名；前端渲染取 `subsystemLabel || subsystem`，无则「—」，对齐 KB-01 AC-3。2026-07-23：修「子系统显英文 name（如 `audit`）应显中文 desc（如『审方』）」——原 `subsystem` 存英文 name，`subsystemLabel` 为加法字段供展示，`subsystem` 保留供搜索/过滤）、来源徽标（`.src-{manual,consult,auto}`，文案 `manual→人工`/`consult→答疑`/`auto→自动`，对齐 KB-01 AC-2）。跨产品命中在同一列表内按分数排序，产品字段可视（不同产品条目可辨）。
- **AC-4（展开看解法）** Given 结果某条 When 点击该条（或「展开」）Then 展开显示完整解法 `a`（Markdown 受控渲染，仅 `**加粗**`/`` `code` ``/换行，先转义 `&`/`<` 再渲染，防 XSS，复用 KB-01 `md()` 口径）；再点收起。
- **AC-5（相关度与 Top-N · 全库聚合）** Given 关键词与多产品多条命中 When 检索返回 Then **对所有产品逐一 `kbSearch` 后合并、按关键词重叠打分全局降序**（复用 `kbSearch` 的中文 bigram + 英文词逻辑），返回全局 Top-N（N 默认 5，可由入参控制上限、封顶如 20）；无任何 token 命中或全库无条目时返回空数组。

### 空态与提单联动
- **AC-6（查不到 → 引导提单）** Given 检索结果为空 When 渲染 Then 显示空态「未找到相关经验」+ 一个「去 AI 对话提交」入口（跳 FS-04 的 AI 对话提交），**引导先自查再提单**；命中并展开解法时不显示强制提单。
- **AC-7（命中自查免提单 · 可观测）** Given 现场检索命中并展开解法 Then 面板不产生任何工单/写库副作用（纯读）；关闭面板回到工作空间，无新增 `intakes`/`kb_entries` 行（检索为只读，用于「先自查再提单」）。

### 权限（决策 B）
- **AC-8（现场只读 · 无编辑入口 + 后端纵深）** Given 现场账号（`impl`/`pm`）打开经验库检索 Then 面板内**无**新增/编辑/删除按钮（前端按角色隐藏）；即便绕过前端，现场账号直调 `POST /api/kb-save`、`POST /api/kb-delete` 仍被 `authGate` 判 `forbidden`（403，因二者**不在** `FIELD_OK` 白名单）；而现场可用的检索端点（见 §4）**已加入** `FIELD_OK`，现场账号调用返回 200（否则 403）。

## 4. 接口契约

> ⚠️ **事实源核对（禁臆造，已逐字对 `server.mjs`）**：
> - `/api/kb-list`（server.mjs L973）**当前不在 `FIELD_OK`**（L590 白名单仅含 `kb-from-consult`）；方案 A 下 **`kb-list` 维持仅管理端、不加白名单**——需 **🔧 把新端点 `kb-search` 加入 `FIELD_OK`** 才能现场可用（任务简报「kb-list 已在 FIELD_OK」与真实代码不符）。
> - **无对外 `/api/kb-search` 端点**：`kbSearch(projId, query, n)`（L475-480）仅内部函数，只嵌在 `/api/consult`/`/api/intake-chat`（L945）内部调用，不对外暴露。→ **🆕 新增 `GET /api/kb-search`（方案 A 已裁决）**，在其外做**全库跨产品聚合**（遍历各产品调 `kbSearch`、合并 Top-N、标产品）。

| 端点 | 方法 | 入参 | 出参 | 复用度 | 说明 |
|---|---|---|---|---|---|
| `/api/kb-search` | GET | `q`（关键词；`all=1` 且无 `q` 时可空）、`all?`（**`1`=浏览全库全部条目**，见 AC-9）、`project?`（**可选**产品 id 过滤；**缺省 = 全库所有产品**）、`n?`（检索上限，默认 5、封顶 20） | `{entries:[{id,project,productName,q,a,subsystem,subsystemLabel,module,tags[],from,at}]}`（`subsystemLabel`=子系统中文 desc，`subsystem`=英文 name） | 🆕（**已裁决 · 方案 A**） | **本 spec 新增（方案 A 已定）**：**全库跨产品检索**——对所有产品逐一 `kbSearch(pid,q,n)`、合并后按分全局降序取 Top-N；每条结果**加 `project`（产品 id）+ `productName`（产品名，取自 `projById(pid).name`）以区分产品**。**`all=1` 且无 `q`（2026-07-23 AC-9）**：返回跨所有产品的**全库条目**（分数无关的稳定顺序：产品登记序 × 产品内条目序，直接读各产品 `loadKB(pid)`）、**封顶 50**、每条同样带 `project/productName`；供打开面板即浏览。`q` 有值 → 现有检索行为不变；`q` 空且**无 `all`** → 空数组（温和空态契约不变）。**必须加入 `FIELD_OK`**（现场只读检索），管理员天然放行。 |
| `/api/kb-list` | GET | `project`（返回该产品全部条目） | `{entries:[...]}` | 复用（**不改 · 维持仅管理端**） | 现有端点（L973）。**方案 B（扩 kb-list + 前端本地过滤）已裁决不采纳**；`kb-list` **不加入 `FIELD_OK`**，维持仅管理端（KB-01 运营端用）。现场检索一律走上方 `kb-search`。 |
| `/api/kb-save` | POST | — | — | 复用（不改） | **现场无权**：不在 `FIELD_OK` → 现场调用 403（AC-8 纵深断言，本 spec 不改其实现）。 |
| `/api/kb-delete` | POST | — | — | 复用（不改） | 同上，现场 403。 |

**内部函数（非 HTTP，供实现对照，勿臆造签名）**：
- `kbSearch(projId, query, n=5)`（server.mjs L475）：中文 bigram + 英文词重叠打分 Top-N（**单产品**）；返回内存对象数组 `[{id,q,a,subsystem,module,tags,from,at}]`。**全库检索（方案 A）= 在其外遍历所有产品各调一次、给每条打上 `project`/`productName`、合并后按分全局降序取 Top-N**（打分逻辑不改，仅在其外做跨产品聚合）。产品列表/产品名取 `projects`（`loadProjects()` / `projById(pid).name`）。
- `loadKB(projId)`：读该产品全部经验条目（缓存）；`projects`/`projById` 提供产品名（供结果 `productName`）。
- `srcKind(from)` / `subLabel(...)`：复用 KB-01 的来源徽标映射与子系统中文展示（`from∈{manual,consult}` 原样，其余「自动」）。

> **已裁决（2026-07-22）：采用方案 A（新 `kb-search`）**——语义清晰、只回相关条目、复用现成 `kbSearch` 打分、便于全库跨产品聚合与标产品、契约与 PRD §6「`GET /api/kb/search?q=`」最接近（本平台路径统一用 `kb-search` 连字符）。方案 B（扩 kb-list + 前端过滤）**不采纳**（把全量条目吐给现场、且难以跨产品聚合与标产品）。

## 5. 数据契约
**表 `kb_entries`（对照 `db.mjs init()` 真实 DDL 逐列核对，禁止臆造）**：本 spec **只读**，不新增/改列。

| 列 | 类型 | 检索侧用途 |
|---|---|---|
| `id` | VARCHAR(40) PK | 条目 id（结果 key）。 |
| `project_id` | VARCHAR(40) NOT NULL | **全库检索不按单产品收敛**；作为结果字段 `project` 回传（+ 关联 `projById(pid).name` 得 `productName`）用于**区分产品**（AC-3）。`project?` 入参可选过滤。 |
| `q` | TEXT | **问题/现象**（检索匹配 + 结果标题）。内存映射 `q`。 |
| `a` | TEXT | **解法/答复**（检索匹配 + 展开内容，Markdown）。内存映射 `a`。 |
| `subsystem` | VARCHAR(80) | 子系统（检索匹配 + 结果列，`subLabel` 中文展示）。 |
| `module` | VARCHAR(120) | 模块（检索匹配 token 之一）。 |
| `tags` | JSON | 标签（检索匹配 token 之一）。 |
| `source` | VARCHAR(20) | 来源枚举 `manual`/`consult`/`auto`（结果来源徽标）。 |
| `from_ref` | VARCHAR(60) | 来源引用；内存里映射为 `from`（`manual`/`consult`/工单 id）。 |
| `created_at` | VARCHAR(20) | 创建时间；内存里映射为 `at`；展示用共享 `fmtTime` → `yyyy-MM-dd HH:mm`。 |

> **字段名对账要点（易错，按真实列名）**：问题=`q`（非 `question`）、解法=`a`（非 `answer`）、来源引用=`from_ref`（内存对象里是 `from`）、时间=`created_at`（内存里是 `at`）。检索返回在 `kbSearch` 的**内存形状** `{id,q,a,subsystem,module,tags[],from,at}` 基础上**追加 `project`（产品 id，即 `project_id`）+ `productName`（`projById(pid).name`）用于区分产品**，前端渲染读这套键。
> **本条无库变更**：不新增表/列（纯检索，只读 `kb_entries`）；客户/模型文件存与本条无关。

## 6. 业务规则 / 非功能
- **数据权限（决策 B · 核心）**：现场账号（`impl`/`pm`）**只读检索全库**经验库。落地必须 **🔧 把新端点 `kb-search` 加入 `server.mjs` 的 `FIELD_OK`**（方案 A 已定；`kb-list` **不加**，维持仅管理端）。`kb-save`/`kb-delete` **绝不加入 `FIELD_OK`**（deny-by-default，现场自动 403，见 lessons「新增仅管理员 API」条）。**全库检索不做 sites/产品收敛，故不经 `scopedForField`**，也就绕开了 FS-01 的 `scopedForField` 决策 B 缺口（本条不依赖其修复）。
- **检索范围（已裁决 2026-07-22：全库）**：现场检索**面向全公司经验库（所有产品），不限「我负责医院已上产品」、不限当前工作空间产品**——理由：经验库的价值在于**全公司积累共享**、跨产品可复用解法才有意义。实现：`kb-search` 缺省遍历全部产品聚合（见 §4），`project?` 仅作可选过滤。**必须按产品区分**：每条结果带 `project`+`productName`，前端结果列可辨所属产品（AC-3）。
- **按钮级权限**：检索面板内不渲染新增/编辑/删除按钮（前端按 `role` 隐藏 + 后端 `authGate` 双层，AC-8）。
- **留痕**：检索为纯读，无写库、无操作日志（对齐 KB-01「经验条目本身无独立操作日志」）。
- **幂等/并发**：只读，无幂等/并发问题。
- **展示格式**：时间列用共享 `fmtTime` → `yyyy-MM-dd HH:mm`；解法用受控 Markdown（复用 KB-01 `md()` 口径，防 XSS）。
- **界面基线**：入口对齐原型 `redesign.html` 417 行（顶栏「经验库」与「待办」并列）；原型**仅一个入口按钮**、检索面板交互 PRD §4.8 未细化，本 spec 据 §4.8 合理补齐（检索框 + 问题→解法结果列表 + 从空态转提单）。落地 `public/field.html`：抽屉/面板 **自实现** open/close（部署 `shell.js` 无 `UI.openDrawer`，见 lessons L-004）；来源徽标复用 KB-01 的 `.src-*` 类。
- **非功能**：检索为轻量本地打分（现有 `kbSearch` 零依赖、内存召回）；**全库 = 遍历各产品调 `kbSearch` 后合并 Top-N**，产品数量级小（个位到十位数）、条目已内存缓存，性能负担可忽略；若后续产品/条目量大再加缓存或倒排（本期不做）。

## 7. 测试要点（交付给开发 agent）
- **单元**：
  - 检索召回：`kbSearch(projId, query, n)` 中文 bigram/英文词命中、无 token 命中返回空、Top-N 截断（复用 KB-01 已验逻辑，本条声明为消费方）。
  - 来源徽标映射 `srcKind(from)`（manual→人工/consult→答疑/其余→自动）+ 子系统 `subLabel` 中文优先。
- **接口（覆盖每条 AC + 异常分支）**：
  - 检索端点 `kb-search`：现场账号（`impl`/`pm`）调用 **200**（AC-8：证明已进 `FIELD_OK`）；带 `q` **全库**命中返回相关条目（**每条带 `project`+`productName`**，AC-3）、`q` 无命中/全库无条目返回空数组（AC-5）；给 `project` 可选过滤时只回该产品。**跨产品聚合**：造两个产品各有命中条目，一次 `q`（不带 `project`）应能同列表召回并按分排序。
  - **权限纵深**：现场账号直调 `POST /api/kb-save`、`POST /api/kb-delete` → **403**（AC-8，证明未误加进 `FIELD_OK`）。
