## 1. 用户故事 / 目标
作为**运营（admin）**，我要在上传包后**从产品代码拉出该版本区间的部署/更新清单草稿（实施任务 + 升级 SQL 正文），人工增删改后确认冻结成批次快照**；作为**现场实施（管理员+field）**，我要按 `batchId` **读批次冻结快照渲染累积更新计划、逐条勾选执行、下载合并 SQL、逐项进度按（批次×医院）各院各记**——以便**清单跟随产品代码不失真、发包有人审核关、实施读稳定快照不受代码变动影响、各院进度独立可追溯**。

## 2. 范围
**包含（现行 · §K 快照机制）：**
- **草稿源 = 产品代码 @HEAD**：各子系统仓 `docs/deploy/<版本>.json`（一版一文件）+ `sql/*.sql`；intake 只读 clone，`git show HEAD:...` 读。
- **发包审核**：运营在批次已有 `pkgVersion` 后，`batch-deploy-draft` 拉 `(起始版本, pkgVersion]` 累积草稿（tasks + sql，SQL 正文一并读出）→ 可增删改 → `batch-deploy-save` 冻结进 `batch.deployPlan`（含 SQL 正文 + `reviewedBy/At`）。
- **实施读快照**：`field/update-plan` 按 `batchId` 读 `batch.deployPlan` + 左连 `customer.updateProgress[batchId]` 完成度；`field/update-toggle` 按（批次×医院）勾选；`field/update-sql-merged` 读快照冻结正文拼合并 SQL 下载。
- **完成度按 (批次 × 医院)** 记：`customer.updateProgress[batchId]={tasks,sqlBundle}`（存 intake，不回写产品仓）。

**保留为备用 / 约定源（§I · 跟随产品代码「按 tag 读」）：**
- `readDeployManifest(proj,tag)`（按 git tag 读单文件 `docs/deploy.json`）保留为「**首次部署（现场版本空=未部署）·RS-6·下一步单独做**」备用；数据格式约定源。**实施更新流以 §K 快照为准**。

**不包含（划归它处 / 已废）：**
- **§H 更新包按版本手工登记（`implTasks` + `batch-task` 全局勾选）→ 已废并从代码删除**（见 §3.H·历史留证 + CHG）。
- **§I 实施侧「实时读代码 + 跨版累积」→ 被 §K 取代**（实施不再实时读代码、不在实施侧跨版累积）。
- 手工「版本发版登记」（`releases.html` / `data/version-releases.json` / `version-release-save` / `version-releases` 端点）→ **已废并删除**。
- 定档 / 列表详情 / 双向编辑 → `BP-02`；导清单 / 上传包 → `BP-03`；批次闭环 / 排期 → `BP-04`。
- 现场端更新计划 UI 渲染 / 逐单验证 / 一键改版本交互 → `FS-05`（本 spec 提供快照读端点 + 数据支撑；AC-29/33 的现场卡渲染由 FS-05 承载）。
- **steward 自动对接三接口** → future（BP-01 导读 §8·NH-6）。

### K. 核心更新流「代码=草稿源 → 发包时人审可改 → 快照进批次 → 实施用快照」（🆕 2026-08-05 · 用户拍板 · 现行 · 取代 §I 实施侧实时读代码）

## 4. 接口契约

## 6. 业务规则 / 非功能
- **草稿源 = 产品代码**（intake 只读，不回写产品仓）；发包审核 = **人审核关**（运营可增删改后冻结）；实施 = **读稳定快照执行**（不实时读代码，隔离代码变动）。
- **规范化 / 长度约束**：`title` 非空丢弃、`title≤120`/`desc≤2000`/`sql title≤200`/`sql desc≤200`/`content≤20000`、补/去重 id、gid=`<子系统>:<原id>`。
- **数据权限 / 按钮级权限**：发包审核（`batch-deploy-draft/save`）为**运营 admin**（`isAdmin`）；现场（`field/update-*`）为**管理员+field·按 `user.sites` 越权收敛**（越权 site 403）。**`pm` → NH-1**。
- **完成度按 (批次×医院) 分记**（`updateProgress[batchId]`）；task/sqlBundle 分桶隔离；假删；**幂等**（同态不重复写、`changed=false`）。
- **SQL 系统不碰库**：只列出 + 合并下载，实施手动跑、勾「已执行」（整份合并为一个点）。
- **优雅降级**：缺文件/JSON 非法/tag 无文件 → 静默跳过（不报错、不 500）；批次未审核 → `noManifest:true` + 提示；空 SQL → 含说明注释的文件（不 500）。
- **操作留痕**：发包审核写 `batch.history` `deploy-review`（记任务/SQL 数 + 区间）；完成态挂 `customer.updateProgress`（by/at）。
- **展示格式**：时间 `yyyy-MM-dd HH:mm`（全局 UI 规范⑫）。

**NEEDS-HUMAN**（引用 BP-01 导读 §8）：**NH-1** pm 权限；**NH-6** steward 自动回写包=future。
