## 1. 用户故事 / 目标
作为**运营/维护人员**，我要一套**统一的现代化后台外壳（App Shell）+ 设计系统**，让所有运营后台页面（工作台 / 收件箱 / 详情 / 产品 / 客户 / 经验库 / 模型 / 账号 共 8 页）**共用同一套深色分组侧边栏 + 顶栏 + 多标签工作区 + 组件样式**，以便：
- 页面开发者只写「页面正文」，外壳（深色分组侧栏 / 顶栏机构胶囊·面包屑·帮助·通知·用户下拉 / 多标签历史栏）由注入式 `shell.js` 统一注入、菜单按业务域分组稳定排序，风格一致、零重复；
- 用户在多页间穿梭有稳定分组导航（当前页高亮左竖条）、面包屑定位、多标签工作区（访问即成 Tab、可关闭、工作台固定），交互与视觉统一；
- 后续业务 spec（WB/TK/BP/PD/CU/KB/MC/AM…）都 `depends_on: [UI-01]`，直接复用本外壳（`theme.css` 设计系统 + `shell.js` 注入外壳 + `ui.js` 弹窗助手），不再各自造轮子。

> 本条是**纯前端基建**：只提供外壳（深色分组侧栏 + 顶栏 + 多标签）+ 设计系统（`theme.css` Design Token + 组件）+ 全局弹窗助手（复用现有 `ui.js`），**不含任何业务数据 CRUD**；仅被动消费现有 `/api/me`、`/api/notifications`、`/logout`、`/api/change-password`。**只换外壳、不重做页面内容**：各管理页原有表格 / 筛选 / 抽屉 / 弹窗 / 业务 `<script>` 照常工作。

## 2. 范围（以「臻遴结构化原型」为唯一基线）
**包含：**
- **深色分组侧边栏（`.sidebar`）**：品牌区（`.sidebar-brand` = logo + 主标题「收件 intake」+ 副标题「运营后台 · 维护端」）+ 按业务域分组的 `nav-section` 分组标题（概览 / 工单 / 主体管理 / 知识库 / AI 引擎 / 系统）+ `.nav-item`（图标 + 文案）+ **激活态**（`.nav-item.active`：左 3px 靛蓝竖条 `::before` + 浅底 `--sidebar-bg-soft`）+ `.nav-badge`（收件箱未读红角标）+ 底部 `.sidebar-footer` 版本号。深色底 `--sidebar-bg:#1B2145`。
- **顶栏（`.topbar`）**：左侧**面包屑**（`data-breadcrumb` 拆分渲染，末段高亮）+ 右侧一排：**机构胶囊 `.org-pill`**（靛蓝浅底，机构名占位「收件运营部」）+ **帮助**图标按钮 + **通知**图标按钮（红点 `.dot`，点击去收件箱）+ **用户区 `.user-area`**（`.user-trigger` = 头像 + 姓名 + 角色 + 下拉箭头；点击展开 `.dropdown`：修改密码 / 退出登录，退出为 danger 色）。
- **多标签工作区（`.tab-bar` / `.tab-item`）**：访问某页即成一个 Tab、`localStorage`（key `intake_admin_tabs`）持久化；**工作台固定不可关**（`.fixed`，无关闭图标）、其余可关（`.tab-close`）；关闭当前 Tab 跳相邻/回工作台；上限 12（超出淘汰最旧非固定）。
- **注入式 `shell.js`**：读 `<body data-shell="admin" data-nav="X" data-breadcrumb="…">` → 拉真库 `/api/me`（用户区）+ `/api/notifications`（未读角标）→ 收集页面原有内容节点包进 `.page-content` → 注入 `.app-layout`（侧栏 + `.app-main`（顶栏 + tab-bar + page-content））。**非管理员**（`pm`/`impl`）只见「新建进件」入口、隐藏后台菜单；**token 链接访客**（`me.link`）不注入外壳（保持公开面）。
- **设计系统 / 组件库 `theme.css`（唯一样式源）**：Design Token（`--color-primary:#3A4CA8` 靛蓝 + 衍生 hover/active/light/border、`--color-accent` 青、中性色、语义色、工单类型色、圆角/阴影/布局 token、深色侧栏 token）+ App Shell 布局（`.app-layout`/`.sidebar`/`.topbar`/`.tab-bar`/`.page-content`）+ 组件（`.btn` 及变体、`.card`/`.card-header`/`.card-body`、`.stat-card`、`.data-table`（表头 sticky）、`.tag` 及语义/工单变体、`.progress`、`.modal`/`.drawer` mask 等）。
- **全局弹窗助手 `ui.js`（复用现有）**：`window.uiConfirm / uiAlert / uiPrompt`（返回 Promise，Esc / 点遮罩关闭）—— 改密下拉项走 `uiPrompt` 收原/新密码。
- **真实鉴权/未读数接入点**：用户区来源 `/api/me`、未读角标来源 `/api/notifications`、退出走 `/logout`（302 → `/login.html`）、改密走 `/api/change-password`（契约见 §4）。

**不包含：**
- 任何业务页面的具体内容与数据（工单/批次/客户…各自在对应 spec）。**本条只套外壳、不重做页面内容。**
- 登录页 / 登录鉴权流程本身（复用现有 `server.mjs` 的 `/api/login`、`/login.html`；本条只**读** `/api/me`）。
- 后端新增端点、新增/改动数据库表（外壳不建表、不加接口，纯前端）。
- 现场提交页 `submit.html`（全屏现场页）、`login.html` —— 不套后台壳。
- 移动端 / 响应式完整适配。

## 3. 验收标准（AC · 以原型外壳为基线）
> 回归套件逐条锁定：`tools/ui-shell.test.mjs`（A 组静态 DOM/CSS 断言 + B 组连真库冒烟）。

### A. 深色分组侧边栏
- **AC-1** Given 任一管理页加载并注入 shell Then 页面存在 `.app-layout > .sidebar`，侧栏含品牌区 `.sidebar-brand`（logo + 主标题「收件 intake」+ 副标题）与底部 `.sidebar-footer` 版本号；侧栏底色为深色（`--sidebar-bg`）。
- **AC-2** Given `shell.js` 注入侧栏 Then 导航按业务域**分组分级**：`nav-section` 分组标题依固定顺序 概览 / 工单 / 主体管理 / 知识库 / AI 引擎 / 系统；每组内 `.nav-item` 顺序稳定（不依赖插入/随机），两次刷新完全一致。各 `.nav-item` 映射真实页：工作台=`/console.html`、新建进件=`/submit.html`、收件箱=`/inbox.html`、产品管理=`/projects.html`、客户/医院=`/customers.html`、经验库=`/kb.html`、模型配置=`/model-config.html`、账号管理=`/accounts.html`。
- **AC-3** Given 当前页 `data-nav` 值 When 渲染 Then 有且仅有该 id 的 `.nav-item` 带 `.active`（`theme.css` 定义 `.nav-item.active` 浅底 + `::before` 左 3px 靛蓝竖条），其余不带。
- **AC-4** Given 管理员 & `/api/notifications` 返回 `count>0` Then 收件箱 `.nav-item` 尾部注入 `.nav-badge`（红底、文本 = count）；`count===0`（或请求失败）不渲染角标。
- **AC-5** Given 任一 `.nav-item` When 点击 Then 跳转到其 `data-href` 对应页。

### B. 顶栏（面包屑 / 机构胶囊 / 帮助 / 通知 / 用户下拉）
- **AC-6** Given 页面设 `data-breadcrumb="A > B > C"` When 注入顶栏 Then `.topbar .breadcrumb` 按 `>` 拆分渲染多段 `.crumb`（段间 `.sep` 分隔符），末段高亮；空则回退「运营后台」。
- **AC-7** Given 注入顶栏 Then 右侧 `.topbar-right` 依序含：机构胶囊 `.org-pill`（含机构名占位「收件运营部」）、帮助图标按钮、通知图标按钮（`#topbarBell`，点击去 `/inbox.html`）、用户区 `.user-area`。
- **AC-8** Given `me` 存在 When 渲染 Then 用户区 `.user-trigger` 含头像 `.avatar`（姓名首字）+ `.u-name`（`me.name||me.username`）+ `.u-role`（`roleLabel(me.role)`：`admin/dev→管理员`、`pm→产品经理`、`impl→实施工程师`）+ 下拉箭头；点击展开 `.dropdown`（`.open`），含「修改密码」`#ddChpw` 与 danger 色「退出登录」`#ddLogout`（`.dropdown-item.danger`）。点击外部 / Esc 收起下拉。
- **AC-9** Given 用户下拉「修改密码」`#ddChpw` When 点击 Then 依次弹 `uiPrompt`（原密码 → 新密码，`inputType:password`），任一步取消（返回 `null`）则中止；两步都填则调 `POST /api/change-password {old,new}`，成功 `uiAlert('密码已修改')`、失败 `uiAlert('修改失败…')`。
- **AC-10** Given 用户下拉「退出登录」`#ddLogout` When 点击 Then 跳转 `GET /logout` —— server 清会话 Cookie 并 302 到 `/login.html`（本系统单应用**无门户**，退出去登录页，**不用**原型的 `../index.html`）。
- **AC-11** Given `me===null && authEnabled` Then 顶栏右侧渲染「登录」按钮（`/login.html`）；`me===null && !authEnabled`（未建任何账号）Then 渲染「去创建管理员」按钮（`/accounts.html`）。

### C. 多标签工作区
- **AC-12** Given 首次访问某页 When 注入 Then 该页对应 Tab 加入 `.tab-bar` 并 `localStorage`（`intake_admin_tabs`）持久化；工作台 Tab 恒存在且 `.fixed`（无 `.tab-close`）。
- **AC-13** Given `.tab-bar` 中当前页 Tab Then 带 `.active`；点击其它 Tab 跳转其 `data-href`；点击可关 Tab 的 `.tab-close` 关闭之，关闭当前 Tab 跳相邻/回工作台；Tab 数上限 12（超出淘汰最旧非固定）。

### D. 设计系统 / Design Token / 组件（theme.css）
- **AC-14** Given 加载 `theme.css` Then `:root` 定义主色 token `--color-primary:#3A4CA8`（靛蓝）+ `--color-primary-hover/active/light/border` 衍生、`--color-accent`（青）、中性色、`--color-success/warning/danger/info` 语义色、工单类型色（`--ticket-req/bug/consult`）、圆角/阴影/布局 token、深色侧栏 token（`--sidebar-bg` 等）；主色引用均 `var(--color-primary)`，改 token 即换肤。
- **AC-15** Given `theme.css` 加载 Then 下列组件基类存在且可用：App Shell（`.app-layout`/`.sidebar`/`.nav-item`/`.nav-badge`/`.topbar`/`.breadcrumb`/`.org-pill`/`.user-area`/`.dropdown`/`.tab-bar`/`.tab-item`/`.page-content`）、组件（`.btn` 及 `.btn-primary/.btn-danger/.btn-ghost/.btn-sm`、`.card`/`.card-header`/`.card-body`、`.stat-card`、`.data-table`、`.tag` 及 `.tag-success/.tag-danger/.tag-primary/.tag-gray`、`.progress`）。
- **AC-16** Given 数据表格 `.data-table` 内容超高滚动 Then `thead th` 因 `position:sticky; top:0` 固定可见（对齐全局 UI 规范③表头 sticky）。

### E. 全局弹窗助手（ui.js · 复用）
- **AC-17** Given `ui.js` 加载 Then `window.uiConfirm`、`window.uiAlert`、`window.uiPrompt` 均存在且为函数（返回 Promise）；支持 Esc / 点遮罩关闭（走取消分支，`uiPrompt` 取消 resolve `null`）。

### E'. 运营端统一自定义下拉组件（ui.js · 2026-07-23 用户裁决 · **draft 待评审**）
> 【2026-07-23 用户裁决】运营后台的下拉一律用**自定义下拉组件**（复刻 `theme.css` 收起态 `.select` 外观 + 藏青主题）替代 OS 原生 `<select>` 弹窗，视觉/交互统一。**纯前端增强**：原生 `<select class="select">` 保留在 DOM 作数据源，各页 `select.value` / `addEventListener('change')` 逻辑**完全不变**。落地 = `public/assets/ui.js` 注入的 `.ui-sel-*` 组件（样式内联注入，未改 `theme.css`）；回归套件 `tools/ui-select.test.mjs`。
- **AC-20** Given 任一管理页加载 Then `ui.js` 通过**初次扫描 + `document.body` 子树 `MutationObserver`（childList+subtree）** 自动增强每个 `select.select:not([data-enh])`（打 `data-enh="1"` 防重、时机无关：shell.js 注入后 / 抽屉里动态 `createElement('select')`（如 customers 关联产品行）出现即增强）；`<select multiple>` 保留原生不增强。
- **AC-21** Given 被增强的 select Then 原生 `<select>` 被隐藏（`opacity:0;pointer-events:none` 覆盖）但**保留在 DOM 作数据源**；插入自定义触发器 `.ui-sel-trigger`（复刻收起态 `.select`：同高度 34px / `filter-bar` 内 30px、同边框圆角、右侧 chevron、藏青 focus ring），显示当前选中项文案；`disabled` 时触发器灰态禁用。
- **AC-22** Given 点击触发器 Then 弹出 `.ui-sel-pop` 面板：`position:fixed` 挂 `document.body`（**逃祖先 `overflow` 裁剪**——抽屉/卡片裁剪坑）、据 `getBoundingClientRect()` 定位于触发器正下方（下方空间不足则上翻）、`z-index:9600`（盖过 drawer/modal 300/310 与 `ui.js` 弹窗 9000）、`max-height:280px` 内滚；渲染全部 `<option>`，**支持 `<optgroup>`**（不可点组头 `.ui-sel-grp` + 组内 `.sub` 缩进）；当前项 `.on` 高亮 + 勾选。
- **AC-23** Given 点击面板某项 Then 回写 `select.selectedIndex`/`value` 并**派发 `change`（`bubbles:true`）**，更新触发器文案并关闭面板——由此**保住每页原有 `change` 监听**。键盘：触发器可聚焦，ArrowUp/Down 移高亮、Enter/Space 选中/展开、Esc 关闭；点击外部 / 滚动关闭。
- **AC-24** Given 代码**命令式**改 `select.value`（如 customers `openEdit` 里 `$('#edLevel').value='三乙'` 回显编辑）Then 触发器文案自动同步——机制 = `Object.defineProperty` 覆盖 `value`/`selectedIndex` setter 调 `syncFromSelect()` + 监听 select 自身 `change` + `MutationObserver`（childList 选项变化 / attributes `disabled`）重同步并重建打开中的面板。
- **AC-25** Given 单个 select 增强抛错 Then `try/catch` 兜底复原原生 select（清 `data-enh`、恢复可见/可用），不冻结页面；**不侵入实施端**：`field.html` 不引 `ui.js`（0 处）、其自带 `.f-proddd` 下拉与本组件互不影响；`submit.html` 的老 `.fancy` 增强器保留（`.select` 与 `.fancy` 不重叠）。

### F. 8 页共用同一外壳资产 + 内容原样保留
- **AC-18** Given 全部 8 个管理页（`console/inbox/detail/projects/customers/kb/model-config/accounts.html`）Then **每一页** `<body>` 带 `data-shell="admin"` + `data-nav` + `data-breadcrumb`，`<head>` `<link>` 引 `/assets/theme.css`、`<script defer>` 引 `/assets/ui.js` 与 `/assets/shell.js`（`ui.js` 在 `shell.js` 之前），且**不含**旧 `<nav class="topnav">` / `<body class="sidebar">`。
- **AC-19** Given 套壳后任一管理页渲染 Then 页面原有业务内容（表格/筛选/抽屉/弹窗/业务 `<script>`）由 `shell.js` 收进 `.page-content` 后**原样保留、交互不报错**（inbox 聚合、detail 操作台、projects 双栏、kb 手风琴等保持可用）；全高内滚页（inbox/projects）通过 `data-content-layout="list"` 让 `.page-content` 走 `list-layout`（flex 列 + 内滚），业务 DOM 不删。

## 4. 接口契约（对齐部署 server.mjs 实际返回 · 外壳不新增端点/不建表）
> 外壳**只读/会话消费**现有端点。形状**已对 `server.mjs` 逐字段核过**，B 组连真库冒烟锁定。

**① 取当前用户（用户区姓名 / 角色）**
```
GET /api/me  →
{ "authEnabled": true,
  "me": { "id":"u...", "username":"admin", "role":"admin|pm|impl|dev(遗留)",
          "name":"管理员", "projects":[...], "sites":[...],
          "mustChange":false, "enabled":1 },
  "defaultAdmin": false }
```
- `pubUser(u)` 字段**仅** `id/username/role/name/projects/sites/mustChange/enabled` —— **无机构字段**（故 `.org-pill` 用固定占位「收件运营部」，见 §6 NH-1）。
- `me` 另两态：token 链接访客 → `{ role:"link", link:true, name, project, site, ver, ptype }`（`shell.js` 见 `me.link` 即不注入外壳）；未登录 → `me:null`（据 `authEnabled` 渲染登录 / 建管理员按钮）。
- 判管理员统一 `me.role==='admin' || me.role==='dev'`（`dev` 遗留 admin 值），**不要**只判 `admin`（会漏 dev 管理员）。

**② 取站内未读数（`.nav-badge` 收件箱角标）**
```
GET /api/notifications  →
{ "count": 7, "items":[ { "project","id","title","lifecycle","type" } ], "role":"dev|field" }
```
- `shell.js` 用 `count>0` 驱动收件箱 `.nav-item` 尾的 `.nav-badge`（`count===0` 或失败不渲染）。

**③ 退出登录 / 改密**
```
GET  /logout               →  302 清会话 Cookie, Location: /login.html   // 用户下拉退出用这个
POST /api/change-password  { "old","new" }  →  { "ok":true } | { "error":"..." }
```

## 5. 数据契约

## 6. 业务规则 / 非功能
- **菜单分组分级 + 稳定排序**：侧栏按业务域 `nav-section` 分组，组序与组内顺序固定（对齐全局 UI 规范①②）。
