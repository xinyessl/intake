# 进件平台 intake · 功能模块地图（系统总纲）

> **AI/人进来先读这里定位** → 找到要动的功能属于哪个模块 → 点进对应功能 spec（**只读那一条**）→ 复杂链路再看该模块导读。
> 本文件 `status: living`——新增/删除/拆分功能 spec 时同步维护本表。
> **两端**：`实施端 FS`（现场实施工程师，只提交与查看）+ `运营后台`（运营处理）。评审/规划附录见 `00-实施端-spec清单.md`、`00-运营后台-spec清单.md`。

## 0. 系统构成
- **栈**：Node.js 零依赖原生 http（`server.mjs` 单文件后端）+ mysql2 + 原生 HTML/JS 前端（`public/*.html` + `assets/`）。**不是 Java**。部署 Docker `node:20-slim`。
- **界面基线**：`public/*.html`（实现事实源，优先于原型 `prototype/`）。

## 1. ⚠️ 数据契约事实源（写持久层前必看 · 禁臆造）
intake 数据**分两处**，写数据契约前先分清落在哪：

| 事实源 | 内容 | 备注 |
|---|---|---|
| **真库 5 表** `db.mjs` 的 `init()` | `projects` / `accounts` / `sessions` / `intakes`（工单+咨询）/ `kb_entries`（经验库） | 逐列对 `db.mjs`，禁臆造列；工单嵌套字段挂 `intakes.data`(JSON)，不加列 |
| **文件存** `data/*.json` | `customers.json`（客户/医院/站点/版本/维保/更新进度）、`model-api.json`（模型配置）、`batches.json`（批次） | 非表；`impl`/`ticketCount` 等为**读时派生**（自 `accounts.sites` / `intakes.site`） |
| **git tag** | 产品线归档版本（`/api/versions`） | 更新包"跟随产品代码·按 tag 读 `deploy.json`" |
| **接口契约** | `docs/P0-数据模型对账与接口清单.md`（§A 现有端点 + §D 新增 + §E steward） | 各 spec §4 |
