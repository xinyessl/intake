> **【本条 = 实施端「医院视图 · 提交清单」功能规约（对齐 `docs/specs/00-实施端-spec清单.md` 之 FS-02）】**
> 现场账号登录后，医院视图左侧的**提交清单**（本条负责）：平铺我负责的医院 tab → 选医院 → 看该医院提交记录，可**按批次 / 按类型**切换 + 按**全部子项目（子系统）**下拉筛选。落地 = `public/field.html`（实施端工作空间 SPA，外壳/维度切换由 FS-01 承载，本条只负责其左侧清单区）+ `server.mjs` 新增 `GET /api/field/submissions`（按当前账号 `sites` 收敛）。
>
> **三条跨条决策（贯穿本 spec）：**
> - **A｜Node 栈**：落地 = `public/field.html` + `server.mjs` 端点，**不是** PRD §2/§9 写的 Vue3+TS+ElementPlus / Java（那是被跟踪产品的栈，非本平台）。样式复用 `public/assets/theme.css`。
> - **B｜角色 impl**：现场账号 = 真库 `impl`（+ `pm`）；`role='field'` 是 PRD 术语，真库经 `normRole` 归一为 `impl`。清单按当前登录用户的 `accounts.sites` 过滤（服务端收敛，不信前端传参）。
> - **C｜批次 P2**：**「按批次分组视图」依赖运营端 BP-01 的 `batches` 表（尚未建）→ 全部标 P2**；**「按类型视图 + 平铺医院 tab + 子项目筛选 + 清单基础（基于真实 `intakes`）」不依赖批次 → P1**。BP-01 未上线前，按批次视图**降级**为「按提交周聚合 / 或整体隐藏『按批次』切换项，默认『按类型』」。

## 1. 用户故事 / 目标
作为**现场实施工程师 / 产品（role=impl）**，我要在医院视图里**只看我负责医院的提交记录**，并能**按批次**（回答"这家医院这周/这批提的都进展到哪了、能不能下载了"）或**按类型**（回答"我提的需求 / BUG / 咨询各自到哪一步了"）两种角度查看、再用**子项目（子系统）下拉**收窄范围，以便随时掌握自己现场诉求的落地进度，且**绝不看到别的账号负责医院的数据**。

## 2. 范围
> **【2026-07-23 用户裁决：医院选择由「平铺医院 tab」改为「医院下拉选择器」】** 与 FS-03 系统视图下拉样式/交互一致——复用同一套 `.f-sysdd*` 样式（触发器在深色顶栏 `.f-sysdd-cur`、面板 `.f-sysdd-panel` `position:fixed` 逃 `#fHtabs` 的 `overflow` 裁剪、搜索框 `.f-sysdd-search` + 列表 `.f-sysdd-list`）。区别于系统视图：医院视图是**单选一家**（`curSite` 单选、即选即查），故**无分组、无「全部医院」聚合项**；`me.sites` 平铺为下拉项，可按医院名搜索；「🔒 医院由运营端分配」提示移入面板底部。落地 = `public/field.html` 的 `buildHospDropdown`/`renderHospList`/`onHospSelect`（id：`fHospDD`/`fHospCur`/`fHospList`/`fHospSearch`；state：`hospOpen`/`hospQuery`）。以下 AC-1~4 描述已按此裁决更新。

**包含（本条 = 医院视图左侧「提交清单」区）：**
- **医院下拉选择器**（触发器取自当前账号 `accounts.sites`，显当前所选医院 `curSite`）+ 面板底部灰色不可点提示「🔒 医院由运营端分配」；选医院 → 左侧清单显示**该医院**提交记录（即选即查）。（下拉容器塞进 FS-01 提供的顶栏 `#fHtabs`，本条负责下拉数据来源=sites + 选中→驱动清单刷新。）
- **提交清单子控件**：`按批次 / 按类型` 切换（`f-tabs2`）+ `全部子项目 ▾` 下拉筛选（`f-proddd`，按产品分组的子系统，选中即筛）。
- **按类型视图（P1，默认降级态）**：跨批次按 需求 / BUG / 咨询 三组重组，每条保留状态 + 上下文（子系统·医院·时间）。
- **按批次视图（P2，BP-01 上线后为默认）**：按「产品·周批次」分组，组头 = 产品名 / 周次(时间范围) / 批次状态 / 条数 / 节奏提示；批次状态 → 现场语义映射（见 §6.3 表）；组内每条 = 类型标签 + 标题 + 状态标签 + 子系统·医院 + 时间。
- **数据源**：新增 `GET /api/field/submissions?dimension=hosp&hospitalId=&groupBy=batch|type&subsystem=`（按 `sites` 收敛）；`groupBy=type` 走 P1（基于真实 `intakes`）；`groupBy=batch` 走 P2（依赖 `batches`，未建前降级）。清单基础数据可复用现有 `GET /api/intake-list?project=`（已按 sites 过滤）。

**不包含：**
- 系统视图（跨医院按子系统聚合）→ **FS-03**。
- 右侧 AI 对话提交（归档上下文 chip、提需求/咨询、对话流）→ **FS-04**。
- 更新包下载卡、一键改版本、待办 popover（待下载/待改版本/待验证）→ **FS-05**（P2）。
- 登录门 / 工作空间隔离外壳 / 维度下拉（医院视图·系统视图）/ `scopedForField` 隔离缺口修复 → **FS-01**。
- **「添加医院 / 产品」** —— 由运营端账号管理（AM-01）绑定 `sites`，实施端不自助添加（PRD §1.2/§4.1）。
- `batches` 表建表、发包、批次进度端点本身 → 运营端 **BP-01**（本条只**读**批次做分组）。

## 3. 验收标准（AC · Given-When-Then · 每条可自动化判定 · 标 P1/P2）

### A. 医院下拉选择器（数据源 = sites · 2026-07-23 裁决替代平铺 tab）【P1】
> 与 FS-03 系统视图下拉样式/交互一致，复用 `.f-sysdd*` 样式；医院视图单选一家（`curSite` 单选、即选即查），无分组、无「全部医院」聚合项；面板 `position:fixed`（打开时按触发器 `getBoundingClientRect` 定位 `top/left`，逃 `#fHtabs` 的 `overflow-x:auto` 裁剪）。落地 = `buildHospDropdown`/`renderHospList`/`onHospSelect`。
- **AC-1【P1】** Given 现场账号（role=impl）已登录、`accounts.sites=["山东省立医院","郑州人民医院"]` When 进入医院视图 Then 顶栏出现**一个医院下拉触发器** `#fHospCur`（`.f-sysdd-cur` 样式 + `ti-building-hospital` 图标），显当前所选医院 `curSite`（默认 sites[0]，即「山东省立医院」）；展开面板列出**恰好这两家**医院项（`me.sites` 平铺，顺序稳定 = sites 数组顺序），当前所选项 `.opt.on` 高亮；**不含**任何不在 `sites` 内的医院、**无**「全部医院」项。
- **AC-2【P1】** Given 医院下拉面板已展开 Then 面板**底部**含一个**灰色不可点**提示节点 `.f-htab-note.f-hospdd-lock`（含锁图标 + 文案「医院由运营端分配」），点击它不切换医院、不触发任何请求（点面板内 `stopPropagation` 不关菜单）。
- **AC-3【P1】** Given 面板列出多家医院项 When 点击第二家医院项（如「郑州人民医院」）Then `onHospSelect(site)`：`state.curSite=该医院`、关闭面板（`hospOpen=false`/`hospQuery=''`）、触发器文案更新为该医院、该项变 `.opt.on`，并触发左侧清单重新按**该医院**加载（`onHospitalChange` → 请求 `hospitalId=郑州人民医院` 或等价 `site` 过滤），清单只含该医院记录（即选即查，无需再点查询）。
- **AC-4【P1】** Given `accounts.sites` 为空（未分配医院）When 进入医院视图 Then 触发器显「尚未分配医院」，面板列表显空态占位「尚未分配医院，请联系运营端」（仍显🔒提示），清单区亦为空态，不报错、不发越权请求。搜索无命中时面板显「未找到匹配的医院」。

### B. 提交清单子控件：按批次/按类型 + 子项目下拉【P1】
- **AC-5【P1】** Given 医院视图清单区 Then 存在子控件条 `.f-ph`：含标题「提交清单」+ `f-tabs2`（两项 `按批次` / `按类型`）+ `全部子项目 ▾` 触发器（`.prod`）。
- **AC-6【P1】** Given `全部子项目 ▾` When 点击 Then 展开下拉 `.f-proddd`：首项「全部子项目」（默认 `.on`）+ 按**产品分组**的子系统列表——分组标题 = 产品名（`.grp`），组内 `.opt.sub` = 该产品各子系统。**子系统集合来源（2026-07-23 裁决「运营端维护到子系统 + 各自版本」· 向后兼容）**：
  - **新形状**（客户产品 `customers.products[i]` 含 `subsystems:[{name,version}]`）→ 下拉**只列该医院实际维护的子系统**（`name`），desc 从产品目录 `projects[].subsystems[].name→desc` 查、并记住各子系统的 `version`（供归档条取版本，见 FS-03 AC-18）。
  - **旧形状**（客户产品 `{project,version}`，无 `subsystems` 字段）→ **兜底列该产品全部子系统**（现状行为不变），各子系统 `version` 预填产品级 `version`。
  - `buildSubOptions` 产出 `[{product, subs:[{name,desc,version}]}]`；`state.subOptions` 结构相应带上 `version`；`subVersion(name→version)` 供归档条取所选子系统版本。**子系统「双键」显示（同 FS-03 系统视图 `sysLabel`）**：下拉项**显示中文 `desc`**（`desc||name`，如 `audit→审方`），而 `data-sub`/`selectSub` 传参/过滤值一律用**英文/原始 `name`**（匹配 `intakes.subsystem`）——`renderProdDD` 显 `desc||name`、`subLabel(name→desc)` 供选中标签/空态显中文。
- **AC-7【P1】** Given 子项目下拉展开 When 选中某子系统（如显示「审方」、值 `audit`）Then 该项变 `.on`、触发器文案更新为该子系统**中文 desc**（`subLabel(curSub)`，非英文 name），并**即选即筛**（无需再点查询）——清单按 `subsystem===<英文 name>`（`&subsystem=state.curSub`）过滤（对齐全局规范⑪选择型筛选即选即查）。**过滤值仍是英文 name，只有显示变中文 desc**（别把过滤值也改成 desc，否则筛不出数据）。
- **AC-8【P1】** Given 已按某子系统筛选 When 选回「全部子项目」Then 清除子系统过滤，清单恢复该医院全部记录。
- **AC-9【P1】** Given 医院视图 When 点击 `按类型` tab Then `.f-tab2` 高亮切到「按类型」，清单容器切到按类型视图（`fListType` 显示、`fListBatch/fListSystem` 隐藏）；点回 `按批次` → `.f-tab2` 高亮切到「按批次」（**始终随点击切换、不回弹**），批次视图当前为 P2 降级空态（见 AC-15）。

### C. 按类型视图（跨批次重组）【P1】
- **AC-10【P1】** Given 该医院有多条不同类型的提交记录 When 切到「按类型」Then 按 **需求 / BUG / 咨询** 三组分别渲染（`type` 英文值 `requirement/bug/consult` → 组标题「需求/BUG/咨询」），**跨批次**聚合（不再按批次拆），组头显示该组条数。
- **AC-11【P1】** Given 按类型视图某组 Then 组内每条记录含：类型标签（需求/BUG/咨询，`--ticket-{req/bug/consult}` 描边色）+ 标题（`intakes.title`）+ 状态标签（由真实 `lifecycle` 经 UI 映射，见 §6.2）+ 上下文「子系统 · 医院」（`subsystem` · `site`）+ 时间（`submittedAt` 或 `updatedAt`，格式 `yyyy-MM-dd HH:mm`，对齐全局规范⑫）。
- **AC-12【P1】** Given 某类型（如咨询）该医院无记录 When 切到按类型 Then 该空组**不渲染**（只出有数据的组），无空白占位组。
- **AC-13【P1】** Given 按类型视图 + 已选某子系统 When 切换视图/筛选 Then 子系统过滤对按类型视图**同样生效**（两视图同一数据源，见 §5.1），组内只剩该子系统记录。

### D. 按批次视图（依赖 BP-01 · P2）
- **AC-14【P2】** Given BP-01 `batches` 表已就绪、该医院有已归批工单 When 切到「按批次」Then 清单按「产品 · 周批次」分组（`f-batch`），组头 `f-bhd` 含：产品名 + 周次(时间范围) + 批次状态标签 + 条数 + 节奏提示（`bmeta`）；组内 `f-item` 同 AC-11 的记录结构。
- **AC-15【P2 · 降级】** Given BP-01 `batches` 表**尚未就绪**（当前）When 请求 `groupBy=batch` Then 端点**降级**：不返回 `batches` 分组，而是 `{degraded:true, groups:[], msg:'批次分组待运营端发包功能上线'}`（后端契约不变，见 §4.1）—— 前端据此**保持「按批次」选中不回弹**（点了「按批次」按钮就切过去，`.f-tab2` 仍高亮「按批次」、`state.groupBy='batch'`），在**批次容器（`fListBatch`）显空态提示**（复用 `.f-list-empty`，标题「批次分组暂未开放」+ 描述透传后端 `msg`、前端 fallback「批次分组功能待运营端上线后开放」避 FS-01 A6 禁词），**不强切回按类型、不加载按类型数据混入批次视图**；点回「按类型」→ 正常加载三组。「按批次」恒 degraded 属预期（P2 未上线），BP-01 上线后端不再 degraded 时自然显真实批次。**不报 500、不臆造批次**。〔2026-07-23 裁决：由「回弹按类型 + 顶部提示条」改为「保持按批次 + 空态提示」，解决"按钮没切过去内容却变了"的割裂观感。〕
- **AC-16【P2】** Given 按批次视图某批次状态 = `收集中(本周)/待开发会议/开发中/可下载/已交付` When 渲染组头 Then 批次状态标签文案与配色、组内「节奏提示」严格按 §6.3「批次状态 → 现场语义」映射表（如 收集中→「周日截止 → 开发会议」；开发中→回链 steward UC；可下载→更新包卡由 FS-05 承载，本条只出组头状态与占位）。
- **AC-17【P2】** Given 咨询类记录 When 按批次视图 Then 咨询单独成组「咨询答疑（不发包）」，**不参与发包批次**（PRD §4.3：咨询不进批次），组头无批次状态标签。

### E. 数据权限与收敛（贯穿 · 本条必守）【P1】
- **AC-18【P1】** Given 现场账号 A（sites=["山东省立医院"]）When 请求 `GET /api/field/submissions?hospitalId=郑州人民医院`（越权传参，郑州不在其 sites）Then 服务端**忽略越权传参**，只返回其 sites 内数据（郑州记录一条不出），或返回 403；**绝不**因前端传参而泄露非负责医院数据（对齐 PRD §3.3/§7 硬约束）。
- **AC-19【P1】** Given 未登录 When 请求 `GET /api/field/submissions` Then 返回登录态错误（依 FS-01 登录门 / authGate），不返回任何数据。
- **AC-20【P1】** Given 现场账号且 `accounts.projects` 有限定 When 请求 Then 返回结果同时受 `projects`（产品范围）与 `sites`（医院范围）双重收敛（复用 `intake-list` 现有 project+site 收敛逻辑，见 §6.1）。

### F. 记录删除（软删除）【P1】
- **AC-21【P1】** Given 现场账号处于医院视图/系统视图、某条提交记录**可删**（非已转工单、非已归批）When 渲染该记录卡 Then 卡右上角挂删除入口（`.f-item-del`）；`/api/field/submissions` 的 item 下发 `deletable=true`（=`!convertedTo && !batch`）。已转工单/已归批的记录 `deletable=false`、不挂删除入口。
- **AC-22【P1】** Given 点击某可删记录的删除入口 When 触发 Then 弹 **app 风格确认框**（复用 `#fModalMask`，非浏览器原生 confirm/prompt）；确认 → `POST /api/intake-delete {project,id}`；点击 `stopPropagation`，不触发卡片 reopen。
- **AC-23【P1】** Given 确认删除一条记录 When `POST /api/intake-delete` 成功 Then 服务端**软删除**：置 `data.deleted=true`+`deletedAt`+`deletedBy`（随 `data` JSON 落库、**不加库列、不真删库/磁盘**，media/history 全保留），并在 `history[]` 追加一条 `{to:'已删除', note:'删除', by, byRole, at}` 留痕；此后该记录**不再出现在任何提交清单/聚合/导出/待办**（`listIntake` 过滤 `deleted`），`intake-detail` 对其返回 404（不可 reopen）。前端从清单移除该卡；若删的正是右侧当前打开的会话则清空右侧对话区。
- **AC-24【P1】** Given 记录**已转工单**（`convertedTo` 有值）或**已归批**（`batch` 有值）When 请求删除 Then 服务端**拒绝**（400，error 分别为「已转工单的咨询不可删除」/「已归批的需求/BUG 不可删除」），保护在办流程；前端 toast 显该原因。
- **AC-25【P1】** Given 现场账号请求删除**不在其 `sites`** 的记录 When `POST /api/intake-delete` Then 服务端 **403**「无权删除该记录」（现场账号只能删自己名下 sites 的记录；管理员不限）。已删记录再删 → 幂等返回 `{ok:true,alreadyDeleted:true}`。

> **AC 计数**：P1 共 **21** 条（AC-1~13 共 13 条 + AC-18/19/20 共 3 条 + AC-21~25 删除 5 条）；P2 共 **4** 条（AC-14/15/16/17）。合计 **25** 条。
