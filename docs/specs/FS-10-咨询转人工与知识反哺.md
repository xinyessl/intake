## 1. 用户故事 / 目标
- 作为**实施工程师**，当 AI 咨询答疑答不好时，我要一键「转人工」把这条咨询升级给运营，**但它仍是咨询、不转开发工单**，以便拿到更权威的人工答复。
- 作为**运营**，我要在后台看到「待人工回复」的咨询队列，打开看完整对话后写回复，回复直接进这条咨询的对话流；回复后可让 AI 把「原问题 + 我的权威回复」整理成经验库草稿，**我编辑确认后才入库**，以便下一个人问同类问题时 AI 能直接答上来（反哺闭环）。
- 作为**实施工程师**，我要在原咨询会话里看到运营的人工答复（区别于 AI 气泡），有未读时给我提醒。

## 2. 范围
- **包含**：
  1. 实施端「转人工」按钮 + 端点 `POST /api/consult-escalate`（在咨询记录 `data` JSON 打 escalated 标记，**不建工单**）。
  2. 运营端新页 `public/consult-reply.html`（导航「咨询回复」）+ 队列端点 `POST /api/consult-escalations` + 回复端点 `POST /api/consult-human-reply`（把人工回复 append 进咨询 chat，标 `human:true`）。
  3. 实施端只读渲染 chat 里 `human:true` 消息为「运营人工答复」样式 + 未读提醒 badge。
  4. AI 草稿端点 `POST /api/consult-kb-draft`（原问题 + 人工回复整理成 q/a，不入库）+ 运营编辑确认后沉淀 KB（`source=escalated`，复用现成 kb 保存机制）。
- **不包含**：
  - 不改 `/api/consult`、`answer_audit`、`consultAnswerSemanticAudit`、prompts 里 consult 答复模板（lsy 活跃维护区，只加新端点/新页/外挂）。
  - 不新建库表（全用 `intakes.data` JSON 附加字段 + 现有 `kb_entries` 表）。
  - 不改 `kbRetrieveScored` / `consultKbFilter` 检索逻辑——新 KB 条目**自动**被下次咨询检索命中（反哺闭环靠现成机制）。
  - 不把转人工的咨询转成开发工单（`consult-to-intake` 是另一条路，保持独立）。

## 3. 验收标准（AC · Given-When-Then）
- **AC-1（转人工·打标记不建单）** Given 一条存在、未删、type=consult 的咨询 When 实施端 POST `/api/consult-escalate {project, convId}` Then 该咨询 `data` JSON 置 `escalated:true, escalatedAt, escalatedBy, escalateQuestion`（=chat 最后一条 user 文本快照）；`type` 仍为 consult、**不产生新工单**；返回 `{ok:true}`。
- **AC-2（转人工幂等）** Given 一条已 escalated 的咨询 When 再次 POST `/api/consult-escalate` Then 不报错、返回 `{ok:true, alreadyEscalated:true}`，`escalatedAt` 不被后一次覆盖（首次为准）。
- **AC-3（转人工权限=field+admin）** Given 现场账号（impl/pm）已登录 When POST `/api/consult-escalate` Then 允许（端点 ∈ FIELD_OK ∩ FS08_FIELD_API）；越权对不在自己 sites 的咨询发起 → 403；admin 不限。
- **AC-4（队列 admin 限定）** Given 未登录 / 现场账号 When POST `/api/consult-escalations` Then 401 / 403（端点**不在** FIELD_OK/LINK_OK/FS08_FIELD_API）；admin 登录后返回 escalated=true 的咨询列表，带 `status`（待回复/已回复）、`escalateQuestion` 快照、`site`/`subsystem`/`project`/`escalatedAt`，**倒序 escalatedAt** 稳定排序，可按 `project`/`status` 过滤。
- **AC-5（人工回复 append 进 chat）** Given admin 打开一条 escalated 咨询 When POST `/api/consult-human-reply {project, convId, reply}` Then 咨询 chat 末尾 append `{role:'assistant', human:true, by:运营名, byRole:'admin', at, text:reply}`；置 `humanReplied:true, humanReplyAt, humanReplyBy`；返回 `{ok:true}`。reply 空 → 400。端点 admin 限定（不在 field 白名单）。
- **AC-6（实施端看人工回复）** Given 咨询 chat 含 `human:true` 消息 When 实施端 reopen 该咨询会话 Then 该消息渲染为「运营人工答复」样式（区别于普通 AI 气泡）；有未读人工回复时在对话记录入口给 badge/提醒。
- **AC-7（AI 草稿·不入库）** Given 一条已人工回复的 escalated 咨询 When admin POST `/api/consult-kb-draft {project, convId}` Then 用 AI 把「原问题 + 人工回复（权威答案）」整理成 `{q, a}` 返回，**不写 KB**；AI 未配/失败则用兜底（q=原问题、a=人工回复）。端点 admin 限定。
- **AC-8（确认沉淀 KB · source=escalated）** Given 运营编辑好 q/a When 走 kb 保存（`/api/kb-save` 带 `source:'escalated'` 或 `/api/kb-from-consult` 直传 q/a 路径）Then 存进 `kb_entries`，`source` 派生为 `escalated`（或 auto with from_ref），挂对应 project/subsystem/module。
- **AC-9（反哺闭环）** Given 沉淀了一条 escalated KB 条目 When 下次对同类问题调 `kbRetrieveScored(projId, query, 5, 2)` Then 能检索到该新条目（证 AI 下次可直接引用；不改检索逻辑）。
- **AC-10（隔离 lsy consult）** Given 本 spec 全部改动 When 审查 diff Then `/api/consult`、`answer_audit`、`consultAnswerSemanticAudit`、prompts consult 答复模板均**未改动**（新端点/新页/field.html 最小外挂）。
- **AC-11（两端轻量轮询·实时性增强）** Given 实施端已「转人工」、运营在「咨询回复」页答复 When 实施端 `public/field.html` 页面可见 Then 前端每 15~20s 轮询 `/api/field/conversations`（`document.visibilityState==='visible'` 才轮、切回可见立即拉一次、`inFlight` 防并发、登出/卸载 `clearInterval`）比对上次已知 `humanReplyAt` 检测「新人工回复」，命中即：① toast 提醒「运营已回复你的咨询」；② 翻新右上「对话记录」转人工徽标（待回复→已回复，抽屉开着时静默重载列表）；③ **若该咨询正开在右侧对话区**（`chat.convId` 匹配）则复用 `appendHumanReplyBubble` 增量 append 人工回复气泡（只补新增、不清空/不重建对话流、不动输入框），不在打开态则只提醒+翻徽标；顺带刷新 `/api/notifications` 待办计数。同样地，运营端 `public/consult-reply.html` 每 15~20s 可见时轮询 `/api/consult-escalations` 静默翻新队列（新「待回复」自动出现、已回复翻态），但**回复抽屉打开时跳过刷新**、不打断运营正在输入/看 AI 草稿。**为判「新」，`/api/field/conversations` consult 项出参补透 `humanReplyAt`**（其余后端逻辑不动；不改 `/api/consult` 答复 SSE）。

## 4. 接口契约（本 spec 新增 4 端点）

### 4.1 `POST /api/consult-escalate`（field + admin）
- 权限：∈ FIELD_OK ∩ FS08_FIELD_API（实施可发起）。
- 入参：`{ project, convId }`。
- 校验：proj 存在；咨询存在、未删、`type==='consult'`；现场账号 site 收敛（不在 user.sites → 403，admin 不限）。
- 效果：`e.escalated=true; e.escalatedAt=<首次>; e.escalatedBy=<reporter/user 名>; e.escalateQuestion=<chat 末条 user text 快照>; e.updatedAt`；`saveIntake`。
- 返回：`{ ok:true }` 或 `{ ok:true, alreadyEscalated:true }`（幂等）。
- 错误：400（缺 convId / 咨询不存在），403（越权 site）。

### 4.2 `POST /api/consult-escalations`（admin 限定）
- 权限：不在任何 field/link 白名单 → authGate deny-by-default（非 admin 401/403）。
- 入参：`{ project?, status? }`（status ∈ {待回复, 已回复}，缺省全部）。
- 返回：`{ ok:true, items:[{ project, id, title, site, subsystem, escalateQuestion, escalatedAt, escalatedBy, status(待回复|已回复), humanReplyAt }] }`，倒序 `escalatedAt`。

### 4.3 `POST /api/consult-human-reply`（admin 限定）
- 权限：admin 限定（同上）。
- 入参：`{ project, convId, reply }`。
- 校验：proj 存在；咨询存在、未删、`type==='consult'`；`reply` 非空（空 → 400）。
- 效果：chat.push `{role:'assistant', human:true, by, byRole:'admin', at, text:reply}`；`e.humanReplied=true; e.humanReplyAt=at; e.humanReplyBy=by`；`saveIntake`。
- 返回：`{ ok:true }`。

### 4.4 `POST /api/consult-kb-draft`（admin 限定）
- 权限：admin 限定。
- 入参：`{ project, convId }`。
- 效果：读咨询 chat，取原问题（第一条 user）+ 人工回复（最后一条 human=true assistant，缺则最后一条 assistant），用 AI（复用 `kbFromConsult` 方式，点明人工回复为权威答案）整理成 `{q,a}`；不入库。AI 未配/失败 → 兜底 q=原问题、a=人工回复。
- 返回：`{ ok:true, q, a, subsystem }`。

## 5. 数据契约（对照真实库结构 db.mjs · 禁臆造列）
- **库表**：不新增表。咨询记录随 `intakes` 表 `data JSON` 列（`db.mjs` L34-42：`intakes(project_id,id,type,version,site,subsystem,module,title,priority,severity,env,freq,status,lifecycle,assignee,reporter,submitted_at,data JSON,...)`）；新增字段全部落 `data` JSON 附加字段（`escalated/escalatedAt/escalatedBy/escalateQuestion/humanReplied/humanReplyAt/humanReplyBy`）+ chat 消息新增 `human/by/byRole/at`——**不加库列**（同 e.batch/media/kbRefs/retrieval 范式，老记录 undefined 天然兼容）。
- **KB 表**：现有 `kb_entries(id,project_id,q,a,subsystem,module,tags JSON,source VARCHAR(20),from_ref VARCHAR(60),created_at)`（db.mjs L43-47）；沉淀走现成 `saveKB`/`replaceKB`，`source` 取值 `escalated`（VARCHAR(20) 容得下）。
- **文件存**：客户/模型文件存，不涉本 spec。

## 6. 业务规则 / 非功能
- **权限矩阵**：
  | 端点 | field(impl/pm) | admin | 白名单归属 |
  |---|---|---|---|
  | `/api/consult-escalate` | ✅（site 收敛） | ✅ | FIELD_OK + FS08_FIELD_API |
  | `/api/consult-escalations` | ❌ 403 | ✅ | 不进任何白名单（deny-by-default） |
  | `/api/consult-human-reply` | ❌ 403 | ✅ | 不进任何白名单 |
  | `/api/consult-kb-draft` | ❌ 403 | ✅ | 不进任何白名单 |
- **数据权限**：现场账号 escalate 越权收敛（只能对自己 sites 内咨询发起，越权 403，复用 intake-verify/kb-from-consult 的 sites 校验范式）；admin 不限。
- **幂等**：escalate 重复点不覆盖首次 escalatedAt、不报错。
- **留痕**：escalate 记 escalatedBy/At；人工回复记 humanReplyBy/At + chat 里 human 消息带 by/byRole/at。
- **隔离**：不碰 lsy 的 consult 答复流；实施端只读渲染 human 消息，不动发送/答复逻辑。
