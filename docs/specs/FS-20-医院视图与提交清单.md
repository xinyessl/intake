## 1. 用户故事 / 目标
作为**现场实施工程师 / 产品（role=impl）**，我要在医院视图里**只看我负责医院的提交记录**，先用**医院下拉**单选一家医院，再能**按批次**（回答"这家医院这批提的进展到哪了"）或**按类型**（回答"我提的需求 / BUG / 咨询各自到哪一步了"）查看、并用**子项目（子系统）下拉**收窄范围，以便随时掌握自己现场诉求的落地进度。

## 2. 范围
> **【2026-07-23 用户裁决：医院选择由「平铺医院 tab」改为「医院下拉选择器」】** 与 FS-03 系统视图下拉样式/交互一致——复用同一套 `.f-sysdd*` 样式（触发器在深色顶栏 `.f-sysdd-cur`、面板 `.f-sysdd-panel` `position:fixed` 逃 `#fHtabs` 的 `overflow` 裁剪、搜索框 `.f-sysdd-search` + 列表 `.f-sysdd-list`）。区别于系统视图：医院视图是**单选一家**（`curSite` 单选、即选即查），故**无分组、无「全部医院」聚合项**；`me.sites` 平铺为下拉项，可按医院名搜索；「🔒 医院由运营端分配」提示移入面板底部。落地 = `public/field.html` 的 `buildHospDropdown`/`renderHospList`/`onHospSelect`（id：`fHospDD`/`fHospCur`/`fHospList`/`fHospSearch`；state：`hospOpen`/`hospQuery`）。以下 AC 描述已按此裁决更新。

**包含（本条 = 医院视图左侧「提交清单」区的 医院下拉 + 子控件 + 按类型视图）：**
- **医院下拉选择器**（触发器取自当前账号 `accounts.sites`，显当前所选医院 `curSite`）+ 面板底部灰色不可点提示「🔒 医院由运营端分配」；选医院 → 左侧清单显示**该医院**提交记录（即选即查）。（下拉容器塞进 FS-01 提供的顶栏 `#fHtabs`。）

## 3. 验收标准（AC · Given-When-Then · 每条可自动化判定 · 全 P1）

### A. 医院下拉选择器（数据源 = sites · 2026-07-23 裁决替代平铺 tab）【P1】
> 与 FS-03 系统视图下拉样式/交互一致，复用 `.f-sysdd*` 样式；医院视图单选一家（`curSite` 单选、即选即查），无分组、无「全部医院」聚合项；面板 `position:fixed`（打开时按触发器 `getBoundingClientRect` 定位 `top/left`，逃 `#fHtabs` 的 `overflow-x:auto` 裁剪）。落地 = `buildHospDropdown`/`renderHospList`/`onHospSelect`。
- **AC-1【P1】**（原 AC-1）Given 现场账号（role=impl）已登录、`accounts.sites=["山东省立医院","郑州人民医院"]` When 进入医院视图 Then 顶栏出现**一个医院下拉触发器** `#fHospCur`（`.f-sysdd-cur` 样式 + `ti-building-hospital` 图标），显当前所选医院 `curSite`（默认 sites[0]，即「山东省立医院」）；展开面板列出**恰好这两家**医院项（`me.sites` 平铺，顺序稳定 = sites 数组顺序），当前所选项 `.opt.on` 高亮；**不含**任何不在 `sites` 内的医院、**无**「全部医院」项。
- **AC-2【P1】**（原 AC-2）Given 医院下拉面板已展开 Then 面板**底部**含一个**灰色不可点**提示节点 `.f-htab-note.f-hospdd-lock`（含锁图标 + 文案「医院由运营端分配」），点击它不切换医院、不触发任何请求（点面板内 `stopPropagation` 不关菜单）。
- **AC-3【P1】**（原 AC-3）Given 面板列出多家医院项 When 点击第二家医院项（如「郑州人民医院」）Then `onHospSelect(site)`：`state.curSite=该医院`、关闭面板（`hospOpen=false`/`hospQuery=''`）、触发器文案更新为该医院、该项变 `.opt.on`，并触发左侧清单重新按**该医院**加载（`onHospitalChange` → 请求 `hospitalId=郑州人民医院` 或等价 `site` 过滤），清单只含该医院记录（即选即查，无需再点查询）。
- **AC-4【P1】**（原 AC-4）Given `accounts.sites` 为空（未分配医院）When 进入医院视图 Then 触发器显「尚未分配医院」，面板列表显空态占位「尚未分配医院，请联系运营端」（仍显🔒提示），清单区亦为空态，不报错、不发越权请求。搜索无命中时面板显「未找到匹配的医院」。

### B. 提交清单子控件：按批次/按类型 + 子项目下拉【P1】
- **AC-5【P1】**（原 AC-5）Given 医院视图清单区 Then 存在子控件条 `.f-ph`：含标题「提交清单」+ `f-tabs2`（两项 `按批次` / `按类型`）+ `全部子项目 ▾` 触发器（`.prod`）。
- **AC-6【P1】**（原 AC-6）Given `全部子项目 ▾` When 点击 Then 展开下拉 `.f-proddd`：首项「全部子项目」（默认 `.on`）+ 按**产品分组**的子系统列表——分组标题 = 产品名（`.grp`），组内 `.opt.sub` = 该产品各子系统。**子系统集合来源（2026-07-23 裁决「运营端维护到子系统 + 各自版本」· 向后兼容）**：
  - **新形状**（客户产品 `customers.products[i]` 含 `subsystems:[{name,version}]`）→ 下拉**只列该医院实际维护的子系统**（`name`），desc 从产品目录 `projects[].subsystems[].name→desc` 查、并记住各子系统的 `version`（供归档条取版本，见 FS-03 AC-18）。
  - **旧形状**（客户产品 `{project,version}`，无 `subsystems` 字段）→ **兜底列该产品全部子系统**（现状行为不变），各子系统 `version` 预填产品级 `version`。
  - `buildSubOptions` 产出 `[{product, subs:[{name,desc,version}]}]`；`state.subOptions` 结构相应带上 `version`；`subVersion(name→version)` 供归档条取所选子系统版本。**子系统「双键」显示（同 FS-03 系统视图 `sysLabel`）**：下拉项**显示中文 `desc`**（`desc||name`，如 `audit→审方`），而 `data-sub`/`selectSub` 传参/过滤值一律用**英文/原始 `name`**（匹配 `intakes.subsystem`）——`renderProdDD` 显 `desc||name`、`subLabel(name→desc)` 供选中标签/空态显中文。
- **AC-7【P1】**（原 AC-7）Given 子项目下拉展开 When 选中某子系统（如显示「审方」、值 `audit`）Then 该项变 `.on`、触发器文案更新为该子系统**中文 desc**（`subLabel(curSub)`，非英文 name），并**即选即筛**（无需再点查询）——清单按 `subsystem===<英文 name>`（`&subsystem=state.curSub`）过滤（对齐全局规范⑪选择型筛选即选即查）。**过滤值仍是英文 name，只有显示变中文 desc**（别把过滤值也改成 desc，否则筛不出数据）。
- **AC-8【P1】**（原 AC-8）Given 已按某子系统筛选 When 选回「全部子项目」Then 清除子系统过滤，清单恢复该医院全部记录。
- **AC-9【P1】**（原 AC-9）Given 医院视图 When 点击 `按类型` tab Then `.f-tab2` 高亮切到「按类型」，清单容器切到按类型视图（`fListType` 显示、`fListBatch/fListSystem` 隐藏）；点回 `按批次` → `.f-tab2` 高亮切到「按批次」（**始终随点击切换、不回弹**），批次视图当前为 P2 降级空态（降级行为在 **FS-21 AC-3**）。

### C. 按类型视图（跨批次重组）【P1】
- **AC-10【P1】**（原 AC-10）Given 该医院有多条不同类型的提交记录 When 切到「按类型」Then 按 **需求 / BUG / 咨询** 三组分别渲染（`type` 英文值 `requirement/bug/consult` → 组标题「需求/BUG/咨询」），**跨批次**聚合（不再按批次拆），组头显示该组条数。
- **AC-11【P1】**（原 AC-11）Given 按类型视图某组 Then 组内每条记录含：类型标签（需求/BUG/咨询，`--ticket-{req/bug/consult}` 描边色）+ 标题（`intakes.title`）+ 状态标签（由真实 `lifecycle` 经 UI 映射，见 §6.2）+ 上下文「子系统 · 医院」（`subsystem` · `site`）+ 时间（`submittedAt` 或 `updatedAt`，格式 `yyyy-MM-dd HH:mm`，对齐全局规范⑫）。
- **AC-12【P1】**（原 AC-12）Given 某类型（如咨询）该医院无记录 When 切到按类型 Then 该空组**不渲染**（只出有数据的组），无空白占位组。
- **AC-13【P1】**（原 AC-13）Given 按类型视图 + 已选某子系统 When 切换视图/筛选 Then 子系统过滤对按类型视图**同样生效**（两视图同一数据源，见 §5.1），组内只剩该子系统记录。

> **AC 计数**：本条共 **13** 条（AC-1~13），全 P1。数据权限收敛（原 AC-18/19/20）、按批次视图（原 AC-14~17）、软删除（原 AC-21~25）在 **FS-21**。

## 4. 接口契约

> 统一前缀 `/api`；返回 `{...}` JSON。实施端接口一律按**当前登录用户 `sites`（+`projects`）** 服务端收敛，忽略前端越权传参。契约锚点见 `docs/specs/00-实施端-spec清单.md §4` + 导读 §3.1。

### 4.1 🆕 新增：`GET /api/field/submissions`（本域定义 · 本条实现 `groupBy=type`）
现场医院视图提交清单数据源。**入参/`groupBy=batch` 出参/降级契约见 FS-21 §4**（同一端点，本条只约定 `groupBy=type`）。

**入参（query）：**
| 参数 | 必填 | 说明 |
|---|---|---|
| `dimension` | 否 | `hosp`（默认，本域）/ `sys`（FS-03 用）。本条只实现 `hosp`。 |
| `hospitalId` | 否 | 医院名（= `intakes.site` 值 / `accounts.sites` 项）。缺省 = 我负责全部医院；**越权（不在 sites）→ 忽略或 403**（收敛坐实 AC 在 FS-21）。 |
| `groupBy` | 否 | `type`（P1，本条默认降级态）/ `batch`（P2，FS-21）。 |
| `subsystem` | 否 | 子系统名过滤（= `intakes.subsystem`）。空 = 全部子项目。 |
| `project` | 否 | 产品 id 限定（受 `accounts.projects` 收敛）。 |

**出参（P1 · `groupBy=type`）：**
```jsonc
{
  "dimension": "hosp",
  "hospitalId": "山东省立医院",
  "groupBy": "type",
  "degraded": false,
  "groups": [
    { "key": "requirement", "label": "需求", "count": 3,
      "items": [
        { "id": "XQ-...", "type": "requirement", "title": "审方列表支持按开方科室筛选",
          "subsystem": "审方", "site": "山东省立医院", "version": "v1.3",
          "lifecycle": "待处理", "statusLabel": "待评审",
          "submittedAt": "2026-07-16 10:20", "updatedAt": "2026-07-16 10:20",
          "deletable": true, "convertedTo": "" }
      ]
    },
    { "key": "bug", "label": "BUG", "count": 1, "items": [ ... ] },
    { "key": "consult", "label": "咨询", "count": 5, "items": [ ... ] }
  ]
}
```
> item 补两字段 `"deletable": true, "convertedTo": ""`（供 FS-21 软删入口判定，真值以 `/api/intake-delete` 端点为准）。

- **子项目下拉分组来源（已裁决 2026-07-22：精确）** = 「该医院已上产品的子系统」，精确取自客户台账 `customers.json` 每家医院的 `products[].project`（**CU-01 模型已含此关系，无需新建表**），按医院名匹配。台账空/未录该医院 → 下拉空（带提示）。**不用** intakes 记录近似。依赖医院名在 `accounts.sites`/`customers.name`/`intakes.site` 间一致。
