> **本条聚焦「系统视图（跨医院聚合）+ 归档版本模型（两类版本务必区分）」两块。**
> - 承接 FS-01（登录门 / 工作空间隔离 / `sites` 边界 / 维度下拉「医院视图 ▾ / 系统视图」）与 FS-02（医院视图提交清单 / 按批次·按类型切换 / 全部子项目下拉）。
> - **落地形态遵三条跨条决策**（见 `docs/specs/00-实施端-spec清单.md §1`）：**A｜Node 原生栈**（`public/field.html` + `server.mjs` field 端点，**不是** PRD §2/§9 写的 Vue3/Element/Java）；**B｜角色=真实库 `impl`**（`field`→`impl` 已归一），系统视图=跨"我负责的全部医院"（按 `accounts.sites` 收敛）；**C｜本条系统视图基于工单聚合 `intakes` + git tag 版本，不强依赖批次表 BP-01（P2）**，故列 P1 可先做。
> - **版本模型分两类**（§4.6，务必区分）：① **运营维护版本(tag)**——来源 `/api/versions`（git tag，= 批次产物 pkgVersion），用于**系统视图归档上下文**「提问基于哪个版本」，下拉可选、最新在前；② **现场版本**——来源 `customers.json` 的 `products[].version`（某医院某产品当前版本），用于**医院视图归档上下文**（本条只做"读"，回写在 FS-05），跟随所选医院只读。
> - 归档上下文 chip 的**本体交互与提交动作在 FS-04**（AI 对话提交）；**本条只定义「系统视图聚合规则 + 两类版本模型 + 系统视图下 chip 的版本下拉行为」**，与 FS-04 交叉处显式引用。

## 1. 用户故事 / 目标
作为**现场实施工程师（`impl` 角色）**，我常常**跨我负责的多家医院**关心"某个系统（子系统，如 审方 / 抗网上报 / 药学门诊 / 点评…）在我这些医院里的诉求都到哪步了"——而不是逐家医院翻。为此我要一个**系统视图**：
- 顶部一个**系统下拉选择器**（`全部系统` + 平台**全部产品**的各子系统，**按产品分组·可搜索·显中文**；2026-07-23 用户裁决替代早前的平铺 tab），**忽略医院维度**、把我负责的**全部医院**的该系统提交记录聚到一起看；
- 顶部一条提示条明确"我现在是跨全部医院、只看某个系统"，避免与医院视图混淆；
- 在系统视图下向 AI 提问/归档时，**归档上下文 chip** 明确落在「**产品 · 子系统 · 版本▾**」上，且**版本是运营维护 tag 版本**（最新在前、可切换），让"这条诉求是基于哪个版本提的"有据可查；
- 同时区分：回到医院视图时，归档上下文的版本是**该医院该产品的现场版本**（只读），两类版本语义不同、不能混。

> 价值：把"以医院为主线"补上"以系统为主线"的另一视角（PRD §4.2 的核心诉求），并把 PRD §4.6 的**两类版本模型**在归档上下文里落清楚——运营 tag 版本（提问基准）vs 现场版本（医院当前）。

## 2. 范围
**包含：**
- **维度=系统视图时的顶部系统下拉选择器**（`.f-sysdd`；2026-07-23 用户裁决替代平铺 tab）：深色顶栏上一枚触发器（`.f-sysdd-cur`，参照维度下拉 `.f-mode` 样式，显当前选择：默认「全部系统」、选了某系统显其**中文名** `sysLabel`）+ 点开面板（`.f-sysdd-panel`，白底）内**搜索框**（即输即过滤）+ 列表（首项「全部系统」+ **按产品分组** `.grp`=`productName`、组内各子系统 `.opt.sub` 显**中文 desc**、`data-sys`=英文 name）。数据源=**平台全部产品的子系统清单**（新增 `GET /api/field/systems`，见 §4；已裁决 2026-07-22 NH-2=全部产品，**非**已上产品）。列表稳定排序（依后端返回序）、单选高亮（`.opt.on`）。搜索按**中文 desc 或英文 name** 匹配。点外部 / Esc 关闭（复用 `closeAllMenus`）。**值 / 过滤 / `curSys` / `&system=` 一律用英文 `name`（匹配 `intakes.subsystem`），显示一律中文 desc。**
- **跨医院聚合规则**：选某系统 → 左侧提交清单跨"我负责的全部医院"（按 `sites` 收敛）、**只显示该系统**（按 `intakes.subsystem` 匹配）的提交记录；`全部系统` → 各系统分组一起看（每系统一分组）。
- **跨医院提示条（`.f-xnote`）**：选某系统时「跨你负责的**全部医院**，只看『X』系统的提交记录」；`全部系统` 时「已忽略医院维度：聚合你负责的**全部医院**，按系统查看提交记录」。
- **系统视图下的界面收敛**：**隐藏**「全部子项目」下拉（`.prod`）与「按批次 / 按类型」切换（`.f-tabs2`）——系统已是顶部 tab（对齐原型 `intakeShowSystem`）；切回医院视图恢复（`intakeShowHospitalMode`，属 FS-02 主场，本条只定"系统视图必须隐藏"）。
- **归档版本模型（两类，务必区分）**：
  - **运营维护版本(tag)**：`GET /api/versions?project=<产品id>` 的 `versions[]`（git tag，最新在前）；用于**系统视图**归档上下文 chip 的版本下拉。
  - **现场版本**：`customers.json` 的 `products[].version`（某医院某产品当前版本）；用于**医院视图**归档上下文，**只读展示**（回写在 FS-05）。
- **系统视图归档上下文 chip 的版本部分**：chip 文案 `📦 <产品> · <子系统> · <版本▾>`，版本为**运营 tag 版本下拉**（最新在前、标「最新」、单选打勾），选定后后续提问/归档**基于该版本**（提交动作本体在 FS-04）；`全部系统` 时 chip 退化为「全部系统 · 各系统按运营版本」（无具体版本下拉）。
- **子系统 → 产品映射（SUB_PRODUCT）在归档上下文中的落点**：确定"某子系统属哪个产品"，从而定归档 chip 的产品名与可选 tag 版本集。**真实库无独立 SUB_PRODUCT 映射表**（见 §5 / §6 NH-1），本条给出"由 `projects` + `subsystems` 反查"的**建议实现**，来源未定则标 `NEEDS-HUMAN`。

**不包含：**
- **AI 对话提交本体 / 归档 chip 的确认与建单动作** → FS-04（本条只定系统视图聚合 + 版本模型 + chip 版本下拉行为，提交在 FS-04）。
- **医院视图的按批次 / 按类型 / 全部子项目下拉的完整逻辑** → FS-02（本条只定"系统视图下须隐藏这些控件"这一约束）。
- **现场版本回写（一键改版本）/ 更新包下载 / 待办闭环** → FS-05（本条现场版本只做"读"）。
- **批次分组视图 / `batches` 表 / pkgVersion 发包** → BP-01（P2）；本条系统视图基于工单 `intakes` 聚合，不依赖批次（决策 C）。
- **登录门 / `sites` 隔离缺口修复 / 维度下拉本体** → FS-01。
- 新增/修改任何真实数据库表或列（系统视图纯读现有 `intakes`/`projects`/`customers.json`/git tag）。

## 3. 验收标准（AC · Given-When-Then · 每条可自动化判定）
> 回归套件建议：`tools/fs-03.test.mjs`（A 组前端静态锁原型元素/交互 + B 组连真库冒烟 `/api/field/systems`·`/api/versions`）。凡原型明确交互均落成 AC。

### A. 系统视图 · 顶部系统下拉选择器（2026-07-23 用户裁决替代平铺 tab）
> 早前 AC-1~5 描述的「顶部平铺系统 tab（`.f-htab.sys`）」已于 **2026-07-23 用户裁决**改为**下拉选择器**（`.f-sysdd`，按产品分组·可搜索·显中文 desc）。以下为现行 AC；**跨医院聚合规则（§B）、界面收敛（§C）、两类版本模型（§D/E/F）不变**，只是系统选择的触发来源从 tab 变为下拉项。
- **AC-1** Given 已登录现场账号（`impl`，`sites` 非空）When 维度下拉切到「系统视图」（`mode='sys'`）Then 顶部 `#fHtabs` 渲染**一枚系统下拉控件** `.f-sysdd`（触发器 `.f-sysdd-cur` 在深色顶栏、参照 `.f-mode` 样式，图标 `ti-stack-2`、文案默认「全部系统」）；不再渲染平铺系统 tab、也不渲染医院视图的医院 tab 与「🔒 医院由运营端分配」提示。
- **AC-2** Given 系统视图 When 点开下拉面板（`.f-sysdd-panel`）Then 面板顶部一个**搜索框**（`#fSysSearch`，即输即过滤）+ 列表：首项「全部系统」（`ti-stack-2`）+ **按产品分组**（组头 `.grp`=`productName`，组内各子系统 `.opt.sub` 图标 `ti-git-fork`、显**中文 desc**、`data-sys`=英文 name）。子系统清单来源 = `GET /api/field/systems`（平台**全部产品**的子系统全集，已裁决 NH-2；**非**已上产品收敛），**不是**前端硬编码。清单为空时列表只含「全部系统」+ 空提示「暂无系统」（不报错）；搜索无命中显「未找到匹配的系统」。**搜索按中文 desc 或英文 name 匹配。**
- **AC-3** Given 系统视图下拉列表已渲染 When 两次进入 Then 列表分组与项顺序**稳定一致**（依后端返回顺序，不随机、不依赖插入序）；「全部系统」恒在首位。
- **AC-4** Given 系统视图下拉 Then 触发器在**深色顶栏**上可读（`.f-sysdd-cur` 青色描边，参照 `.f-mode`），面板**白底分组**（复用 `.f-proddd` 的 `.grp`/`.opt`/`.opt.on`/`.opt.sub`/`.f-proddd-empty` 样式），与医院视图 tab 视觉可区分。
- **AC-5** Given 系统视图下拉面板展开 When 点击某系统项（`.opt.sub`）Then 该项置 `.on`、触发 `onSystemTab(name)`（**值用英文 `name`**，匹配 `intakes.subsystem`）、关闭面板、更新触发器为该系统**中文名**（`sysLabel`）、按该系统重建左侧清单（跨医院聚合）；点「全部系统」→ `onSystemTab(null)`（`curSys=null`，聚合全部系统分组）。

### B. 跨医院聚合 · 提交清单
- **AC-6** Given 系统视图选中某具体系统「X」When 渲染左侧清单 Then 清单跨**当前账号负责的全部医院**（`sites` 全集，非单家）聚合，且**只含 `subsystem==='X'`** 的提交记录（按 `intakes.subsystem` 匹配）。
- **AC-7** Given 系统视图选中 `全部系统` When 渲染 Then 左侧按**各系统分组**一起展示（每个子系统一个分组 `.f-batch`，组头系统名 + 条数），跨全部负责医院；分组顺序稳定。
- **AC-8** Given 系统视图选中某具体系统「X」When 渲染 Then 顶部提示条 `.f-xnote` 文案 =「跨你负责的**全部医院**，只看『**X**』系统的提交记录」（图标 `ti-affiliate`）。
- **AC-9** Given 系统视图选中 `全部系统` When 渲染 Then 提示条 `.f-xnote` 文案 =「已忽略医院维度：聚合你负责的**全部医院**，按系统查看提交记录」。
- **AC-10** Given 系统视图任意状态 When 渲染 Then 聚合数据边界严格限定在**当前登录用户 `sites`** 内——后端返回的提交记录不含任何非该用户负责医院的数据（不信任前端传参，服务层按 `sites` 过滤；对齐 FS-01 隔离约束）。

### C. 系统视图下的界面收敛
- **AC-11** Given 从医院视图切到系统视图（`intakeShowSystem`）Then **隐藏**「按批次 / 按类型」切换（`.f-tabs2`）与「全部子项目」下拉（`.prod`）——因系统已是顶部 tab；左侧只显示系统聚合清单容器（`#fListSystem` 可见，`#fListBatch`/`#fListType` 隐藏）。
- **AC-12** Given 从系统视图切回医院视图（`intakeShowHospitalMode`）Then 恢复显示「按批次 / 按类型」切换与「全部子项目」下拉，并默认回到「按批次」（此切回逻辑属 FS-02，本条仅断言"系统视图确已隐藏、切回确已恢复"的对称性）。

### D. 归档版本模型 · 运营维护 tag 版本（系统视图）
- **AC-13** Given 系统视图选中某具体系统「X」When 计算归档上下文（`updateCtx` sys 分支）Then chip 文案 = `📦 <产品P> · <子系统X> · <版本▾>`，其中 `P` = X 所属产品（SUB_PRODUCT 映射，见 §5/§6 NH-1），版本集 = `GET /api/versions?project=<P的id>` 的 `versions[]`。
- **AC-14** Given 系统视图 chip 版本下拉（`.f-ver-menu`）When 展开 Then 版本按**最新在前**排列（沿用 `/api/versions` 已倒序的顺序），**首项标「最新」徽标**（`.latest`），当前选中项打勾（`.chk`/`.on`）；下拉头部提示「运营维护版本(tag) · 提问基于此版本」。
- **AC-15** Given chip 版本下拉展开 When 点击某版本项（`[data-v]`）Then 该版本置为 `ctxVer`、chip 版本文案更新、下拉收起；**未手动选择时默认取 `versions[0]`（最新）**；切换系统 tab 时 `ctxVer` 重置（`ctxVer=null`）、重新默认到新产品的最新版本。
- **AC-16** Given 系统视图选中 `全部系统` When 计算归档上下文 Then chip 退化为「全部系统 · 各系统按运营版本」（图标 `ti-stack-2`），**不出现**单一产品的具体版本下拉（此时无单一归档产品/版本）。
- **AC-17** Given 系统视图某产品的运营 tag 版本列表为空（`/api/versions` 返回 `versions:[]`，如该产品仓无 tag）When 渲染 chip Then 版本位显示占位（如 `—`）、下拉无可选项，**不报错、不阻断**（AI 兜底：无版本仍可提问，版本记为空/占位）。

### E. 归档版本模型 · 现场版本（医院视图，只读）
- **AC-18** Given 维度=医院视图选中某医院 H When 计算归档上下文（`updateCtx` else 分支 → `renderHospChip`）Then chip 文案**按是否选中具体子系统分两种形状**（`renderHospChip` 两分支）：
  - **【2026-07-24 问题② · 选中具体子系统 `state.curSub` 非空】** chip = `🏥 <医院H> · 系统：<subLabel(curSub)> · 版本：<该子系统版本>`；**版本** = `subVersion(curSub)`（该医院该子系统维护的版本；新形状按子系统查、旧形状兜底产品级 `version`；查不到显「—」）。**此形状不再挂产品级「现场版本：<各产品版本列>」**——系统已选定具体子系统，再列全部产品版本冗余且逻辑不对（早前「选中子系统仍挂现场版本：合理用药 —」为 bug，本次修正）。`renderHospChip` 在该分支内 early-return。
  - **【2026-07-24 问题③ · 未选子系统 `state.curSub` 为空（全部子项目）】** chip = `🏥 <医院H> · 现场版本：<产品名（多产品用『、』连接）>` + 紧跟**一枚小 icon 按钮**（`.f-verdd-btn`，`ti-list-details`，`title=「查看各子系统版本」`）。**归档条只显紧凑产品名摘要，不再平铺该医院所有子系统 + 版本**（早前把每个子系统@版本并列拼在归档条里 → 又长又换行、观感乱，本次修正）。点 icon 弹出**「版本明细」小面板**（`#fVerDetail`，复用 `.f-sysdd-panel` `position:fixed`、`getBoundingClientRect` 按 icon 定位逃 `.f-rtool` overflow 裁剪、白底卡片 `max-height`+内部滚动、`z-index` 够高；点面板外 / 滚动 / Esc 关闭，接入 `closeAllMenus`），内容由 `renderVerDetailRows(cust)` 生成 = **逐产品 → 其各子系统 + 版本**：**新形状**（含 `subsystems:[{name,version}]`）→ 列该医院维护的各子系统各自版本；**旧形状**（`{project,version}`）→ 兜底列该产品全部子系统 @ 产品级 `version`（与 `buildSubOptions` 一致）。子系统显中文 desc（`subLabel`/产品目录 desc），版本等宽 `--font-num` 对齐。**无产品** → 「未上线产品」占位、不显 icon；**产品无子系统数据** → 面板显「暂无子系统版本信息」。
  - **【`currentArchive` 归档取值不变】** `out.version` = 选了子系统（`state.curSub`）时取 `subVersion(curSub)`（新形状按子系统查、旧形状兜底产品级）、未选时回退产品级 `version`、查不到空串。**本次仅改 `renderHospChip` 全部子项目态归档条显示 + 加版本明细面板，`currentArchive` 过滤/归档 version 取值逻辑、`&subsystem=` 过滤键不动。**
  - **【2026-07-23 问题① · 已被问题② 覆盖调整】** 早前「选中子系统时在医院名之后、现场版本之前插一段『· 系统：<subLabel> <ver>』且仍保留产品级现场版本列」的口径**已作废**——现选中子系统时只显「系统 · 版本」、不再挂产品级现场版本（见问题②）。切子系统（`selectSub`）末尾调 `updateCtx()` 使归档条**随所选子系统实时刷新**（保留，详见 FS-06 AC-C9③）。
- **AC-19** Given 医院视图 chip 现场版本 Then **只读展示**、无版本下拉（现场版本跟随所选医院，不可在此切换；回写在 FS-05）——与系统视图的 tag 版本下拉形成对照。

## 6. 业务规则 / 非功能
- **数据权限（硬约束）**：系统视图所有聚合以**当前登录用户 `sites`** 为边界（服务层过滤，忽略前端越权传参）；系统 tab 清单（`/api/field/systems`）与提交记录聚合均不得越出 `sites`。依赖 FS-01 已修复 `scopedForField` 隔离缺口 + `intake-list`/`intake-detail` 现有的 `!isAdmin(user) && user.sites` 过滤（`server.mjs` L1057/L1062/L1080）。
- **按钮级权限**：系统视图纯查看（无决策/发包/改版本入口）；`/api/field/systems` 只读、加入 `FIELD_OK` 白名单供现场调用（deny-by-default，见 `docs/lessons.md`）。
- **维度层级视觉区分**：维度选择器=下拉（医院视图 ▾ / 系统视图）；实体=平铺 tab；系统 tab 用青色系与医院 tab 视觉区分（PRD §3.4）。
- **两类版本不混**（核心）：系统视图=运营 tag 版本（`/api/versions`，可下拉、最新在前、提问基准）；医院视图=现场版本（`customers.json products[].version`，只读、跟随医院）。切维度时归档上下文版本语义随之切换，来源不得互串（AC-21）。
- **AI 兜底 / 空态**：产品无 tag（`versions:[]`）→ 版本占位 `—` 不阻断提问（AC-17）；医院未上产品 → 「未上线产品」（AC-20）；系统清单为空 → 仅 `全部系统` tab（AC-2）。
- **稳定排序**：系统 tab / 系统分组顺序稳定（依后端返回，`全部系统` 恒首位）；对齐全局 UI 规范②。
- **时间格式**：清单内如展示提交时间，按全局规范 `yyyy-MM-dd HH:mm`（共享格式化函数，空值占位）——具体列表渲染属 FS-02，本条仅提示系统聚合分组内沿用。
