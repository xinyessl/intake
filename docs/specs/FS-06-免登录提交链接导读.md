## 0. 三份 spec 怎么读

- 想了解**运营端怎么生成一条链接、怎么吊销** → 看 **FS-18**。
- 想了解**访客打开链接后发生什么、提交落到哪、越权怎么被拒** → 看 **FS-19**。
- 想了解**底层 token 怎么签 / 怎么验 / 访客身份怎么识别 / 白名单是哪几个端点** → 看本导读 §1~§3（两 feature 都引用这里的公共机制，不重复展开）。

> ⚠️ **PRD 与真实实现差异（写 spec/测试务必按真实实现）：** PRD §6 写的 `GET /api/s/{token}` 端点**真实不存在**。真实实现是：token 从 URL query `?token=` 或 cookie `intake_link` 取，由 `linkUserFrom(req,url)` 在**每个请求的鉴权闸**里验签（`verifyToken` = HMAC 验签 + `exp` 过期 + `project` 存在校验），无独立"取上下文"端点；访客上下文经 `GET /api/me` 以 `{role:'link',link:true,project,site,ver,ptype}` 返回。FS-18/FS-19 一律按真实实现写。

> ⚠️ **决策 D（两域名部署 / FS-08）影响本条：** field 与 admin 各用独立域名后，`submit-link` 现返回**相对路径** `path` 之外**已补返 field 域绝对地址** `url`（`FIELD_ORIGIN + '/submit.html?token='+token`，未配 `FIELD_ORIGIN` 时 `url` 回退相对路径）。此绝对地址由 **FS-08** 的 `FIELD_ORIGIN` 提供；FS-18 生成 AC 引用之。

## 1. token 机制（HMAC 自验签 · 无库存储）

> **token 无持久化**——HMAC 自验签，密钥文件 + payload 即全部状态。真实库 5 表（`db.mjs`）**无** `intake_submit_link` 表（PRD §5 的概念表在本平台落为文件 + HMAC）。

**① token 结构**（`signToken` · server.mjs L5893）
- `token = b64u(JSON(payload)) + '.' + b64u(HMAC-SHA256(payload_b64u, secret))`，含且仅含一个 `.`。
- `b64u` = base64 URL-safe（`+`→`-`、`/`→`_`、去尾 `=`）。

**② payload 字段**
- `{ project:string(产品id), site:string, ver:string, type:''|'bug'|'requirement'|'consult', exp:number(毫秒时间戳) }`。
- `type` 归一：`(b.type==='bug'||'requirement'||'consult') ? b.type : ''`（其它/缺省 → 空串"类型不锁定"）。
- `exp = Date.now() + days*86400000`；`days` 夹取 `Math.min(3650, Math.max(1, +b.days||365))`。

**③ 验签**（`verifyToken` · server.mjs L5894）
- 重算 `HMAC-SHA256(payload_b64u, secret)` 比对签名段（不等 → `null`）；再验 `exp >= Date.now()`（过期 → `null`）；异常/格式错 → `null`。
- 注意：`verifyToken` 只验签名 + 过期；`projById(project)` 存在性校验在 `linkUserFrom` 里做（见 §3）。

**④ 密钥文件 `data/link-secret`**（`linkSecret()` · server.mjs L5891）
- 内容：24 字节随机 hex（`crypto.randomBytes(24).toString('hex')`，48 字符）。
- 生命周期：读 `DATA_DIR/link-secret`；不存在则**当场生成并写入**；同一进程后续复用同密钥。**更换/删除该文件 = 整体吊销所有旧 token**（详见 FS-18 §3 F 组）。

## 2. LINK_OK 白名单（访客 deny-by-default）

> `LINK_OK`（server.mjs L5900）是访客身份**唯一放行集**；其外一律拒（`/api/*`→403、页面→302 登录）。

```
LINK_OK = {
  '/', '/submit.html',
  '/api/intake-submit', '/api/intake-chat', '/api/intake-commit-plan',
  '/api/consult',
  '/api/projects', '/api/customers', '/api/versions',
  '/api/spec-modules', '/api/model-config'
}
```

- **⚠️ 2026-08-07（FS-04 v2）新增 `/api/intake-commit-plan`**：访客链接原经 `intake-chat` 自动建单，现"建单"挪到「建单前确认清单」`commit-plan` 确定性建单，故此端点须进 `LINK_OK`，否则访客建不了单（server.mjs L5900 注释在案）。
- **不在 `LINK_OK`** 的典型：`/api/intake-list`、`/api/intake-detail`、`/api/intake-transition`、`/api/accounts`、`/api/account-save`、`/api/submit-link`（生成链接本身仅管理员）——访客访问 `/api/*` →403、访问其它页面 →302 `/login.html`。
- **闸前恒放行**（在 `authGate` 前置，访客亦可）：`/assets/*`、`/vendor/*`、`/login.html`、`/field.html`、`/api/login`、`/api/logout`、`/api/me`、`/api/health`、`/api/version`。

## 3. 访客身份识别机制（`linkUserFrom` + `authGate` 访客分支）

**① 取访客身份**（`linkUserFrom(req,url)` · server.mjs L5895）
```
tok = url.searchParams.get('token') || parseCookies(req).intake_link   // query 优先，回退 cookie
若无 tok → null
p = verifyToken(tok)                                                    // HMAC 验签 + exp 未过期
若 !p || !p.project || !projById(p.project) → null                      // 产品须存在（删产品 = 链接失效）
否则 → { link:true, role:'link', project:p.project, site:p.site||'',
         ver:p.ver||'', ptype:p.type||'', name:p.site||'现场' }
```

**② 登录优先**（server.mjs L6019）
- `const link = user ? null : linkUserFrom(req, url)`——**有登录会话时访客身份让位**，二者不叠加（访客白名单不叠加登录权限）。

**③ 鉴权闸访客分支**（`authGate` · server.mjs L5906，`link && !user`）
```
LINK_OK.has(pathname) ? 'allow'
: pathname.startsWith('/api/') ? 'forbidden'（→403 {error:"forbidden"}）
: 'login'（→302 /login.html）
```

**④ 首次带 token 记住身份**（server.mjs L8325）
- 访客首次带 `?token=` 访问静态资源/页面时，响应写 `Set-Cookie: intake_link=<token>; HttpOnly; SameSite=Lax; Path=/; Max-Age=31536000`（365 天），后续请求无需再带 query。

**⑤ 取访客上下文**（`GET /api/me` · server.mjs L6052）
- 访客态返回 `me:{ role:"link", link:true, name:<site||"现场">, project, site, ver, ptype }`；登录态返回 `pubUser(u)`；均无则 `me:null`。前端 `submit.html` 据 `me.link` 触发 `applyLinkLock`（详见 FS-19 §3 B 组）。

## 4. 数据契约（公共）

- **token**：无库存储（见 §1）。
- **密钥文件 `data/link-secret`**：见 §1④。
- **访客提交落库**：复用现有 `intakes` 表（真实列见 `db.mjs`），与登录用户提交同表同结构；`project_id`/`site`/`version` 取 token 预置值，`data JSON` 存整份内存对象（含 `history[]` 留痕、`reporter=link.name`、`byRole='field'`）。**无新增表/列**。详见 FS-19 §5。
