## 1. 用户故事 / 目标
作为**现场实施工程师 / 产品（真实库角色 `impl`，兼含 `pm`）**，我要一个**受登录门保护、按我负责医院严格隔离的工作空间外壳**，并能在**医院视图 / 系统视图**两个维度间切换、在其下平铺选择具体医院 / 系统，以便：
- 未登录时整端被登录页遮罩，登录后**只看到我负责的医院**（`accounts.sites`）范围内的一切数据，与其他账号的工作空间互不干扰、互不可见；
- 顶部维度选择器（下拉）与实体 tab（平铺）视觉层级一眼可辨，明确「选维度」还是「选具体项」；
- 现场端**只提交 / 查看 / 版本回写**，看不到任何决策 / 发包 / 账号管理入口；
- **服务层强制按当前登录用户的 sites 过滤所有查询/写入，忽略前端越权传参**，即便前端被篡改也拿不到别家医院数据（PRD §3.3/§7 硬约束落地）。

> 本条是实施端的**外壳 + 门禁 + 隔离基座**：登录门 / 工作空间隔离核心约束 / 顶部维度切换 + 修复 `scopedForField` 隔离缺口。其余 FS-02~07 都 `depends_on: [FS-01]`，在此外壳内填充清单 / 对话 / 下载等业务。**只复用 UI 资产 `theme.css`，不强依赖运营后台 spec。**

## 2. 范围
**包含（对齐 redesign.html ① 实施端 + PRD §3/§7）：**
- **登录门（`f-login` 遮罩）**：未登录时整端遮罩为登录卡（品牌 + 账号/密码输入 + 错误内联提示 + 安全提示文案；**不含演示账号 chip**——见 CHG-FS-01-去演示账号）；密码框带**显示/隐藏眼睛**；错误内联展示、不弹 toast；登录态本地持久化（刷新保留），退出清除。**复用真实 `POST /api/login` 会话 Cookie**（非原型的纯前端 mock 任意密码登录）。
- **工作空间外壳（`f-top` 顶栏）**：品牌区 + 维度选择器 `f-mode` + 竖分隔线 + 实体 tab `f-htabs` + 右侧工具区（待办 `f-todo` / 经验库入口占位 / 用户区 `f-user` 头像+姓名+退出）。
- **顶部维度切换（层级区分）**：维度选择器 = 一个下拉（`医院视图 ▾` / `系统视图`，半透明描边 + chevron + 弹菜单）；实体 tab = 下拉右侧、以竖分隔线隔开的平铺 tab（实心高亮）；末尾灰色**不可点**「🔒 医院由运营端分配」（不提供自助添加医院/产品）。
- **工作空间隔离（核心约束）**：登录后只加载当前账号 `accounts.sites` 内的医院；医院 tab / 提交清单 / 系统聚合 / 待办 / 版本全部限定在这些医院内；不同账号 = 互相独立的工作空间。**服务层双层过滤**（gate 白名单 + 服务层按 sites 过滤，忽略前端传参）。
- **必修回归（决策 B 缺口）**：修 `server.mjs scopedForField(user, items)` —— 现覆盖 `impl`（+`pm`）角色而非仅死值 `field`；确保实施端账号所有工单查询/写入在服务层按当前用户 sites 过滤。
- **按钮级 / 留痕**：实施端顶栏**无**决策 / 发包 / 账号管理入口（仅提交 / 下载 / 版本回写在各自 FS spec）；本条建立「现场端不注入后台菜单、无管理按钮」的前端 + 后端 `authGate` 双层约束；提交 / 下载 / 版本回写的留痕规则在此声明（谁 / 何时 / 哪院 / 哪产品版本），具体写入落在 FS-04/FS-05。

**不包含：**
- 提交清单内容与分组（FS-02）、系统视图聚合与归档版本模型（FS-03）、AI 对话提交（FS-04）、更新包下载 / 版本回写 / 待办数据源（FS-05）、免登录访客页（FS-06）、经验库检索（FS-07）—— 本条只搭外壳骨架 + 门禁 + 隔离，业务内容在各自 spec。**待办 popover 本条只建空壳/挂载点**，真实待办数据（待下载/待改版本/待验证）由 FS-05 填充。

## 3. 验收标准（AC · Given-When-Then · 每条可自动判定）
> 回归套件（建议）：`tools/fs-01.test.mjs`（A 组静态 DOM/JS 断言锁 field.html 外壳 + B 组连真库冒烟 `/api/login`·`/api/me`·`/api/logout` + C 组服务层隔离/越权）。

### A. 登录门（gate）
- **AC-1** Given 未登录（无有效会话 Cookie）访问 `/field.html` When 页面加载 Then 登录门遮罩 `#fLogin`（`.f-login`）**可见且覆盖整端**（工作空间内容被遮罩，无法看到任何医院/清单数据）；`#fLogin` 不带 `.done` 类。
- **AC-2** Given 登录卡 Then 含品牌区（标题「收件 · 实施端」）、账号输入 `#loginUser`、密码输入 `#loginPwd`（`type=password`）、密码框右侧**显示/隐藏眼睛** `#loginPwdEye`（点击在 `password↔text` 切换、图标 `ti-eye↔ti-eye-off`）、登录按钮、安全提示文案（含「现场账号由运营后台开通并绑定你负责的医院……账号之间数据相互独立」）；**不含演示账号区**（原型的「演示账号（点击填入）」块已去除，见 CHG-FS-01-去演示账号）。
- **AC-3** Given 已填账号密码 When 点登录 Then 调 `POST /api/login {username,password}`；返回 `{ok:true, me}` 则隐藏登录门（`#fLogin` 加 `.done`）并进入工作空间（复用真实会话 Cookie，非前端 mock）。
- **AC-4** Given 账号或密码错误 When 提交 Then `/api/login` 返回 `{ok:false, error}`，页面在 `#loginErr` **内联**展示错误（`.on`，文案取 `error`），**不弹 toast**、不进入工作空间。
- **AC-5** Given 账号或密码任一为空 When 点登录 Then 前端拦截、`#loginErr` 内联提示「请输入账号和密码」，不发请求。
- **AC-6** Given 停用账号（`accounts.enabled=0`）密码正确 When 登录 Then `/api/login` 返回 `{ok:false, error:'账号已停用，请联系管理员'}`，内联展示、不进入。
- **AC-7** Given 登录成功 When 刷新页面 Then 会话 Cookie（`intake_sess`，7 天 TTL）仍在 → `/api/me` 返回当前 `me`（含 `sites`）→ 自动跳过登录门直接进工作空间（登录态持久化）。
- **AC-8** Given 已登录 When 点退出（`#v-field .f-logout` / `fieldLogout()`）Then 调 `GET /api/logout` 清会话 Cookie（`Max-Age=0`），前端清空工作空间状态并重新显示登录门（`#fLogin` 去 `.done`），清空账号/密码/错误/tab/待办。
- **AC-9** Given 已退出后再次 `/api/me` Then 返回 `me:null` —— 会话已失效，工作空间不可再进入。

### B. 工作空间隔离（核心约束 · 数据权限硬约束）
- **AC-10** Given `impl`/`pm` 账号登录 When 渲染顶栏医院 tab `#fHtabs` Then tab 集合**只含**该账号 `accounts.sites` 内的医院，一个不多一个不少（不同账号登录得到不同 tab 集）。
- **AC-11** Given `impl`/`pm` 账号 When 请求任一工单查询接口（如 `/api/intake-list`）Then 返回条目全部满足 `item.site ∈ me.sites`；`sites` 外的工单**不出现**（服务层按当前用户 `sites` 过滤，见 §4）。
- **AC-12** Given `impl`/`pm` 账号越权传参（如查询串带一个**不属于自己 sites** 的 `hospitalId`/`site`/`project`）When 请求接口 Then 服务层**忽略越权传参**，仍只返回自己 sites 内数据（不信任前端参数，PRD §7 硬约束）；即便前端 JS 被篡改也拿不到别家医院数据。
- **AC-13** Given `impl`/`pm` 账号访问某条**不属于自己 sites** 的工单详情（`/api/intake-detail?id=<别家医院工单>`）When 请求 Then 返回 `403`（`{item:null, error:'无权查看该工单'}`），不泄露内容。
- **AC-14** Given 甲、乙两个账号 `sites` 无交集 When 各自登录 Then 甲看不到乙 sites 的任何医院/工单，乙亦然（工作空间互相独立）。
- **AC-15** Given `impl`/`pm` 账号 When 页面加载 Then 前端**不注入**任何后台管理菜单/入口（无「决策/发包/账号管理/产品管理」等），仅现场工作空间元素（维度切换 / 医院 tab / 待办 / 经验库入口 / 提交对话挂载点）。

### C. 顶部维度切换（层级区分）
- **AC-16** Given 已登录工作空间 Then 顶栏最前是**维度选择器** `#fMode`（一个下拉：当前项 `#fModeCur` 显示「全览 ▾」/「医院视图 ▾」/「系统视图」，半透明描边 + chevron；点击展开 `#fModeMenu` 含 `全览`/`医院视图`/`系统视图` 三项，全览在最前）；其右侧一条**竖分隔线** `.f-topdiv`；再右侧是**实体 tab** `#fHtabs`（平铺、实心高亮；全览时隐藏）。三者顺序与视觉层级固定；首次进入默认仍为医院视图。
- **AC-17** Given 维度下拉 When 选「系统视图」`data-m=sys` Then `mode` 切为 `sys`，下拉当前项标签更新为「系统视图」，实体 tab 重渲染为平铺系统（`全部系统` + 各子系统，取自我负责医院已上产品的子系统）；选「医院视图」`data-m=hosp` 则回平铺医院 tab；选「全览」`data-m=overview` 则隐藏左右工作区并展示全宽 `#fOverview`（具体行为见 FS-09）。
- **AC-18** Given 医院视图 Then 实体 tab 末尾有**灰色不可点** `.f-htab-note`「🔒 医院由运营端分配」（不提供「添加医院/产品」入口，绑定关系由运营端账号管理维护）。
- **AC-19** Given 维度选择器（下拉）与实体 tab（平铺）Then 二者视觉语言不同（下拉 = 描边 + chevron + 弹菜单；tab = 平铺实心高亮），DOM 结构可区分（`.f-mode` vs `.f-htab`），层级一眼可辨。

### D. 🔴 必修回归 AC（决策 B 要害缺口）
- **AC-20** Given `server.mjs` 的 `scopedForField(user, items)` 现仅在 `user.role==='field'` 时按 sites 过滤（角色归一为 `impl` 后此判断**永不命中** → 现场 sites 数据隔离失效）When 修复 Then 该函数对**实施端账号（`impl`，且 `pm` 若受 sites 约束同样纳入）**生效，按 `user.sites`（+ `user.projects` 若限定）过滤；且实施端所有工单查询/写入在服务层按当前用户 sites 双层过滤（gate 白名单 + 服务层过滤，忽略前端越权传参）。回归：构造一个 `impl` 账号 + 跨 sites 的工单集，断言过滤前含别家医院工单、过滤后不含；断言 `scopedForField` 对 `role==='impl'` 不再原样返回全集。
- **AC-21（全览渐进式前端边界）** Given 现场端加载 Then 登录门、权限、顶栏 mode 与医院/系统/对话仍由 `field.html` 管理；只有 `#fOverview` 允许由 `/assets/field-overview/field-overview.js` 渐进挂载 React。bundle 不可用时旧原生全览继续可用；离开全览和退出时卸载组件，不影响登录态、sessionStorage 导航恢复或其它视图。

## 4. 接口契约（复用真实端点 · Node `server.mjs` · 禁臆造）
> 对齐 `docs/P0-数据模型对账与接口清单.md §A.4`。**复用**端点 = server.mjs 已有、字段已逐个核过；**🔧** = 需在本条修改逻辑；**🆕** = 需新增（本条尽量复用，不新增业务端点）。

**① 登录（复用 `/api/login`，server.mjs 已有）**
```
POST /api/login    body: { "username":"zhanggong", "password":"…" }
  成功 →  200 { "ok":true, "me": <pubUser> }   + Set-Cookie: intake_sess=<token>; HttpOnly; SameSite=Strict; Path=/; Max-Age=604800  // 7天
  失败 →  200 { "ok":false, "error":"用户名或密码错误" }        // 密码错
          200 { "ok":false, "error":"账号已停用，请联系管理员" } // enabled=0（校验密码通过后才判，避免泄露停用状态）
```

**② 取当前用户（复用 `/api/me`，server.mjs 已有）**
```
GET /api/me  →
{ "authEnabled": true,
  "me": <pubUser> | null | <link访客对象>,
  "defaultAdmin": false }
```
- `pubUser(u)` 字段仅 `{ id, username, role, name, projects[], sites[], mustChange, enabled }` —— `sites` = 工作空间边界（负责医院数组）；`role ∈ {admin,pm,impl}`（`dev/field` 遗留已归一）。**无机构字段**（品牌区用固定文案，见 §6 NH-2）。
- `me===null` = 未登录 → 前端显示登录门；实施端使用者是 `role==='impl'`（+`pm`）。

**③ 退出（复用 `/api/logout`，server.mjs 已有）**
```
GET /api/logout  →  200 { "ok":true }  + Set-Cookie 清除（Max-Age=0）   // 实施端 SPA 用这个（AJAX 退出，不跳转）
GET /logout      →  302 清 Cookie, Location: /login.html                // 备用（整页跳转登录页）
```

**④ 工单查询/详情（复用 `/api/intake-list`、`/api/intake-detail`，server.mjs 已有；🔧 隔离修复）**
```
GET /api/intake-list?project=<pid>[&…]  →  { "items":[ {id,project,site,type,lifecycle,title,…} ] }
GET /api/intake-detail?id=<ticketId>    →  { "item":{…} } | 403 { "item":null, "error":"无权查看该工单" }
```
- 现状：server.mjs 内 `/api/intake-list`(L1057)、`/api/intake-detail`(L1062)、`/api/notifications`(L1080) 已各自用 `!isAdmin(user) && user.sites` 过滤（可命中 `impl`）；但独立工具函数 `scopedForField`(L593~597) 死判 `role!=='field'` 早返回，为死码/隔离盲区。
- **🔧 本条修复**：`scopedForField` 覆盖 `impl`（+ 受 sites 约束的 `pm`），使其与内联过滤一致、可复用；确保**忽略前端越权传参**（服务层以 `me.sites` 为准，不采信查询串里的 `site`/`hospitalId`/`project`）。见 §5 + AC-20。

> **本条不新增业务端点**。PRD §6 列的 `/api/field/*`（hospitals/systems/submissions/todos…）在 FS-02~05 落地；本条只复用 login/me/logout + 修 intake 查询隔离。医院 tab 数据来源：`me.sites`（工作空间边界）即可平铺，无需新端点。

## 5. 数据契约（对齐真实库 `db.mjs` init() · 禁臆造列名）
> 只写真实库能确证的（`accounts`/`sessions`）；PRD 概念表名映射到真实实现；缺口标 `NEEDS-HUMAN`。

**表 `sessions`（真实列，`db.mjs` L30~32）：**

## 6. 业务规则 / 非功能
- **登录门硬约束**（PRD §3.2/§7）：未登录不可访问任何实施端工作空间数据/接口；前端遮罩 + 后端 `authGate` deny-by-default 双层（`authGate` 已白名单放行 `/api/login`/`/api/me`/`/api/logout`，其余对非管理员按 `FIELD_OK` 白名单，越白名单一律 403）。
- **数据权限（硬约束）**（PRD §3.3/§7）：`impl`（+受 sites 约束的 `pm`）所有查询/写入以当前登录用户 `accounts.sites` 为边界；**服务层过滤 + 忽略前端越权传参**（拦截器/服务层双重，AC-11~14/20）。
- **按钮级权限**（PRD §7）：实施端无决策/发包/账号管理入口，仅提交/下载/版本回写；前端不渲染管理按钮 + 后端 `authGate` 不把管理写接口放进 `FIELD_OK`（非管理员调之自动 403，见项目经验库「白名单 deny-by-default」）。
- **登录态持久化**：会话走真实 Cookie（`intake_sess`，HttpOnly + SameSite=Strict + 7 天）；前端**不再自行往 localStorage 存密码/明文用户**（原型是纯前端 mock，落地改为凭 Cookie + `/api/me` 恢复登录态，避免明文持久化风险）。刷新 = 读 Cookie → `/api/me` 恢复。
- **留痕**（PRD §7）：提交/下载/版本回写记录「谁/何时/哪院/哪产品版本」（写入落 FS-04/FS-05，本条声明规则）。
- **并发**（PRD §8）：多端同账号以最新登录会话为准（`sessions` 表按 token；不做单点强制下线，NH 见下）。
- **非功能**：图标沿用现有资产；AI/业务降级不在本条（FS-04）。

**已裁决（2026-07-22 · 人工拍板，无需再确认 diff）：**
- **NH-2 机构文案 → 固定占位「收件·实施端」**：`/api/me` 无机构字段，顶栏用固定占位，**不臆造 `me.org`**（同 UI-01）。
- **NH-3 鉴权 → 复用现有 Session Cookie**：`sessions` 表 + `intake_sess`（HttpOnly+SameSite+7 天），与运营端同一套；不上 JWT。
- **NH-4 工作空间默认加载范围 → 当前所选医院**：默认只拉当前所选那家医院的数据，切换医院再拉（更轻、贴合顶栏医院/系统维度切换）；tab 集仍 = `me.sites`（我负责的全部医院）。**影响 FS-02**：提交清单默认按「当前所选医院」加载 + 分页。
- **NH-5 pm 边界 → 设了 sites 就受约束**：服务层对所有非管理员按 sites 过滤（与 server.mjs 现状 `!isAdmin(user) && user.sites` 一致）；pm 绑了医院只见这些医院。
- **NH-1 演示账号（非决策 · 数据准备）**：`zhanggong/ligong/zhaogong` 未必在真库——连真库冒烟前由开发**自造 3 个 `impl` 账号（各绑不同 `sites`）、测后清理**，绝不假设真库已有。
