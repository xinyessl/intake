> **【本条 = FS-05 机制的「下载与状态翻转」环节】**（机制全景见导读 `FS-05-下载版本回写与待办导读.md`）。
> 现场账号在**「可下载」批次**里看到更新包 → **下载** → 覆盖工单自动「已出包→待验证」→ 为后续「改版本 + 逐单验证」（FS-16）铺路。落地 = `public/field.html` 按批次视图 + `server.mjs` 新增 `GET /api/field/batches`、`POST /api/batch-download`（进 `FIELD_OK` + `FS08_FIELD_API`，按 `sites` 二次收敛）。
>
> **三条跨条决策（贯穿）**：A｜Node 栈（`public/field.html` + `server.mjs`，非 Vue/Element/Java）；B｜角色 impl（按 `accounts.sites` 服务端收敛，不信前端传参）；C｜批次依赖 BP-01（未上线走 H 组降级）。

## 1. 用户故事 / 目标
作为**现场实施工程师（`impl`）**，我要把「我提的单」按落进的**批次(产品)分组**查看，在**「可下载」批次**里看到更新包信息、**下载更新包**，并让下载动作**自动把我负责医院的覆盖工单从「已出包」翻到「待验证」**——以便进入逐单验证前置态、形成「上传包 → 下载 → （待验证）→ 逐单验证 → 批次交付」链路的前半段；BP-01 未上线时**降级不报错**。

- 更新包由运营端管理身份上传（BP-01），现场**只下载**、不自助发包。
- 下载**幂等**：重复下载不重复计数（`downloads` 不叠加）、返回同一 `artifactUrl`。
- 下载后返回 `bumps`（我负责医院×子系统 `v_old→v_new`）驱动 FS-16 的改版本提示条。

## 2. 范围
**包含：**
- **按批次视图**（FS-02「按批次」落地）：把我负责医院的提交单**按落进的批次(产品)分组**，每组显示：产品 + 批次状态（开发中/可下载/已交付）+ 排期（计划交付日期）+（可下载时）更新包信息 + 组内逐单列表（每单状态；逐单验证入口由 FS-16 承载）。
- **更新包信息 + 下载**：「可下载」批次组内展示 `<产品> v<pkgVersion> 更新包`（发包时间 + 更新说明 + 下载按钮）；点下载 → `POST /api/batch-download` 记录下载 + 返回 `artifactUrl` → 触发下载 / 提示地址；按钮转「已下载」。
- **下载 → 状态翻转（闭环联动前半段）**：下载后我负责医院的覆盖工单 `已出包→待验证`（系统动作直接置态 + 留痕）；返回 `bumps` + `verifyTickets`（随下载转「待验证」的单）驱动 FS-16 改版本条 / 逐单验证入口。
- **闭环联动收口**：全批覆盖工单验证过（FS-16 逐单验证驱动）→ 批次「已交付」→ 按批次视图该组头 tag 更新、下载/验证入口收起或标记完成。
- **BP-01 未上线降级**：批次接口未就绪时按批次视图显占位 / 降级为「按类型」视图，下载/改版本/逐单验证入口不出现，不报错。

**不包含（划归它处）：**
- 一键改版本、逐单确认「验证过」/「反馈打回」、越权改版本/验证的数据隔离 → **FS-16**。
- 维保到期回写、更新包实施任务清单 → **FS-17**。
- 批次创建/定档/导清单/上传包/审核部署清单/闭环判定本体 → **BP-01**；本条只**读**「可下载」批次 + 包信息、**写**下载事件 + 触发覆盖工单转「待验证」。
- 医院选择器 / 按类型视图 / 子项目筛选（→ FS-02，本条复用其批次分组容器）。

## 3. 验收标准（AC · Given-When-Then · 每条可自动化判定）
> ⚠️ 涉及批次/更新包/下载的 AC 依赖 **BP-01（批次「可下载」+ 包信息 + 上传包）**；BP-01 未上线前走 H 组降级、不可正式验收。前端结构/交互可先在 `public/field.html` 静态锁定。

### A. 按批次视图（批次分组 · 对齐 FS-02「按批次」落地）
- **AC-1**（原 A/AC-1）Given 当前所选医院在若干批次内（其提交单 `intakes.data.batch` 非空），When 切「按批次」视图，Then 按批次(产品)分组展示：每组头 `<产品> · <批次状态 tag>`（开发中/可下载/已交付，tag 色对齐 theme.css）+ 组内我提的工单逐单列表；无批次归属的单归「未入批」组或按 FS-02 降级处理。
- **AC-2**（原 A/AC-1b · 排期可见）Given 某批次运营端已设排期（`scheduleDate` 非空，纯日期 `yyyy-MM-dd`），When 现场端切「按批次」视图渲染该组头，Then 组头显示排期「计划交付 <scheduleDate>」（次要色）；未排期（`scheduleDate` 空）显「未排期」灰字占位。后端 `GET /api/field/batches` 每个批次 group **必须回传 `scheduleDate` 字段**（旧批次回读为空串）——根因回归：该字段是排期后加的，`field/batches` 输出曾漏带，导致排期在实施端不可见。不使用「发包」类字样（现场端 A6 禁词）。
- **AC-3**（原 A/AC-1c · 工单卡醒目显排期 · 2026-07-26 修订：底部灰字→顶行醒目 chip + 系统视图同显）Given 现场端工单卡（「按类型」视图 `mkItem` **或**「系统视图」`mkSysItem`）某工单已归批且该批设了排期，When 渲染该卡，Then 在**卡片顶行**（类型标签「BUG/需求/咨询」+ 状态标签行）之后追加一枚**醒目的排期 chip** `.f-sched-chip`（带日历图标 + 强调色字浅底，文案「计划交付 <scheduleDate>」，纯 `yyyy-MM-dd`），一眼可见、与状态标签配色分明；未归批或批次无排期则**不显**。旧实现把排期放在底部上下文行灰字（`.isched`）里太不起眼、用户看不到——现提升为顶行 chip 且**从底部去掉不重复**。`mkItem`/`mkSysItem` 两处用同一 `.f-sched-chip` 样式类、视觉一致。后端 `field/submissions` 每条 item **回传 `batchId` + `batchSchedule`**（`batchSchedule` = 该工单 `data.batch` 对应批次的 `scheduleDate`，读时按 `loadBatches()` 派生、不落库；无批次/无排期为空串）；`dimension=sys`（系统视图）与 `hosp`（按类型/医院视图）**共用同一 `mapItem`**，故系统视图 item 同样带 `batchSchedule`（无需额外改后端）。不使用「发包」类字样（A6 禁词）。
- **AC-4**（原 A/AC-2）Given 某批次状态=「可下载」，When 渲染该组，Then 组内出现更新包信息区：`<产品> v<pkgVersion> 更新包` + 发包时间（`yyyy-MM-dd HH:mm`）+ 更新说明（点开看 `releaseNote`）+ `下载更新包` 按钮。
- **AC-5**（原 A/AC-3）Given 某批次状态=「开发中」（未上传包），When 渲染该组，Then **不**出现更新包/下载区（仅「可下载/已交付」态挂包信息）；组内工单显各自 lifecycle 映射标签。
- **AC-6**（原 A/AC-4）Given 数据按 sites 隔离，When 生成按批次视图，Then 后端 `GET /api/field/batches` 只返回**当前账号 `sites`** 内医院涉及的批次 + 我提的单（`scopedForField`），换账号得不同集（对齐 FS-01 隔离 + §6 决策）。

### B. 下载 + 状态翻转
- **AC-7**（原 B/AC-5）Given 「可下载」批次的 `下载更新包` 按钮，When 点击，Then 调 `POST /api/batch-download {batchId, customerId}`（当前医院），成功后：① 按钮转「已下载」（`.done` 绿）；② 出现改版本提示条：`<医院> <产品/子系统> v_old → <b>v_new</b>` + `一键改版本`（该批次覆盖的我负责医院各一条，改版本动作本体见 FS-16）。
- **AC-8**（原 B/AC-6）Given 已下载过（后端 `downloads` 已计当前账号本次），When 重复调 `POST /api/batch-download`，Then **不重复计数**（`downloads` 不叠加）、返回同一 `artifactUrl`；前端不重复插入改版本提示条。
- **AC-9**（原 B/AC-7）Given `POST /api/batch-download` 返回 `artifactUrl`，When 前端拿到，Then 触发下载（新标签 / `<a download>`）或提示地址；地址为空（BP-01 产物形式未定）时降级提示「更新包地址待运营发布」，不报错。
- **AC-10**（原 B/AC-8）Given 越权：当前账号 `sites` 不含某医院，When 下载/生成提示条，Then 后端只按当前用户 `sites` 收敛（`scopedForField`），提示条只列我负责医院，越权医院不出现（`forbidden` 或收敛）。

### G. 闭环联动（下载 → 改版本 → 逐单验证 → 批次交付）
- **AC-11**（原 G/AC-22）Given 完成下载（AC-7），When 后端记录，Then 覆盖工单经 `已出包→待验证`（下载触发，见 §5.3），按批次视图该单出现「确认验证过」入口（入口动作本体见 FS-16）。
- **AC-12**（原 G/AC-23）Given 「一键改版本」（FS-16）+「逐单验证过」（FS-16）联动，When 全批单验证过（FS-16 触发闭环），Then 批次「已交付」、该组下载/验证入口收起或标记完成，闭环达成、按批次视图该组头 tag 更新为「已交付」。

### H. 分期占位（BP-01 未上线时的降级）
- **AC-13**（原 H/AC-24）Given BP-01 未上线（`GET /api/field/batches` / `/api/batch-download` 未就绪），When 现场端渲染按批次视图，Then **不报错**：按批次视图显占位「批次功能待运营端上线」或降级为 FS-02「按类型」视图；下载/改版本/逐单验证入口不出现（§6 记待接续）。

## 4. 接口契约
> 统一前缀 `/api`；实施端接口按**当前登录用户 `sites`** 收敛，忽略前端越权传参；返回体 `{ok/error}` 或 `{...data}`。**新增端点均需显式加入 `server.mjs` 的 `FIELD_OK` 白名单**（否则 `authGate` deny-by-default 对现场 `impl` 403），且服务层再按 `sites` 二次校验。
> **⚠️ 双域名同步约束（对齐 FS-08 AC-9b）**：本条 2 个现场端点（`field/batches` / `batch-download`）除进 `FIELD_OK` 外，**还必须同步加进 `server.mjs` 顶层 `FS08_FIELD_API`**。漏配时：运营域（admin）能调、**实施域（field, `intake.lcpharmacy.cn`）被 `originGate` 判 deny 返 `{"error":"forbidden"}`** → 实施端整段批次流挂掉且隐蔽（登录、页面都正常，仅接口越域拒）。回归由 `tools/fs-08.test.mjs` 的「FIELD_OK 的 /api/ 端点全部 ∈ FS08_FIELD_API」防漂移断言守。

### 4.1 🆕 更新包下载 —— `POST /api/batch-download`（依赖 BP-01）
```
POST /api/batch-download
body: { "batchId":"B-01", "customerId":"c..." }   // 当前所选医院
  →  200 { "ok":true, "artifactUrl":"...", "pkgVersion":"v2.1",
           "bumps":[ { "customerId","hospital","product","subsystem?","fromVer":"v2.0","toVer":"v2.1" } ],
           "verifyTickets":[ { "project","id","title" } ] }   // 我提的、随下载转「待验证」的单
     403 forbidden（越权 sites）
     503 / {ok:false,error:"批次功能未就绪"}（BP-01 未上线 → 降级 AC-13）
```
- 读 BP-01 批次（`data/batches.json`，命名对齐 BP-01 落地）；仅「可下载」批次可下载。
- `downloads` 计数 +1（同账号重复下载**不叠加** → 幂等，AC-8，按账号 `downloadedBy[]` 幂等）；下载触发覆盖工单 `已出包→待验证`（§5.3，我负责医院的单，系统动作直接置态 + 留痕）。
- `bumps` = 该批次覆盖的**我负责医院** × 产品/子系统的版本提示（驱动 FS-16 改版本提示条 + 一键改版本）。
- `artifactUrl` 形式（URL / 上传）随 BP-01 落地 → 空则前端降级（AC-9）。

### 4.2 🆕 按批次视图 —— `GET /api/field/batches?hospitalId=`
```
GET /api/field/batches?hospitalId=c...    // 不传=当前账号全部 sites 汇总
  →  200 { "groups":[ {
        "batchId","product","productName","status":"开发中|可下载|已交付",
        "pkgVersion","releaseNote","releaseTime","artifactUrl","scheduleDate",

```

- 依赖 BP-01（未上线 → 空 / 降级，AC-13）。

## 5. 数据契约
> **对照真实结构核对，禁止臆造列名。**

### 5.1 批次 / 包信息（读 BP-01 存储 · 依赖 BP-01）
- BP-01 批次存储 `data/batches.json`（对齐 BP-01 §5.1）字段：`id/product/status(可下载/已交付…)/pkgVersion/releaseNote/artifactUrl/releaseTime/scheduleDate/ticketIds/downloads/downloadedBy[]/arrangedAt`。本条**只读**这些字段驱动按批次视图 + 下载；下载计数 `downloads` + `downloadedBy[]`（幂等）挂点与 BP-01 对齐。
- 更新包**大小**：BP-01 未定 size 字段 → 展示可省略或占位 `—`（NH-1）。

### 5.2 工单联动（复用真库 `intakes` + `TRANSITIONS`，禁臆造）
- **回链**：工单 `intakes.data.batch`（BP-01 定档写，server.mjs L1305 范式）标识所属批次——本条读它做按批次分组。
- **下载触发**：下载后我负责医院的覆盖工单 `已出包→待验证`（真库 `TRANSITIONS['已出包']=['待验证']`，server.mjs L523；系统动作直接置态 + 留痕，同 batch-release 范式）。
- 复用现有 `intake-transition` 留痕（`history[]`），本条不重造流转。

### 5.3 数据边界
- 医院-账号边界 = `accounts.sites`（JSON，负责医院列表）；隔离见 FS-01。批次/下载/按批次视图全部按当前账号 `sites` 服务端收敛（`scopedForField`），忽略前端越权传参。

## 6. 业务规则 / 非功能
- **数据权限（硬约束）**：下载/按批次视图**全部限当前 `impl` 账号 `sites`**（服务层收敛，忽略前端越权传参）；越权 `forbidden`(403)（对齐 FS-01 隔离 + authGate）。
- **按钮级权限**：现场端**无**定档/建批/上传包/账号管理入口；仅下载（改版本/逐单验证见 FS-16）。新写端点默认**不进** `LINK_OK`（免登录访客无权）。
- **幂等**：下载重复不重复计数（AC-8，按账号 `downloadedBy[]` 幂等）；前端不重复插入改版本提示条。
- **闭环不回退**：批次态由 FS-16 逐单验证驱动；全验证过才 `batch-deliver-check` → 「已交付」（本条只显示 tag 更新）。
- **留痕**：下载记「谁/何时/哪院/哪批次」；覆盖工单 `已出包→待验证` 复用 `intake-transition` `history`。
- **时间格式**：发包时间等展示统一 `yyyy-MM-dd HH:mm`（排期 `scheduleDate` 纯日期 `yyyy-MM-dd`），空值 `—`。文案避 FS-01 A6 禁词（不用「发包」类字样）。
- **降级**：BP-01 未上线时按批次视图/下载入口降级占位、不报错（AC-13）。

**NEEDS-HUMAN（本条待裁决）：**
- **NH-1 更新包 size 字段**：BP-01 未列 size 列；包大小来源/展示待定（当前占位 `—`）。
- **NH-2 下载端点命名 + 产物形式对齐 BP-01**：`POST /api/batch-download` 与 BP-01 批次存储/命名统一；`artifactUrl` URL vs 上传（BP-01 NH-2）——已随 BP-01 落地对齐（`data/batches.json`），残留产物形式待运营发布确认。

## 7. 测试要点（交付给开发 agent）
