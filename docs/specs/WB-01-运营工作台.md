## 1. 用户故事 / 目标
作为**收件运营人员（管理员）**，我要在一个工作台一眼掌握全局：进件总量与各状态分布、各产品进件数、最近进件，并能从产品概览/最近进件下钻到收件箱或工单详情，以及从功能磁贴快速进入各模块——以便快速定位今天要处理的事。

> 说明：本条聚焦**工作台聚合展示 + 点击下钻 + 功能入口磁贴**，数据全部**读时派生**、只读无副作用。统计口径以旧粗粒度 `status` 为准（`lifecycleToStatus` 映射），TK-01 新态只被动并入聚合。

## 3. 验收标准（AC · Given-When-Then · 可自动化判定）

> 页面基线 = 部署 `public/console.html`；接口基线 = 部署 `/api/overview`。

### 聚合接口
- **AC-1** Given 已登录用户 When `GET /api/overview` Then 返回 200 且 `Content-Type: application/json`，body 含字段 `projects`（数组）、`totals`（对象）、`recent`（数组）、`model`（对象）。
- **AC-2** Given 后端聚合 When 返回 `totals` Then 至少含键 `total / requirement / bug / 待处理 / 沟通中 / 已归档 / 已处理`（数值型）；`total = requirement + bug`（每条进件按 `type==='bug'` 记 bug、否则记 requirement）；`consult` 类会话不计入（`listIntake` 默认过滤 `type==='consult'`）。

### 统计口径（旧粗粒度 status·`lifecycleToStatus`）
- **AC-3** Given 库中进件 When 计算 `totals.待处理` Then 等于所有 `status='待处理'` 的进件数（`lifecycle='待处理'` → `status='待处理'`）。
- **AC-4** Given 库中进件 When 计算 `totals.沟通中` Then 等于所有 `status='沟通中'` 的进件数（`lifecycle ∈ {分析中,已回复,已立项,开发中,已出包,待验证,已重开}` → `沟通中`）。
- **AC-5** Given 库中进件 When 计算 `totals.已处理` Then 等于所有 `status='已处理'` 的进件数；**TK-01 新态对齐**：`lifecycle ∈ {已关闭, 暂缓, 已驳回}` 经 `lifecycleToStatus` 均映射为 `已处理`，故「暂缓/已驳回」工单**并入 `已处理` 计数**，不漏算、不单列。（含此断言以防 TK-01 状态回归。）
- **AC-6** Given `lifecycleToStatus` 值域仅 `{待处理, 沟通中, 已处理}` When 统计 Then `totals.已归档` 恒为 0（旧归档态已并入 `已处理`，为遗留保留键，前端不渲染 `已归档` 卡——现状如此，非缺陷）。

### 展示卡片（console.html renderStats · re-target 原型 5 卡）
- **AC-7** Given 工作台已渲染 When 检查统计卡 Then 为 5 张 `.stat-card`（`.grid.grid-cols-5`，lifecycle 视角）依次：`待评审 / 进行中 / 已处理 / 本周待发包批次 / 本月已交付`；每卡含 `.stat-card-icon` + `.stat-card-label` + `.stat-card-value` + `.stat-card-foot`。前 3 卡数值分别取自 `totals.待处理 / totals.沟通中 / totals.已处理`（三桶口径），带 `.clickable`，点击跳 `/inbox.html?pipe=<组>`（待评审→`pipe=待评审`、进行中→`pipe=开发中`、已处理→`pipe=已关闭`）。
- **AC-7b** Given 「本周待发包批次」「本月已交付」两卡 When 渲染 Then 为**占位卡**：值分别为 `0` / `—`、脚注含告警图标 + NEEDS-HUMAN 提示、**不带 `.clickable`、无 onclick**（BP-01 批次表未建 / 需 lifecycle+月份口径扩 overview；见 §5 NH-2/NH-4）。前端不臆造这两个数值。

### 产品概览 / 最近工单下钻
- **AC-8** Given `/api/overview` 返回 `projects` When 渲染产品概览 Then 每行显示产品 `id`（徽标）、`name`、`count` 条数，未绑代码仓（`hasRepo=false`）显示「未绑代码仓」标记；行点击跳 `/inbox.html?project=<id>`；`projects` 空时显示占位。
- **AC-9** Given `/api/overview` 返回 `recent` When 渲染最近工单表（`.data-table`，列 编号/类型·标题·现场·状态·更新时间）Then 至多 12 行、按 `submittedAt` 倒序；每行含类型徽标（`type==='bug'`→BUG、`consult`→咨询、否则 需求）、编号、标题（+产品名/版本子行）、现场（`site`，无则 `—`）、状态徽标（旧粗粒度 `status`）、更新时间；`recent` 空时表体显示占位行。
- **AC-9b** Given 真实 `overview.recent` 项**无 `customer`/`updatedAt` 字段** When 渲染表 Then 「现场」列用 `site`、「更新时间」列用 `submittedAt`（overview.recent 只给此时间字段）——不臆造 customer/更新时间字段（对齐 L-004：原型 mock 字段 ≠ 真实端点出参）。
- **AC-10** Given 最近工单某行 When 点击该行 Then 跳 `/detail.html?project=<project>&id=<id>`。
- **AC-11** Given 最近工单的 `submittedAt` When 渲染 Then 经共享 `fmtTime` 格式化为 `yyyy-MM-dd HH:mm`（兼容 ISO/时间戳/`空格分隔` 串），空值显示 `—`；不直接显示后端原始值。

### 模型状态 / 本周批次占位
- **AC-12** Given `/api/overview` 返回 `model` When 渲染模型状态 panel Then `model.configured=true` 显示「已配置」绿徽标 + 模型名/provider、否则「未配置」黄徽标 + 引导文案；点击进 `/model-config.html`。
- **AC-12b** Given BP-01 批次表未建 When 渲染「本周批次」panel Then 显占位「暂未开放」+ NEEDS-HUMAN 徽标，不臆造批次数据。

### 权限 / 异常
- **AC-13** Given 未登录（无有效 session） When `GET /api/overview` Then 返回 401，不返回聚合数据。
- **AC-14** Given 任一子数据源异常/为空 When 聚合 Then 接口仍 200、以空数组/0 值降级（如无进件时 `totals` 全 0、`recent=[]`、`projects` 仅示例项目），前端不白屏（`renderStats/renderProjects/renderRecent` 各有空态分支）。

## 4. 接口契约

**主接口：`GET /api/overview`（部署现状，单一聚合入口）**

返回（`server.mjs`）：
```jsonc
{
  "projects": [ { "id","name","count","hasRepo" } ],                       // 各产品进件数 + 是否绑仓（含子系统仓）
  "totals":   { "total","requirement","bug","待处理","沟通中","已归档","已处理" },  // 旧粗粒度 status 计数；已归档恒 0
  "recent":   [ { "id","project","projectName","type","title","site","version","status","submittedAt" } ],  // 前 12，按 submittedAt 倒序，排除 consult
  "model":    { "configured","model","provider" }                          // 模型配置只读状态
}
```
- 鉴权：需登录 session，未登录 401（AC-13）。
- 只读 GET、幂等、不改库。
- 计数按 `listIntake(project)` 逐项：`type==='bug'`→bug、否则 requirement；`status` 命中 `totals` 的中文键则 +1。
- **降级**：无进件/无产品时首启动会兜底建示例项目 `demo`；接口恒 200。

> **未采纳（原型愿景，不在本条契约内）**：`stats`（5 lifecycle 卡）/`weekBatches`/`topProduct`/`models`/`meta`——如未来实现另开 spec。

**下钻链接（前端跳转）**：`/inbox.html?project=<id>`（产品概览）、`/detail.html?project=<p>&id=<id>`（最近进件）、功能磁贴各自 href。

## 5. 数据契约

> **对照 `intake_bak/db.mjs` 真实列，禁止臆造。** 注意：`loadAll` 把每条进件**整份从 `data JSON` 反序列化**（`const e = P(r.data)`），列仅用于索引；聚合读的是内存对象字段。

**`intakes` 表（现有，`db.mjs`）** — 工作台统计数据源（真实 20 列）：
- `project_id, id, type, version, site, subsystem, module, title, priority, severity, env, freq, status, lifecycle, assignee, reporter, submitted_at, data(JSON), created_at, updated_at`。
- 聚合用到：`type`（bug/requirement/consult）、`status`（旧粗粒度：待处理/沟通中/已处理，由 `lifecycleToStatus(lifecycle)` 写入）、`submittedAt`（`data.submittedAt`，`yyyy-MM-dd HH:mm` 串）、`site`、`version`、`title`。
- `consult` 类进件由 `listIntake` 默认过滤（`opts.withConsult` 未开时不计入 totals/recent）。
- 状态口径以旧 `status` 列为准；`lifecycle` → `status` 映射见 `server.mjs lifecycleToStatus`：`待处理→待处理`、`已关闭/暂缓/已驳回→已处理`、其余→`沟通中`。**TK-01 新态「暂缓/已驳回」经此并入 `已处理`（AC-5）。**

**`projects` 表** — 产品概览源：`id, name, repo_path, specs_path, subsystems(JSON)`；`hasRepo` = 顶层或任一子系统绑了仓（`repoPath/specsPath/gitUrl/subsystems[].repoPath|repoUrl` 任一）。`count` = 该产品下非 consult 进件数。

**`batches` 表**：本条**不涉及**（原型 weekBatches/待发包愿景未采纳）。

**留痕**：本条为只读聚合，不写库、不产生留痕。

### NEEDS-HUMAN / 依赖（re-target 原型后）
1. **【已裁决·NH】前端事实源=原型（2026-07-21 re-target）**：见 §0.2。工作台内容按原型重做（5 stat-card + 最近工单表 + 本周批次占位）。未采纳原型区块（SLA 条/topProduct/多模型明细/meta）不在本条范围。
2. **【NH-2·批次统计需扩后端】本周待发包批次卡占位**：BP-01 `batches` 表未建，`/api/overview` 无批次字段。「本周待发包批次」卡显 `0` 占位。**要出真实数**须先建 BP-01 批次表 + 扩 `/api/overview` 返回 `weekBatches`（后端改动，本次纯前端不做）。
3. **【NH-3·本月已交付口径需扩后端】本月已交付卡占位**：现 `/api/overview` 无 lifecycle 细粒度、无按月份聚合，无法算「本月已交付」（已出包/待验证/已关闭且 submittedAt/closedAt 在本月）。卡显 `—` 占位。要出真实数须扩 overview（后端），本次不做。
4. **【NH-4·精确 lifecycle 口径需扩后端】前 3 卡为三桶近似**：`totals` 是旧粗粒度三桶（待处理/沟通中/已处理），原型 5 卡本应各按独立 lifecycle 计数（待评审/已落实·排期/开发中/已交付…）。本条：待评审←`待处理`（分析中也属待评审但落在沟通中桶，未计入本卡值）、进行中←`沟通中`（已落实/开发中/待交付合并，无法拆分）、已处理←`已处理`。**点击下钻走 `?pipe=<组>`，inbox 端按 lifecycle 集合精确筛选**，故值近似但落地筛选精确。要卡值也精确须扩 `/api/overview` 增 lifecycle 分桶（后端改动，本次不做）——已写进交付说明供串行处理。
5. **【NH·客户位用现场】** 真实 `overview.recent` 无 `customer` 字段（只有 `site` 现场）、无 `updatedAt`（只有 `submittedAt`）。最近工单表「现场」列用 `site`、「更新时间」列用 `submittedAt`（AC-9b）。若产品要「客户」维度（工单关联客户台账），须先定 intakes↔customers 关联（无 customerId 列，改库范畴），标 NEEDS-HUMAN。

## 6. 业务规则 / 非功能
- **权限**：仅登录用户可见（依 UI-01 统一鉴权）；未登录 401（AC-13）。本页无按钮级差异（皆只读 + 跳转）。
- **数据权限**：工作台为全局视图，聚合所有**已注册产品**的进件（`loadProjects()` 不按登录人过滤）；孤儿 project_id（未注册产品的历史进件）不计入。若后续要按登录人负责范围过滤，属数据权限扩展，标 `NEEDS-HUMAN`，本版全局聚合。
- **只读 / 无副作用**：`/api/overview` 为 GET、幂等、不改库、无并发写。
- **时间格式**：展示时间统一 `yyyy-MM-dd HH:mm`（共享 `fmtTime`）（AC-11，全局规范 §12）。
- **降级不阻塞**：无进件/无产品时接口 200，前端各区块空态占位、不白屏（AC-14）。
- **留痕**：无（只读）。
