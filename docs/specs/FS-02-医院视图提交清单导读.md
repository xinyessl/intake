## 0. 一句话
现场实施工程师（`impl`，`field`→`impl` 已归一）在**医院视图**里，用一个**医院下拉选择器**（数据源 = 当前账号 `accounts.sites`）单选一家我负责的医院，看该医院提交记录，可**按批次 / 按类型**切换 + 按**全部子项目（子系统）**下拉筛选，并对**可删**记录做软删除——且**绝不看到别的账号负责医院的数据**。落地 = `public/field.html`（实施端 SPA，外壳/登录门/维度切换由 FS-01 承载，本域只负责其左侧清单区）+ `server.mjs` 新增 `GET /api/field/submissions`（按当前账号 `sites` 收敛）与 `POST /api/intake-delete`（软删）。

## 3. 关键机制口径（贯穿两条子 spec 的共同约定）

### 3.1 医院视图数据权限收敛机制（硬约束 · 本机制核心）
- 所有查询/删除以**当前登录用户 `accounts.sites`（医院）+ `accounts.projects`（产品）** 为边界，**服务端过滤，忽略前端越权传参**（PRD §3.3/§7）。复用 `server.mjs` 的 `intake-list` 收敛：`!isAdmin(user) && projects.length && !projects.includes(project)` → 空；`!isAdmin(user) && sites.length` → `filter(sites.includes(site))`。
- `hospitalId` 越权（不在 sites）→ 裁掉该项 / 或 403（FS-21 AC-11），不泄露。
- 判断"是否现场账号（非管理员）"用 `isAdmin(u)` 取反（`isAdmin` 含 `admin/dev`）——现场 impl/pm 走收敛分支（与 `docs/lessons.md` isAdmin 条一致）。
- **🔴 关联缺口（FS-01 修）**：`server.mjs scopedForField` 仍判 `role==='field'`（归一后永不命中）——本机制**依赖 FS-01 修复该缺口**；若走 `/api/intake-list` 则已被其内联收敛保护，不受该缺口影响；若新增 `/api/field/submissions` 必须用 `isAdmin`+sites 收敛（**不得**复用有缺口的 `scopedForField`）。
- **软删同守收敛**：`POST /api/intake-delete` 现场账号只能删**自己名下 sites** 的记录（`site∉sites`→403），管理员不限。

### 3.2 视图重组口径（按类型 / 按批次 / 子系统筛选）
- **按类型分组（P1）**：前端/服务端按 `intakes.type ∈ {requirement,bug,consult}` 三桶重组（原型 `buildTypeView`），**跨批次**聚合，组标题「需求/BUG/咨询」；空组不渲染（无空白占位组）。子系统过滤对两视图同一数据源同样生效。
- **按批次分组（P2 · 依赖 BP-01）**：按「产品 · 周批次」分组（`f-batch`/`f-bhd`/`f-item`）；BP-01 `batches` 表未建前**降级**——端点返回 `{degraded:true,groups:[],msg}`，前端保持「按批次」选中不回弹 + 空态提示，不强切回按类型、不混入按类型数据（2026-07-23 裁决：由「回弹按类型 + 提示条」改为「保持按批次 + 空态提示」，解决"按钮没切过去内容却变了"的割裂观感）。
- **子项目下拉分组（按产品分组的子系统）**：`{ 产品名(projects.name): [子系统, …] }`，只列**当前所选医院已上产品**的子系统。子系统集合来源（2026-07-23 裁决「运营端维护到子系统 + 各自版本」· 向后兼容）：
  - **新形状**产品（`customers.products[i]` 含 `subsystems:[{name,version}]`）→ 只列该医院实际维护的子系统并带各自 `version`；
  - **旧形状**产品（`{project,version}`，无 `subsystems`）→ 兜底列 `projects[].subsystems[].name` 全集（现状不变），`version` 预填产品级 `version`。
  - 台账未录该医院 / 该医院无 `products` → 下拉空 + 提示「运营端未维护该医院上线产品」。**依赖医院名一致**（`accounts.sites` ↔ `customers.name` ↔ `intakes.site`）。
- **子系统「双键」显示**（同 FS-03 `sysLabel`）：下拉/标签显**中文 `desc`**（`desc||name`，如 `audit→审方`），而过滤/传参值一律用**英文/原始 `name`**（匹配 `intakes.subsystem`）——`subLabel(name→desc)` 供选中标签/空态显中文；**过滤值别改成 desc**，否则筛不出数据。

### 3.5 通用约定
- **即选即查**：子系统下拉、按批次/按类型切换均为「选择型」→ 选中即刷新（全局规范⑪），不需再点查询按钮。
- **时间格式**：所有展示时间统一 `yyyy-MM-dd HH:mm`（全局规范⑫），空值占位 `—`；纯日期无时间部分可只到 `yyyy-MM-dd`。用共享格式化函数。
- **只读/写边界**：清单查看为**只读**（不产生新写/留痕）；本机制**唯一写操作 = 软删**（FS-21 F 组，落 `data` JSON 假删 + `history` 留痕，不加库列）。提交留痕在 FS-04，下载/改版本留痕在 FS-05。
- **空态**：无医院 / 某医院无记录 / 某类型无记录（空组不渲染）均有占位或不渲染，不报错。
- **双域名同步约束**：`/api/intake-delete` 已在 `FIELD_OK` + `FS08_FIELD_API` 双白名单；新增 field 端点须同步进两处（对齐 FS-08，避免 field 域被 `originGate` 判 deny 隐蔽挂掉）。
