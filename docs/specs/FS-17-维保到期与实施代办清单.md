## 1. 用户故事 / 目标
作为**现场实施工程师（`impl`）**，我要：① 随时看到我负责医院的**维保到期日**（临期标黄、过期标红）并能**编辑回写**，且到期前后能在**待办铃铛**里收到提醒——以便主动续保、不漏期；② 在把某院某产品升到目标版本时，看到一份**统一的「实施任务清单」**（来自产品代码、发包时审核冻结的批次快照）逐条勾选完成，并**合并下载升级 SQL** 手动执行——以便部署过程有清单可循、可追溯完成度。

- 维保回写**认医院名 `site`**（同 `customer-version`，`customers.json` 无对外 `customerId` 契约）；同值幂等；格式须 `yyyy-MM-dd`。
- 实施清单**当前以「读批次快照 `batch.deployPlan`」为准**（不再实时读代码、不再实施侧跨版累积）；完成度键 = **(批次×医院)**。
- **SQL 系统不执行**，仅列出让实施手动跑、勾「已执行」单点，并可合并成单 `.sql` 下载。

## 2. 范围
**包含：**
- **维保到期回写 + 待办提醒（原 §I）**：
  - 医院视图归档条常驻显示 `maintainEnd`（到期 ≤15 天标黄、已过期标红）+「编辑」入口；`POST /api/customer-maintain {site,maintainEnd}` 回写 + 追加 `maintainLog[]`；同值幂等；格式校验（前后端双层）；越权 403（判定同 `customer-version`）。
  - `GET /api/notifications` 追加维保项（`daysLeft ≤ 15` 含负数=已过期持续提醒）；可见范围管理员=全部、impl=仅 `user.sites`；`count` 含维保项，维保项排工单前。
- **更新包实施任务清单（原 §K · 当前实现 · 读批次快照）**：
  - 「按批次视图」某批次有目标版本 `pkgVersion` → 卡内渲染更新计划块：头显 `现场 <from> → 目标 <to>` + 进度 `N/M` + 累积实施任务逐条（checkbox）+ 末尾「执行数据库升级 SQL」单点（有 SQL 才加）+「下载合并 SQL」按钮。
  - `GET /api/field/update-plan?site=&batchId=` 读 `batch.deployPlan` 快照渲染；`POST /api/field/update-toggle {site,batchId,kind:'task'|'sql',itemId,done}` 勾选（写 `updateProgress[batchId]`）；`GET /api/field/update-sql-merged?site=&batchId=` 读快照冻结 SQL 正文合并下载。
  - 批次未审核部署清单 → `noManifest:true` + 友好提示，不报错。

**不包含（划归它处）：**
- 按批次视图容器 / 更新包下载 / 下载翻转 / 闭环 tag → **FS-15**。

- 部署清单草稿拉取（`batch-deploy-draft`）/ 审核存快照（`batch-deploy-save`）/ 产品代码 `docs/deploy.json` 读取器 / 累积算法本体 → **BP-01 §I/§K**（本条只**读**冻结后的 `batch.deployPlan` 快照 + 记完成度）。

### I. 维保到期回写 + 待办提醒（🆕 2026-07-31）
- **AC-1**（原 I/AC-25）Given 实施端登录 impl，When 在「医院视图」选中一家自己负责的医院，Then 归档条常驻显示「维保到期：yyyy-MM-dd」（`data/customers.json` 该医院 `maintainEnd`，空显「未设置」）+「编辑」入口；到期 ≤15 天标黄、已过期标红。
- **AC-2**（原 I/AC-26）Given impl 点归档条「维保到期·编辑」或待办里的维保项，When 弹编辑并填合法 `yyyy-MM-dd` → `POST /api/customer-maintain {site,maintainEnd}`，Then 回写 `customers.json` 该医院 `maintainEnd`（`c(maintainEnd,20)`）+ 追加 `maintainLog[]`（谁/何时/哪院/`from→to`）+ 刷新前端归档条与待办。
- **AC-3**（原 I/AC-27 · 幂等）Given 新值 === 旧值，When 调 `POST /api/customer-maintain`，Then **幂等**：不写文件、不追加 `maintainLog`，仍返回 `{ok:true}`。
- **AC-4**（原 I/AC-28）Given `maintainEnd` 不匹配 `/^\d{4}-\d{2}-\d{2}$/`（含空值，本期不支持清空）或 `site` 不存在，When 调 `POST /api/customer-maintain`，Then 400（前后端双层日期格式校验）。
- **AC-5**（原 I/AC-29 · 越权）Given 越权：`site` 不在当前 impl 账号 `sites`（`isAdmin` 不限），When 调 `POST /api/customer-maintain`，Then 403，不改文件（判定写法与 `customer-version` 完全一致）。
- **AC-6**（原 I/AC-30 · 待办提醒）Given `GET /api/notifications`，When 某医院 `maintainEnd` 合法且 `daysLeft ≤ 15`（`daysLeft = 到期日 − 今天`，date-only 归一避免时区 off-by-one；含负数=已过期，过期后持续提醒），Then 追加维保项 `{kind:'maintain', site, maintainEnd, daysLeft}`；`daysLeft = 15` 命中、`= 16` 不命中、`< 0` 命中。可见范围：**管理员=全部医院；impl=仅 `user.sites`**。工单项增 `kind:'ticket'`；维保项（尤其已过期）排在工单前更醒目；`count` 含维保项；`items.slice(0,50)`。
- **AC-7**（原 I/AC-31）Given 运营管理员铃铛读 `/api/notifications`，When 有临期/过期医院，Then `count` 含维保项（后台外壳 `shell.js` inbox 角标计数随之增加）；`customers.html` 列表「维保到期」列临期黄/过期红高亮（可选增强）。

## 4. 接口契约
> 统一前缀 `/api`；实施端接口按**当前登录用户 `sites`** 收敛，忽略前端越权传参；返回体 `{ok/error}` 或 `{...data}`。**新增端点均需显式加入 `server.mjs` 的 `FIELD_OK` 白名单**，且服务层再按 `sites` 二次校验。

### 4.1 🆕 维保到期回写 —— `POST /api/customer-maintain`（镜像 customer-version）
```
POST /api/customer-maintain
body: { "site":"XX医院", "maintainEnd":"2027-03-31" }   // 认医院名(site)，同 customer-version（customers.json 无对外 customerId 契约）
  →  200 { "ok":true }                                   // 幂等（新值===旧值）：不写不留痕，直接返回
     200 { "ok":true, "customer":{...}, "customers":[custWithTicketCount...] }   // 变更：回写 + 留痕，返回整表方便前端刷新（对齐 customer-save 风格）
     400 { "ok":false, "error":"维保到期日期格式须为 yyyy-MM-dd" | "客户不存在" | "缺少医院" }
     403 { "ok":false, "error":"无权改该医院维保到期" }   // 越权：site 不在当前账号 sites（isAdmin 不限）
```
- `maintainEnd` 必须匹配 `/^\d{4}-\d{2}-\d{2}$/`（本期**不支持清空**，空→400）；越权判定与 `customer-version` **完全一致**。
- 变更则：`c.maintainEnd = maintainEnd.slice(0,20)`（对齐 `normCustomer` `pick('maintainEnd',20)` 长度）；`c.maintainLog.push({by:user.username, at:nowStamp(), site, from:旧值, to:maintainEnd})`（≤200 条截断）；`c.updatedAt=nowStamp()`；`saveCustomers(list)`。
- 端点须进 `FIELD_OK` **和** `FS08_FIELD_API` 两个 Set（同 §4 双域名同步约束）。

### 4.2 🆕 更新计划（读批次快照）—— `GET /api/field/update-plan?site=&batchId=`

```
GET /api/field/update-plan?site=甲医院&batchId=B-01     // 管理员+field·按 sites 越权收敛·越权 site 403

           "tasks":[ {id,title,desc,done,by,at} ],
           "sql":{ hasSql,scriptCount,done,by,at },
           "taskDone","taskTotal", "noManifest":false }
     200 { "ok":true, "noManifest":true, "noManifestHint":"该批次尚未审核部署清单（运营审核确认后会出现在这里）", "tasks":[], "sql":{hasSql:false} }
     400 缺 batchId ; 404 批次不存在 ; 403 越权 site
```

### 4.3 🆕 清单勾选 —— `POST /api/field/update-toggle`
```
POST /api/field/update-toggle
body: { "site":"甲医院", "batchId":"B-01", "kind":"task"|"sql", "itemId":"kwsb:t1"(task需·sql忽略), "done":true }
  →  200 { "ok":true, "changed":bool, "site","batchId","kind","itemId","done" }

```

### 4.4 🆕 合并 SQL 下载 —— `GET /api/field/update-sql-merged?site=&batchId=`

```
GET /api/field/update-sql-merged?site=甲医院&batchId=B-01     // 管理员+field·按 sites 收敛
```

## 5. 数据契约
> **对照真实结构核对，禁止臆造列名。**

### 5.1 维保到期（真实已有 · 文件存）—— `data/customers.json`
- 该医院 `maintainEnd`（纯日期 `yyyy-MM-dd`，`c(maintainEnd,20)` / `normCustomer` `pick('maintainEnd',20)`）+ `maintainLog:[{by,at,site,from,to}]`（≤200 条截断）+ `updatedAt`。**绝不迁 MySQL、绝不建 customers 表**（CU-01 定文件存）。
- 医院-账号边界 = `accounts.sites`（JSON）；越权判定同 `customer-version`。

### 5.2 更新计划完成度（快照左连 · 文件存）—— `data/customers.json` `updateProgress`
- **完成度键 = (批次×医院)**：`customer.updateProgress[batchId] = { tasks:{ [itemId]:{done,by,at} }, sqlBundle:{done,by,at} }`（tasks 桶 + sqlBundle 单点隔离，假删幂等）。快照 tasks/sql 无 version 概念（AC-10）。
- **数据来源 = 批次快照**：`batch.deployPlan = { from, to, tasks:[{id,title,desc}], sql:[{id,title,desc,content(冻结正文)}], reviewedBy, reviewedAt }`（发包时运营审核冻结，存 `data/batches.json`，主实现 BP-01 §K/§5.5）；本条**只读**快照 + 记完成度，不写 `deployPlan`。

### 5.3 待办提醒（复用 `/api/notifications`，禁臆造）

## 6. 业务规则 / 非功能
- **数据权限（硬约束）**：维保回写/清单勾选/更新计划**全部限当前 `impl` 账号 `sites`**（`isAdmin` 不限）；越权 `forbidden`(403)（判定与 `customer-version` 一致）。待办可见范围按 sites 收敛（管理员=全部）。
- **按钮级权限**：现场端仅维保编辑、清单勾选、合并 SQL 下载；无部署清单草稿/审核入口（运营 BP-01）。新写端点默认**不进** `LINK_OK`。
- **幂等**：① 维保回写同值不写不留痕（AC-3）；② 清单勾选同态不重复写（`changed=false`，AC-9/10）；③ 假删（`done=false` 删键）。
- **SQL 系统不执行**：仅列出让实施手动跑、勾「已执行」单点（整区间一个完成态·非逐脚本），并可合并成单 `.sql` 下载。
- **留痕**：维保回写记 `maintainLog[]`（谁/何时/哪院/from→to）；清单完成记 `updateProgress[batchId]` 的 `{done,by,at}`。
- **时间格式**：维保为纯日期 `yyyy-MM-dd`；清单完成人时间展示 `yyyy-MM-dd HH:mm`，空值 `—`。文案避 FS-01 A6 禁词。
- **降级**：批次未审核部署清单 → `noManifest:true` + 友好提示，不报错（AC-10）。

**NEEDS-HUMAN（本条待裁决）：** 无（维保规则、清单快照来源均已由用户拍板并落地；J 组已废弃删码）。
