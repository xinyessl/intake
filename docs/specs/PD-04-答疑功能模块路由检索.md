## 1. 用户故事 / 目标
作为**实施/运营**，现在 consult 答疑用 `specSearch`（chunk 级 IDF 检索，跨全部 spec）常召回跑题内容、AI 据此答偏。我要**先按提问路由到功能模块，命中才在该模块内检索**；**未命中直接明确返回「无相关说明书描述」、不让 AI 凭感觉编**。路由方式是**纯代码打分 + 阈值**（确定性、不调 AI）。

## 2. 范围
- 包含：
  - 产品仓里有**结构化功能模块地图** `docs/specs/00-功能模块地图.json`（当前仅 pwrs 有）时，consult 走「specSearch 底座 + 路由加成」链路（**修订**：路由不再排他替换 specSearch，见 AC-8）。
  - 三层路由（纯代码打分 + 阈值·确定性）：tier-1 `questionRoutes`（优先，带 answerFacts/mustNotConfuse）> tier-3 精确名反查（`indexes.configs/tables/apis`，tier-1 未过阈值时兜底）> tier-2 `specs` 兜底。
  - 命中 → 读 route 的 `primaryRefs`(+`contextRefs`) 指定 spec 章节 + 注入 `answerFacts`（经确认事实·最高优置顶）+ `mustNotConfuse`（负向提示），**并在其上叠加 specSearch 底座（去重、cap≤7）**一起喂 consultSystem（不再排他替换 specSearch，防路由错配盖掉更强的 specSearch 内容）。
  - miss（路由未命中）→ **specSearch 底座仍作事实源**：首条 IDF 得分 ≥ `SPEC_MIN_RELEVANT` → 照常喂 specSearch（由提示词功能级覆盖判定答/说没覆盖）；**只有 specSearch 也弱/空**（首条 < 阈值 或 无结果）且（非 deep，或 deep 但 codeSearch 也无命中）→ **不调模型答实质内容**，返回固定话术；正常收尾、落库该轮。
  - 深入思考(源码)单独走：spec 模块没命中，deep 仍可 `codeSearch` 查源码；命中源码 → 照常用源码答。
  - 路由决策（matched/tier/routeId/score/topN 或 miss）并入 PD-03 的 `retrieval.routing`，检索诊断页可见「路由到哪个模块 / 或未命中」；回放端点同样接入。
- 不包含：
  - **无地图产品严格保持现状**（完全走原 `specSearch`，行为不变——向后兼容是硬要求）。
  - 不改 specSearch/kbRetrieve/codeSearch 的打分逻辑；不改 consult 的 kbRefs / 首片段门控 / 刷新恢复 / PD-03 retrieval 捕获（均在其上叠加）。
  - 不做历史 consult 回溯路由（仅新对话起生效）。
  - answerFacts/mustNotConfuse 的注入**不改 PD-02 默认模板**（作为 specHits 内容 + system 追加段注入，走既有 `{{specExcerpts}}`；DEFAULT_PROMPTS 不变）。

## 3. 验收标准（AC · Given-When-Then · 每条必须可自动化判定）
- **AC-1** Given 产品仓有 `docs/specs/00-功能模块地图.json` When consult 提问 Then `loadModuleMap` 解析成功、走 `routeQuestion` 路由（有地图才走新链路）。
- **AC-2** 三层路由 + 阈值（`ROUTE_MATCH_MIN`）：
  - tier-1：query 整串命中某 `alias` → 强 bonus（`ROUTE_ALIAS_BONUS`）命中；关键词 IDF 加权重叠 ≥ 阈值也命中；完全无关 → miss。
  - tier-3：tier-1 未过阈值时，query 含 `indexes.configs/tables/apis` 精确名（≥4 字子串）→ 直接强命中（`ROUTE_EXACT_TIER3`）对应 spec。
  - tier-2：tier-1/tier-3 都没到 → 对 `specs[]`（title+module+summary+headings）打分取最高，≥ 阈值命中，否则 miss。
- **AC-3** 命中 → `loadRouteContext` 读 `primaryRefs`(+`contextRefs`) 指定章节（按 `anchor`/`section` 标题定位截取；定位不到退回该 spec 前段，不空返、不越界到下一同级标题）；`answerFacts` 作「经确认事实」段**置顶**注入（文本自带「优先据此、勿臆造」）、`mustNotConfuse` 作负向提示注入 system。命中时 `specHits` = 路由精选事实（置前）+ specSearch 底座（`specSearchScored` 结果，去重、cap≤7），answerFacts 仍最高优。
- **AC-4** miss 且 **specSearch 底座也弱/空**（首条 < `SPEC_MIN_RELEVANT` 或无结果）且（非 deep，或 deep 但 codeSearch 无命中）→ **不调模型**，SSE 返回固定话术「该问题在《<产品名>》说明书里没有找到相关描述，建议转成工单或联系开发确认。」，`done` 正常收尾、落库该轮。
- **AC-8（回归·路由错配不该盖掉强 specSearch）** Given 提问的正确内容在某 spec 里、specSearch 给它高分（如「系统激活失败」→「系统激活注册」spec 得 16.5）When 路由**错配/未过阈值**（如误命中/弱重叠到「HIS 收费失败」）Then 组装 `specHits` 仍包含该强 specSearch 内容 → **不判「没覆盖」，据 spec 底座作答**。判据：`assembleConsultSpecHits`——① 路由命中：`specHits` 含 specSearch 强匹配（去重合并）；② 路由未命中但 specSearch 首条 ≥ `SPEC_MIN_RELEVANT`：`noSpec=false`、喂 specSearch（不 miss）；③ 路由未命中且 specSearch 首条 < 阈值/空：`noSpec=true`（走 AC-4 固定话术）。`retrieval.routing` 额外透出 `usedSpecSearch`/`specTop`/`specMinRelevant` 供回放调阈值。
- **AC-5** miss 但 deep 且 codeSearch 有命中 → 源码单独走，照常用源码答（走既有 deep 分支）。
- **AC-6** **无地图产品**（`loadModuleMap` 返 null）→ consult 完全走原 `specSearch`，行为不变（向后兼容，有测试断言）。
- **AC-7** 路由决策并入 `retrieval.routing`（`{enabled,matched,tier,score,routeId,routeTitle,threshold,topN}`），consult 落库 + 回放端点均接入；无地图 → `routing.enabled=false`。

## 4. 接口契约
- **复用** `POST /api/consult`（FS-04/FS-06，SSE）：入参不变（`project/version/subsystem/messages/images/deep/convId`）。行为增量：有地图→路由；miss 固定话术不经模型；`retrieval.routing` 随 chat 末条 assistant 落库（不新增库列，同 PD-03 JSON 附加字段范式）。
- **复用** `POST /api/retrieval-replay`（PD-03，admin）：出参增 `retrieval.routing` + `routeContext`（命中时的 specHits/mustNotConfuse），供调阈值对照。
- 无新增端点、无新增库表/列。

## 5. 数据契约
- **无库表变更**。功能模块地图 = 产品仓文件 `docs/specs/00-功能模块地图.json`（**只读**，走现有 `specSources`/`specFileText` 读法 + 10min 缓存）；结构见「①本项目信息」相关说明（`questionRoutes[]`/`specs[]`/`indexes{configs,tables,apis}`/`tree[]`）。
- `retrieval.routing` 随 consult 记录 `chat[].retrieval.routing` 落 `intakes.chat`（JSON 列附加字段，老记录 undefined 天然兼容）。

## 6. 业务规则 / 非功能
- 路由 = **纯代码打分 + 阈值（确定性）**，不调 AI。阈值为**可配置常量**：`ROUTE_MATCH_MIN=3.0`、`ROUTE_ALIAS_BONUS=6.0`、`ROUTE_EXACT_TIER3=8.0`、`SPEC_MIN_RELEVANT=8.0`（specSearch 底座首条 IDF 得分阈值，路由未命中时决定「据 spec 作答」还是「miss 固定话术」；部署后在 pwrs 上用回放调准）。
- **specSearch 始终作底座、路由作「精选事实」加成**（修复架构缺陷）：路由不再排他替换 specSearch——弱/错的路由命中不会盖掉更强的 specSearch 内容。`answerFacts` 仍最高优置顶注入；specSearch 强匹配一起喂给模型，覆盖判定交给提示词。
- tier-1 优先于 tier-3：questionRoute 命中即带出人工 answerFacts（高价值），tier-3 仅作 tier-1 未过阈值的兜底（否则「order_instruction 怎么配」会被 tier-3 抢走、丢 answerFacts）。
- 章节定位鲁棒性：`anchor` slug 近似 + 标题文本双路匹配，定位不到退回前段，绝不臆造。
- 权限/留痕：consult 权限/留痕不变（FS-06 authGate）；retrieval-replay 仍 admin 域（PD-03）。
- answerFacts/mustNotConfuse 注入**不改 PD-02 默认模板**（DEFAULT_PROMPTS 逐字不变，仍走 `{{specExcerpts}}` + system 追加段）。
