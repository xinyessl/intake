## 1. 用户故事 / 目标
作为**运营（admin）**，我要对已定档的批次**【导出按子系统的开发清单】**（描述清晰、带截图、可下载 Markdown/JSON）发给开发去 steward 做；开发打包、外部测试验收通过后，我以**管理身份【上传包】**（填包版本/说明/地址）把批次转「可下载」，并让**覆盖工单同步转「已出包」+ 回写 `resolution.fixedVersion`**——以便**开发清单可直接落地、上传包一步转态、工单交付进度自动跟随**。

## 2. 范围
**包含：**
- **导出开发清单**（出站产物）：按子系统分组，每条含 工单号/类型/标题/**描述(清晰)**/验收标准/AI 初判/涉及医院(跨院合并后哪些医院提了)/现场版本/**截图(media)**。形态：`format=json`（结构化）+ `format=md`（可下载 Markdown，含图链接，为主产物）。
- **上传包（管理身份）**：admin 填包版本 `pkgVersion` / 更新说明 `releaseNote` / 包地址 `artifactUrl` / 上传时间 `releaseTime` → 批次转 `可下载`，覆盖工单转「已出包」+ `resolution.fixedVersion=pkgVersion`。

**不包含（划归它处）：**
- 定档建批 / 列表详情 / 双向编辑 → `BP-02`；批次闭环 / 排期 → `BP-04`；发包后审核部署清单快照 → `BP-05`（上传包**之后**运营再审核冻结部署清单，属 BP-05）。
- **steward 自动对接三接口**（拉清单 / 回写进度 / 自动发包）→ **future**（BP-01 导读 §8·NH-6），本期不实现；本 spec 出站仅「导出开发清单」，入站仅「人工上传包」。
- 现场端下载 / 改版本 / 逐单验证 → `FS-05`。

## 3. 验收标准（AC · Given-When-Then · 每条必须可自动化判定）

### D. 导出开发清单（出站产物 · 按子系统 · 带截图）
- **AC-9** Given 批次 `B-01` 覆盖工单跨子系统 kwsb（2 条）/adr（1 条），When 运营 `GET /api/batch-checklist?id=B-01`（或 `?format=md` 导出），Then 返回**按子系统分组**的开发清单，每条含：`ticketId / type(BUG|需求) / title / desc(描述清晰) / accept(验收标准) / ai(AI初判) / hospitals(涉及医院·跨院合并后哪些医院提了) / siteVersion(现场版本) / media(截图链接数组)`；结构形如 `{batch, product, groups:[{subsystem, items:[...]}]}`。
- **AC-10** Given 同上，When 以 `?format=md` 请求，Then 返回**可下载 Markdown**（`Content-Type: text/markdown` 或 `text/plain`；含子系统分节标题、每单描述、验收标准、截图为图片链接 `![](url)`），内容与 AC-9 的结构数据一致；无截图的单不报错（截图段留空）。
- **AC-11** Given 工单含 `media[]`（截图），When 导出清单，Then 每条截图以可访问链接（复用现有 `/api/intake-media` 或存储 URL）出现在该单条目下；`media` 为空时该单不含截图段但其余字段完整。

### E. 上传包（管理身份 → 可下载）
- **AC-12** Given 批次 `B-01` 为「开发中」、当前登录为 admin，When `POST /api/batch-release {id:"B-01", pkgVersion:"v2.1", releaseNote:"...", artifactUrl:"https://.../psp-2.1.zip"}`，Then 批次落包信息（`pkgVersion/releaseNote/artifactUrl` + `releaseTime`=服务器当前时间）、状态转 `可下载`；且其覆盖工单经 `intake-transition` 推进到「已出包」、工单 `resolution.fixedVersion = pkgVersion`。
- **AC-13** Given 当前登录**非 admin**（如 impl），When `POST /api/batch-release`，Then 返回 `403 forbidden`（`authGate` deny-by-default + `isAdmin` 校验），不改任何数据。
- **AC-14** Given 批次**非「开发中」**（已「可下载」或「已交付」），When `POST /api/batch-release`，Then 返回 `{ok:false, error:"仅开发中批次可上传包"}`（防重复上传/非法态；如需换包由后续增强定，标 NH-3）。
- **AC-15** Given `pkgVersion` 为空 或 `artifactUrl` 为空，When `POST /api/batch-release`，Then 返回 `{ok:false, error:"包版本/包地址必填"}`（400），不改数据。

## 4. 接口契约
> 统一前缀 `/api`；运营侧批次接口按 admin 鉴权（`isAdmin`，`authGate` deny-by-default）。出参统一 `{ok/error}` 或 `{...data}`。

### 4.1 本 spec 端点
| 端点 | 方法 | 入参 | 出参 | 说明 |
|---|---|---|---|---|
| `/api/batch-checklist` | GET | `id`, `format?(json\|md)` | `{batch,product,groups:[...]}` 或 Markdown | **导出开发清单**（按子系统 · 带截图）；`format=md` 返回可下载 Markdown（AC-9/10/11） |
| `/api/batch-release` | POST | `{id, pkgVersion, releaseNote, artifactUrl}` | `{ok, item}` / `{ok:false,error}` | **管理身份上传包**：填包信息 + 转 `可下载` + 覆盖工单转「已出包」+ `fixedVersion` 回写（AC-12~15） |

### 4.2 复用现有端点（不改语义）
| 方法 | 路径 | 用途 | 出处 |
|---|---|---|---|
| POST | `/api/intake-transition` | 上传包时覆盖工单 `→已出包`（带 `resolution.fixedVersion`） | server.mjs（`TRANSITIONS['开发中']=['已出包']` 已存在） |
| GET | `/api/intake-detail` | 导清单时读工单 desc/accept/ai/media/version | server.mjs |
| GET | `/api/intake-media` | 导出清单截图链接来源 | server.mjs |
| GET | `/api/customers` | 导清单 `siteVersion` + 涉及医院 | server.mjs L919 |

> **NH-2 导出清单产物形态**：本 spec 定为 `format=json`（结构化）+ `format=md`（可下载 Markdown，含图链接）；是否还需服务器落文件、导 zip 打包截图、或对接 steward 目录 → 实现期定，倾向先「可下载 Markdown / JSON」（AC-10）。
> **NH-3 换包/撤包**：批次上传包后能否换包/撤回（`可下载→开发中`）本期未定，AC-14 先拒绝重复上传；换包机制 → 后续增强。

## 5. 数据契约
> 🚫 已核真库 `db.mjs`：批次落文件存 `data/batches.json`（NH-4 已裁决 A）；工单侧复用 `intakes.data JSON`（不加库列）。

### 5.1 批次存储 —— 上传包相关字段（`data/batches.json`）
```jsonc
{ "batches": [ {
  "id":"B-01", "product":"psp", "status":"可下载",   // 上传包后 开发中→可下载
  "pkgVersion":"v2.1",             // 包版本（上传包时填；前占位 "-"）
  "releaseNote":"...",             // 更新说明（上传包时填）
  "artifactUrl":"https://.../psp-2.1.zip", // 包地址（URL；上传包时填）
  "releaseTime":"2026-07-24 15:00",// 上传/发包时间（上传包时记，服务器当前时间）
  "history":[ { "action":"release", "by":"<username>", "at":"...", "note":"批次B-01发包(v2.1)" } ]
} ] }
```

### 5.2 工单状态联动（复用真库 `TRANSITIONS`，不重造流转）
真库 `LIFECYCLE`/`TRANSITIONS`（server.mjs L519-525，逐字核对）：`已立项→开发中；开发中→已出包；已出包→待验证；待验证→已重开/已关闭`。
- **上传包**（`/api/batch-release`）：对每条覆盖工单推进到 **`已出包`** + 回写 `resolution.fixedVersion=pkgVersion`。
- **NH-5 跳态·已裁决（选型 A）**：覆盖工单多停在 `已立项`，到 `已出包` 本需 `已立项→开发中→已出包` 两跳。batch-release 作为**批次驱动的系统动作直接置态 `已出包`**（在工单对象上补 `history` 留痕 `by:'系统·发包' byRole:'system' note:'批次B-xx发包(pkgVersion)'` + `resolution.fixedVersion` + `saveIntake` 穿透 data JSON），**不走中间 `开发中` 态**——避免中间态噪音，且不重造流转（复用工单对象 + saveIntake，与 `intake-transition` 留痕格式一致）。已在 `已出包/待验证/已关闭` 的工单幂等 skip，不阻断整批。

### 5.3 导清单数据源（复用，禁臆造）
- `desc/accept/ai/media`：读工单 `intakes.data`（`desc/reqDesc`、`accept`、`opinion/analysis`、`media[]`）。
- `hospitals`（涉及医院）：由覆盖工单 `intakes.site` 去重派生（真库 `intakes.site VARCHAR(80)`）。
- `siteVersion`（现场版本）：读 `data/customers.json` 该医院该产品版本——**真实形状**（server.mjs L188-215）：`products:[{project, subsystems:[{name,version}]}]`（新）或 `{project,version}`（旧兼容）。导清单按子系统时取对应子系统版本，旧形状兜底产品级 version，空显 `—`。
- 截图链接复用现有 `/api/intake-media` 或存储 URL。

## 6. 业务规则 / 非功能
- **数据权限 / 按钮级权限**：导清单 / 上传包为**运营 admin** 操作（`isAdmin`，含遗留 `dev`）；非 admin（impl）不可，`authGate` deny-by-default + 服务层 `isAdmin` 双层（AC-13）。**`pm` → NH-1**。
- **状态流转合法性**：上传包仅允许「开发中」批次（AC-14 拒非法态）；上传包后 `开发中→可下载`（不可跨级/回退）。
- **操作留痕**：上传包写 `batches.history`（`{action:'release',by,at,note}`）；工单联动复用工单 `history`（系统·发包留痕，见 §5.2）。
- **幂等**：上传包对非「开发中」批次拒绝（AC-14）；覆盖工单批量 transition 对已在目标态者 skip 不报错。
- **导清单描述清晰 + 带截图**：每单必含 `desc`、`accept`、`media`；缺字段不报错但清单标注（如「（无验收标准）」）；无截图单不含截图段但其余字段完整（AC-11）。
- **展示格式**：上传时间统一 `yyyy-MM-dd HH:mm`（全局 UI 规范⑫），空值 `—`。

**NEEDS-HUMAN**（引用 BP-01 导读 §8）：**NH-1** pm 权限；**NH-2** 导出清单产物形态（默认 md/json 可下载）；**NH-3** 换包/撤包（AC-14 先拒绝重复上传）；**NH-5** 上传包工单跳态（已裁决 选型 A）；**NH-6** steward 自动回写包=future。
