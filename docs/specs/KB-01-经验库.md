## 1. 用户故事 / 目标
作为**运营/产品经理**，我要沉淀「问题 → 解法」条目并按产品/子系统/来源/关键词检索、增删改，以便工单/答疑解决时能自动/手动积累经验，并在后续答疑与 AI 分析时按关键词召回（RAG）作为依据，越攒越准。

## 2. 范围
- **包含（运营后台「经验库」页 `public/kb.html` · 臻遴原型为前端基线，用 theme.css 组件类）**：
  - 顶部工具行筛选（`.filter-bar`/`.filter-grid` 四列）：产品下拉（`#fProduct`）、子系统下拉（`#fSub`，随产品联动）、来源下拉（`#fSource`：全部/人工/答疑/自动）、关键词搜索框（`#fKw`，回车触发、匹配 问题/解法/子系统/模块）、右上「新增经验」按钮（`.page-header-actions`）。
  - 条目呈现为**表格**（`.data-table` 六列）：问题/现象（`q` 加粗 + 一行解法预览 `kbPrev`）、子系统（`subLabel` 中文优先）、来源（徽标 `.tag.src-{manual,consult,auto}` + 自动沉淀附来源工单号）、标签（前 2 个 `.tag.tag-gray`）、时间（`at`，`fmtTime` → `yyyy-MM-dd HH:mm`）、操作（查看/编辑/删除 `.row-action`）。整行/「查看」→查看抽屉。
  - **分页**（`.pagination`）：底部「共 N 条」计数（带筛选附「筛出 M」）+ 每页 8/20/50 切换 + `.pager` 页码。
  - **查看抽屉**（`#viewDrawer`）：来源徽标 + 来源工单 chip、问题标题、模块/更新时间、Markdown 渲染的完整解法（`.evidence-quote`）、标签；底部「编辑」按钮衔接编辑抽屉。
  - 新增/编辑抽屉（`#editDrawer`）：问题（必填，`maxlength=100` + 字数计数 `n/100`）、子系统（下拉，选填）、模块（选填）、来源（下拉 人工/答疑/自动）、来源工单（选填，映射 `from_ref`）、标签（逗号分隔）、解法/答复（Markdown，必填）。**产品取自页面 `#fProduct`（抽屉内无产品选择器）**。抽屉的「来源」下拉 + 「来源工单」输入经 `kb-save` 已具备的 `source`/`from_ref` 入参落库（AC-8b，向后兼容）。
  - 消费方点出：**工单解决（→已回复 / →已关闭）自动沉淀**、答疑「解决了」一键沉淀（`kb-from-consult`）、答疑/分析检索召回（`kbSearch`）。
- **不包含**：
  - RAG 召回算法本身的改造（沿用现有 `kbSearch`，本 spec 只声明它为消费方，不改其实现）。
  - 工单流转 / 答疑对话本身的 spec（分属 TK / 答疑 spec，本 spec 只覆盖它们触发的**沉淀写入**行为）。
  - 经验条目的多产品跨项目聚合（KB 按 `project_id` 隔离，本 spec 维持单产品维度）。

## 3. 验收标准（AC · Given-When-Then · 每条必须可自动化判定）

### 列表与筛选（前端事实源 = 臻遴原型 `admin/knowledge.html`，落成 `public/kb.html`，用 theme.css 组件类）
- **AC-1（列表加载 · 表格渲染）** Given 某产品下已有若干 `kb_entries` When 打开经验库页并选中该产品 Then 按 `created_at`（内存 `at`）顺序渲染 `.data-table` 行；每行六列：问题（`q` 加粗 `.cell-strong` + 一行解法预览 `kbPrev(a)` `.cell-sub`）、子系统（`subLabel`：中文描述优先，否则子系统名，无则「—」）、来源（徽标 `.tag.src-{manual,consult,auto}` + 自动沉淀附来源工单号 `.cell-sub`）、标签（前 2 个 `.tag.tag-gray`）、时间（`at`，`fmtTime` → `yyyy-MM-dd HH:mm`）、操作（查看/编辑/删除 `.row-action`）；分页栏「共 N 条」计数 = 当前产品条目总数（带筛选时附「（筛出 M）」）。**注：re-target 原型 = 六列表格 + 查看抽屉（非部署旧手风琴）。**
- **AC-2（来源徽标映射）** Given 条目内存 `from`（列表数据源）由库列派生 When 渲染来源徽标 Then `srcKind(from)` 映射为 `manual→「人工」`(`.src-manual` 灰底)、`consult→「答疑」`(`.src-consult` 紫底)、其余（工单 id / auto，即自动沉淀）→`「自动」`(`.src-auto` 靛蓝底)；自动沉淀且 `from` 为工单 id 时行内附来源工单号。**注：徽标文案自动沉淀显示「自动」，配色用 theme.css token（`.tag` + `.src-*`）；库列 `source` 仍为 `manual`/`consult`/`auto`。**
- **AC-3（子系统中文展示）** Given 条目 `subsystem` 存的是子系统名（与产品 `subsystems[].name` 对齐，来自 `projects.subsystems` JSON 的 `name`/`desc`）When 渲染子系统列 / 筛选下拉 / 抽屉下拉 Then 用 `subLabel`（有 `desc` 中文描述则显示描述、否则显示 `name`），下拉 `value` 用 `name`（与落库一致）；产品筛选变更时子系统下拉联动为该产品的 `subsystems`。
- **AC-4（选择型筛选即选即查）** Given 列表已加载 When 修改「产品」下拉 Then `@change` 联动刷新子系统下拉候选、清空其它筛选并重新 `loadKB` 拉该产品条目；When 修改「子系统」或「来源」下拉 Then `@change` 立即重置到第 1 页 + `render` 本地过滤重渲。**注：re-target 原型 = 含「来源」筛选下拉（全部/人工/答疑/自动，对齐 `srcKind`）。**
- **AC-5（关键词搜索 · 回车触发）** Given 关键词自由文本框 When 按 Enter Then 按「问题 `q` 或 解法 `a` 或 子系统 或 模块 包含关键词」（大小写不敏感）本地过滤、重置到第 1 页并重渲。**注：re-target 原型 + 全局规范 #11 = 自由文本框回车触发（非即输即查），匹配范围含解法/子系统/模块。**
- **AC-6（产品切换清空过滤）** 页面无独立「重置」按钮；切换「产品」下拉时自动清空 子系统/来源/关键词 三项过滤并回到第 1 页；用户亦可手动把各下拉选回「全部」、清空关键词框回车。
- **AC-7（空态 + 分页）** Given 当前产品无条目或筛选后无匹配 When 渲染 Then 显示空态（`.empty`：未选产品「先在上方选择产品」；有产品无条目「该产品暂无经验条目」+ 描述；有条目但筛选无匹配「没有匹配的经验条目」）；有条目时按每页 8/20/50（`#pageSize`）分页，`.pager` 上/下页 + 页码，切页/切每页数正确。**注：re-target 原型 = 恢复 8/20/50 分页。**

### 新增
- **AC-8（新增成功）** Given 打开「新增经验」抽屉，填写问题（`q`）、解法（`a`）、可选 子系统/模块/标签/来源/来源工单（产品取自页面 `#fProduct`）When 点保存 Then `POST /api/kb-save` 成功，`at=服务器当前时间戳（yyyy-MM-dd HH:mm）`、`tags` 为数组，列表刷新后出现该条且计数 +1；抽屉「来源」缺省选「人工」（`source=manual`）、不填来源工单时 `from='manual'`。**注：re-target 原型 = 抽屉暴露「来源」下拉（人工/答疑/自动）+「来源工单」输入，经 `kb-save` 已具备的 `source`/`from_ref` 入参落库（AC-8b）；产品仍取页面下拉。**
- **AC-8b（kb-save 微扩接受 source/from_ref · 本单增量·NH 已裁决）** Given 消费方（或未来抽屉扩展）调 `POST /api/kb-save` 带可选 `source`（`manual`/`consult`/`auto`）和/或 `from_ref`（来源工单 id）When 保存 Then 服务端经 `kbFromOf(source, from_ref)` 归一为内存 `from`，`replaceKB` 据此落库：`source∈{manual,consult}`→库 `source`=同名、`from_ref`=同名；带工单 `from_ref`（非 manual/consult）→库 `source='auto'`、`from_ref`=工单 id（对齐自动沉淀口径）；`source='auto'` 无工单→`from_ref='auto'`；**两者都不传时行为与旧实现完全一致（`from='manual'`）**，向后兼容。
- **AC-9（必填校验）** Given 新增抽屉「问题」或「解法」为空 When 点保存 Then 前端阻断并给出「问题和解法都要填」提示（`.msg-box` 红字），不发请求；即便绕过前端直调 `/api/kb-save`，服务端在 `q` 或 `a` 为空时返回 `{ok:false,error:'问题和解法都要填'}`（HTTP 400）。
- **AC-10（长度约束）** Given 新增/编辑抽屉 When 输入 Then 前端问题框 `#edQ` 加 `maxlength=100` + 字数计数 `n/100`；服务端对 `q` 截断到 400、`a` 截断到 2000（对齐现有 `kb-save` 实现，不改列宽约束）。**注：re-target 原型 = 恢复问题框 `maxlength=100` + `n/100` 计数（纵深仍以服务端截断为准）。**

### 编辑
- **AC-11（编辑回填 + 保存）** Given 某条目 When 点行内「编辑」（或查看抽屉底部「编辑」）Then 抽屉标题为「编辑经验」并回填 问题/子系统/模块/来源/来源工单/标签/解法（`openEdit` 回填）；改后保存调用 `POST /api/kb-save`（带该条 `id`）Then 服务端按 `id` 原地更新（保留 `at`/`id`；来源随抽屉「来源」下拉/来源工单经 `source`/`from_ref` 派生），列表刷新反映新值，计数不变。
- **AC-12（查看抽屉 + 衔接编辑）** Given 某行 When 点整行或「查看」Then 打开 `#viewDrawer`，显示 来源徽标/来源工单 chip + 问题标题 + 模块·更新时间 + Markdown 渲染完整解法（`.evidence-quote`）+ 标签；底部「编辑」按钮关闭查看抽屉并以该 `id` 打开编辑抽屉回填。**注：re-target 原型 = 独立查看抽屉（自实现 open/close，部署 shell.js 无 UI.openDrawer）。**

### 删除
- **AC-13（删除条目）** Given 某条目 When 点行内「删除」并在 `uiConfirm`（ui.js 共享二次确认弹窗，`danger:true`）确认 Then `POST /api/kb-delete`（带 `project`+`id`）成功，该条从列表移除、计数 -1；取消（`uiConfirm` 返回 false）则不发请求、不变更。**注：部署二次确认用共享 `uiConfirm`（非页面内自带 mask 弹窗）。**

### 自动沉淀（消费方 / 写入方）
- **AC-14（工单解决自动沉淀）** Given 某工单经 `POST /api/intake-transition` 流转到 `已回复` 或 `已关闭` 且能抽取到解法（`resolution.note`/`fixedVersion`、或末条 dev 回复、或 `opinion`/`analysis.detail`）When 流转成功 Then 触发 `kbAddFromIntake`，向该产品 KB 追加一条内存 `from=<工单id>`（库列 `source='auto'`、`from_ref=工单id`；列表来源徽标 `.src.auto` 显示「自动」）、`subsystem`/`module` 取自工单，接口响应带 `kbSunk:true`。
- **AC-15（自动沉淀去重）** Given 同一工单已沉淀过（KB 中存在 `from=<该工单id>` 的条目）When 再次流转到已回复/已关闭 Then `kbAddFromIntake` 不重复插入，返回 `kbSunk:false`，条目数不变。
- **AC-16（答疑一键沉淀）** Given 答疑对话中有一问一答 When 调用 `POST /api/kb-from-consult`（带 `project`+`q`+`a`）Then 追加一条 `from='consult'`（列表来源列显示「答疑」）、`subsystem`/`module` 空、`tags` 空；`q`/`a` 任一为空时返回 `{ok:false}`（HTTP 400）。
- **AC-17（答疑检索召回 · 消费方）** Given 该产品 KB 有条目 When 答疑/分析走 `kbSearch(projId, query, n)` Then 按「中文 bigram + 英文词」关键词重叠打分召回 Top-N（无匹配返回空数组），命中项以「问：q / 答：a」形式拼入答疑系统提示（`consultSystem`）供 AI 引用——本 spec 声明其为经验库的消费方，KB 写入的 `q/a/subsystem/module/tags` 即其召回语料。

## 4. 接口契约
沿用 intake_bak **现有真实端点**（`docs/P0-数据模型对账与接口清单.md §A.4「经验库」`），**均为已实现、复用**，本 spec 不新增端点：

| 端点 | 方法 | 入参 | 出参 | 说明 |
|---|---|---|---|---|
| `/api/kb-list` | GET | `project`（产品 id） | `{entries:[{id,q,a,subsystem,module,tags[],from,at}]}` | 列出该产品全部条目（按 `created_at` 序，来自缓存 `loadKB`）。产品不存在时返回空数组。 |
| `/api/kb-save` | POST | `{project,id?,q,a,subsystem,module,tags[], source?, from_ref?}` | `{ok,entries[]}` / `{ok:false,error}` | 无 `id`=新增（缺省 `from='manual'`、`at=nowStamp()`）；有 `id`=按 id 原地更新（保留 `from`/`at`）。`q` 截 400、`a` 截 2000。`q`/`a` 空 → 400。**KB-01 微扩**：可选 `source`(`manual`/`consult`/`auto`)、`from_ref`(来源工单 id) → 经 `kbFromOf` 归一为内存 `from`，`replaceKB` 据此派生库列 `source`/`from_ref`（不传时行为不变，向后兼容）。 |
| `/api/kb-delete` | POST | `{project,id}` | `{ok,entries[]}` | 从该产品 KB 移除指定 id。 |
| `/api/kb-from-consult` | POST | `{project,q,a}` | `{ok}` / `{ok:false,error}` | 答疑一键沉淀，`from='consult'`、`at=nowStamp()`，`subsystem`/`module` 空、`tags` 空。 |
| `/api/intake-transition` | POST | `{project,id,to,...}` | `{ok,lifecycle,kbSunk,...}` | **消费/触发方**：`to∈{已回复,已关闭}` 时调用 `kbAddFromIntake` 自动沉淀，响应 `kbSunk` 表示是否新沉淀。（工单流转本体属 TK spec，此处仅声明其触发 KB 写入。） |

**内部函数（非 HTTP，供实现对照，勿臆造签名）**：
- `kbFromOf(source, from_ref)`：**KB-01 微扩**（`server.mjs`）——把 kb-save 传入的 `source`/`from_ref` 归一为内存 `from`：`source∈{manual,consult}`→返回同名；有工单 `from_ref`（非 manual/consult）→返回工单 id（截 60，派生 `auto`+`from_ref=工单id`）；`source='auto'` 无工单→返回 `'auto'`；都无→返回 `''`（调用方回退 `'manual'`）。
- `kbAddFromIntake(proj, e)`：工单解决自动沉淀（`server.mjs`）——抽解法 `intakeSolution(e)`（`resolution.note`/`fixedVersion` → 末条 dev 回复 → `opinion` → `analysis.detail`）；`q=title(+desc/reqDesc)`；`from=e.id` 去重；写库 `source='auto'`。
- `kbSearch(projId, query, n=5)`：答疑/分析召回（`server.mjs`）——中文 bigram + 英文词重叠打分，Top-N；消费方为 `consultSystem`（答疑系统提示拼装）。
- `saveKB / loadKB / replaceKB`：缓存 + 落库 + `data/kb/<projId>.json` 镜像。

## 5. 数据契约
**表 `kb_entries`（对照 `intake_bak/db.mjs` 真实 DDL，禁止臆造）**：

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | VARCHAR(40) PK | 条目 id（新增 `'k'+randomBytes(4).hex`；自动沉淀同规则） |
| `project_id` | VARCHAR(40) NOT NULL | 所属产品；`INDEX idx_kb_proj` |
| `q` | TEXT | **问题/现象**（原型字段 `question`；写库前截 400） |
| `a` | TEXT | **解法/答复**（原型字段 `answer`，支持 Markdown；写库前截 2000） |
| `subsystem` | VARCHAR(80) | 中文子系统名（对齐产品 `subsystems[].name`/`desc`） |
| `module` | VARCHAR(120) | 模块 |
| `tags` | JSON | 标签数组 |
| `source` | VARCHAR(20) | 写库枚举 `manual`/`consult`/`auto`（见 `replaceKB`：`from∈{manual,consult}` 原样，否则写 `auto`）；UI 映射 `manual→人工`、`consult→答疑`、`auto→BUG沉淀` |
| `from_ref` | VARCHAR(60) | 来源引用：手动=`'manual'`、答疑=`'consult'`、自动沉淀=**来源工单 id**（去重键，对应原型 `sourceTicket` 的实际来源） |
| `created_at` | VARCHAR(20) | 创建时间戳（内存对象里映射为 `at`）；UI 用共享 `fmtTime` 展示为 `yyyy-MM-dd HH:mm` |

> **字段名对账要点（易错，务必按真实列名）**：问题=`q`（非 `question`）、解法=`a`（非 `answer`）、来源=`source`、来源引用/工单=`from_ref`（内存对象里是 `from`；`created_at` 内存里是 `at`）。原型 mock 的 `question/answer/sourceTicket/time` 只是展示层命名，落库须映射到 `q/a/from_ref/created_at`。
> **`source` 与 `from_ref` 关系**：`replaceKB` 依据内存对象 `from` 派生 `source`（`manual`/`consult` 原样、其余 `auto`），并把原始 `from` 存入 `from_ref`。故来源列渲染读 `source`；来源工单号读 `from_ref`（当其为工单 id 时）。

> ✅ **NEEDS-HUMAN（已按推荐默认裁决 · KB-01 落地）**：
> 1. ~~人工新增是否可手选 source？~~ **裁决：`kb-save` 后端微扩，接受可选 `source` 入参并落库**（`manual`/`consult`/`auto`），列已存在、向后兼容（不传恒 `manual`，与旧实现一致）。**部署抽屉 UI 暂不加「来源」下拉**（人工场景仍恒 `manual`）；`source` 入参供消费方 / 未来 UI 扩展使用。
> 2. ~~人工条目是否可关联来源工单？~~ **裁决：`kb-save` 微扩接受可选 `from_ref`（来源工单 id）**，经 `kbFromOf` 归一后 `replaceKB` 落 `from_ref`+派生 `source='auto'`（对齐自动沉淀口径）。**部署抽屉 UI 暂不加「来源工单」输入框**；入参供消费方使用。

## 6. 业务规则 / 非功能
- **数据权限**：经验库按 `project_id` 隔离；后台经验库页属管理端功能——依 `authGate`，管理员（`admin`）全放行；`/api/kb-from-consult` 现场侧（`FIELD_OK`）亦放行（答疑沉淀）；`kb-list`/`kb-save`/`kb-delete` 现场侧不在 `FIELD_OK`，仅管理端可用（对齐现有实现）。
- **按钮级权限**：新增/编辑/删除按钮仅管理端可见可用（前端按角色 + 后端 `authGate` 双层）。
- **留痕**：自动沉淀以 `from_ref=工单id` 天然可回溯来源工单；工单流转的 `history[]` 留痕属工单侧（TK spec）。经验条目本身无独立操作日志（现有实现如此）。
- **幂等**：自动沉淀按 `from_ref==工单id` 去重（AC-15），同一工单重复流转不重复沉淀；`kb-save` 带 `id` 为原地更新（幂等更新）。
- **并发**：`saveKB` 采用「整表 `replaceKB`（DELETE + 批量 INSERT）+ 内存缓存整体替换」——高并发下存在覆盖窗口，沿用现有实现（本 spec 不改；若后续暴露丢写再评估行级 upsert）。
- **校验**：问题 ≤100（前端）/ 服务端截 400；解法必填、服务端截 2000；`tags` 前端按 `,`/`，` 分隔去空。
- **展示格式**：所有时间列/详情用共享 `fmtTime` → `yyyy-MM-dd HH:mm`；解法用受控 Markdown 渲染（仅 `**加粗**`、`` `code` ``、换行；先转义 `&`/`<` 再渲染，防 XSS，对齐原型 `md()`）。
- **界面基线**：**逐条以臻遴原型 `admin/knowledge.html` 为前端基线**（2026-07-21 re-target；数据/接口仍接真实端点、字段=真实列）。落地：外壳由 UI-01 提供（`data-shell="admin" data-nav="kb"`，引 `theme.css/shell.js`，`data-content-layout="list"` 内滚），页面内容用 theme.css 组件类；`.page-header` 右上「新增经验」按钮 + `.filter-bar` 四筛选（产品/子系统/来源/关键词回车）+ `.data-table` 六列表格 + `.pagination` 8/20/50 分页；来源徽标 `.tag.src-{manual,consult,auto}`（自动沉淀文案「自动」）；查看抽屉 `#viewDrawer`（Markdown `.evidence-quote`）+ 编辑抽屉 `#editDrawer`（问题带 `maxlength=100`+`n/100` 计数、子系统/模块/来源/来源工单/标签/解法，无产品选择器）；抽屉 open/close **自实现**（部署 shell.js 无 `UI.openDrawer`）；删除走共享 `uiConfirm`、成功/失败用自建 `toast`（theme.css `.toast`）。选择型下拉即选即查，关键词框回车触发。
