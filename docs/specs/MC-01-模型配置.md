## 1. 用户故事 / 目标
作为运营后台管理员，我要配置供答疑 / 进件 / 分析用的 AI 直连模型 API（一个主模型 + 若干备用），并能测试各模型连通性、随时切换主备，以便主模型异常 / 超时时 AI 自动按序切到备用、答疑不中断，同时 API Key 只留在服务本机、页面永不泄漏明文。

## 3. 验收标准（AC · Given-When-Then · 每条必须可自动化判定）

> 接口全部复用现有真实端点：`GET /api/model-config`、`POST /api/model-config-save`、`POST /api/model-test`。列表 = 主（primary=true）在前 + 备用按序。

- **AC-1（记录列表展示 · 整宽 data-table）** Given `data/model-api.json` 已配置 1 主 2 备 When 管理员打开模型配置页并请求 `GET /api/model-config` Then 返回 `{models:[{provider,model,baseUrl,keyMask,configured,primary}...]}`，`#modelBody` 按序渲染出 N 行 `<tr>`（**整宽 `.data-table`，含 `<thead>` 7 列**：主/备、模型、服务商、API Key、接口地址、连通状态、操作）；每行含：主/备标签（`primary=true` → `.tag.tag-primary`「主」，其余 `.tag.tag-gray`「备」）、模型名（`.mono.cell-strong`，空则显「默认 <默认模型名>」）、服务商（`m.provider==='openai'`→「OpenAI 兼容」、否则「Anthropic」）、Key 掩码（`.mono`）、接口地址（`.mono`，空则「官方默认地址」）、连通状态（`.tag`，未测显「未测试」`.tag-gray`）、行内操作（`.row-actions`：设为主/测试连通/编辑/删除）；表头右上「当前主模型：<主模型名>」（`#primaryName`）。

- **AC-2（Key 掩码回传，明文不泄漏）** Given 某模型 `apiKey="sk-ant-api03-abcd...7f2a"`（长度 > 8）When 调 `GET /api/model-config` Then 该模型 `keyMask` 为 `maskKey` 掩码格式（前 4 位 + `……` + 后 4 位，如 `sk-a……7f2a`），**响应体中不出现完整 apiKey 明文**；掩码渲染在「API Key」列。Key 长度 ≤ 8 且非空时掩码为 `已配置`，空 Key 掩码为空串。

- **AC-3（新增模型，主/备落地）** Given 管理员在**抽屉**选服务商 `OpenAI 兼容`、填模型名 `deepseek-chat`、接口地址 `https://api.deepseek.com`、API Key `sk-xxx`、主/备选「备用」（点「保存」）When 保存（`POST /api/model-config-save`，body `{models:[...现有, {provider:"openai",model:"deepseek-chat",baseUrl:"https://api.deepseek.com",apiKey:"sk-xxx",primary:false}]}`）Then 返回 `{ok:true, models:[...]}`，`data/model-api.json` 的 `backups` 追加该模型（真实 apiKey 落文件）；再次 `GET /api/model-config` 列表含该备用模型且 `configured=true`、`keyMask` 为掩码。〔前端提交前对每条 `apiKey` 传 `_newKey`（本次新填明文）或空 + `mask`（保留旧值）；主/备由抽屉单选 → `primary`。首次新增（列表原为空）若选「备用」，后端 `models.find(primary)||models[0]` 仍会把它取为主，前端应引导首个为主。〕

- **AC-4（编辑保留旧 Key：空 Key 用掩码解析）** Given 某模型已存 `apiKey="sk-real-old"`（掩码由 `maskKey` 生成）When 管理员点行内「编辑」打开抽屉、**API Key 输入框留空**（占位「留空 = 保留已配置的 Key」）、改模型名后点「保存」（body 该模型 `apiKey=""`、携带 `mask=<该模型掩码>`）Then 服务端 `resolveKey` 用 `mask` 在旧模型集（旧主 + 旧 backups）里按 `maskKey` 匹配回 `sk-real-old`，保存后文件里该模型 apiKey 仍为 `sk-real-old`（**旧 Key 不丢失**）；模型名更新为新值。**反例**：留空 Key + 一个匹配不到任何旧模型的 mask → 该模型 `resolveKey` 得空 → 被 `filter(m=>m.apiKey)` 过滤掉（不落文件）。

- **AC-5（设为主，唯一主 + 原主降备）** Given 当前主为 M-A、M-B 为备 When 管理员对 M-B 点行内「设为主」（保存时 M-B `primary=true`、M-A `primary=false`）Then `POST /api/model-config-save` 后 `data/model-api.json` 顶层字段（provider/model/baseUrl/apiKey）= M-B，`backups` 含 M-A；`GET /api/model-config` 返回 `models[0]` 为 M-B 且 `primary=true`，**有且仅有一个 `primary=true`**；页面主标签移到 M-B 行、「当前主模型」`#primaryName` 显示 M-B 的 model。

- **AC-6（删除模型）** Given 列表有 1 主 2 备 When 管理员点某备用行内「删除」→ `uiConfirm('删除这个模型？',{danger:true})` 确认后，前端从 `MODELS` 移除该条并保存（提交的 `models` 数组不含该模型）Then 保存后 `data/model-api.json` 不再含该模型，`GET /api/model-config` 列表相应减少一条；若删除的是主模型，则剩余模型中第一个（前端：`if(MODELS.length&&!MODELS.some(m=>m.primary))MODELS[0].primary=true`；后端：`models.find(m=>m.primary)||models[0]`）成为新主，仍保持唯一主。

- **AC-7（测试连通 · 单行）** Given 某模型已配 Key When 管理员点该行「测试连通」（`POST /api/model-test`，body `{provider,model,baseUrl,apiKey:_newKey||'',mask:keyMask}`）Then 服务端用 `callModelOnce` 真实发一次 `只回复两个字：正常`（maxTokens=16）的请求：成功返回 `{ok:true, reply, model}`，该行「连通状态」列显示「正常」`.tag-success`；失败返回 `{ok:false, error}`（HTTP 仍 200），显示「异常」`.tag-danger` + toast 报错。测试时若未传明文 Key 则用 `mask` 解析回旧 Key（同 AC-4 逻辑）。〔连通状态是测试后会话内内存态、非常驻列、不落文件；不显示延迟毫秒。〕

- **AC-8（测试连通 · 抽屉内）** Given 抽屉已填 Key（新增态）或正在编辑某已配 Key 的记录 When 点抽屉「测试连通」按钮 Then 调 `POST /api/model-test`（编辑态携带该记录 `mask` 以解析旧 Key），结果 toast 反馈（成功显模型名 + 回复，失败显 error）。〔**无原型的「全部测试连通」批量按钮**——只有「抽屉内测试」+「每行测试」两处；批量测试本期不做（见 §2「不包含」）。〕

- **AC-9（主挂自动切备用 · failover）** Given 配置为主 M-A + 备 M-B（均有 Key）When 运行时 AI 调用（答疑/进件/分析走 `callModel`/`callModelStream`）且主 M-A 请求失败或超时 Then `modelCandidates` 生成的候选按序 `[M-A, M-B]`，M-A 抛错后自动重试 M-B；仅当**还未吐出任何内容且非用户主动中止**时才切（流式），已开始输出则不重复切；全部候选失败才向上抛错。候选只保留配了 `apiKey` 的模型。

- **AC-10（必填校验 · 抽屉表单）** Given 管理员在抽屉**新增态** When **模型名 / 接口地址 / API Key 任一为空**即点「保存」Then 前端阻断保存、对应输入框标 `.invalid` + toast 提示（模型名「请填写模型名」、接口地址「请填写接口地址」、Key「请填写 API Key」）。〔**编辑态** Key 可留空表示保留旧值（见 AC-4），若该记录本就无 Key 且仍留空则提示「该模型还没有 Key，请填」。服务商为 segment（`Anthropic`/`OpenAI 兼容`，默认 `anthropic`）；主/备由抽屉单选。**校验对齐原型抽屉**——原型抽屉将模型名/接口地址/Key 均设为必填（`*`）；本页按原型：新增时三者皆必填。〕

- **AC-11（安全：Key 不入库、只存文件）** Given 任意保存 / 读取模型配置 When 检查持久化 Then apiKey 明文只写入本机文件 `data/model-api.json`（`writeModelCfg`），**MySQL 任何表均不含模型 apiKey**；`GET /api/model-config` / `model-config-save` 返回体只含 `keyMask`，不含明文；`data/model-api.json` 应在 `.gitignore`（本地不入库、不进 git）。

- **AC-12（阿里云 Qwen 3.8 Anthropic 兼容）** Given 候选同时满足 `provider="anthropic"`、模型名为 `qwen3.8` 系列且 `baseUrl` 主机属于 `aliyuncs.com` When `callModelOnce` 发非流式请求或 `callModelStreamOnce` 发流式请求 Then Anthropic `/v1/messages` 请求体自动带 `thinking:{type:"disabled"}`，避免响应额度只产出 `thinking` 块而没有可显示 `text`；普通 Claude/Anthropic、非阿里云 Qwen 及 OpenAI 兼容候选的请求体保持原样，不自动添加 `thinking`。

## 4. 接口契约

复用现有真实端点（`server.mjs` L817–851），**不新增接口**。

### 4.1 `GET /api/model-config` —— 读配置（Key 掩码回传）
出参：
```jsonc
{
  "models": [
    { "provider": "anthropic", "model": "claude-opus-4-8", "baseUrl": "https://api.anthropic.com",
      "keyMask": "sk-a……7f2a", "configured": true, "primary": true },
    { "provider": "openai", "model": "deepseek-chat", "baseUrl": "https://api.deepseek.com",
      "keyMask": "sk-x……3d9c", "configured": true, "primary": false }
  ],
  // 兼容旧单模型字段（主模型）：
  "provider": "anthropic", "model": "claude-opus-4-8", "baseUrl": "https://api.anthropic.com",
  "keyMask": "sk-a……7f2a", "configured": true
}
```
- `models[0].primary=true` 为主，其余按序为备用；**明文 apiKey 绝不出现**。

### 4.2 `POST /api/model-config-save` —— 存配置
入参：
```jsonc
{ "models": [
  { "provider": "anthropic", "model": "...", "baseUrl": "...", "apiKey": "sk-...或空", "mask": "sk-a……7f2a", "primary": true },
  { "provider": "openai",    "model": "...", "baseUrl": "...", "apiKey": "",             "mask": "sk-x……3d9c", "primary": false }
] }
```
- **空 apiKey 保留旧值**：`resolveKey(m)` 取 `m.apiKey.trim()`；为空则用 `m.mask` 在旧模型集（旧主 + 旧 backups）里按 `maskKey` 匹配回旧明文。过滤掉最终无 Key 的模型。
- 落地：`primary`（或 `models[0]`）→ 顶层 `{provider,model,baseUrl,apiKey}`；其余 → `backups[]`。写 `data/model-api.json`。
- 出参：`{ "ok": true, "models": [...同 4.1 视图...] }`。models 为空数组时写 `{provider:'anthropic'}` 清空并回 `{ok:true, models:[]}`。

### 4.3 `POST /api/model-test` —— 测试连通
入参：`{ "provider", "model", "baseUrl", "apiKey"(可空), "mask"(可选) }`
- 空 apiKey + 有 mask → 同 4.2 用 mask 解析回旧 Key。
- 服务端 `callModelOnce`，messages=`[{role:"user",content:"只回复两个字：正常"}]`，maxTokens=16。
- 出参：成功 `{ "ok": true, "reply": "正常", "model": "claude-opus-4-8" }`；失败 `{ "ok": false, "error": "<msg>" }`（HTTP 仍 200）。

### 4.4 供应商适配（`callModelOnce` / `callModelStreamOnce`）
- `provider="anthropic"`：POST `baseUrl + /v1/messages`，头 `x-api-key` + `anthropic-version: 2023-06-01`；默认 baseUrl `https://api.anthropic.com`、默认 model `claude-sonnet-4-6`。
- 阿里云 `aliyuncs.com` 上的 Anthropic 兼容 `qwen3.8*` 候选：流式与非流式请求体都追加 `thinking:{type:"disabled"}`；该兼容项由 provider、模型名和 URL 主机三项共同判定，不影响 Claude 或其它 Anthropic 端点。
- `provider="openai"`（UI 文案「OpenAI 兼容」）：POST `baseUrl + /v1/chat/completions`，头 `Authorization: Bearer <key>`；默认 baseUrl `https://api.openai.com`、默认 model `gpt-4o`。〔**映射已核对无误**：抽屉 segment 的 `data-v` 存储码 `anthropic`/`openai`，中文只是文案，落文件为英文码、非中文（已由 mc-01.test.mjs「provider 映射」用例连真机文件断言）；列表回显 `m.provider==='openai'?'OpenAI 兼容':'Anthropic'`。〕

## 6. 业务规则 / 非功能
- **唯一主**：任意时刻 `primary=true` 的模型有且仅有一个；设为主时原主自动降备（前端保存前重置所有 `primary`，再置目标为主）。models 非空但无人标 primary 时取 `models[0]` 为主。
- **failover 顺序**：候选 = `[主, ...backups]` 且只保留有 apiKey 的；`callModel` 顺序重试（非流式：任一失败切下一个）；`callModelStream`：仅在未产出内容且非用户中止时切，已开始输出不切，避免重复。流式内置 90s 超时。
- **思考模式兼容边界**：仅 Anthropic provider + 阿里云主机 + `qwen3.8*` 三项同时命中时禁用 thinking；不得按 provider 单项全局禁用，避免误伤 Claude 备用模型。
- **Key 安全（硬规则）**：apiKey 明文只存 `data/model-api.json`；接口出参只含掩码；**不写任何 MySQL 表、不进 git**；编辑留空 Key 用掩码解析保留旧值，避免"编辑一次就把 Key 抹了"。
- **校验**：新增——模型名 / 接口地址 / API Key 必填；编辑——模型名 / 接口地址 必填，API Key 可空（保留旧值）。服务商 ∈ {Anthropic→anthropic, OpenAI 兼容→openai}。
