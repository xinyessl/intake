## 1. 用户故事 / 目标
作为**现场实施工程师**（如账号 wanglong，负责若干医院），我要一个「全览」视图，用**卡片**给我一张个人全局图（医院维度 + 产品维度），以便一眼看清我负责的每家医院工单/版本/更新状态、以及每个产品跨院的分化与待发布/待更新，快速定位当下最该处理的事（尤其待验证、维保临期/过期、紧急工单）。

## 2. 范围
- 包含：
  - 现场端顶栏维度菜单新增「全览」入口（放最前，作个人落地页入口；默认 mode 仍是医院视图，不改默认）。
  - **医院维度卡**（每家我负责医院一张）：医院名 + 维保到期（临期黄/过期红/正常/无）、工单 4 阶段计数（待评审/开发中/待验证[高亮]/已关闭）、紧急工单角标、现场版本（各产品各子系统）、下次更新、待下载更新包数、最近一次更新；点卡片跳该院「医院视图」。
  - **产品维度卡**（每个我负责产品一张 · 跨院聚合总览）：产品名 + 医院数、工单总况（4 阶段 + 紧急）、各医院版本分布（按子系统分组：版本→哪些医院）、待发布/待更新提醒。
  - 新增只读端点 `GET /api/field/overview`，服务端按 `user.sites`+`user.projects` 收敛。
- 不包含：
  - 全览页内的编辑/操作（改版本/下载/验证仍走各自现有端点与视图，全览只读汇总）。
  - 新数据表 / 新库列（全部复用现有工单/批次/客户文件存与字段）。

## 3. 验收标准（AC · Given-When-Then）
- **AC-1** Given 现场账号登录，When 打开顶栏维度菜单，Then 看到「全览」项（在医院视图前、最上）；点击后隐藏左右分栏工作区、显示全宽「全览」面板，含「医院维度」「产品维度」两段带小标题的区块；默认进入实施端时 mode 仍为医院视图（不是全览）。
- **AC-2** 医院卡字段：Given 我负责医院 H，Then 卡上显示——① 维保到期：`≤30天` 标黄（临期）、已过期标红、正常正常色、无维保日期显占位；② 工单 4 阶段计数（待评审/开发中/待验证/已关闭），其中**待验证高亮**；③ 紧急工单数（`priority∈{紧急,高}` 且未关闭）>0 时红角标；④ 现场版本（仅我负责产品各子系统的 `custSubVersion`，中文名 + 版本）；⑤ 下次更新（覆盖本院、可下载/已交付、**本院尚未应用**[= 该批覆盖本院工单未全关闭，见 AC-9]的批次 → 显 `pkgVersion`+`scheduleDate`；无则「暂无」）；⑥ 待下载更新包数（覆盖本院、`status=可下载`、`downloadedBy` 不含我、本院尚未应用）；⑦ 最近一次更新（本院工单最大 `updatedAt`，无则占位）；⑧ 点卡片 → 切 mode=hosp 且选中该 hospitalId（复用现有医院视图逻辑）。
- **AC-3** 产品卡（跨院聚合）：Given 我负责产品 P，Then 卡上显示——① 产品名 + 我负责且装了该产品的医院数；② 工单总况（跨院聚合 4 阶段 + 紧急数）；③ 各医院版本分布（按子系统分组，每子系统下「版本→哪些医院」，让版本分化/落后医院一眼可见）；④ 待发布/待更新提醒（开发中未出包批次=「待发布」；可下载/已交付但有院未应用=「待更新 vX.Y」，列 {批次号, pkgVersion, 状态, scheduleDate, 覆盖我几家院}）。
- **AC-4** 服务端 `sites`+`projects` 收敛：Given 前端传越权 `site`/`project` 参数，When 调 `/api/field/overview`，Then 服务端**忽略前端传参**，一律按登录账号的 `user.sites`（`fieldSites`）+ `user.projects` 收敛（工单走 `listIntake(withConsult:false)`→`scopedForField`，批次走 `batchTicketsForUser`，均裁掉越权医院/别账号的单）；未登录返 401；管理员不受 sites 限制。
- **AC-5** 内部滚动：Given 全览卡片超出视口，When 滚动，Then 面板**自身内部滚动**（`#fOverview` flex:1;min-height:0;overflow:auto），外壳 100vh，**不出现 body 全局滚动条**。
- **AC-6**（阶段归并口径）Given 工单 lifecycle，Then 4 阶段归并与用户在提交清单/批次里看到的现场状态标签（`fieldStatusLabel`）**同源**：待评审←{待处理,已重开,分析中}；开发中←{已立项(已受理·排期),开发中}；待验证←{待验证}；已关闭←{已关闭,已交付(本包已含),已答复,暂缓,已驳回}。
- **AC-7**（维保天数无 off-by-one）Given 维保到期日，Then `daysLeft` 用 date-only 归一算整天差（`Date.UTC`），阈值 30 天：+30 临期、+31 正常、-1 已过期、今天到期=剩 0 天=临期。
- **AC-8**（空态）Given 无负责医院或无负责产品，Then 对应区块给友好占位（「尚未分配医院」/「尚未分配产品」），不报错、不空白崩。
- **AC-9**（「本院已应用某批」用工单生命周期判，非版本字符串相等）Given 某批次覆盖本院的工单**全部已关闭/已交付**（lifecycle∈{已关闭,已交付}），Then 视为本院已应用该批（口径同 `bumpSiteVersionForBatch`），**不再显「下次更新」/产品卡「待更新」**；即便现场版本号与包版本号不等（现场版本可能比包版本更高或带尾号，如 `2.8.260801-2` vs `2.8.260801-1`）也不误判。医院卡「待下载」只统计 `status=可下载`（不含已交付=已下发完）、`downloadedBy` 不含我、本院未应用的批次数。（回归：安吉县人民医院 B-01 已交付、覆盖 3 单全关闭、现场 pkb 高于包版本 → 全览不显「下次更新/待更新」。）

## 4. 接口契约

### GET /api/field/overview
- 鉴权：必须登录（现场 impl/pm/admin）；在 `FIELD_OK` + `FS08_FIELD_API` 双白名单（否则实施域 originGate deny）。未登录 → 401。
- 入参：无（**服务端不采信任何前端传参**，一律按 `user.sites`+`user.projects` 收敛）。
- 出参：
```jsonc
{
  "me": { "username": "wanglong", "name": "王龙", "siteCount": 3, "projectCount": 1 },
  "hospitals": [
    {
      "site": "安吉医院", "hospitalName": "安吉医院", "hasCustomer": true,
      "maintainEnd": "2026-08-20", "maintainDaysLeft": 10, "maintainStatus": "soon",   // normal|soon|expired|none
      "stages": { "review": 1, "dev": 0, "verify": 1, "closed": 1 }, "ticketTotal": 3, "urgent": 1,
      "versions": [ { "product": "hlyy", "productName": "合理用药系统", "subsystems": [ { "subsystem": "audit", "subsystemLabel": "审方", "version": "v2.8" } ] } ],
      "nextUpdate": { "batchId": "B-01", "product": "hlyy", "productName": "合理用药系统", "pkgVersion": "v2.9", "scheduleDate": "2026-08-15", "status": "可下载" },  // 无则 null
      "pendingDownload": 1,
      "lastUpdated": "2026-08-09 15:30"
    }
  ],
  "products": [
    {
      "product": "hlyy", "productName": "合理用药系统", "hospitalCount": 2,
      "stages": { "review": 1, "dev": 1, "verify": 1, "closed": 0 }, "ticketTotal": 3, "urgent": 2,
      "versionDist": [ { "subsystem": "audit", "subsystemLabel": "审方", "versions": [ { "version": "v2.8", "hospitals": ["安吉医院"] }, { "version": "v2.7", "hospitals": ["B院"] } ] } ],
      "reminders": [
        { "kind": "pending-release", "batchId": "B-10", "pkgVersion": "", "status": "开发中", "scheduleDate": "2026-08-20", "coverSites": 1 },
        { "kind": "pending-update",  "batchId": "B-11", "pkgVersion": "v2.9", "status": "可下载", "scheduleDate": "2026-08-18", "coverSites": 1 }
      ]
    }
  ]
}
```
- 时间字段（`lastUpdated`）返回既有 `yyyy-MM-dd HH:mm` 戳原样（前端按此格式展示）。
- 纯聚合逻辑在 `tools/fs-09-overview-logic.mjs`（`buildHospitalCards`/`buildProductCards`/`maintainStatus`/`stageOf`/`appliedToSite` 等，脱 DB 可单测）。
- 「本院已应用某批」由 `appliedToSite(mineTickets, site)` 判（覆盖本院工单全 lifecycle∈{已关闭,已交付}），端点侧给 `_mineTickets` 每条附派生 lifecycle（`e.lifecycle||deriveLifecycle(e)`，同 `/api/field/batches`）；**不用版本字符串相等**（见 AC-9）。

## 5. 数据契约
**不新增表/列**，全部复用现有（逐字段核对，禁止臆造）：
- 工单（`intakes` 表 + intake-store JSON，经 `listIntake`）：`site`（=医院名，与 customer.name 匹配）、`subsystem`（英文 key）、`priority`∈{紧急,高,中,低}、`lifecycle`（中文态）、`updatedAt`/`submittedAt`（`yyyy-MM-dd HH:mm`）、`project`。
- 客户（`data/customers.json`，文件存·prod）：`name`、`maintainEnd`（`yyyy-MM-dd`）、`products[].{project, subsystems:[{name,version}] | version}`；版本读法同 `custSubVersion(cust, productId, subsystem)`。
- 批次（`data/batches.json`，文件存）：`id`、`product`、`status`∈{开发中,可下载,已交付}、`pkgVersion`、`scheduleDate`、`ticketIds[]`、`downloadedBy[]`（username）。
- site↔customer 匹配一律**按医院名**（`c.name.trim()===site.trim()`，与 `custWithTicketCount`/`customer-version`/`bumpSiteVersionForBatch` 全库一致），**不是 id**。

## 6. 业务规则 / 非功能
- 数据权限：deny-by-default，服务端按 `user.sites`+`user.projects` 收敛，忽略前端越权传参；管理员（`isAdmin`，含遗留 `dev`）不受 sites 限制、按相关院/产品全景展示。
- 只读端点，无写副作用、无留痕需求（改版本/下载/验证仍走各自端点）。
- 阶段归并复用 `fieldStatusLabel`（单一事实源），不另写 lifecycle→阶段映射表。
- 维保天数 date-only 归一（无 off-by-one，见全局 lessons）。
- 内部滚动，无 body 全局滚动条（全局 UI 规范 #3）；卡片紧凑（规范 #5）；响应式网格 `minmax(320px,1fr)`。
- 卡片配色复用现场端 `.f-*` 设计语言（藏青 + theme.css token），不引新主题。

## 7. 测试要点
- 单元（纯逻辑 `tools/fs-09-overview.logic.test.mjs`）：阶段归并各桶、维保状态边界（过期/临期/正常/无 + ±1 天精确）、紧急计数（紧急/高 且未关闭）、版本读法两形状、医院卡派生（下次更新/待下载/最近更新/找不到 customer 仍出卡）、产品卡跨院聚合 + 版本分布分组 + 待发布/待更新、越权收敛（越权 site/project 不进卡）。
- 接线断言：端点存在 + 双白名单 + 按 sites+projects 收敛 + 复用现成 helper + site 按名匹配；field.html 全览入口/隐藏 workspace/内部滚动/两维度渲染/医院卡点击进院/待验证高亮/响应式网格/空态。
