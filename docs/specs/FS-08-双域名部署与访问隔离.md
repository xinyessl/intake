> **跨条决策（源自 `docs/specs/00-实施端-spec清单.md` §1 决策 D，2026-07-21 用户已裁决 · 本 spec 全程贯穿）：**
> - **两独立域名，共用后端 + 库**：上线后 **admin（运营后台）与 field（实施端）各用一个完全独立的域名**（如 `admin.example.com` / `field.example.com`），但**共用同一 `server.mjs` 进程 + 同一 MySQL 库**——现场工单同库直连进运营工单箱，**不做跨库/跨服务同步**。拆分只在 **web/域名层**。
> - **同源反代免 CORS**：两个 nginx vhost，各自 `location /api/` **反代到同一后端**（`http://127.0.0.1:5180`），浏览器视角**同源**（页面与其 `/api/*` 同域名）→ 免 CORS、cookie 正常发。
> - **域名层 deny-by-default**：field 域只暴露 `field.html`/`submit.html`/`assets` + `FIELD_OK`/`LINK_OK` 接口；admin 域只暴露后台页 + admin 接口。`server.mjs` **新增按 `Host` 的访问闸 + 根路由**（现无 Host 判定，需新增），取代现 `server.mjs:1099` 的按 role 分发 `/`→`console.html`/`submit.html`。
> - **cookie 天然隔离**：两独立域名各自 `intake_sess` cookie（`SameSite=Strict; Path=/`）互不可见 → 各域名各自登录会话，无需额外代码。
> - **免登录链接绝对地址**：`submit-link` 现返回相对路径 `/submit.html?token=`（两域名下打不通），需改返回 **field 域绝对地址**（配置项 `FIELD_ORIGIN`）。

## 1. 用户故事 / 目标
作为**运维 / 平台管理员**，我要把**运营后台（admin）与实施端（field）部署到两个完全独立的域名**、但**共用同一 `server.mjs` 后端与同一 MySQL 库**，以便：
- 两端各有清晰独立的入口域名（现场只知道 field 域、运营只知道 admin 域），互不暴露对方入口；
- 现场提交的工单**同库直连**进运营工单箱，**无需任何跨库/跨服务同步**（决策 D）；
- **域名层就构成访问隔离**（field 域拿不到后台页/后台接口，admin 域拿不到现场提交面之外的东西），不依赖前端隐藏、即便直接敲 URL 也越不了域；
- 两域名 cookie 天然隔离，各自登录会话互不串；
- 运营端为现场生成的免登录提交链接是 **field 域的绝对地址**，发出去能直接打开。

> 本条是实施端与运营端的**部署与访问隔离基座**：在 web/域名层把两端拆开（nginx 双 vhost 同源反代 + `server.mjs` 按 Host 的访问闸/根路由 + `submit-link` 绝对地址），**不拆进程、不拆库、工单不同步**。与 FS-01 的关系：FS-01 管「域内按 `accounts.sites` 数据隔离 + 登录门」，**本条管「按域名的访问隔离 + 路由 + 部署」**——两层隔离叠加（见 §2「不包含」与 §6 边界说明）。

## 2. 范围
**包含（web/域名层 · 部署 + `server.mjs` Host 路由改造 + 运维文档）：**
- **nginx 双 vhost（同源反代）**：两个独立域名各一个 `server` 块，各自 `server_name` + 证书；各自 `location /api/ { proxy_pass → 同一后端 }`（浏览器同源、免 CORS）；静态页各 vhost `root`/`proxy` 到同一 `public/`（经后端分发或 nginx 直供，实现见 §4/运维文档）。
- **server.mjs 按 Host 的访问闸（域名层 deny-by-default）**：新增按 `req.headers.host` 判定「当前请求来自 field 域还是 admin 域」→ field 域只放行 `field.html`/`submit.html`/`assets/*`/`vendor/*` + `FIELD_OK`/`LINK_OK` 接口；admin 域只放行后台页 + admin 接口；**越域名访问**（field 域请求 `/console.html` 或 admin-only 接口、admin 域请求 field 专属页）→ 拒（404/403），**不依赖前端隐藏**。Host→域标识用配置项 `FIELD_ORIGIN`/`ADMIN_ORIGIN`。
- **按 Host 的根路由**：field 域 `/` → `field.html`；admin 域 `/` → `console.html`（取代现 `server.mjs:1099` 的按 role 分发）；未匹配任一配置 Host 时的兜底行为明确定义（NH，见 §6）。
- **同源会话隔离**：确认两独立域名各自 `intake_sess` cookie（`SameSite=Strict; Path=/`）不互通 → 各自登录；field 页面调 `/api/*` 与 field 页**同源**（经该域 vhost 反代），`SameSite=Strict` cookie 正常发出。
- **免登录链接绝对地址**：`submit-link`（`server.mjs:643~651`）改返回 `FIELD_ORIGIN + '/submit.html?token='+token`（field 域绝对地址）；运营端产品管理生成链接时展示该绝对 URL。
- **运维文档**：`docs/运维部署.md` **新增一节**「双域名部署（admin / field 两 vhost，共用后端+库）」（两 server 块 nginx 样例 + `FIELD_ORIGIN`/`ADMIN_ORIGIN` 环境变量说明 + 「共用后端+库、工单不同步」要点），**保留原单域名内容**。

**不包含：**
- **拆进程 / 拆库 / 工单跨库同步**：明确**不做**（决策 D——共用同一 `server.mjs` + 同一 MySQL，同库直连，无同步）。
- **域内数据隔离（按 `accounts.sites`）**：那是 FS-01（`scopedForField` 修复 + 服务层按 sites 过滤）；本条只管「按域名的访问闸/路由」，不重复落地 sites 过滤。
- **登录门 / 工作空间外壳 / 维度切换**：FS-01。
- **免登录链接的生成/校验逻辑**（HMAC token 签发、`linkUserFrom` 验签、`LINK_OK` 闸）：那是 FS-06；本条只管「跨独立域名下链接地址必须**绝对** + 地址来源配置（`FIELD_ORIGIN`）」，不改 token 结构/验签。
- **HTTPS 证书签发的具体手段**（Let's Encrypt / 自签 / 商业证书）：运维文档给样例位，实际证书路径/签发方式属 NH（见 §6，对齐项目记忆 deploy-cloud「HTTPS/证书待办」）。
- **新建/改动数据库表**：无库表改动（部署/路由层），见 §5。

## 3. 验收标准（AC · Given-When-Then · 每条可自动判定）
> 回归套件（建议）：`tools/fs-08.test.mjs`。**A/B/C/D/E 组**多为「构造带不同 `Host` 头的请求，断言 server.mjs 路由/闸行为」——本条改造集中在 `server.mjs`（Host 闸 + 根路由 + submit-link 绝对地址），可直接对起在配置了 `FIELD_ORIGIN`/`ADMIN_ORIGIN` 的实例打真接口冒烟；**A 组（nginx 配置）**为对运维文档 nginx 样例的静态断言（文档即产物，无需真起 nginx）。

### A. nginx 双 vhost（同源反代 · 运维文档产物）
- **AC-1** Given `docs/运维部署.md` 新增的「双域名部署」节 Then 含**两个 `server {}` 块**，各自 `server_name`（一个 field 域、一个 admin 域），各自 `listen 443 ssl` + `ssl_certificate`/`ssl_certificate_key`（证书位）。
- **AC-2** Given 每个 vhost Then 含 `location /api/ { proxy_pass http://127.0.0.1:5180; ... }` **反代到同一后端**（两 vhost 的 `proxy_pass` 指向同一后端地址）；含 `proxy_set_header Host $host;`（把真实域名 Host 透传给后端，供 server.mjs 判域——**必须透传，否则 Host 闸拿不到 field/admin 域名**）。
- **AC-3** Given 浏览器访问 field 域页面并请求其 `/api/*` Then 页面与 `/api/*` **同域名（同源）**→ 免 CORS（AC 断言：文档明确说明「页面与 /api 同域名同源、免 CORS」，且各 vhost 的 `/api/` 反代 `proxy_set_header Host $host` 保证同源转发）。
- **AC-4** Given 静态页分发 Then 文档给出各 vhost 到同一 `public/` 的分发方式（经后端反代或 nginx `root` 直供），两域名指向**同一份** `public/`（不复制两份静态资源）。

### B. server.mjs 按 Host 的访问闸（域名层 deny-by-default）
- **AC-5** Given `server.mjs` 现状 Then 现**无**按 Host 区分 field/admin 域的访问闸（`req.headers.host` 仅在 `server.mjs:612~616` 用于本机模式 DNS-rebinding 防护，判 `SELF_HOSTS`，**与 field/admin 域名无关**）→ 本条**需新增** Host→域标识（`FIELD_ORIGIN`/`ADMIN_ORIGIN` 配置）+ 按域的白名单闸。
- **AC-6** Given 请求 Host = field 域（`FIELD_ORIGIN`）When 请求 `/console.html`（后台页）或任一 **admin-only 接口**（不在 `FIELD_OK`/`LINK_OK` 的写接口，如 `/api/account-save`）Then **拒**（页面 404 或 302 到 field 提交面；接口 403/404），**不依赖前端隐藏**（即便直接敲 URL 也越不了域）。
- **AC-7** Given 请求 Host = field 域 When 请求 `field.html`/`submit.html`/`/assets/*`/`/vendor/*` 或 `FIELD_OK`/`LINK_OK` 内接口 Then **放行**（field 域正常可用其允许集）。
- **AC-8** Given 请求 Host = admin 域 When 请求后台页（`console.html`/`inbox.html`/…）或 admin 接口 Then **放行**；When 请求 field 专属页（`field.html`）Then 按定义处理（NH：admin 域是否也可访问 field.html，见 §6；默认 admin 域不暴露 field.html，越域拒）。
- **AC-9** Given 域名层闸与现有 `authGate`（`server.mjs:582~592` `LINK_OK`/`FIELD_OK` deny-by-default）Then 两者**叠加**（域名层先按 Host 收窄允许集，再走原 `authGate` 按登录态/白名单判）——域名层是**新增的外层**闸，不替换、不削弱原 `authGate`。
- **AC-9b（防漂移·2026-07-26 补）** Given `FS08_FIELD_API`（field 域外层闸的接口允许集）是 `authGate` 内 `FIELD_OK` 的镜像常量 Then **`FIELD_OK` 里每个 `/api/` 开头的端点都必须 ∈ `FS08_FIELD_API`**——否则该端点在 field 域被 `originGate` 判 `deny` → 接口返 `{"error":"forbidden"}`，而 admin 域/本机正常，形成「运营域能调、实施域被拒」的隐蔽错配。**回归约束**：`tools/fs-08.test.mjs` 从 `server.mjs` 源码抽取两 Set 比对，`FIELD_OK` 的 `/api/` 端点有任一漏进 `FS08_FIELD_API` 即红（实测坑：FS-05 新增的 4 现场端点 `field/batches`/`batch-download`/`customer-version`/`intake-verify` 只进了 `FIELD_OK`、漏配 `FS08_FIELD_API` → 实施域整段批次流被域名闸拒）。

### C. 按 Host 的根路由
- **AC-10** Given 请求 Host = field 域 When 访问 `/` Then 返回 `field.html`（取代现 `server.mjs:1099` `rel = ... ? '/submit.html' : '/console.html'` 的按 role 分发）。
- **AC-11** Given 请求 Host = admin 域 When 访问 `/` Then 返回 `console.html`。
- **AC-12** Given 请求 Host **未匹配** `FIELD_ORIGIN`/`ADMIN_ORIGIN` 任一（如直接用 IP、未配置的域名、本机回环）When 访问 `/` Then 走**明确定义的兜底行为**（NH：兜底选项见 §6——建议兜底为 admin 域行为或 404；本机开发回环 `127.0.0.1`/`localhost` 需仍可用，不能因 Host 闸把本机开发打死）。

### D. 同源会话隔离
- **AC-13** Given 两独立域名（field 域 / admin 域）各自登录 Then 各自签发的 `intake_sess` cookie（`server.mjs:636` `SameSite=Strict; Path=/`）**按域名天然隔离**——field 域的会话 cookie 不会随 admin 域请求发出，反之亦然（浏览器同域 cookie 隔离，无需额外代码）。
- **AC-14** Given field 域页面调 `/api/*` Then 该请求与 field 页**同源**（经该域 vhost 反代到同一后端），`SameSite=Strict` cookie **正常发出**（同源不受 SameSite 限制）；断言：文档/配置保证 field 页与其 `/api/*` 同域名，故 `intake_sess`（Strict）在其 AJAX 请求中携带。
- **AC-15** Given 在 field 域已登录、未在 admin 域登录 When 直接访问 admin 域 `/api/me` Then 返回 `me:null`（field 域会话不串到 admin 域）——各域独立登录。

### E. 免登录链接绝对地址
- **AC-16** Given `server.mjs:643~651` `submit-link` 现返回 `path: '/submit.html?token=' + token`（**相对路径**）When 本条改造 Then 返回中含 **field 域绝对地址** `FIELD_ORIGIN + '/submit.html?token=' + token`（两独立域名下相对路径 `/submit.html?token=` 打不通，必须绝对）。
- **AC-17** Given 运营端（admin 域）产品管理生成提交链接 When 展示链接 Then 展示的是 **field 域完整 URL**（如 `https://field.example.com/submit.html?token=...`），复制发给现场即可在 field 域打开。
- **AC-18** Given `FIELD_ORIGIN` **未配置**（本机/单域名开发）When 生成 `submit-link` Then **回退**为原相对路径 `/submit.html?token=`（不因缺配置报错——单域名/本机仍按相对路径工作；`FIELD_ORIGIN` 配了才用绝对地址）。

## 4. 接口契约（改造真实端点 · Node `server.mjs` · 禁臆造）
> 逐字核过 `server.mjs`（行号为当前真实位置）。**🔧** = 改现有逻辑；**🆕** = 需新增；**复用** = 现状不变、仅引用。

**① 🆕 按 Host 的域标识 + 访问闸（现无，需新增）**
```
配置项（环境变量 / data 配置，与现有 PORT/BIND/INTAKE_DB_* 同范式）：
  FIELD_ORIGIN   如 https://field.example.com   → field 域标识 + submit-link 绝对地址前缀
  ADMIN_ORIGIN   如 https://admin.example.com   → admin 域标识
判域：originOf(req) = 由 req.headers.host 匹配 FIELD_ORIGIN / ADMIN_ORIGIN 的 host 部分 → 'field' | 'admin' | 'other'
```
- **现状（`server.mjs`，逐字核过）**：
  - `req.headers.host` 现**仅**用于 `server.mjs:612~616` 本机模式 DNS-rebinding 防护（`if (!PUBLIC) { if (!SELF_HOSTS.has(req.headers.host||'')) ... }`，`SELF_HOSTS` = `127.0.0.1:PORT`/`localhost:PORT`/`[::1]:PORT`，`server.mjs:50`）——**与 field/admin 域名无关**。**现无任何按域名区分 field/admin 的逻辑**（grep 确认 host 仅这几处）。
  - `authGate(pathname, user, link)`（`server.mjs:582~592`）：`LINK_OK`(`server.mjs:581`)/`FIELD_OK`(`server.mjs:590`) 白名单 deny-by-default，`isAdmin` 全放行——**入参无 Host**。
- **🆕 本条新增**：一层**按 Host 的外层闸**——在 `authGate` 之前（或作 `authGate` 的 Host 参数），按 `originOf(req)` 收窄允许集：field 域 = `{field.html, submit.html, /assets/*, /vendor/*} ∪ FIELD_OK ∪ LINK_OK`；admin 域 = 后台页集 ∪ admin 接口集。越域 → 404（页面）/ 403（接口）。**不改动原 `authGate` 的登录态/白名单语义**，域名层是叠加的外层（AC-9）。

**② 🔧 按 Host 的根路由（改 `server.mjs:1099`）**
```
现状（server.mjs:1099，逐字核过）：
  let rel = url.pathname === '/' ? (((user && !isAdmin(user)) || link) ? '/submit.html' : '/console.html') : url.pathname;
  // 现按 user 角色 / link 分发 /；与 Host 无关。
🔧 改为按 Host：
  origin==='field' → rel='/field.html'
  origin==='admin' → rel='/console.html'
  origin==='other' → 兜底（NH，见 §6；本机 127.0.0.1/localhost 需仍可用）
```

**③ 🔧 submit-link 返回绝对地址（改 `server.mjs:643~651`）**
```
现状（server.mjs:650，逐字核过）：
  send(res, 200, JSON.stringify({ ok:true, token, path:'/submit.html?token='+token, days }));
  // path 是相对路径。
🔧 改为：
  const rel = '/submit.html?token=' + token;
  const url = FIELD_ORIGIN ? (FIELD_ORIGIN.replace(/\/+$/,'') + rel) : rel;   // 配了 FIELD_ORIGIN 用绝对，否则回退相对（AC-18）
  send(res, 200, JSON.stringify({ ok:true, token, path:rel, url, days }));
  // 保留 path（向后兼容），新增 url（绝对/回退）；前端展示优先 url
```

- **不改**：`intake_sess`（`SameSite=Strict; Path=/`）在两独立域名下**天然按域名隔离**（浏览器同域 cookie 机制），无需改代码即满足 AC-13~15。**这是决策 D「cookie 按域名天然隔离」的实现依据**。

**⑤ 复用 · authGate 白名单（`server.mjs:581/590`，现状不变，域名层在其外叠加）**

## 5. 数据契约（对齐真实库 `db.mjs` init() · 禁臆造列名）
- **无新增表/列**（本条是**部署/路由层**改造）：不建表、不改字段。
- 会话仍走真实 **`sessions` 表**（`db.mjs`，列 `token`/`user_id`/`exp`）+ cookie **`intake_sess`**（`server.mjs:636`，`SameSite=Strict; Path=/`，7 天 TTL）——**现状不变**，两独立域名各自 cookie 天然隔离即满足会话隔离，**无需任何库/会话结构改动**。
- `FIELD_ORIGIN`/`ADMIN_ORIGIN` 是**部署配置**（环境变量 / `data/` 配置文件，与现有 `PORT`/`BIND`/`INTAKE_DB_*` 同范式，`data/` 已 gitignore），**非库字段**。
- submit-link token 仍是 HMAC 自验签（`data/link-secret`，`server.mjs:575/649`），**无库存储、无改动**——本条只改返回地址是否加 `FIELD_ORIGIN` 前缀。
- **真实库映射锚点**（对齐清单 §4）：`sessions` 表 = 会话；无「域名/vhost」相关表（部署配置层，不入库）。

## 6. 业务规则 / 非功能
- **域名层访问隔离（deny-by-default）**：field 域只暴露现场提交面 + `FIELD_OK`/`LINK_OK`；admin 域只暴露后台。越域访问一律拒（404/403），**不依赖前端隐藏**（AC-6/7/8）——即便攻击者知道 field 域并直接敲 `/console.html` 也进不去。域名层闸**叠加**在原 `authGate` 之外，不削弱原白名单（AC-9）。
- **共用后端 + 库、工单不同步**（决策 D 硬约束）：**不拆进程、不拆库**；现场经 field 域提交的工单同库直连进 `intakes` 表，运营经 admin 域在同一库读写，**无任何跨库/跨服务同步逻辑**（NEEDS-HUMAN 若将来要拆库另议）。
- **同源免 CORS**：两 vhost 各自 `/api/` 反代同一后端，页面与其 `/api/*` 同域名同源 → 免 CORS、`SameSite=Strict` cookie 正常携带（AC-3/14）。`proxy_set_header Host $host` 必须透传真实域名，否则 server.mjs 的 Host 闸判不出 field/admin（AC-2）。
- **cookie 隔离**：`intake_sess`（`SameSite=Strict; Path=/`）在两独立域名下由浏览器天然隔离，各域各自登录（AC-13~15），**无需改 cookie 代码**。
- **本机/单域名兼容**：`FIELD_ORIGIN`/`ADMIN_ORIGIN` 未配置时，行为回退到现状（单域名、按 role 分发、submit-link 相对路径）——**不能因新增 Host 闸把本机开发（`127.0.0.1`/`localhost`）打死**（AC-12/18）。
- **留痕/权限**：本条不新增留痕/权限逻辑（复用 FS-01 的 sites 数据隔离 + 现有 `authGate`）；域名层只做「访问哪个域看哪些资源」的路由级隔离。

## 7. 测试要点（Node + 原生 HTTP · 交付给开发 agent）
> 本项目无编译期，测试 = `node --test tools/fs-08.test.mjs`。多数用例 = **起一个配了 `FIELD_ORIGIN`/`ADMIN_ORIGIN` 的 server 实例，构造带不同 `Host` 头的请求**打真接口（`fetch(BASE+path, {headers:{Host:'field.example.com'}})` 或底层 `http.request` 设 `headers.host`）断言路由/闸行为——**连真库冒烟**（起真 server + 真 MySQL）。A 组为对运维文档 nginx 样例的静态断言。

- **A 组 · nginx 配置静态断言（对 `docs/运维部署.md` 新增节）**：
  - 含**两个 `server {}` 块**、两个不同 `server_name`、各含 `ssl_certificate`（AC-1）；各含 `location /api/ { proxy_pass ... }` 反代**同一**后端 + `proxy_set_header Host $host`（AC-2/3）；两域名指向同一 `public/`（AC-4）。
  - 含 `FIELD_ORIGIN`/`ADMIN_ORIGIN` 环境变量说明 + 「共用后端+库、工单不同步」要点。
- **B 组 · 连真库冒烟 · 按 Host 的访问闸（域名层 deny-by-default）**：
  - 起 server（配 `FIELD_ORIGIN=http://field.local`/`ADMIN_ORIGIN=http://admin.local`）；`Host: field.local` 请求 `/console.html` → 拒（404 或 302 到提交面）（AC-6）；请求 `/submit.html`/`/field.html`/`/assets/theme.css` → 放行（AC-7）。
  - `Host: field.local` 请求某 admin-only 接口（不在 FIELD_OK/LINK_OK，如 `/api/account-save`）→ 403/404（AC-6）；请求 `FIELD_OK` 内接口 → 不被域名层拒（走原 authGate）（AC-7/9）。
  - `Host: admin.local` 请求后台页/admin 接口 → 放行（AC-8）。
- **C 组 · 连真库冒烟 · 按 Host 的根路由**：
  - `Host: field.local` GET `/` → 响应体是 `field.html` 内容（含 field 外壳标识，如 `#fLogin`）（AC-10）；`Host: admin.local` GET `/` → `console.html`（AC-11）。
  - `Host: 127.0.0.1:<port>`（本机回环）GET `/` → 兜底可用（不 500、不打死本机开发）（AC-12）。
- **D 组 · 同源会话隔离**：
  - `Host: admin.local` 登录（真库账号，`/api/login`）拿到 `intake_sess`；带该 cookie 但 **`Host: field.local`** 请求 `/api/me` → 断言不因跨域拿到 admin 会话身份（模拟浏览器 cookie 隔离——测试层用不带 field 域 cookie 的请求验 `me:null`）（AC-15）。断言登录响应 `Set-Cookie` 含 `SameSite=Strict; Path=/`（AC-13/14）。
  - **数据准备**：用真库现有账号（如 `admin`/`zhangx`）或临时造 `impl` 账号（after 钩子清理，对齐项目经验库「造账号要清干净」）。
- **E 组 · submit-link 绝对地址**：
  - 配 `FIELD_ORIGIN=http://field.local` 起 server，管理员登录后 `POST /api/submit-link {project:<真库产品>}` → 返回 `url` = `http://field.local/submit.html?token=...`、`path` 仍相对（向后兼容）（AC-16/17）。
  - **不配** `FIELD_ORIGIN` 起 server → `submit-link` 返回 `path`/`url` 均相对（AC-18 回退）。
  - **数据准备**：用真库现有产品（如 `hlyy`）生成链接，不造脏数据；生成的是签名 token，不落库、无需清理。
