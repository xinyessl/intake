## 1. 用户故事 / 目标
作为**平台管理员**，我要在运营后台**统一管理平台账号与角色权限**（新增/编辑/停用/改密/删除），并给账号绑定其**负责医院 / 负责产品**，以便控制后台可见范围与操作权限、把现场与产品数据权限落到具体人。

> **[2026-07-21 前端事实源 re-target 原型]** 账号管理页**内容重做为 `admin/accounts.html` 原型样**：整宽 `.data-table`（用户名/姓名/角色/负责医院/状态/创建时间/操作）+ 新增/编辑**抽屉**（`.drawer`，自写开关——部署 `shell.js` **无** `UI.openDrawer`）。外壳由 UI-01 注入式 shell 提供（`<body data-shell="admin" data-nav="accounts" data-content-layout="list">`，用 `theme.css` 组件类）。落成 `public/accounts.html`。**旧「card+rowlist 两栏」布局已废弃**。

## 2. 范围
- **包含**：
  - 账号列表页（用户名 / 姓名 / 角色 / 负责医院 / 状态 / 创建时间 / 操作）+ 筛选（角色 / 状态 / 关键词）+ 分页，对齐原型 `admin/accounts.html`（整宽 `.data-table`）。
  - 新增/编辑抽屉：用户名、姓名、角色、负责医院（多选，实施必填）、**负责产品（多选，非管理员角色可绑）**、初始密码（仅新增）、状态。
  - 行操作：**编辑**、**改密（重置密码）**、**停用/启用**、**删除**（NH-2 已定版）。
  - 角色枚举（展示标签 ↔ 代码枚举，见 §5）：管理员=`admin`、产品经理=`pm`、实施=`impl`（**部署真实枚举 3 类**；不参考原型的"运营/开发"项）。历史遗留 `dev` 值兼容归为管理员（真库 `admin` 账号 role 实为 `dev`）。
  - 权限：账号管理页与其写接口**仅管理员可用**——判定用 `isAdmin(u) = role==='admin' || role==='dev'`（**保留 `dev`**，见 §6；NH-4「收紧到 admin-only」未落地，属待裁决）。
- **不包含**：
  - 用户**自助改自己的密码**（走 `/api/change-password`，本 spec 只覆盖管理员**重置他人**密码；自助改密属登录/我的账户 spec）。
  - 账号与登录会话（登录 `/api/login`、会话过期）属登录 spec，本 spec 不含。

## 3. 验收标准（AC · Given-When-Then · 每条必须可自动化判定）

### 列表与筛选
- **AC-1（列表列对齐原型 · 整宽 data-table）** Given 管理员已登录并进入账号管理页 When 页面加载 Then 整宽 `.data-table` 表头依次为 `用户名 / 姓名 / 角色 / 负责医院 / 状态 / 创建时间 / 操作`；每行：用户名 mono 加粗、姓名带首字头像（`.avatar-sm`）、角色渲染为标签（管理员=`tag-primary`、产品经理/实施=`tag-gray`）、负责医院（值为"全部"→`全部（全局）`绿标；值为"—"/空→占位灰"—"；否则逐家医院灰标签）、状态（启用=`tag-success` 圆点、停用=`tag-gray` 圆点）、创建时间按 `yyyy-MM-dd HH:mm` 格式化、操作 `.row-actions` 含 `编辑 / 改密 / 停用（或启用） / 删除`。
- **AC-2（角色筛选·选中即查）** Given 列表有多种角色账号 When 在「角色」下拉选择某角色 Then 立即（onchange，无需点搜索）重置到第 1 页并只显示该角色账号；选「全部角色」恢复全部。
- **AC-3（状态筛选·选中即查）** Given 列表含启用与停用账号 When 「状态」下拉选择"启用"或"停用" Then 立即按 status 过滤并重置到第 1 页。
- **AC-4（关键词搜索·回车触发）** Given 关键词框输入 `zhang` When 按回车 Then 仅显示 用户名或姓名（不区分大小写）包含该词的账号；空关键词不过滤。
- **AC-5（分页）** Given 过滤后账号数 > 每页条数 When 切换页码或每页条数（8/20） Then 表格按页切片显示，`共 N 个账号` 统计为过滤后总数，页码超界自动回落到末页。

### 新增账号
- **AC-6（新增·必填校验）** Given 打开新增抽屉 When 未填用户名或姓名点保存 Then 该输入框标 `invalid` 并 toast 提示，不提交；用户名格式须匹配 `^[A-Za-z0-9_.-]{2,32}$`（后端 `account-save` 同校验），不符返回 400 且前端就近提示。
- **AC-7（新增·用户名计数与长度）** Given 新增抽屉用户名框 When 输入 Then 实时显示 `X/20` 计数，`maxlength=20`（前端）；后端用户名列 `VARCHAR(40)`、正则上限 32（以后端为准，前端取更严的 20）。
- **AC-8（新增·初始密码必填且强制改密）** Given 新增账号 When 未填初始密码点保存 Then 阻止提交并提示"请设置初始密码"；填了则保存时以 `scrypt(salt,hash)` 落库、`must_change=1`（下次登录强制改密）。密码前端提示"8-20 位，含字母与数字"（后端最低 6 位，取前端更严的 8）。
- **AC-9（角色→负责医院联动）** Given 新增/编辑抽屉 When 角色选为"实施" Then 显示「负责医院」多选区且标必填(*)；选为其它角色 Then 隐藏该区。
- **AC-10（实施必绑负责医院）** Given 角色=实施 When 未勾选任何医院点保存 Then 阻止提交并提示"实施须绑定至少一家负责医院"。
- **AC-11（负责医院取值规则）** Given 保存账号 When 角色=实施 Then `hospitals`(=真表 `sites`) 存所勾选医院数组；角色=管理员 Then 存 `["全部"]`；角色=开发/产品经理 Then 存 `["—"]`（无现场范围）。负责医院候选来自客户/医院台账（`/api/customers`，见 §4）。
- **AC-24（负责医院列表按名称即输即过滤 · 纯前端 · 保住勾选态）** Given 角色=实施、「负责医院」勾选列表上方有名称搜索框（`#edHospSearch`，复用 `.input-with-icon`+`ti-search`，placeholder「按医院名称筛选…」，随 `#hospitalsGroup` 一起随角色联动显隐；`CUSTOMERS` 为空即无可选医院时该搜索框隐藏） When 在搜索框输入关键词 Then **客户端即输即过滤**（不发请求）——按医院名（并可含区域）**子串、不区分大小写**匹配，**仅切换 `label.style.display` 显隐、绝不重渲染 `#edHospitals` 的 innerHTML**（重渲染会丢未保存的勾选态）；被过滤隐藏但仍 `checked` 的医院，保存时 `checkedValues('#edHospitals')`（读 `input:checked`，与 display 无关）**照样读得到**，勾选与保存不受过滤影响；有搜索词且 0 命中 → 显一条「无匹配医院」灰提示（`.empty-line`，独立于 `#edHospitals`、不被重渲染污染）；清空搜索词 → 全部医院重现。搜索框 `input` 事件页面初始化时**只绑一次**（`#edHospSearch` 是 `#edHospitals` 的兄弟节点、不随 `renderHospitals` 重渲染销毁）；`renderHospitals` 每次打开/重渲染都**清空 `#edHospSearch.value`** 并隐藏无匹配提示，避免上次搜索词残留过滤新列表。
- **AC-20（负责产品绑定 · NH-2 已定版）** Given 新增/编辑抽屉 When 角色为非管理员（`pm`/`dev`/`impl`） Then 显示「负责产品」多选区（候选来自 `/api/projects`），保存写入 `projects` 列（产品 id 数组）；角色=`admin` Then 隐藏该区、`projects` 存 `[]`（全局不限）。空 `projects` = 不限产品（数据权限见 §6）。
- **AC-22（手机号字段 · 单一来源）** Given 新增/编辑抽屉 When 填「手机号」输入（`#edPhone`，`maxlength=20`，**选填**）点保存 Then `account-save` 收 `phone`、`String(b.phone||'').trim().slice(0,20)` 落 `accounts.phone` 列（格式宽松、可空）；`/api/accounts` + `pubUser` 出参含 `phone`；账号列表姓名旁展示手机号（空则不显）。编辑不带 `phone`（如停用/启用 `doToggle` 提交）→ **保留原值不清空**（同 enabled 保护语义）。**该手机号是医院管理（CU-01）实施人电话的唯一来源**——CU-01 列表实施人电话不再存客户文件，按实施人姓名匹配账号后取其 `phone` 派生显示。db.mjs 用 `ensureColumn('accounts','phone','VARCHAR(20)')` 幂等给存量库补列（安全不动数据）。
- **AC-23（account-save 照原样存 sites · 账号侧不排他 · 允许共管 · 2026-07-23 用户裁决「能共管」已定版 · draft 待评审）** Given 保存账号（`account-save`）When 该账号 `sites` 含医院名 H Then **照原样存 sites，不做任何跨账号移除**——**允许 pm 统筹 + impl 落地共管一院**（一家医院可被多个账号覆盖）。判定：先 `account-save` 把 H 塞进 impl 账号 A，再 `account-save` 一个 pm 账号 B 带 `sites=[H]` → **A、B 都仍含 H**（共管不互斥）。「一院一实施」仅由**医院管理侧 `customer-save` 写穿保证**（CU-01 AC-20：设「负责实施」时把该院唯一归给目标账号 + 从其他账号移除）；账号管理侧不承担排他。**医院管理『负责实施』列**在共管场景优先显示 `role==='impl'` 的账号（真正实施人），其次 pm（见 CU-01 AC-19 `deriveImpl` 排序）。
  > **裁决留痕（2026-07-23，NEEDS-HUMAN 已闭环）**：早稿 AC-23 曾要求账号侧也排他（一院一实施双向），与 `tools/fs-01.test.mjs` 固件（impl `U_A=[SITE_A]` + pm `U_PM=[SITE_A,SITE_C]` 共管 SITE_A）冲突。用户裁决 = **能共管·账号侧不排他**（一家医院可 pm 统筹 + impl 落地共管）→ 删除账号侧排他块，恢复照原样存 sites，FS-01 共管固件不再被破坏（恢复 21/21）。一院一实施主路径保留在 customer-save 侧不变。

### 编辑账号
- **AC-12（编辑回填）** Given 点某账号「编辑」 When 抽屉打开 Then 回填 用户名/姓名/角色/状态 与已选负责医院、**负责产品**；**初始密码组隐藏**（改密走独立"改密"入口）。
- **AC-13（编辑不改用户名主键语义）** Given 编辑保存 When `account-save` 以 `username` 匹配既有记录 Then 更新 role/name/hospitals(sites)/**projects**/enabled，**不重置密码**（密码字段留空即保留原 salt/hash）。前端须回传完整 `projects`/`sites` 避免清空。**改密不走此路径**（走 `/api/account-reset-password`，见 AC-15）。

### 改密（管理员重置他人密码）
- **AC-14（改密弹窗）** Given 点某账号「改密」 When 弹窗打开 Then 标题含该账号 `姓名（用户名）`；密码框右侧有**显示/隐藏眼睛**（`ui.js` 的 `uiPrompt({inputType:'password'})` 统一提供，点击查看明文，见 CHG-FS-01-去演示账号+密码查看眼睛）；输入新密码 < 8 位 → toast "密码需 8-20 位" 不提交；≥8 位确认 → 调 `POST /api/account-reset-password {id,password}` 重置该账号密码（`salt/hash` 更新、置 `must_change=1` 强制对方下次登录改密）。
- **AC-15（改密走专用端点 · NH-3 已定版）** Given 现有 `/api/change-password` 仅允许**登录用户改自己**（需旧密码）、不适用管理员重置他人 When 管理员为**他人**重置 Then 走**新增端点** `POST /api/account-reset-password {id,password}`（仅 `admin` 可调，`authGate` 挡非管理员）：以 `id` 定位账号、重设 `salt/hash`、置 `must_change=1`；不改动 用户名/角色/负责范围。判定：重置后目标账号**新密码可登录、旧密码 `verifyPw` 失败**，且下次登录被要求改密。

### 停用/启用
- **AC-16（停用二次确认）** Given 某启用账号 When 点「停用」 Then 弹危险确认框，确认后提交 `account-save` 带 `enabled=0`（启用反向 `enabled=1`），该账号行状态标签转灰、操作项变为"启用"；点「启用」反向切换。
- **AC-17（停用后不可登录 · 本版直接接入）** Given 账号 `enabled=0` When 该账号用**正确**用户名密码尝试登录 Then `verifyPw` 通过后仍被拒，返回 `{ok:false,error:'账号已停用，请联系管理员'}`、**不创建会话**（无降级、无"仅列表标记"的已知限制）。启用账号（`enabled=1` 或旧行 NULL 兜底为 1）登录不受影响。

### 权限
- **AC-18（仅管理员可访问）** Given 非管理员（产品经理/实施）用户 When 访问 `/accounts.html` 或调用 `/api/account-save` `/api/account-delete` `/api/account-reset-password` Then 被 `authGate`（白名单 deny-by-default）挡下（页面重定向、API 返回 403）。放行条件 = `isAdmin(u)`（`role==='admin' || role==='dev'`）——**遗留 `dev` 仍视为管理员**（真库 `admin` 账号 role 实为 `dev`；NH-4「收紧到 admin-only」未落地，见 §6 裁决留痕）。
- **AC-19（不能停用/删除最后一个启用管理员）** Given 系统仅剩一个**启用的**管理员 When 尝试停用（`enabled=0`）或删除该管理员 Then 拒绝并提示"不能删除/停用最后一个管理员"。删除与停用**共用同一保护 helper**（`isLastEnabledAdmin`，避免两套逻辑漂移）。
- **AC-21（删除账号 · NH-2 已定版）** Given 账号列表某行「删除」 When 点击 Then 弹**危险二次确认**（含账号 `姓名（用户名）`）；确认 → 调 `POST /api/account-delete {id}` 物理删除；**不能删除最后一个启用管理员**（复用 `isLastEnabledAdmin`，同 AC-19）→ 被拒并提示。删除成功后列表移除该行、`共 N 个账号` 减 1。

## 4. 接口契约
**全部复用 intake_bak 真实端点**（`docs/P0-…§A.4`）：

| 端点 | 方法 | 入参 | 出参 / 说明 |
|---|---|---|---|
| `/api/accounts` | GET | — | `{ accounts: [pubUser…] }`；`pubUser={id,username,role,name,phone,projects[],sites[],mustChange,enabled}`（`phone` 手机号选填空串兜底；`enabled` 1启用/0停用，NEEDS-HUMAN-1 已落地） |
| `/api/account-save` | POST | `{ username, role, name, phone?, projects?[], sites?[], password?, enabled? }` | `{ ok, accounts:[pubUser…], first }`；用户名匹配则更新、否则新建（新建必带 password）；role 经 `normRole` 归一到 `admin/pm/impl`（首个账号强制 admin；遗留 `dev→admin`、`field→impl`）；`projects` 现可编辑（负责产品，NH-2）；`phone` 选填 `slice(0,20)`（**编辑不带 phone 保留原值**，防停用/启用清空）；`enabled` 缺省：编辑保留原值、新建默认 1；**新建置 `must_change=1`**（AC-8，强制首登改密，与 bootstrap admin 一致） |
| `/api/account-delete` | POST | `{ id }` | `{ ok, accounts:[…] }`；**本页「删除」行操作暴露**（NH-2）；`isLastEnabledAdmin` 保护（不能删最后一个启用管理员） |
| `/api/account-reset-password` | POST | `{ id, password }` | **[新增·NH-3]** 管理员重置**他人**密码：仅 `admin` 可调（`authGate` 挡非管理员）；以 `id` 定位、重设 `salt/hash`、置 `must_change=1`；不改角色/负责范围。返回 `{ ok }` |
| `/api/change-password` | POST | `{ old, new }` | 仅**当前登录用户改自己**、校验旧密码——**不适用**管理员重置他人（见 AC-15，走 `account-reset-password`） |
| `/api/customers` | GET | — | 负责医院候选来源（原型 `renderHospitals` 用 `M.customers` 的 `name/region`）；对齐 DM-01/CU-01 客户台账 |
| `/api/projects` | GET | — | **负责产品候选来源**（NH-2）：`{ projects:[{id,name}] }` |

**扩展点**：
- **[✅ 已落地 NEEDS-HUMAN-1] `enabled`**：`/api/accounts` 出参与 `pubUser` 带 `enabled`；`/api/account-save` 入参接收 `enabled`（启用/停用）。
- **[✅ 已落地 NEEDS-HUMAN-1] 停用即禁止登录（直接接入）**：登录侧（`/api/login`）在 **`verifyPw` 通过后**判 `enabled !== 0`（停用则返回 `{ok:false,error:'账号已停用，请联系管理员'}`、不创建会话）。放在密码校验通过之后判，避免向密码错误的尝试泄露账号停用状态。
- **[✅ 已落地 NH-3] 管理员重置他人密码专用端点** `POST /api/account-reset-password { id, password }`：仅 `admin` 可调；重设 `salt/hash` + 置 `must_change=1`（强制对方下次登录改密）；`/api/change-password` 保持"仅改自己"。
- **[✅ 已定版 NH-2] 负责产品编辑 + 删除入口**：`account-save` 收 `projects`（本页可编辑）；`account-delete` 行操作暴露（带 `isLastEnabledAdmin` 保护）。
- **[✅ 已定版 NH-4] 角色收紧**：`isAdmin(u)=u.role==='admin'`（移除 `||role==='dev'`）；`ACCOUNT_ROLES=['admin','pm','dev','impl']`。**⚠️ 与存量迁移同批上线**（见 §5）。

## 5. 数据契约
**表：`accounts`**（对照 `intake_bak/db.mjs` 真实列，禁止臆造）：

| 真实列 | 类型 | 本 spec 用途 | 备注 |
|---|---|---|---|
| `id` | VARCHAR(40) PK | 账号主键 | `u`+随机 hex（server 生成） |
| `username` | VARCHAR(40) UNIQUE | 用户名/登录名 | 唯一；`account-save` 以此匹配更新；正则 `^[A-Za-z0-9_.-]{2,32}$` |
| `role` | VARCHAR(20) | 角色（代码枚举） | 见下角色映射 |
| `name` | VARCHAR(80) | 姓名 | 空则回退用户名 |
| **`phone`** | VARCHAR(20) | **手机号（选填）** | 账号手机号，可空；**医院管理（CU-01）实施人电话取自此列 = 单一来源**（不再存客户文件里）；`account-save` `String(b.phone||'').trim().slice(0,20)`，格式宽松不强校验；编辑不带 phone 时保留原值（同 enabled 保护语义，防停用/启用等提交清空）。**db.mjs 用 `ensureColumn('accounts','phone','VARCHAR(20)')` 幂等给存量库补列**（同 enabled，安全不动数据） |
| `salt` | VARCHAR(64) | 密码盐 | `scrypt`；不可逆 |
| `hash` | VARCHAR(256) | 密码散列 | 同上 |
| `must_change` | TINYINT | 强制改密标记 | 新建/重置置 1，用户改后置 0 |
| `projects` | JSON | 负责产品（数组·产品 id） | **本页可编辑**（负责产品多选，NH-2）；非管理员绑定=限定其工单可见产品范围，空=不限 |
| **`sites`** | JSON | **负责医院（= 原型 `hospitals`）** | 数组：具体医院名 / `["全部"]` / `["—"]` |
| `created_at` | DATETIME | 创建时间 | 展示按 `yyyy-MM-dd HH:mm` |
| **`enabled`** | TINYINT DEFAULT 1 | **状态：启用/停用（本决定 NEEDS-HUMAN-1 新增列）** | 1=启用 / 0=停用；DEFAULT 1 存量默认启用；展示↔存储：`启用↔1`、`停用↔0`（前端筛选下拉中文值须映射，勿原样入库） |

**角色枚举 · 部署真实枚举 3 类（`server.mjs` `ACCOUNT_ROLES=['admin','pm','impl']`；不参考原型"运营/开发"项）**：

| 展示标签 | 代码枚举 `role` | 标签样式 | 权限 / 范围 |
|---|---|---|---|
| 管理员 | `admin`（遗留 `dev` 兼容归此） | `tag-primary` | 全后台权限（`isAdmin` 放行）；`sites=["全部"]`、`projects=[]` 不限 |
| 产品经理 | `pm` | `tag-gray` | 现场侧；按 `projects` 限产品；`sites=["—"]` |
| 实施 | `impl` | `tag-gray` | 现场侧；`sites` 决定其可见工单医院范围；遗留 `field` 归一到此 |

- **`isAdmin`（部署现状，未收紧）**：`isAdmin(u) = u.role === 'admin' || u.role === 'dev'`——**保留 `dev`**：真库 `admin` 账号 role 实为遗留 `dev`，去掉会瞬间"零管理员"。NH-4 提议的「收紧到 admin-only + 存量迁移」**未落地**，属待裁决（见 §6 裁决留痕修订）。
- **`normRole` / `ACCOUNT_ROLES`**：`ACCOUNT_ROLES=['admin','pm','impl']`；首个账号强制 `admin`；遗留 `dev→admin`、`field→impl`；未知值归 `admin`（`normRole` 现状）。
- **前端角色下拉/筛选 = 3 项**（管理员/产品经理/实施工程师），值为 `admin/pm/impl`。列表按 `roleClass(r)` 把 `dev` 归 `admin` 显示。

**`enabled`（启用/停用）· ✅ 已裁决 NEEDS-HUMAN-1**：`accounts` 加列 `enabled TINYINT DEFAULT 1`（1=启用 / 0=停用）。**选 `enabled` 而非 `status`**：布尔语义清晰、便于 SQL 按状态过滤/统计，且避免与 `intakes.status`（工单状态：待处理/沟通中…）语义混淆。落地需改：
- `db.mjs`：建表加列；`loadAll` 映射 `enabled: r.enabled == null ? 1 : (r.enabled ? 1 : 0)`（**存量旧行 NULL 兜底为启用**）；`replaceAccounts` upsert 带 `enabled`。
- `pubUser` 出参加 `enabled`；`account-save` 入参收 `enabled`（**编辑缺省保留原值、新建默认 1**，勿像 projects 那样被清空/误停用）。
- **停用即禁止登录本版直接接入**（见 §4 扩展点与 AC-17）。

**留痕**：账号增删改本 spec 暂不要求独立审计表（真代码亦无）；如需操作留痕 → NEEDS-HUMAN。

## 6. 业务规则 / 非功能
- **按钮级/页面级权限**：账号管理仅 `isAdmin(user)`（部署现状 = `role==='admin' || role==='dev'`）可见可用。`authGate` 是**白名单 deny-by-default**——账号写接口（`account-save`/`account-delete`/`account-reset-password`）不在 `FIELD_OK`/`LINK_OK` 白名单 → 非管理员一律 forbidden 403（AC-18），无需额外判权代码。**NH-4 提议的「收紧 `isAdmin` 到 admin-only + 存量迁移」未落地**——因真库 `admin` 账号 role 实为遗留 `dev`，贸然收紧会瞬间零管理员；`isAdmin` 在 `server.mjs` 有多处用（authGate、`intake-list/detail/transition` 数据权限、console 路由），收紧牵连 UI-01/TK-01/WB-01，**属待裁决**（见 §6 裁决留痕修订）。
- **数据权限（跨模块·关键）**：实施工程师账号的 `sites`（负责医院）**决定其可见工单范围**——真代码 `intake-list`/`intake-detail` 对非管理员按 `user.sites` 过滤 `it.site`（`server.mjs` L985/L1008/L990）。故本页给实施工程师绑定/修改负责医院，**直接影响其在工单模块能看到哪些工单**（与 TK-01/TK-02 强关联；改一个账号的负责医院即改其数据权限面）。
- **密码安全**：`scrypt(salt,hash)`，不可逆、不回显；新建/重置置 `must_change=1` 强制首登改密。前端密码规则提示"8-20 位含字母数字"，后端最低 6 位——**取前端更严**；建议后端 DTO 补 `@Size(8,20)`+含字母数字校验做纵深防御（本项目为 Node，等价为 `account-save` 内加同款正则）。
- **唯一性/幂等**：`username` UNIQUE；`account-save` 以 username upsert（同名即更新，天然幂等）。
- **保护规则**：不能删除**最后一个管理员**（`account-delete` 已实现）；**停用**复用同一 helper——不能停用最后一个启用管理员（AC-19，随 `enabled` 落地一并实现）。
- **停用语义**：`enabled=0` 的落地含义是**禁止登录**（AC-17）——本版**直接接入**登录侧读 `enabled`，`verifyPw` 通过后判停用即拒登；非"仅列表标记"的降级版。
- **负责产品（projects）· NH-2**：本页**提供编辑入口**——编辑抽屉「负责产品」多选（候选 `/api/projects`），保存写 `projects`；前端须回传完整 `projects` 数组避免清空。数据权限：非管理员 `intake-list`/`detail` 按 `user.projects` 过滤可见工单产品（`server.mjs` L996/L1003），空=不限产品。
- **删除 vs 停用 · NH-2**：本页**同时提供**「停用」（软禁用，可恢复）与「删除」（物理删，`account-delete`）；删除走**危险二次确认** + `isLastEnabledAdmin` 保护（AC-21）。建议日常优先「停用」，「删除」仅用于误建/离职清理。
- **时间格式**：创建时间展示统一 `yyyy-MM-dd HH:mm`（原型 `M.fmtTime`），不显后端原始 ISO/时间戳。
- **性能**：账号量级小（几十~百级），列表内存过滤+前端分页即可，无需服务端分页。
