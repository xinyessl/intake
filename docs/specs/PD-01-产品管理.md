## 1. 用户故事 / 目标
作为**收件运营后台的产品经理/管理员**，我要**登记并维护需要跟踪收件的产品**——贴一次 GitLab 组地址就自动带出产品 id / 名称 / 子系统（含中文描述），保存时后端克隆各子系统仓、读版本(git tag)与 spec，之后可一键「同步」拉最新代码——**以便**提交页能按产品联想版本 / 模块，进件能落到正确子系统。

## 3. 验收标准（AC · Given-When-Then · 每条必须可自动化判定）

### 解析（Git inspect）
- **AC-1**（贴组地址→带出子系统含中文 desc）Given 已在「Git 集成」配好可用的 host+token，When 在 Git 地址输入框填入某产品的 GitLab **组地址**（如 `https://gitlab.lcpharmacy.cn/steward/psp`）并点「解析」，Then 调 `POST /api/git-inspect {url}` 返回 `{ok:true, id, name, subsystems:[{key,name,desc,repoUrl}...]}`；前端自动把 `id` 填入项目 id 框、`name` 填入项目名框，并在「已发现子系统」预览区按 `subsystems` 渲染 chip（`key · name`），子系统数 = `subsystems.length`。
- **AC-2**（贴单仓地址→子系统仅它一个）Given 同上配置，When 填入的是**单个仓库地址**（GitLab 里不是组），Then 后端 `gitInspect` 回退到 `/projects/{path}`，`subsystems` 仅含该仓一项（`key=仓path, name=仓name, desc=仓 description, repoUrl=http_url_to_repo`），前端预览区显示 1 个 chip。
- **AC-3**（子系统中文描述来自 repo description）Given GitLab 上某子系统仓的 `description` 字段为中文（如「抗菌药物网络上报」），When 解析该组，Then 返回的对应 `subsystems[i].desc` 等于该仓 `description`（trim 后）；保存后该 desc 落入 `projects.subsystems` JSON，可回显。
- **AC-4**（未配置 Git 集成的失败提示）Given 尚未配置 host+token，When 点「解析」，Then `/api/git-inspect` 返回 `{ok:false, error:"未配置 Git 集成（host + token）"}`（HTTP 200，业务 error），前端 toast 该错误、不填充字段、不误建产品。
- **AC-5**（解析地址不合法）Given 已配置，When 填入无法解析出命名空间的地址，Then 返回 `{ok:false, error:"Git 地址无法解析"}`，前端提示且不填充。

### 保存（含 clone）
- **AC-6**（新增保存→clone 各子系统仓）Given 解析成功、id/项目名合法（`/^[a-z0-9][a-z0-9-]{0,39}$/`、名≤40字），When 点「新增」提交 `POST /api/project-save {id,name,gitUrl,subsystems:[{key,name,desc,repoUrl}]}`，Then 后端对每个带 `repoUrl` 的子系统 `cloneRepo` 到 `data/repos/<id>/<key>`，成功则回填 `subsystems[i].repoPath`，落库并返回 `{ok:true, projects:[...]}`；返回的目标产品 `subsystems` 每项含 `{name,key,desc,repoUrl,repoPath?}`。
- **AC-7**（id 校验，**回校部署实现**）Given 表单，When 提交 `id`，Then 后端**先 `trim().toLowerCase()` 再校验**（server.mjs L719）：规范化后仍不满足 `^[a-z0-9][a-z0-9-]{0,39}$`（如含空格、前导连字符、`_`、非 ASCII、>40 位）→ 返回 `{ok:false, error:"项目 id 只能小写字母/数字/连字符，1~40 位"}`（HTTP 400），前端 `#fId` 标红并 toast；**纯大写 id（如 `ETL`）不被拒，而是规范化为小写（`etl`）后接受**。前端亦同步：`ID_RE` 校验 + `maxlength=40` + `oninput` 实时转小写（与后端一致）。〔部署真相回校：原 AC 表述为"不满足正则即 400"，未体现后端先小写化，导致纯大写会误判为应拒；实测部署为小写化后接受。〕
- **AC-8**（项目名必填 + 长度）Given 表单，When `name` 为空 Then 返回 `{ok:false,error:"项目名必填"}`；When `name` 长度 > 40 Then 返回 `{ok:false,error:"项目名不超过 40 字"}`（HTTP 400），前端对应字段标红。
- **AC-9**（编辑保留已有子系统/Git）Given 已存在产品 `p`（有 subsystems 与克隆路径），When 以 `startEdit(p.id)` 进入编辑、**只改项目名**、未重新解析（本次不带 subsystems）后 `project-save`，Then 后端保留 `existing.subsystems` 与 `existing.gitUrl`，不清空克隆路径（对齐 server.mjs「编辑时本次未带子系统/Git 则保留已有」）。
- **AC-10**（id 保存后不可改）Given 编辑态，When 打开编辑抽屉，Then id 输入框 `disabled`；改 id 只能通过删旧建新（前端 hint 明示）。
- **AC-11**（id 唯一性，**回校部署实现**）Given 列表已有 id=`etl`，When 新增模式再次用 id=`etl` 保存，Then **部署现状：前端 `save()` 无重复 id 前置拦截，直接 POST `project-save`；后端按 id upsert，同 id 会静默覆写该产品行**（`save()` 无「已存在」提示，见 projects.html L450-473）。〔部署真相回校：原 AC 要求"前端提交前拦截 toast『项目 id 已存在』"——**该拦截在部署实现中并不存在**，实际是静默 upsert 覆盖。〕**风险/待决策**：新增模式撞已有 id 会无声覆盖既有产品（含其子系统/克隆路径）——是否补一个前端"新增模式下 id 已存在则拦截提示"的小增量，交人裁决（见 §6）。

### 列表展示（读时派生）
- **AC-12**（子系统最新提交常驻展示·本地秒回）Given 某产品已 clone，When 表格渲染该行，Then 调 `GET /api/project-git?project=<id>` 返回 `{syncedAt, subs:[{name, ok, head, fetchedAt}]}`（不走网络、读本地 `git log -1 --format=%h｜%ci｜%s`）；该行「最新提交」列按各子系统展示 `短hash + 提交时间 + 标题`（多子系统时前缀子系统名），并在其下展示「最后同步 `syncedAt`」。
- **AC-13**（版本徽标）Given 某产品，When 读 `GET /api/versions?project=<id>` 得 `{versions:[...],syncedAt}`（各子系统仓 `git tag` 并集，倒序），Then `versions.length>0` 显示「N 个版本」绿徽标，`=0` 显示「未读到版本」黄徽标（title 提示"打了 tag 才有版本"）。
- **AC-14**（时间格式统一）Given 列表任意「最后同步 / 提交时间」展示，When 渲染，Then 一律格式化为 `yyyy-MM-dd HH:mm`（用共享格式化函数，对齐后台样式），空值显示占位 `—`。

### 同步 / 删除
- **AC-15**（单产品同步）Given 某产品已 clone，When 点该行「同步」调 `POST /api/git-refresh {project:<id>}`，Then 后端 `refreshRepos(proj, force=true)`：逐子系统 `fetch --all --tags --prune --force` + `reset --hard @{u}`，返回 `{ok:true, syncedAt, repos:[{name,ok,head,tags}], versions:[...]}`；前端刷新该行提交/版本/最后同步时间，toast 已同步到最新。
- **AC-16**（全部同步）Given 列表 N 个产品，When 点页头「全部同步」，Then 对每个产品调 `git-refresh`（可串行），全部完成后逐卡刷新并 toast「全部产品同步完成」。
- **AC-17**（同步失败不崩）Given 某产品仓 fetch 失败（网络/权限），When 同步，Then 后端捕获异常返回 `{ok:false, error:<msg>}`（HTTP 200），前端 toast 错误、其余产品不受影响。
- **AC-18**（删除只解除登记）Given 某产品有已归档进件，When 点该行「删除」并在共享 `uiConfirm`（danger）确认调 `POST /api/project-delete {id}`，Then 后端从 `projects` 移除该行、返回 `{ok:true, projects:[...], keptData:<保留进件数>}`；`data/intake-store/<id>/` 下进件文件仍在（不删数据）；前端从表格移除该行、toast「已解除登记」。

### 子系统版本清单来源（分支+tag 多选 · 2026-08-10 draft 待评审）
> **背景/决策**（已与用户确认）：产品编辑抽屉「已发现子系统」里，**每个子系统各自**支持「分支多选 + tag 多选」，用途 = 定该子系统的**「版本清单」来源**——选中的 tag/分支才作为该子系统可选版本，**收窄**现在「该仓全部 git tag 并集」。**本期不改 spec@tag / refreshRepos 分支读取行为**（refreshRepos 仍对齐默认分支、spec@tag 不变），只做「版本清单来源」这一项。
- **AC-21**（每子系统各自分支+tag 多选）Given 编辑抽屉打开、某产品有 N 个「已发现子系统」，When 渲染每个子系统行，Then 其下各有两个多选控件「分支」+「tag」，选项来自 `POST /api/git-refs`（下拉复选面板：触发器显「已选 N 项」摘要、tag 面板内可搜索过滤、已选高亮）；**各子系统独立**（甲子系统所选不影响乙）。
- **AC-22**（版本清单来源改造·选中优先）Given 某子系统 `s` 已选了 tag/分支（`s.tags` 或 `s.branches` 任一非空），When 读 `GET /api/versions?project=<id>` 的 `bySub[s.name]` 或产品级 `versions`，Then 该子系统版本清单 = **所选 tags（按版本倒序在前）+ 所选 branches（在后，作「滚动版本」，版本字符串=分支名）**；产品级 `versions` = 各子系统改造后清单的并集（倒序、slice 上限 200）。
- **AC-23**（未选回落·向后兼容）Given 某子系统 `s` **未选**（`s.tags`、`s.branches` 皆空或缺）Then 该子系统版本清单 = **该仓全部 `git tag`（倒序）**——行为与改造前**一模一样**，老产品/未选子系统不受影响。`specFilesAt`/`specFileText`/`refreshRepos`/spec@tag 读取逻辑**不改**。
- **AC-24**（`/api/git-refs` 契约）Given admin 登录，When `POST /api/git-refs`（入参二选一：`{subsystems:[{key,repoUrl}]}` 解析后未保存时用；`{project:<id>}` 已保存产品用其 subsystems 的 repoUrl 还原），Then 后端对每仓 `git ls-remote --heads --tags <authUrl>`（token 注入同 cloneRepo、**不 clone**、20s 超时）解析：`refs/heads/X`→branch X（剥前缀）、`refs/tags/Y`→tag Y（剥前缀、**丢 `^{}` 解引用行**）；返回 `{ok:true, refs:{<key>:{branches:[默认分支置顶其余字母序], tags:[版本倒序], error?:''}}}`。某仓超时/失败 → 该 key 返回空数组 + `error` 字段（**整体不 500**）；未配 token → 各仓 `error='未配置 Git token'`（不静默空）。**admin 域鉴权**（照 `/api/project-save`，不进 FIELD_OK/LINK_OK/FS08 白名单）。
- **AC-25**（持久化 branches/tags）Given 保存产品，When `POST /api/project-save` 的 `subsystems[i]` 带 `{branches:[…],tags:[…]}`，Then 后端 `normRefList` 归一化（字符串数组、trim、去重、单元素 ≤200 字符、数组 ≤100，非数组→[]）后落 `projects.subsystems` JSON；**保留 key/name/desc/repoUrl/repoPath 原字段**；**未选（空数组）不落该字段**（附加式，向后兼容，无需改 DDL）。编辑抽屉**回显**已选（从 `proj.subsystems[i].{branches,tags}` 读），已选但 remote 已无的 ref 仍显示并标「已失效」（不静默丢）。

### Git 集成 / 提交链接
- **AC-19**（Git 集成配置回显掩码）Given 打开「Git 集成」弹窗，When 读 `GET /api/git-config`，Then 返回 `{baseUrl, tokenMask, configured}`；token 仅回显掩码（如 `glpat-…dyPf`），明文不回显；保存 `POST /api/git-config-save {baseUrl, token?}` 时 token 留空则保留已配置。
- **AC-20**（生成提交链接）Given 某产品，When 点该行「链接」并在 `.modal` 弹窗选现场/版本/类型/有效天数后生成，Then 调现有 `/api/submit-link` 生成免登录提交链接，前端展示只读链接框 + 复制按钮。
- **AC-26**（Git 集成支持 GitLab + Gitee，按 host 判 provider · 2026-08-25 draft 待评审）Given「Git 集成」配置的 baseUrl host 含 `gitee.com`（或显式 `provider:'gitee'`），When 贴 Gitee 组/仓地址并「解析」，Then 后端 `gitProvider(cfg)` 判为 `gitee`，`gitInspect` 走 Gitee REST v5（恒 `https://gitee.com/api/v5`，`access_token` 查询参数认证），**不再**误打 `<baseUrl>/api/v4`（原写死 GitLab 导致 Gitee 404）：贴 `owner/repo`（含 `/`）→ `GET /repos/{owner}/{repo}` 单仓（`subsystems` 仅它一个，`repoUrl`=https 克隆地址 `clone_url` 或 `html_url+.git`）；贴 `owner`（无 `/`）→ 先 `GET /orgs/{owner}/repos?type=all&per_page=100`，404/失败兜 `GET /users/{owner}/repos?type=all&per_page=100`，列该 owner 全部仓当子系统（`id/name`=owner、`gitUrl`=`https://gitee.com/{owner}`）。token 注入到克隆地址由共享 `authGitUrl(repoUrl,cfg)` 统一（`cloneRepo`/`lsRemoteRefs`/`refreshRepos` 复用），gitlab/gitee 均 `https://oauth2:{token}@host/...`。**GitLab 分支行为逐字不变**（`provider=gitlab`：组/单仓仍走 `/api/v4/groups`·`/api/v4/projects` + `PRIVATE-TOKEN` 头）。`GET /api/git-config` 出参增 `provider`；`POST /api/git-config-save` 可选收 `provider`（不传按 host 自动判，用户无感）。〔**风险/待验**：Gitee 私有仓的 `oauth2:{token}@gitee.com/...` token 注入格式需真 Gitee token 冒烟确认可 clone/ls-remote；若不支持退回 `https://{token}@gitee.com/...`。公共仓 `.git` 地址已验可达。〕

| `/api/git-config-save` | POST | `{baseUrl, token?, provider?}` | `{ok, tokenMask, configured, provider}` | 保存 Git 集成（**AC-26：provider 可选，不传按 host 自动判**） |
| `/api/spec-modules` | GET | `?project=<id>&ver=` | `{modules:[...]}` | （供提交页；此页不直接用，登记后可验证） |
| `/api/submit-link` | POST | `{project, site?, ver?, type?, days?}` | `{url,...}` | 生成提交链接 |

> **对齐差异（重要）**：原型 `mock-data.js` 里 `products` 直接内联了 `verCount / lastSync / commit / commitDate / subsystems[i].{commit,commitDate,head}`；**真实后端不存这些字段**——`projects` 表只存 `subsystems:[{name,key,desc,repoUrl,repoPath}]`，展示用的提交/版本/同步时间**全部读时派生**（`/api/project-git`、`/api/versions`）。前端接真接口时须：卡片渲染改为 `/api/projects` 出静态信息 + 并发拉 `/api/project-git`（提交/最后同步）+ `/api/versions`（版本数），**不要**期望 `/api/projects` 直接带 commit/verCount。

## 5. 数据契约
**复用现有 `projects` 表，不改结构**（对照 `intake_bak/db.mjs` 真实列，禁止臆造）：

```
CREATE TABLE projects (
  id VARCHAR(40) PRIMARY KEY,        -- 产品 id，^[a-z0-9][a-z0-9-]{0,39}$
  name VARCHAR(100) NOT NULL,        -- 产品名（前端限 40，库列宽 100）
  repo_path VARCHAR(500) NULL,       -- 顶层单仓路径（兼容旧数据；组模式挂在 subsystems）
  specs_path VARCHAR(500) NULL,      -- 顶层 specs 目录（兼容）
  subsystems JSON NULL,              -- [{name,key,desc,repoUrl,repoPath}]
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
)
```
- **subsystems JSON 元素结构**（`project-save` 归一化后落库）：`{ name(必), key?, desc?, repoUrl?, repoPath?, branches?, tags? }`。其中 `desc`=子系统中文描述（来自 GitLab repo `description`）；`repoPath`=clone 到 `data/repos/<id>/<key>` 的本地路径（clone 成功才有）；**PD-01 新增（附加式，向后兼容·无需改 DDL）**：`branches?`/`tags?`=该子系统「版本清单来源」所选分支/tag（`normRefList` 归一化：字符串数组、去重、单元素 ≤200、数组 ≤100；**未选则不落该字段**，老数据无字段=未选=回落全 tag 旧行为）。**上限 60 个子系统**。
- **版本清单派生（读时算·PD-01 改造）**：`versionsBySubsystem(proj)` / `listVersions(proj)` 对每个子系统——有选（`s.tags`/`s.branches` 任一非空）→ 清单=所选 tags(倒序)+branches(滚动版本在后)；未选→回落该仓全 `git tag`（倒序）。产品级 `listVersions` = 各子系统清单并集（倒序、≤200）。**风险/后续**：若某医院现场版本被设成分支名（滚动版本），`spec@version` 读取时该「版本」是分支名而非 tag——本期 refreshRepos/spec@tag 读取逻辑**不改**（`safeRef` 允许分支名字符，git `show <branch>:<file>` 可读），但语义上「按分支读 spec」= 读该分支当下工作树、非冻结版本，**留作后续评估**（见 §6 NEEDS-HUMAN）。
- **唯一键**：`id` 为主键；`project-save` 按 id upsert，`replaceProjects` 同步删除已移除行。
- **派生字段（不入库，读时算）**：`gitUrl`（缺失时 `deriveGitUrl` 从子系统 repoUrl 反推组地址）、提交(head)、版本(tag)、`syncedAt`。
- **留痕**：产品登记本身无独立留痕表；克隆/同步动作落在 `data/repos/` 与 `REPO_SYNC_AT` 内存映射（`FETCH_HEAD` mtime 兜底重启后仍能读上次同步时间）。
- 客户/版本回写不在本 spec（CU-02）。

## 6. 业务规则 / 非功能
- **权限（按钮级）**：产品管理为**管理员/运营**功能。现有 `authGate`（server.mjs `LINK_OK`/`FIELD_OK` 白名单）只放行 `/api/projects`·`/api/versions`·`/api/spec-modules` 给免登录/现场只读；`project-save`·`project-delete`·`git-inspect`·`git-refresh`·`git-config-save` 不在只读白名单，需登录态（默认管理员）。〔**NEEDS-HUMAN 处置**：本单按 spec 推荐默认 = **维持部署现状「登录即可操作，不细分运营/管理员」**，未新增角色闸；实测部署 `authGate` 对非管理员/未登录即 deny-by-default 403（见 lessons 白名单机制）。**仍需人拍板**：是否要区分"运营可改产品 vs 仅管理员可改"。〕
- **数据权限**：产品为**全局资源**（不按医院/现场隔离），所有已登录运营/管理员可见全部产品。
- **校验**：id `^[a-z0-9][a-z0-9-]{0,39}$` 前后端双层（后端先小写化再校验，见 AC-7）；name 必填、库列宽 100 但前端限 40（`maxlength=40` + 计数器 `n/40`）。〔**NEEDS-HUMAN 处置**：本单按 spec 推荐默认 = **以 40 为准**（部署实现前端 `maxlength=40` + 后端 `name.length>40→400`，两端一致，见 server.mjs L721 / projects.html L457）。**仍需人拍板**：是否放宽到库列宽 100。〕
- **幂等**：`project-save` 按 id upsert，重复保存同 id 同内容结果一致；`git-refresh` 幂等（reset 到上游）。
- **并发**：`refreshRepos` 带 15 分钟冷却（`/api/versions`、`/api/project-git` 触发的是软刷新 `force=false`），手动「同步」`force=true` 立即拉；同一产品短时间多次同步以最后一次为准，无锁（clone/fetch 由 git 自身保证仓一致）。〔**NEEDS-HUMAN 处置**：本单按 spec 推荐默认 = **维持部署现状「无乐观锁，最后写覆盖」**（`project-save` 按 id upsert，`projects` 表无 updated_at/version 列，加锁需改表结构——不在本单范围/禁擅改库）。**仍需人拍板**：是否加版本号/updated_at 乐观锁（需先批准改 `projects` 表）。〕
