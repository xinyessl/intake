> **公共机制见导读 FS-06**（token 签发/验签、`LINK_OK` 白名单、`linkUserFrom` 访客身份识别、`/api/me` 访客上下文）。本条只规约**访客侧**：打开链接进干净提交页（B）、提交归属固定为 token 预置值（C）、token 校验拒绝（D）、白名单越权拒（E）。生成/吊销见 FS-18。

## 1. 用户故事 / 目标
作为**访客（无账号）**，我打开免登录链接即进对话，无需登录、无需选产品/现场（已锁定），把需求/BUG/咨询说给 AI，**自动归属到链接预置的产品/现场/版本**——我的提交只能落到链接指定的产品，改不了；越权即拒。

## 2. 范围
**包含：**
- **访客校验（已有 `linkUserFrom` + `LINK_OK`）**：token 经 query 或 cookie 传入，逐请求验签 + 过期 + project 存在校验；通过则获得访客身份 `role='link'`；访客只能访问 `LINK_OK` 白名单端点（deny-by-default），其余一律拒。
- **干净提交页（已有 `public/submit.html` · 访客态）**：`me.link` 为真时锁定并隐藏工作空间（`applyLinkLock`），锁定所属系统/现场/版本/类型，隐藏「我的提交」入口；仅保留 AI 对话提交（对齐 FS-04）。
- **提交归属（服务端强制 · 已有）**：访客经 `intake-submit`/`intake-chat`/`intake-commit-plan`/`consult` 提交时，**产品强制取 token 预置的 `link.project`**（前端传参无法覆盖）；现场/版本/reporter 取 token 预置值（前端空则回退 link）；`byRole` 记为 `field`。

**不包含：**
- 链接**生成/吊销**（在 **FS-18**）。
- 访客查看/追踪已提交工单（`/api/intake-list` **不在** `LINK_OK`，访客不可查列表；「我的提交」入口在访客态隐藏）。
- 登录账号（`impl`/`pm`/`admin`）的工作空间、批次、下载、版本回写（各在 FS-01~FS-05）。
- consult 的对话/引用/深入思考/附图等**对话链路细节**由 **FS-04** 主责；本条 C 组只约束"访客态归属固定"，AC-C5~C11 保留为对访客态同样生效的现状快照（引 FS-04）。

## 3. 验收标准（AC · Given-When-Then · 每条必须可自动化判定）

### B. 打开链接进干净提交页（访客身份识别 · `linkUserFrom` + `/api/me`）
- **AC-B1** Given 有效 token When `GET /submit.html?token=<token>`（未登录）Then `authGate` 命中 `LINK_OK` 放行，返回提交页 HTML；同时响应带 `Set-Cookie: intake_link=<token>; HttpOnly; SameSite=Lax; Path=/; Max-Age=31536000`（server.mjs L8325，记住访客身份，后续请求无需再带 query）。
- **AC-B2** Given 携带有效 token（query 或 cookie `intake_link`）When `GET /api/me` Then 返回 `{authEnabled, me:{role:"link", link:true, name:<site或"现场">, project, site, ver, ptype}, defaultAdmin}`（`linkUserFrom` 产出的访客上下文，`name = link.site || '现场'`；server.mjs L6052）。
- **AC-B3** Given 访客态（`me.link===true`）加载 `submit.html` When `applyLinkLock(me)` 执行（submit.html L411）Then：① `me.ptype∈{bug,requirement,consult}` 时类型切到该值且类型切换器禁用（`pointerEvents:none`）；② `me.project` 存在则选中并 lock 锁定所属系统；③ `me.ver` 非空则锁定版本下拉；④ `me.site` 非空则锁定现场；⑤ 显示"链接已锁定"提示 `#lockNote`（加 `.on`）、隐藏「我的提交」入口 `#mineBtn`（`display:none`，访客不可查列表）。
- **AC-B4** Given 访客态提交页 Then 不注入运营后台外壳（对齐 UI-01/FS-01：`submit.html` 本就是全屏现场页、不套后台壳；页面 `field.html` 外壳亦按 `me.link` 处理），呈现"无后台导航"的干净提交面。

### D. token 校验：过期 / 篡改 / 项目失效即拒
- **AC-D1** Given token 的 `exp < Date.now()`（已过期）When 任一访客请求携带它 Then `verifyToken` 返回 `null` → `linkUserFrom` 返回 `null` → 无访客身份；访问 `LINK_OK` 页面（如 `/submit.html`）走未认证 `login`（302 `/login.html`），访问 `/api/*` 未登录返回 `401 need-login`。
- **AC-D2** Given token 的签名段被篡改（HMAC 校验失败）When 携带它请求 Then `verifyToken` 返回 `null`（`b64u(hmac(p))!==sig`），访客身份不成立，同 AC-D1 拒绝。
- **AC-D3** Given token 有效但其 `project` 对应产品**已被删除**（`projById(p.project)` 为空）When 携带它请求 Then `linkUserFrom` 返回 `null`（`!projById(p.project)`），访客身份不成立、拒绝——即产品删除天然使其所有链接失效。
- **AC-D4** Given 缺失 token（无 query 无 cookie）When 未登录访问 `/api/intake-submit` Then 无访客身份、`authEnabled` 为真 → `401 need-login`（不放行）。

### E. 访客白名单越权拒（`LINK_OK` deny-by-default）
- **AC-E1** Given 有效访客身份 When 访问 `LINK_OK` 集内端点 —— `/`、`/submit.html`、`/api/intake-submit`、`/api/intake-chat`、`/api/intake-commit-plan`、`/api/consult`、`/api/projects`、`/api/customers`、`/api/versions`、`/api/spec-modules`、`/api/model-config` Then `authGate` 返回 `allow`（放行）。〔2026-09-02 校正：真实 `LINK_OK` 含 `/api/intake-commit-plan`（server.mjs L5900，FS-04 v2 访客建单端点），早稿漏列，已补。〕
- **AC-E2** Given 有效访客身份 When 访问**不在** `LINK_OK` 的 `/api/*`（如 `/api/intake-list`、`/api/intake-detail`、`/api/intake-transition`、`/api/accounts`、`/api/account-save`、`/api/submit-link`）Then `authGate` 返回 `forbidden` → `403 {error:"forbidden"}`。
- **AC-E3** Given 有效访客身份 When 访问**不在** `LINK_OK` 的**非** `/api/` 页面（如 `/inbox.html`、`/projects.html`、`/accounts.html`）Then `authGate` 返回 `login` → 302 到 `/login.html`（访客只能停在提交面）。
- **AC-E4** Given 访客身份仅在**无登录会话**时生效 When 访客同时也持有效登录 Cookie（`user` 非空）Then 走登录用户鉴权（`link = user ? null : linkUserFrom(...)`，server.mjs L6019），访客白名单不叠加登录权限——登录优先、link 让位。

## 4. 接口契约（对齐真实 server.mjs · 逐字段核过）
> ⚠️ **PRD §6 的 `GET /api/s/{token}` 端点真实不存在**（见导读 FS-06）。真实链路 = `linkUserFrom` 逐请求验签 + `/api/me` 取访客上下文 + `LINK_OK` 白名单闸 + 访客提交端点归属强制。

### 4.1 取访客上下文 `GET /api/me`（server.mjs L6052 · 访客态）
```
GET /api/me  （携带 ?token= 或 cookie intake_link，且无登录会话）
→ 200 { authEnabled:true,
        me:{ role:"link", link:true, name:<site||"现场">, project, site, ver, ptype },
        defaultAdmin:boolean }
```
- 访客上下文由 `linkUserFrom(req,url)` 产出（详见导读 FS-06 §3）；登录用户态返回 `pubUser(u)`；均无则 `me:null`。

### 4.2 访客校验闸 `linkUserFrom` + `authGate`（server.mjs L5895, L5901-5912）
```
linkUserFrom(req,url)：见导读 FS-06 §3①（tok=query|cookie → verifyToken → projById 校验）
authGate 访客分支（link && !user）：
  LINK_OK.has(pathname) ? 'allow' : pathname.startsWith('/api/') ? 'forbidden' : 'login'
LINK_OK = { '/', '/submit.html', '/api/intake-submit', '/api/intake-chat',
            '/api/intake-commit-plan', '/api/consult', '/api/projects', '/api/customers',
            '/api/versions', '/api/spec-modules', '/api/model-config' }
```
- 闸前恒放行集与 cookie 写入见导读 FS-06 §2/§3④。

### 4.3 访客提交端点（复用 FS-04 · 归属服务端强制）
```
POST /api/intake-submit        → server.mjs L7294：proj = projById(link?link.project:b.project)（强制 link.project）
POST /api/intake-chat          → server.mjs L7340：AI 对话/出计划，归属同上
POST /api/intake-commit-plan   → server.mjs L7402：按确认清单确定性建单，归属同上（FS-04 v2 访客建单入口）
POST /api/consult              → server.mjs L7459：type='consult'，SSE 流式；proj 同强制 link.project
```
- 四端点归属取值：`project = link.project`（强制，前端 project 被忽略）；`version = trim(b.version) || (link?link.ver:'')`；`site = trim(b.site) || (link?link.site:'')`；`reporter = link.name`；`byRole = 'field'`。
- **consult SSE 事件序（2026-08-10，AC-C5/C6）**：模型首个有效片段回调内，若本轮有实际注入命中，则先发 `{kb:[{q,a,subsystem,module,subsystemLabel}],kbInjected:true}` 一次，紧接 `{v:<piece>}`；之后 `{v}`×N，最终 `{done:true,convId,kbHits:<实际注入条数>,stopped}`。未命中/检索异常/未配模型/首片段前失败时无 `kb` 事件且 `kbHits=0`。引用字段由 `consultKbRefs` 统一精简，随对应助手消息 `kbRefs` 持久化；解析端忽略未知字段。
- 详细对话/归档契约见 **FS-04**（本条 depends_on FS-04）；本条只约束"访客态归属固定为 token 预置值、不可切医院/系统/版本"。

## 6. 业务规则 / 非功能
- **数据归属不可越权（硬约束）**：访客提交的**产品**由 token 的 `link.project` 服务端强制决定，前端传参无法覆盖（AC-C4）；site/version 亦以 token 预置为准（前端锁定 + 服务端回退）。
- **访客白名单 deny-by-default**：`LINK_OK` 之外一律拒（`/api/*`→403、页面→302 登录），访客**不可**查工单列表/详情、不可流转、不可管账号/生成链接（AC-E2/E3）。
- **登录优先**：`link = user ? null : linkUserFrom(...)`——有登录会话时访客身份让位，二者不叠加（AC-E4）。
- **留痕**：访客提交同样写工单 `history[]`（`by=link.name`、`byRole='field'`、`note='提交'/'对话提交（确认清单）'`），可追溯"谁（哪个现场）在何时提交"。
- **性能**：token 验签为无 IO 的 HMAC 计算，逐请求校验开销可忽略。

**已裁决（2026-07-22 · 见导读 FS-06 尾）：**
- **NH-1 可提交类型 → 三类都能（不限制）**：访客可提需求/BUG/咨询（或链接锁定某类），与登录现场一致；不做"访客可提类型白名单"收紧。
