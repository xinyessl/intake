> **本条大半是复用（♻️）。** 免登录链接的**生成**（`/api/submit-link`）、**校验**（`linkUserFrom`）、**访客白名单**（`LINK_OK` deny-by-default）、**干净提交页**（`public/submit.html` 的 `applyLinkLock`）在 `server.mjs` + `public/submit.html` **均已落地并跑通**。本 spec 的价值在于：① 把这套已有能力**规约化、可回归验证**（生成/打开/归属/校验/越权拒/吊销 每态一条可自动判定的 AC）；② 把访客干净提交页**对齐 FS-04 的 AI 对话提交**（复用 `intake-chat`/`consult`），并明确「归档上下文固定为 token 预置值、访客不可切医院/系统/版本」；③ 补齐**权限与安全边界**（HMAC 不可枚举、可吊销、`LINK_OK` 白名单外一律拒）。
>
> **⚠️ PRD 与真实实现差异（写 spec/测试务必按真实实现）：** PRD §6 写的 `GET /api/s/{token}` 端点**真实不存在**。真实实现是：token 从 URL query `?token=` 或 cookie `intake_link` 取，由 `linkUserFrom(req,url)` 在**每个请求的鉴权闸**里验签（`verifyToken` = HMAC 验签 + `exp` 过期 + `project` 存在校验），无独立"取上下文"端点；访客上下文经 `GET /api/me` 以 `{role:'link',link:true,project,site,ver,ptype}` 返回。本 spec 一律按真实实现（`submit-link` 生成 + `linkUserFrom` 逐请求校验 + `/api/me` 取上下文 + `LINK_OK` 白名单）写。
>
> **⚠️ 决策 D（两域名部署 / FS-08）影响本条：** field 与 admin 各用独立域名后，`submit-link` 现返回的**相对路径** `path:'/submit.html?token='+token` 打不通（访客可能从 admin 域拿到链接、需落到 field 域）——须改为返回 **field 域绝对地址**（`FIELD_ORIGIN + '/submit.html?token='+token`）。此改造归 **FS-08**（域名/配置层），本条只需在生成/展示链接的 AC 里引用"绝对地址由 FS-08 的 `FIELD_ORIGIN` 提供"。

## 1. 用户故事 / 目标
作为**运营/维护人员**，我要给某产品生成一条**免登录提交链接**（带预置的现场 site / 版本 ver / 可提交类型 type / 有效期 days），发给**现场临时人员或无账号用户**；他们凭链接直接打开一个**干净提交页**（无后台导航、无工作空间、仅 AI 对话提交），把需求 / BUG / 咨询说给 AI，**自动归属到链接预置的产品 / 现场 / 版本**——以便无账号场景也能规范收件，且访客越权即拒、链接可吊销。

作为**访客（无账号）**，我打开链接即进对话，无需登录、无需选产品/现场（已锁定），直接提交，我的提交只能落到链接指定的产品，改不了。

## 2. 范围
**包含：**
- **生成端（运营端调用 · 已有 `/api/submit-link`）**：管理员传 `project`（必填）+ `site` / `ver` / `type` / `days`（可选），返回 HMAC 签名 token + 提交页路径 `/submit.html?token=<token>`。
- **访客校验（已有 `linkUserFrom` + `LINK_OK`）**：token 经 query 或 cookie 传入，逐请求验签 + 过期 + project 存在校验；通过则获得访客身份 `role='link'`；访客只能访问 `LINK_OK` 白名单端点（deny-by-default），其余一律拒。
- **干净提交页（已有 `public/submit.html` · 访客态）**：`me.link` 为真时锁定并隐藏工作空间——锁定所属系统 / 现场 / 版本 / 类型（`applyLinkLock`），隐藏「我的提交」入口；仅保留 AI 对话提交（对齐 FS-04：`intake-chat` 进件 / `consult` 咨询）。
- **提交归属（服务端强制 · 已有）**：访客经 `intake-submit` / `intake-chat` / `consult` 提交时，**产品强制取 token 预置的 `link.project`**（前端传参无法覆盖）；现场 / 版本 / reporter 取 token 预置值（前端空则回退 link）；`byRole` 记为 `field`。
- **安全**：token HMAC-SHA256 签名不可枚举；可吊销（换 `data/link-secret` 令全部旧 token 失效 / 或 `exp` 到期单条失效）；密钥落 `data/link-secret` 文件、无库存储。

**不包含：**
- 免登录链接**生成 UI**（产品管理页的"生成链接"弹窗）——属产品管理 PD 侧，本条只规约 `/api/submit-link` 契约与访客链路，不落生成表单页。
- token 的**逐条吊销列表 / 管理台**（真实实现无 token 库存储，无法按单条吊销；只能整体换密钥或靠 exp 到期）→ 见 §6 NH。
- 访客查看/追踪已提交工单（`/api/intake-list` **不在** `LINK_OK`，访客不可查列表；「我的提交」入口在访客态隐藏）。
- 登录账号（`impl`/`pm`/`admin`）的工作空间、批次、下载、版本回写（各在 FS-01~FS-05）。

## 3. 验收标准（AC · Given-When-Then · 每条必须可自动化判定）

### A. 生成免登录链接（`POST /api/submit-link` · 运营端/管理员调用）
- **AC-A1** Given 管理员已登录 When `POST /api/submit-link {project:<存在的产品id>}` Then 返回 `200 {ok:true, token, path:"/submit.html?token=<token>", days:365}`（`days` 缺省 365）；`token` 形如 `<b64u payload>.<b64u hmac>`（含一个 `.`）。
- **AC-A2** Given `POST /api/submit-link {project:"__不存在__"}` Then 返回 `400 {ok:false, error:"项目不存在"}`（`projById(b.project)` 为空即拒，不签发 token）。〔2026-07-22 校正：真实实现返 **HTTP 400**（server.mjs L678），非本 spec 早稿写的 200；`ok:false` 语义不变。〕
- **AC-A3** Given `POST /api/submit-link {project:<id>, site:"XX医院", ver:"v1.2.0", type:"bug", days:30}` Then token 解出的 payload 含 `{project:<id>, site:"XX医院", ver:"v1.2.0", type:"bug", exp:<约30天后的毫秒时间戳>}`（`exp = Date.now()+days*86400000`）。
- **AC-A4** Given `days` 传 `0` / 负数 / 缺省 / 超大 When 生成 Then `days` 被夹到 `[1,3650]`（`Math.min(3650,Math.max(1,+days||365))`）：`0`→夹为默认 365、`-5`→夹为 365（`+(-5)||365`?——按实现 `+b.days||365`，`-5` 真值故取 -5 再 `Math.max(1,-5)=1`）、`9999`→夹为 3650。
- **AC-A5** Given `type` 传非 `bug|requirement|consult` 之一（如 `"任意"` 或缺省）When 生成 Then token 内 `type` 记为空串 `''`（`(b.type∈{bug,requirement,consult})?b.type:''`），表示"类型不锁定，访客可自选"。
- **AC-A6** Given 非管理员（`pm`/`impl`）或访客 When 调 `POST /api/submit-link` Then **被拒**——`/api/submit-link` 不在 `LINK_OK`/`FIELD_OK` 白名单，`authGate` deny-by-default 返回 `403 {error:"forbidden"}`（登录现场账号）/ `403 forbidden`（访客）。

### B. 打开链接进干净提交页（访客身份识别 · `linkUserFrom` + `/api/me`）
- **AC-B1** Given 有效 token When `GET /submit.html?token=<token>`（未登录）Then `authGate` 命中 `LINK_OK` 放行，返回提交页 HTML；同时响应带 `Set-Cookie: intake_link=<token>; HttpOnly; SameSite=Lax; Path=/; Max-Age=31536000`（记住访客身份，后续请求无需再带 query）。
- **AC-B2** Given 携带有效 token（query 或 cookie `intake_link`）When `GET /api/me` Then 返回 `{authEnabled, me:{role:"link", link:true, name:<site或"现场">, project, site, ver, ptype}, defaultAdmin}`（`linkUserFrom` 产出的访客上下文，`name = link.site || '现场'`）。
- **AC-B3** Given 访客态（`me.link===true`）加载 `submit.html` When `applyLinkLock(me)` 执行 Then：① `me.ptype∈{bug,requirement,consult}` 时类型切到该值且类型切换器禁用（`pointerEvents:none`）；② `me.project` 存在则选中并 `disabled` 锁定所属系统；③ `me.ver` 非空则锁定版本下拉；④ `me.site` 非空则锁定现场；⑤ 显示"链接已锁定"提示 `#lockNote`、隐藏「我的提交」入口 `#mineBtn`（访客不可查列表）。
- **AC-B4** Given 访客态提交页 Then 不注入运营后台外壳（对齐 UI-01：`shell.js` 见 `me.link` 不注入 App Shell；`submit.html` 本就是全屏现场页、不套后台壳），呈现"无后台导航"的干净提交面。

### C. 提交归属固定为 token 预置值（服务端强制 · 对齐 FS-04）
- **AC-C1** Given 访客态 When 经 `POST /api/intake-chat`（对话进件）达成归档 Then 新工单 `project` **强制取 `link.project`**（服务端 `projById(link?link.project:b.project)`，前端传的 `project` 被忽略）；`site` 取 `b.site||link.site`、`version` 取 `b.version||link.ver`；`reporter` 取 `link.name`（无账号）；`history[0].byRole='field'`。
- **AC-C2** Given 访客态 When 经 `POST /api/intake-submit`（表单/首轮提交）Then 同 AC-C1 的归属规则：`project=link.project`（强制）、`site/version` 前端空则回退 link 值、`reporter=link.name`、`byRole='field'`。
- **AC-C3** Given 访客态咨询 When `POST /api/consult` Then 生成 `type:'consult'` 记录，`project=link.project`（强制）、`site=b.site||link.site`、`version=b.version||link.ver`、`reporter=link.name`、`role='field'`；SSE 流式返回答复（复用 FS-04 咨询链路）。〔2026-07-22 修：原 server.mjs L971 `consult` 用 `projById(b.project)`（**未**对访客强制 link.project，是相对本 AC 及「数据归属不可越权（硬约束）」的真实安全缺口），已改为 `projById(link ? link.project : b.project)`，与 `intake-submit`/`intake-chat` 一致；登录用户 `link` 为空、取 `b.project` 不变。〕
- **AC-C4** Given 访客在前端**篡改** `project` 传参（如改成另一产品 id）When 提交 Then 归属仍落到 `link.project`（服务端不采信前端 project），不会串到其它产品——数据归属不可越权篡改。
- **AC-C5**（2026-08-10 修订 · 引用真实性）Given 咨询问题命中该产品经验库（`kbRetrieve(proj.id,qtext,5,2)` 有 hits）When `POST /api/consult` Then 普通与深入思考均把同一 `hits` 组装进 `consultSystem` 的 `kbBlock`；**只有模型已收到该提示且返回首个有效片段时**，服务端才在该片段的 `{v}` 事件前发一次 `data:{kb:[{q,a,subsystem,module,subsystemLabel}],kbInjected:true}`。前端只接受 `kbInjected===true` 的非空事件，在该助手答复后显示「已参考经验（N条）」折叠区；`done.kbHits` 为本轮实际注入并开始生成时的条数。仅检索命中但模型未配置、首片段前失败或返回空内容，均不得展示或计数，不能把“检索到”误报为“已参考”。
- **AC-C5b**（2026-08-10 修订 · 相关度门槛）Given 咨询问题只与某经验条目弱匹配（关键词 `sc===1` 且语义不相关）When `POST /api/consult` Then `kbRetrieve(proj.id,qtext,5,2)` 过滤该条，既不进入 `consultSystem` 也不展示；强关键词匹配或达到语义门槛的条目保留。其它 KB 检索调用方维持默认门槛，不受 consult 收紧影响。
- **AC-C6**（2026-08-10 修订 · 无命中/失败不误导）Given 未命中、检索异常、未注入或模型在首片段前失败 When `POST /api/consult` Then 不发非空 `kb` 事件、`done.kbHits=0`、前端不显示引用；检索异常降级为空命中且不阻断咨询。无命中时 `consultSystem` 明确禁止模型声称“根据历史经验库/根据经验库”，不得编造出处。
- **AC-C7**（2026-08-10 修订 · 点击咨询记录续聊及引用恢复）Given 实施端医院/系统视图有 `type=consult` 记录 When `reopenConsult` 拉取详情 Then 恢复 `item.chat[{role,text,kbRefs?}]`：助手消息的 `kbRefs` 仍显示在对应答复后；实时结束后引用亦随 `chat.messages` 进入 sessionStorage 草稿和 per-system 快照，刷新/切系统恢复不丢。续聊请求只发送 `role/content`，不能把客户端保存的 `kbRefs` 当成新一轮引用；服务端重建 chat 时按助手消息顺序保留旧引用，并只给本轮真实使用的助手消息挂新 `kbRefs`。其余同 convId/project/subsystem 续存、左右选中态与新对话语义保持既有契约。

### D. token 校验：过期 / 篡改 / 项目失效即拒
- **AC-D1** Given token 的 `exp < Date.now()`（已过期）When 任一访客请求携带它 Then `verifyToken` 返回 `null` → `linkUserFrom` 返回 `null` → 无访客身份；访问 `LINK_OK` 页面（如 `/submit.html`）走未认证 `login`（302 `/login.html`），访问 `/api/*` 未登录返回 `401 need-login`。
- **AC-D2** Given token 的签名段被篡改（HMAC 校验失败）When 携带它请求 Then `verifyToken` 返回 `null`（`b64u(hmac(p))!==sig`），访客身份不成立，同 AC-D1 拒绝。
- **AC-D3** Given token 有效但其 `project` 对应产品**已被删除**（`projById(p.project)` 为空）When 携带它请求 Then `linkUserFrom` 返回 `null`（`!projById(p.project)`），访客身份不成立、拒绝——即产品删除天然使其所有链接失效。
- **AC-D4** Given 缺失 token（无 query 无 cookie）When 未登录访问 `/api/intake-submit` Then 无访客身份、`authEnabled` 为真 → `401 need-login`（不放行）。

### E. 访客白名单越权拒（`LINK_OK` deny-by-default）
- **AC-E1** Given 有效访客身份 When 访问 `LINK_OK` 集内端点 —— `/`、`/submit.html`、`/api/intake-submit`、`/api/intake-chat`、`/api/consult`、`/api/projects`、`/api/customers`、`/api/versions`、`/api/spec-modules`、`/api/model-config` Then `authGate` 返回 `allow`（放行）。
- **AC-E2** Given 有效访客身份 When 访问**不在** `LINK_OK` 的 `/api/*`（如 `/api/intake-list`、`/api/intake-detail`、`/api/intake-transition`、`/api/accounts`、`/api/account-save`、`/api/submit-link`）Then `authGate` 返回 `forbidden` → `403 {error:"forbidden"}`。
- **AC-E3** Given 有效访客身份 When 访问**不在** `LINK_OK` 的**非** `/api/` 页面（如 `/inbox.html`、`/projects.html`、`/accounts.html`）Then `authGate` 返回 `login` → 302 到 `/login.html`（访客只能停在提交面）。
- **AC-E4** Given 访客身份仅在**无登录会话**时生效 When 访客同时也持有效登录 Cookie（`user` 非空）Then 走登录用户鉴权（`link = user ? null : linkUserFrom(...)`），访客白名单不叠加登录权限——登录优先、link 让位。

### F. 链接吊销 / 有效期
- **AC-F1** Given 单条链接需失效 When 其 `exp` 到期 Then 该 token 自动失效（AC-D1），无需后台操作——"有效期"即单条链接的吊销机制。
- **AC-F2** Given 需**批量吊销全部**已发链接 When 更换密钥文件 `data/link-secret`（删除令下次 `linkSecret()` 重新随机生成 / 或替换其内容）Then 所有旧 token 的 HMAC 验签全部失败（AC-D2），一次性失效——这是真实实现下的"整体吊销"手段。
- **AC-F3** Given `data/link-secret` 不存在 When 首次调用 `linkSecret()` Then 自动生成 24 字节随机 hex 写入该文件（`crypto.randomBytes(24).toString('hex')`）；同一进程后续复用同密钥，签发/验签一致。

## 4. 接口契约（对齐真实 server.mjs · 逐字段核过）
> ⚠️ **PRD §6 的 `GET /api/s/{token}` 端点真实不存在。** 真实链路 = `submit-link` 生成 + `linkUserFrom` 逐请求验签 + `/api/me` 取访客上下文 + `LINK_OK` 白名单闸。以下按真实实现写。

### 4.1 生成链接 `POST /api/submit-link`（server.mjs L643-652 · 仅管理员，authGate deny-by-default）
```
POST /api/submit-link
body: { project:string(必填,产品id), site?:string, ver?:string,
        type?:'bug'|'requirement'|'consult'(其它→''), days?:number(1..3650, 缺省365) }
→ 200 { ok:true, token:string, path:"/submit.html?token=<token>", days:number }
   或 400 { ok:false, error:"项目不存在" }（projById 为空 · server.mjs L678）
   或 400 { ok:false, error:"bad json"/"请求体过大" }（body 异常）
错误码：403 forbidden（非管理员——不在 LINK_OK/FIELD_OK，authGate 拒）
```
- **签发逻辑**（`signToken`）：`payload = {project:proj.id, site:trim(site), ver:trim(ver), type:t, exp:Date.now()+days*86400000}`；`token = b64u(JSON(payload)) + '.' + b64u(HMAC-SHA256(payload, linkSecret()))`。
- `days` 夹取：`Math.min(3650, Math.max(1, +b.days||365))`。
- `type` 归一：`(b.type==='bug'||'requirement'||'consult') ? b.type : ''`。

### 4.2 取访客上下文 `GET /api/me`（server.mjs L642 · 访客态）
```
GET /api/me  （携带 ?token= 或 cookie intake_link，且无登录会话）
→ 200 { authEnabled:true,
        me:{ role:"link", link:true, name:<site||"现场">, project, site, ver, ptype },
        defaultAdmin:boolean }
```
- 访客上下文由 `linkUserFrom(req,url)` 产出：`{link:true, role:'link', project, site, ver, ptype(=payload.type), name(=site||'现场')}`。
- 登录用户态返回 `pubUser(u)`（见 UI-01 §4）；均无则 `me:null`。

### 4.3 访客校验闸 `linkUserFrom` + `authGate`（server.mjs L576, L581-592）
```
linkUserFrom(req,url):
  tok = url.searchParams.get('token') || parseCookies(req).intake_link
  若无 tok → null
  p = verifyToken(tok)   // HMAC 验签 + exp 未过期
  若 !p || !p.project || !projById(p.project) → null
  否则 → { link:true, role:'link', project:p.project, site:p.site||'', ver:p.ver||'', ptype:p.type||'', name:p.site||'现场' }

authGate(pathname,user,link)（访客分支，link && !user）:
  LINK_OK.has(pathname) ? 'allow'
  : pathname.startsWith('/api/') ? 'forbidden'（→403）
  : 'login'（→302 /login.html）

LINK_OK = { '/', '/submit.html', '/api/intake-submit', '/api/intake-chat',
            '/api/consult', '/api/projects', '/api/customers', '/api/versions',
            '/api/spec-modules', '/api/model-config' }
```
- 静态资源 `/assets/*`、`/vendor/*` 与 `/login.html`/`/api/login`/`/api/logout`/`/api/me`/`/api/health`/`/api/version` 恒放行（在闸前置白名单，访客亦可）。
- 首次带 `?token=` 访问任意页时，响应写 `Set-Cookie: intake_link=<token>; HttpOnly; SameSite=Lax; Path=/; Max-Age=31536000`（server.mjs L1104）。

### 4.4 访客提交端点（复用 FS-04 · 归属服务端强制）
```
POST /api/intake-submit  → server.mjs L874：proj = projById(link?link.project:b.project)（强制 link.project）
POST /api/intake-chat    → server.mjs L905：同上，AI 对话达标即归档建工单
POST /api/consult        → type='consult'，SSE 流式；proj 同强制 link.project
```
- 三端点归属取值：`project = link.project`（强制，前端 project 被忽略）；`version = trim(b.version) || (link?link.ver:'')`；`site = trim(b.site) || (link?link.site:'')`；`reporter = link.name`；`byRole = 'field'`。
- **consult SSE 事件序（2026-08-10，AC-C5/C6）**：模型首个有效片段回调内，若本轮有实际注入的命中，则先发 `{kb:[{q,a,subsystem,module,subsystemLabel}],kbInjected:true}` 一次，紧接 `{v:<piece>}`；之后 `{v}`×N，最终 `{done:true,convId,kbHits:<实际注入条数>,stopped}`。未命中、检索异常、未配模型或首片段前失败时没有 `kb` 事件且 `kbHits=0`。引用字段由 `consultKbRefs` 统一精简，并随对应助手消息的 `kbRefs` 持久化；解析端忽略未知字段。
- 详细对话/归档契约见 **FS-04**（本条 depends_on FS-04）；本条只约束"访客态归属固定为 token 预置值、不可切医院/系统/版本"。

## 5. 数据契约
> **token 无库存储**——HMAC 自验签，密钥文件 + payload 即全部状态。真实库 5 表（`db.mjs`）**无** `intake_submit_link` 表（PRD §5 的概念表在本平台落为文件+HMAC）。

**① token（无持久化）**
- 结构：`b64u(JSON(payload)) + '.' + b64u(HMAC-SHA256(payload, secret))`。
- payload 字段：`{ project:string, site:string, ver:string, type:''|'bug'|'requirement'|'consult', exp:number(毫秒时间戳) }`。
- 验签：重算 `HMAC-SHA256(payload_b64u, secret)` 比对签名段；再验 `exp >= Date.now()`；再验 `projById(project)` 存在。

**② 密钥文件 `data/link-secret`**
- 内容：24 字节随机 hex（`crypto.randomBytes(24).toString('hex')`，48 字符）。
- 生命周期：`linkSecret()` 读文件；不存在则生成并写入 `DATA_DIR/link-secret`。**更换/删除该文件 = 整体吊销所有旧 token**（AC-F2）。

**③ 访客提交落库（复用现有 `intakes` 表）**
- 访客经 `intake-submit`/`intake-chat`/`consult` 建的工单落 `intakes` 表（真实列见 db.mjs），与登录用户提交同表同结构；`project_id`/`site`/`version` 取 token 预置值，`data JSON` 存整份内存对象（含 `history[]` 留痕、`reporter=link.name`、`byRole='field'`）。**本条不新增表/列。**

## 6. 业务规则 / 非功能
- **数据归属不可越权（硬约束）**：访客提交的**产品**由 token 的 `link.project` 服务端强制决定，前端传参无法覆盖（AC-C4）；site/version 亦以 token 预置为准（前端锁定 + 服务端回退）。
- **访客白名单 deny-by-default**：`LINK_OK` 之外一律拒（`/api/*`→403、页面→302 登录），访客**不可**查工单列表/详情、不可流转、不可管账号/生成链接（AC-E2/E3）。
- **登录优先**：`link = user ? null : linkUserFrom(...)`——有登录会话时访客身份让位，二者不叠加（AC-E4）。
- **不可枚举**：token 含 HMAC-SHA256 签名，无密钥无法伪造/枚举有效 token（AC-D2）。
- **可吊销**：单条靠 `exp` 到期（AC-F1）；批量靠换 `data/link-secret`（AC-F2）。真实实现**无按单条主动吊销**能力（无 token 库）→ 见 NH-2。
- **留痕**：访客提交同样写工单 `history[]`（`by=link.name`、`byRole='field'`、`note='提交'/'对话提交'`），可追溯"谁（哪个现场）在何时提交"。
- **生成端权限**：`/api/submit-link` 仅管理员可调（`isAdmin`，含遗留 `dev`）——非管理员/访客被 `authGate` 拒（AC-A6）。
- **性能**：token 验签为无 IO 的 HMAC 计算（密钥文件仅首次读、进程内复用），逐请求校验开销可忽略。

**已裁决（2026-07-22 · 人工拍板，均"保持现状/从简"，无需再确认 diff）：**
- **NH-1 可提交类型 → 三类都能（不限制）**：访客可提需求/BUG/咨询（或链接锁定某类），与登录现场一致；**不做**"访客可提类型白名单"收紧。
- **NH-2 单条主动吊销 → 不做**：无 token 库，靠 `exp` 到期或换 `data/link-secret` 整体失效；**不引入 token 库/黑名单、不改库**（遵护栏）。
- **NH-3 有效期 → 保持 `days=365` 缺省、上限 3650**：不改现状。
- **NH-4 绑定范围 → 保持单产品 + 单现场**：一条 token 绑单一 `project` + 单一 `site`（可空）；**不做**多医院/多产品、不强制必须绑 site。
- **NH-5 验收人**：`owner_human` 待指派（非阻断）。

  - **「深入思考」连真库冒烟（AC-C10）**：consult 带 `deep:true` → 端点接受 deep 参数、SSE 正常出流（本地无 clone 源码仓时 `codeSearch` 返回空/少，consult 仍正常答，只是没源码片段）、落库 `type=consult`；带 `deep:false`/不带 → 默认路径正常——`tools/fs-06.test.mjs` B-DEEP-C1/C2。
